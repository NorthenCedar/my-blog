最初想搭这个站的时候，我的念头非常朴素：弄个清爽的静态博客，写写代码笔记，放几张拍得凑合的照片。

然后手就慢慢不听使唤了。

先是嫌纯文字页太素，给首页塞了根会自己转的 3D DNA 双螺旋和一百多条跟着鼠标晃的流场线；接着觉得滚到底直接见页脚太无聊，干脆在底部挖了条 76 片蝴蝶组成的切片隧道，穿过去正好掉进相册；相册做着做着又上了头，显影板、螺旋盘、球幕、散片画布一口气搓出六套模板；顺手把主题开关换成了 WebGPU 软条，给播放器和友链套上了两套玻璃材质，最后还为了防脚本小子把前后端接口从头到脚加了道锁。

旧版那篇建站记录早就不够看了，干脆删掉重写。前半段聊聊这个站是怎么搭起来、几个花心思的组件背后大概是什么路子；后半段记几个真正有技术含量、折腾得我半夜对着屏幕怀疑人生的坑——那种“忘了放 favicon 报 404”之类的傻坑就不拿出来献丑了。

## 一、底子怎么搭的

整站的骨架不算复杂：**Astro 静态生成 + Cloudflare Pages Functions + D1（SQLite）**。

能静态化的东西全部在构建期烤死成 HTML，文章、归档、说说、相册、项目页统统放在 `content/` 目录下，由 Markdown 和文件夹结构驱动，主题代码本身不持有任何正文。比如想加一本新相册，直接往 `content/gallery/` 里丢一个文件夹，构建脚本会自动把源图压成多档带内容哈希的 WebP、更新清单并生成对应路由——原图压根不上生产环境，产物目录既干净，又能放心地给 `*.webp` 和 `/_astro/*` 挂上一年期的 `immutable` 长缓存。

动态部分全丢给 Cloudflare Pages Functions 和 D1，用来撑访客账密体系、留言回复、点赞、阅读量、友链自助申请和站主小铃铛提醒。为了不每次发文章都手动敲 git，后来我还顺手给自己攒了一套写作台，本地和云端都能直接改正文、传图、维护友链。

全站视觉走了两套配色：亮色是纸白配墨绿，暗色是暖黑配辉光橙。顶栏那根看着像果冻一样的主题滑块，底层是 TypeGPU / WebGPU 渲染的 **Jelly Slider**。拖动它的时候页面不是等松手才“啪”一下切色，而是靠一套连续权重变量 `--theme-w`（从 `0` 滑到 `1`）配合 `color-mix` 实时插值，连图片底纹的 CSS 滤镜和画布里的星链颜色都会跟着手指一起过渡。

换页体验也折腾过一轮。Astro 的 SPA 路由如果直接裸用，点击链接后往往得干等网络拉完页面才开始播过渡动画，体感黏糊糊的。我把过渡改成了即时两段式：点击当帧立刻拉起墨色遮罩，同时后台并行请求目标页和样式，外加悬停、视口停留、浏览器空闲三路预取和内存缓存。等到 DOM 替换完立刻顺着斜切揭幕，把“点了没反应”那半拍尴尬空窗基本抹平了。

## 二、两套玻璃板块是怎么做出来的

站里的玻璃看着是一家子，其实背地里分了两套实现，各管各的地盘。

第一套是**毛玻璃面板**（`.music-glass`），用在展开的歌单播放器、消息小铃铛弹层，还有友链卡片上。核心思路不稀奇：`backdrop-filter: blur(5px) saturate(1.12)` 负责背后的模糊和提饱和，但细节全在“像一块有厚度的玻璃”上——我给它叠了内外四层阴影（外投影抬起高度，顶部亮内边模拟折射高光，底部微暗边兜住轮廓），再在 `::before` 伪元素上铺一条 135° 斜向高光渐变，顺手用 `isolation: isolate` 把 `::before` 关在组件自己的层叠上下文里，免得它一脚踩空掉到整个 `body` 后面。友链卡片稍微特殊点，因为卡片右上角还挂着星座装置的节点星（也占了 `::before`），所以干脆在卡片里面塞了一层独立的底片来挂毛玻璃，各走各的道，互不抢位。

第二套就野一点，是播放器收起后的药丸条和播放圆钮用的**液态镜片玻璃**（`.liquid-glass`）。光靠高斯模糊做不出边缘折射感，于是请出了 SVG 滤镜里的 `<feImage>` + `<feDisplacementMap>`：先把按形状算好的红绿通道位移图转成 base64 直接内联进页面（省得外部图片还没加载完，滤镜先把整块背景拐跑），再通过 `backdrop-filter: url('#glass-pill') saturate(1.2)` 让边缘产生真实的像素位移。最外面再拿 `conic-gradient` 配合 `mask-composite: exclude` 抠出一圈 1 像素的环绕折光边，中心留清透，边缘才亮。

两套材质都留了 `@supports` 和 `prefers-reduced-transparency` 的降级分支——浏览器不支持或者用户开了“降低透明度”，就老老实实退回高对比度半透明纸面，绝不把字糊到看不清。

## 三、首页那片会呼吸的流场线

首页背景那片跟着鼠标软绵绵晃动的线条，很多人第一眼以为是张网格，其实它压根没有横线——就是 116 条平行的竖直 SVG `<path>`。

整片线能动起来，靠的是叠加在每个顶点上的三股力：

1. **Perlin 噪声场**：拿坐标和时间喂给二维 Perlin 噪声，算出方向角再拆成横向和纵向位移，让整片线条像地形等高线一样缓慢流淌。
2. **帧率无关的弹簧 + 横向呼吸**：只加一层统一弹簧其实肉眼根本看不出“弹性”（全场一起慢半拍，没有参照物），所以又叠加了一层沿横轴带波长的周期“呼吸”调制，而且故意让它绕过弹簧直接乘在输出上，避免被二阶系统衰减后跟主波相互抵消。
3. **指针扰动**：鼠标划过时，按移动方向和速度给附近顶点一把推力，同时严格加上 `±100` 的位移限幅、回弹系数和阻尼。限幅和阻尼少一个都不行——早先漏写的时候，鼠标往上一放，所有顶点直接被踹飞出屏幕，活生生演了一出“指针所到之处，蛛网寸草不生”。

性能上没搞花活：每帧只重写 `<path>` 的 `d` 属性，完全不增删 DOM，滚出视口立刻停帧。还有一个偷懒但很顺眼的设计——开场动画里从中间一条线铺开的那批线条，**就是首屏这批线本身**，没有另做一套假覆盖层，所以开场遮罩一撤，线条严丝合缝接着流，不存在闪一下换演员的破绽。

## 四、首页底部的蝴蝶切片隧道

首页滚到最底下，会穿过一扇带 3D 透视的双层玻璃窗，进到一条由 76 片毛玻璃切片排成的隧道里，穿到尽头屏幕一绿，直接切去相册页。

看起来隧道里有一群蝴蝶在扑着翅膀往前飞，但真相有点反直觉：**整个 3D 场景里，从头到尾没有一只蝴蝶在动。**

我拿一个开源蝴蝶模型做了抽稀和双色重映射（暗部翅脉翻白、亮部翼膜染淡黄），然后在初始化时用带二次、三次谐波的波形，一次性把不同拍翼阶段的姿态**烘焙**成几份静态几何体，按顺序钉死在 76 片软边毛玻璃上。做形变的时候特意加了翅膀掩膜——只有翅膜顶点跟着旋转，躯干、触角和六条腿权重恒为 0，不然扇着扇着触角就会在半空拧成麻花。中央隧道外围再铺一圈中心 3×3 留空的玻璃柱阵，免得贴脸遮视野。

滚动页面时，场景里所有蝴蝶和玻璃的坐标一行都不改，动来动去的只有沿着基准轴往前推的摄像机。镜头前方固定距离的那一片会被硬切成实体，前后其余切片和蝴蝶一起压成毛玻璃同款透明度——连续经过不同翼相的静态标本，大脑自动就把它脑补成了飞舞。如果按住鼠标拖歪视角，就能看见周围整齐的玻璃柱阵；手一滚滚轮，视角又乖乖回正。

至于入口那扇双层玻璃窗，是用纯函数按滚动进度现算四个顶点的透视投影，拼出同一条 SVG 路径，既拿去做画布裁切、又拿去画玻璃描边和四角连线，反向往上滚还能原路收回去。

## 五、相册的舞台与六套模板

相册这块算是我折腾得最放飞的一块。总入口 `/gallery/` 做成了整屏翻页舞台，里面塞了两台独立装置加单册封面：

- **第一屏显影板**：一块深墨绿底板，每次进来随机抽一张横幅照片藏在底下。鼠标或者手指在上面涂抹时，照片像泡在显影液里一样浮出来，过一两秒又沿着边缘缩回纯色。底层其实没用 WebGL，直接在 Canvas 2D 里跑了一套简化的流体模拟：每帧拿卷曲噪声对密度场做半拉格朗日回溯（擦痕自己会漂、会扭），配合线性衰减和极窄阈值 + fbm 边缘扰动，退去时才会有水渍往回收的劲儿。
- **第二屏弧形封面 & 全屏螺旋盘**：封面区可以左右拖拽翻册；另外还单独劈了个 `/gallery/spiral/`，用 3D 透视把照片排成一条真正能卷回来的螺旋盘。

点进任意一本相册之后，只需在对应文件夹的 `index.md` 里改一行 `layout`，就能在六套展示模板里随便切：

- `scatter`（散片画布）：一张可以随意拖拽、缩放的无界桌面，每张照片带不同的 `depth` 系数，拖起来有错落视差；
- `slices`（悬浮切片）：滚轮和拖拽都能甩动的一列 3D 纵深相片；
- `dome`（球幕画廊）和 `infinite`（无限球面菜单）：把照片贴到球面上，像转地球仪一样翻着看；
- `willow`（3D 玻璃展厅）：WebGL 空间陈列，配前面那套液态玻璃按钮；
- `wall`（瀑布流砖墙）：最稳妥的网格索引，同时也充当兜底——浏览器不给力、WebGL 上下文丢了、或者用户开了减少动效，所有花哨模板都会无缝退回这堵砖墙。

除了相册，站里其余页面也顺手各塞了点小玩意儿：关于页是一台 400 片双纽线鳍拼出来的立体无限环，标签页是点一下会泛波纹的百褶环，友链页是鼠标停得越久连线越密的星座画布，留言页有声纹带，归档页侧边挂了把跟滚轮走的索引卷尺。规矩倒是统一的：所有纯装饰都关在视口外就停帧，减少动效一律退回静态，不拖垮看字。

## 六、这个站是怎么防恶意攻击的

既然上了动态接口（访客账户、留言、点赞、友链申请），就得把门窗关严实——虽然小博客未必入得了大佬法眼，但网上的自动化扫描器和垃圾评论脚本可不管你流量大不大，见缝就钻。

我主要从四层往下锁：

1. **浏览器响应头先立规矩**：所有经过 Cloudflare Middleware 的页面和接口统一补安全头（`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy`、`Permissions-Policy`、`HSTS`），HTML 挂严格 CSP——`script-src-attr 'none'` 直接掐死所有内联事件、`object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'self'`，允许执行的内联脚本全按 SHA-256 哈希放行。
2. **写接口默认不信任客户端**：评论、点赞、友链申请等写操作全部核验 `Origin`、`Sec-Fetch-Site` 和 `Content-Type: application/json`，关键变更再要求自定义请求头防跨站请求伪造。读取 JSON 请求体时，先看 `Content-Length` 快速拒掉离谱大包，真正读流时再按实际字节数硬掐上限（防止伪造长度头或分块传输把内存撑爆）。表单里藏了真人看不见的蜜罐字段——脚本一旦填了，接口照样大方回一个 `201` 假装成功，背地里根本不写库，让爬虫以为自己得手了赶紧滚蛋。限流则直接写进 D1，用单条 SQL 原子核对并占额，并发请求别想钻空子抢同一份额度。
3. **输入清洗与账号隔离**：昵称、正文、友链描述一律拦控制字符和 BiDi 双向文本伪造字符，拒绝尖括号脚本片段、`javascript:`/`data:` 等危险协议以及带 `user:pass@` 的畸形网址；站主保留昵称先做 `NFKC` 归一化再比对，防各种全角、零宽字符冒充。访客密码服务端用 `scrypt` 派生（顺带躲开了 Cloudflare 生产环境对高迭代 PBKDF2 的限制），校验走常量时间比对，数据库里只留会话令牌的 SHA-256 哈希，恢复码用一次就作废，改密码顺手把所有旧会话一锅端。
4. **堵住只读接口的“读放大”**：之前专门对着一篇安全文章复查过自家 GET 接口，又补了一轮加固——所有公开查询接口实行参数白名单，多传一个未知参数或者重复参数直接 `400`（顺便挡掉靠 `?rnd=xxx` 穿透边缘缓存的玩法）；批量查点赞或回复的 `slugs` 参数限制原始字节长度并改成有界逗号扫描，单次拉取回复的 SQL 行数设死上限，防止有人拼一串巨型参数把免费版 D1 的读额度瞬间抽干。

## 七、那些真把我折腾够呛的坑

### 1. Astro 作用域样式的静默背刺，外加 SVG 的默认黑漆

把首页原型搬进 Astro 的时候，最邪门的一幕出现了：Three.js 跑出来的 DNA 突然竖成一根电线杆，背景那片流场线糊成一团黑漆，控制台居然干干净净，连条黄警告都没有。

我第一反应去怀疑是不是 3D 倾角抄错了，查了半天才反应过来：**DNA 的 `<canvas>` 和流场线的 `<path>` 都是脚本在运行时动态塞进 DOM 的**。Astro 组件里的 `<style>` 默认会给选择器每一段贴上 `[data-astro-cid-xxx]` 做作用域隔离，而这个属性只有编译期写在模板里的标签才带。运行时 `createElement` 出来的节点身上光溜溜的，样式直接静默失效。

更损的是 SVG `<path>` 的默认 `fill` 是纯黑色。`fill: none` 那条样式一哑火，一百多条细线不是消失，而是齐刷刷变成一百多个黑色实心多边形叠在一起，丑得非常有冲击力。

**解法**：凡是带作用域的框架里，给运行时动态插入的 DOM 写样式，老老实实套 `:global()`。排查动态节点样式异常时，先看 DevTools 里选择器匹没匹配上，别上来就重构 3D 引擎。

### 2. `transform` 和 `backdrop-filter` 偷偷给 `fixed` 当了“包含块”

这个坑在站里连着撞了三次，每次死法都不太一样，堪称 CSS 界的惯犯：

- 关于页切进来的时候，视口底纹莫名其妙从下往上跳一截；
- 归档页换页动画播那不到一秒钟里，右侧卷尺偏了快 600 像素，两个年份直接叠成重影；
- 手机端点开内页导航抽屉，本该铺满全屏的菜单只剩顶上 62 像素一条细缝，十个链接全被裁没了。

罪魁祸首全是 CSS 里那条平时没人提的冷规则：平时 `position: fixed` 是认视口当参照系的，可只要它上面任何一个祖先带了 `transform`、`filter`、`backdrop-filter`、`will-change` 里的任意一个，**那个祖先就会原地篡位，变成内部 `fixed` 元素的包含块，顺手再立一层层叠上下文**。页面过渡动画给 `.shell` 加了 `transform`，底纹和卷尺就跟着跳；顶栏为了好看加了 `backdrop-filter` 毛玻璃，塞在里面的抽屉就被死死锁在了顶栏那 62 像素的盒子里。

**解法**：在公共布局里专门把 `.shell` 外面劈出一个 `plate` 具名插槽，所有全屏视口底纹和装置画布全住外面，天然免疫过渡变换；导航抽屉的 DOM 也老老实实挪出毛玻璃顶栏，别跟它同檐。

### 3. 3D 模型自转变成“甩流星锤”，AABB 还帮着量歪

首页 DNA 要求绕着自身中心轴安静自转。第一版跑起来，好家伙，整根双螺旋在画面里左右乱甩，像有人抡着根发光的流星锤。

连猜两次层级和倾角都不对，干脆停手不看画面，直接解析模型顶点算主成分分析（PCA）。一算长轴几乎笔直贴着 Y 轴，模型根本没歪，错的是变换顺序——Three.js 里 `position` 是在父空间平移，不吃自身 `scale`。我先设了 `position = -center` 再放大 `k` 倍，平移量没跟着放大，旋转轴直接被甩到了模型外面，自转就成了公转。把 `scale` 挪到前面、`position` 乘上 `k`，旋转漂移立刻从近 300 像素跌到 0.3 像素。

紧接着顺手用 `Box3.setFromObject` 回算居中，结果又偏了。因为那是**轴对齐包围盒（AABB）**，一根细长柱体斜 26° 之后，贴着坐标轴画出来的外框宽度会虚胀四五倍。拿虚胀的框当真实尺寸用，不偏才怪——后来乖乖改成了逐顶点投影。

### 4. `aspect-ratio` 遇上绝对定位，354px 膨胀成 3455px

DNA 容器是个 900:3200 的细长条，我图省事只写了 `position: absolute`、`height` 和 `aspect-ratio`，指望浏览器顺手算出 354px 的宽。结果在单文件原型里好好的，搬进正式站之后容器宽度直接飙到 3455px，把首屏撑穿了十倍。

拆开一看是个循环依赖：绝对定位且宽为 `auto` 的盒子走收缩适应，等着里面的 `<canvas>` 撑开；而 `<canvas>` 写的又是 `width: 100%`，回头等着父容器给宽度。两边大眼瞪小眼，最终收敛到哪全看外层父容器有多宽。

**解法**：`aspect-ratio` 适合已知一边推另一边，别让它跟百分比子元素互相猜。直接 `width: calc(height * 900 / 3200)` 算死，一劳永逸。

### 5. 显影板调了五轮笔触都不像水，因为漏了“水流”本身

做相册第一屏显影板时，我想要的是鼠标一划，画面像在水面上荡开、边缘自己扭动、过一两秒再顺着轮廓缩回去的质感。前五轮我跟画笔死磕——换噪声形状、改羽化半径、调指数衰减，怎么弄都像拿湿抹布擦黑板，擦完一团灰扑扑地均匀淡掉，毫无水感。

后来彻底推倒，才想明白“像水”根本不在画笔长什么样，而在**场是怎么推进的**：

- 密度场每帧必须被卷曲噪声流场做一次**半拉格朗日回溯**（advection），这样擦痕才不是盖上去就冻住的印章，而是真的会被水流推着漂、边缘一直在扭；
- 衰减要改成**线性衰减**，再配一个极窄的硬阈值带和 fbm 边缘扰动——这样退去时是等值线从外往里收，看起来就像水渍沿着路径缩回去了，顺手还治好了 8 位 alpha 乘性衰减永远归不了零、留一层鬼影的老毛病。

### 6. 拖动主题软条时卡死在半路，松手才“啪”一下变色

给主题软条做拖动实时预览时，刚写完那一版非常喜剧：手指拖着滑块从亮拉到暗，整页大部分区域纹丝不动，结果手一松开，底纹、滤镜、画布全在最后一帧“啪”一下闪现变橙。

扒出来三个洞凑在一块：第一，首页有批暗色变量是覆写在 `body` 上的，而预览脚本只读了 `html` 根元素，压根没采到这些值；第二，透明度、水波强度这类纯数值 token 没法塞进 `color-mix`，被直接跳过；第三，图片滤镜和 Canvas 画布根本不认 CSS 里的 `color-mix` 字符串。

**解法**：根元素和 `body` 分层采样、在哪声明就往哪写回；给全局加一个 `0..1` 的纯数字权重 `--theme-w`，滤镜和底纹浓度全写成按 `--theme-w` 插值的 `calc()`；再把当前进度的纯 hex 中间色通过自定义事件广播给各页 Canvas 装置。整套链路打通后，拖动软条时从纸面到底纹再到星链终于一起丝滑变色。

### 7. 时间差了 1000 倍，以及“高刷屏弹性翻倍”

首页流场线刚移植完的时候，线条站得笔直纹丝不动。拿脚本一量，顶点移动速度是每秒 0.006 像素——不是不动，是慢得像板块漂移。查了半天发现是时间单位对岔了，噪声函数吃的是毫秒级时间戳，我顺手把 `performance.now()` 除了个 1000，整片流场喜提千倍慢放。

修完单位加上弹簧弹性，又撞上第二个坑：在 120Hz 显示器上晃得比 60Hz 快整整一倍。原因很朴素，最初的阻尼和弹性系数是“每帧乘一次”，等效固有频率直接跟刷新率挂钩。改成吃真实 `dt` 的半隐式欧拉积分之后，不管在 60Hz 还是高刷屏上，手感总算一致了。

### 8. 蝴蝶隧道往回滚，摄像机突然向后翻了 116°

蝴蝶切片隧道往下滚的时候岁月静好，一往上回滚，画面突然来了个大掉头，两侧的玻璃柱阵瞬间全没了。

排查半天，发现我当时给摄像机位置多套了一层平滑滞后：往下滚时注视点走在相机前面，一切正常；往回滚时相机因为滞后反超了注视点，注视点掉到相机屁股后面，镜头自然原地倒转了 116°。

**解法**：从结构上断绝这种可能——机位和注视点改用同一个链锚点，视线方向只由方位角和俯仰角算出来，跟滚动方向和位置彻底解耦。不管怎么来回狂搓滚轮，朝向稳如老狗。

### 9. 写了一堆测试全绿，页面却照样是坏的

为了防止改东坏西，我给站里写了一大堆自动化测试（现在攒了一百六十多个测试文件）。但最讽刺的坑恰恰出在测试自己身上：

- 有一次测试断定产物 CSS 里缺一条规则，死活报红。我翻源码明明写着，最后发现那段 CSS 太短，被 Astro 自动内联进了 HTML 的 `<style>` 标签里，而我的测试只扫描了外链的 `dist/_astro/*.css`；
- 另一次更绝：我在一个 SVG 图标的注释里顺手写了句“颜色用 `--accent`”，所有字符串断言全绿，结果浏览器按 XML 规范——注释里不允许出现连续双短横线 `--`——直接把整张 SVG 判了死刑，线上图标凭空消失。

打那以后我学乖了：写完一条关键断言，先故意把对应的源码改坏跑一遍。如果改坏了它还不红，那它不是护栏，是安慰剂。
