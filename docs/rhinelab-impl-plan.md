# 莱茵方向 · 落地实施计划（原型 → `src/`）

> **这份计划解决什么**：把 4 个自包含原型（内容写死、纯 CSS/JS）搬成真实站点（Astro 7 + 内容集合 + 组件 + 构建测试）。
> 中间有 6 个断层，不是"改样式"能覆盖的。
>
> 所有"现状"列的数字都是本轮实测的，不是估的。

---

## 1. 现状差集（实测）

| 维度 | 原型 `prototype/terminal/` | 真实站点 `src/` |
|---|---|---|
| **配色** | 乳白 `#FAFAF7` + 绿 `#2D7D46` | **纯白 `#ffffff` + 橙 `#e4572e`**（`styles/tokens.css` 第 5、9 行）—— 一个绿都没有 |
| **页面** | home / post / gallery / projects = **4 个** | index / archive / about / 404 / tags×2 / posts/[slug] + rss/robots = **9 个** |
| **相册** | `gallery.html`，真实照片 82 帧、4 个相册、灯箱 | **不存在**。`content.config.ts` 只有 `posts` / `pages` / `site` 三个集合 |
| **项目** | `projects.html`（空态） | **不存在** |
| **内容来源** | 全部写死 | `content/` 集合 + `lib/site.ts`（主题不持有任何文案） |
| **内联 JS** | home **6286 B** · gallery 3466 B · post/projects 0 · 合计 **9752 B** | 只有 copy-code / comments；构建测试断言**文章页 ≤ 4096 B**（上次实测 2534 B） |
| **骨架** | 左刻度尺 + 顶 HUD + 中扫描带 + 底 OS 条 | `Base.astro` = `Band`（黑带）+ `Brandline` + `SiteFooter` + `.wrap` |

**一句话结论**：要动骨架、要补两个页面、要新建一个内容集合。**配色替换是全站的**（改 `tokens.css` 等于同时改 9 个页面）。

## 3. 需要站主拍板的五件事（我不替他决定）

1. **配色替换是全站一次性生效的** —— `tokens.css` 一改，旧版橙色在所有页面同时消失。要不要留过渡期（比如先把 `--accent` 换成绿、`--accent-ink` 暂留）？
2. **archive / tags / about / 404 跟不跟** —— 原型只覆盖 4 个页面。这 4 个不换会出现"两种皮"；一起换则 P2 的爆炸半径从 4 页变 9 页。
3. **相册的 82 张照片** —— 现在是 `content/gallery/<相册名>/<序号>.jpg`，**没有集合定义**。要不要建集合 + 写 schema（相册名 / 说明 / 拍摄顺序 / alt）？原图动不动（现在靠 `image.layout:'constrained'` 自动出 srcset）？
4. **内联 JS 预算** —— 现在断言 **≤4096 B**，而新首页一个页面就 **6286 B**（1.5 倍）。预算是提到 ~7 KB，还是把动效拆成外部小文件（那就多一个请求，与"零第三方"不冲突但要重新量）？
5. **旧组件去留** —— `Band.astro`（黑带）/ `Brandline.astro` / `PostIndex.astro` 是旧方向的骨架，新版用不上。删，还是留着以备回退？

---

## 4. 风险与顺序建议

- **P2 是最大的一步**：`Base.astro` 是全站骨架，换它等于同时改 9 个页面。建议**先在 `index.astro` 上试通**，再铺开。
- **P5 是唯一有数据迁移的一步**：82 帧 × 多尺寸，构建产物会变大（现在只优化了 18 张）。
- **JS 预算会先红后绿**：新动效比旧的多。**先量再定预算，不要为了过测试砍动效**（这条写下来是为了以后别做反）。
- **建议的起手**：**P1（配色）+ P3（首页接线）** —— 这两步最快能看出"新皮 + 真数据"长什么样，而且各自都能独立回滚。

---

## 5. 明确不做

- 不做暗色模式 / 站点搜索 / 友链（早已砍掉，规范里也不重新引入）
- 不引第三方动画库、不引网络字体、不引 CDN
- 不动 `content/` 里的正文与文案（相册的新集合除外）
- 不为了"看起来更莱茵"去加假遥测文本或装饰性数字
