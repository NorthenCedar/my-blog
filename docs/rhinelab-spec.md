## 0. 一句话

这套语言可以归结成一句：**界面是一台正在工作的仪器** —— 动效只回答"它在读什么、读到哪了"，不做装饰性表演。

参考实现 README 里的动效词汇刚好印证这一点：逐字输入 · 圆环绕行 · 连续 Logo 笔画 · 对角解密线合拢 ·
盖板自上而下由磨砂变清晰 · 标题与编号连续滚动 · 卡片依次变色。**没有一条是"为了好看"的动效**，每条都在表达进度或层级。

## 1. 动效规范

### 1.1 分四层（关键：别用一套时长打天下）

| 层 | 场景 | 时长 | 缓动 | 依据（参考实现的真实值） |
|---|---|---|---|---|
| **交互层** | 悬停微亮、焦点、按压 | **120–180ms** | `cubic-bezier(.22,1,.36,1)` | `transition: transform 180ms cubic-bezier(0.22,1,0.36,1)`、`background .2s/.3s` |
| **叙事层** | 区段入场、逐层展开、解密线合拢 | **600–1000ms** | `cubic-bezier(.16,1,.3,1)` | `transform 1.6s cubic-bezier(0.16,1,0.3,1)`、`opacity .6s/.7s/.8s`、`transform 1.3s cubic-bezier(.22,1,.36,1)` |
| **错位** | 逐层展开时元素之间的先后 | delay **300–400ms**，层间 **80–120ms** | 同叙事层 | `opacity .8s .3s`、`opacity .7s .4s, transform .7s .4s` |
| **循环层** | 圆环绕行、指示脉冲 | **4s / 8s / 16s**，`linear infinite`（反向加 `reverse`） | `linear` | `animation: orbit 4s/8s/16s linear infinite` |
| **硬切层** | 光标 / 扫描指示 | **800ms `steps(1)`** | 无补间 | `animation: blink .8s steps(1) infinite` —— 仪器是硬切的，不是呼吸灯 |

一句话记忆：**交互快（0.18s）、叙事慢（0.6–1s）、错位 0.3s、循环 linear、光标硬切。**

### 1.2 落到 token

现状：`--dur-fast:120ms; --dur-enter:320ms; --ease:cubic-bezier(.2,0,0,1)`

建议（原型与站点同改；站点落在 `src/styles/tokens.css`）：

```css
--dur-fast:120ms;                          /* 交互层 —— 保留不动 */
--dur-enter:640ms;                         /* 叙事层：320 → 640，才够"逐层展开" */
--dur-stagger:320ms;                       /* 新增：错位延迟 */
--ease:cubic-bezier(.16,1,.3,1);           /* 叙事层主曲线 */
--ease-interact:cubic-bezier(.22,1,.36,1); /* 新增：交互层曲线 */
--dur-orbit:8s;                            /* 新增：循环层基准（4/8/16 按元素体量选） */
--dur-blink:800ms;                         /* 新增：硬切闪烁 */
```

**唯一有争议的一条**是把 `--dur-enter` 从 320ms 提到 640ms —— 入场会明显变慢。这是有意的（参考实现的叙事层就是 0.6–1.6s），
但需要站主点头。**不要**把交互层一起放慢：180ms 说明快反馈才是这套语言的底色。

### 1.3 现有动效逐条对照（哪些已合规、哪些要调）

| 现有动效 | 现在 | 判定 |
|---|---|---|
| 刻度填充 / HUD 百分比 | 跟随滚动，无补间 | ✅ 属于"仪器读数"，**不该**加缓动 |
| 扫描带端点闪光 | 120ms linear | ✅ 交互层 |
| 聚焦弱化（0.65 → 1.0） | `--dur-enter` 320ms | ⬆ 建议提到 640ms（叙事层） |
| 入场揭示 `is-revealed` | 观察器触发，无错位 | ➕ 建议加 320ms 错位 |
| 橙色区段切换 | 160ms linear | ✅ 交互层 |
| 跨页过渡 | 出 200 / 进 260ms | ✅ 交互层 |
| **点击绿色闪烁** | **没有** | ➕ 缺一条（视频里明确有"点击时短暂绿色闪烁"） |
| **数字跳动** | 直接赋值 | ➕ 缺一条（视频里的"数字跳动"） |

### 1.4 还缺的两条（建议实装，本轮尚未做）

1. **点击绿色闪烁** —— `pointerdown` → 加 `.is-flash` → 180ms 后移除；只改 `background` 与 `outline`，不动布局。
2. **数字跳动** —— HUD 百分比由"直接赋值"改成"180ms 内插值到目标值"。`font-variant-numeric: tabular-nums` 已经在了，所以数字不会跳字宽。
   （参考实现的数字时钟是**逐位滚动**，那是 3D 版的做法；纯 DOM 版用插值就够，也更快。）

### 1.5 硬约束（一条都不破）

只动 `transform` / `opacity` / `color` / `background-color`，**不动 layout**；
`prefers-reduced-motion` 下全部压到 1ms 且不做位移（现有全局规则已经做到）；橙色只做瞬时反馈。

## 2. 配色

### 2.1 视频的三条 → 现有 token 的映射

| 视频里的角色 | 现有 token | 判定 |
|---|---|---|
| 白色为主底 | `--paper #FAFAF7` + `--panel #EFEDE7` | ✅ 已经是 |
| **冷绿 = 数据高亮 + 界面元素** | `--accent #2D7D46`（hue **139°**） | ⚠️ **偏中性，不够"冷"** → 见 2.2 |
| 橙色只在关键操作出现 | `--signal #E87722`（仅图形）+ `--signal-text #B45309` | ✅ 已经是，而且比视频更严（只用于区段切换的 160ms） |

### 2.2 建议：把绿换成冷绿（hue 139° → 165°）

> ⚠️ **溯源更正（2026-09-26）：本节数值不是上游数值。** 上游 `src/style.css` 里**没有任何绿色**
> （它是纸白 `#e8e5e1` + 金棕 `#a67d48` + 选中 `#cbb397`）。下面这组冷绿候选是**本站自拟**的对比度方案，
> 与上游无关；且该决定**已被站主否决**（不换绿，见文件头的决定记录）。
> **本节保留仅作"将来要换时的备选"，不得再被当作"参考实现的真实值"引用。**

对乳白纸 / 面板 / 黑带的实测对比度：

| 候选 | hue | 对纸 | 对面板 | 对黑带 | 结论 |
|---|---|---|---|---|---|
| 现状 `#2D7D46` | 139° | 4.86 | 4.34 | 3.72 | 纸上可承载文字 |
| **冷绿 B `#14795F`** | **165°** | **5.11** | **4.56** | 3.53 | ✅ **推荐**：两处都 ≥4.5 |
| 冷绿 A `#1F7A5E` | 162° | 5.02 | 4.48 | 3.60 | 面板上差 0.02，不采用 |
| 冷绿 C `#20786B` | 171° | 5.07 | 4.53 | 3.56 | 偏青，作备选 |

配套替换（均已实测）：

| token | 现在 | 建议 | 实测 |
|---|---|---|---|
| `--accent` | `#2D7D46` | `#14795F` | 纸 5.11 / 面板 4.56 ✅ |
| `--accent-deep`（面板上小字） | `#266B3B` | `#0F6B53` | 纸 6.18 / 面板 5.52 ✅ |
| `--accent-bright`（仅图形 / 黑带上亮档） | `#4CAF50`（hue 122°，偏黄绿） | `#34C08A`（hue 157°） | 黑带 8.14（现在 6.79）/ 纸 2.22 → **只能非文字** ✅ |
| `--accent-wash`（悬停底） | `#EDF3EC` | 按新绿 6% 混纸重算 | 只求"看得出有块底色" |

**代价**：`--accent-bright` 现在和主绿不同源（122° vs 139°），换冷绿后如果只换主绿，两者会差得更远 —— 所以要**成套换**。
**安全网**：换完必须跑 `scripts/assert-tokens.mjs` 与 `tests/tokens.test.ts`。它们断言的是**对比度数值不是色相**，上面这些数字复算通过就安全。

## 3. 布局结构要不要调整？

**结论：不需要为这套动效改结构。**

理由（逐条对上）：

| 视频里的动效 | 落到现有结构的哪里 | 要改结构吗 |
|---|---|---|
| 界面逐层展开 | **已有** `.field-item` + `is-revealed`（IntersectionObserver 已在）加 `transition-delay` | 不用 |
| 数字跳动 | **已有** `hudPct` 节点 | 不用 |
| 扫描线划过 | **已有** `.band` | 不用 |
| 圆环绕行 | 背景层（本轮已加的 `.bg-ring` / 图案） | 不用 |
| 点击绿色闪烁 | 事件委托，约 6 行 JS | 不用 |

**唯一要动的布局**：手机端底部 —— 本轮已把扫描进度线挪到 OS 状态条的顶边上（两者共线，不打架），`body` 底部补 1.9rem。

## 5. 明确不做的

- **不做**"盖板由磨砂变清晰"：那是 Three.js 的材质动画，纯 DOM 做不到；用透明度 + 线宽近似就够，硬做会变成假 3D。
- **不做**逐位滚动的数字时钟：3D 版的做法，DOM 版收益低。
- **不引第三方动画库**：现有 token + 原生 CSS 能覆盖全部四条曲线。

### 6.5 本轮新踩的坑（已写进工作区 `MEMORY.md`）

1. **同一类名在文件里定义两遍 + 后写者赢** ⇒ `--fs-display` 改了纹丝不动（136px 不降）。
   改样式前先 `grep` 这个类名出现几次，比改完再量便宜。
2. **少一个 `}` 静默吞掉后面一整段 CSS** ⇒ 产物里 `.entry` 被错误拼成 `.hero-copy[…] .lede[…] .entry a`，
   grid 完全失效。症状是"新写的样式没生效"，真凶在文件别处；**去 `dist/_astro/*.css` 里搜自己的选择器**最快。
3. **横向溢出的真凶不是刚改的元素** ⇒ 390 视口多出 12px，先怀疑 RhGrid 的 path，加两层 `overflow:hidden` 都没用。
   用「逐个 `display:none`，看 `scrollWidth` 是否回落」二分定位，才发现是滚动带的 `.dup` 副本排到 1813px。
   `.marquee` 自己的 `overflow:hidden` 只裁**视觉**，`scrollWidth` 要**父级**收（用 `overflow-x:clip`）。

### 6.6 three.js 的加载策略（2026-09-30 补：整包 → 具名导出收口）

首屏那个真 3D DNA 是全站**唯一**的第三方库（站主拍板「用 three.js，接受破例」）。它分三层下载，
其中第二层曾经踩过一个不报错、只在体积上显现的坑：

| 层 | 做法 | 为什么 |
|---|---|---|
| ① `dna3d.ts` | 被首页 `<script>` 静态引用，打成小 chunk | 首页内联 JS 有 7168 B 预算，three 装不进去 |
| ② `dna-scene.ts` | **具名静态 re-export** three 的 9 个符号 | ★ 见下 |
| ③ three + GLTFLoader | 动态 `import`，只在「容器在 + 非 reduced-motion + WebGL 可用 + 首屏在视口」时才下载 | 不满足条件的用户一个字节都不付 |

**★ 为什么必须有第 ② 层**：原先写的是 `await import('three')` —— 拿到的是**整个命名空间对象**，
打包器判断不出哪些导出最终没被用到，只能把整包全留着。实测产物 **657.2 KB**。
改成「动态 import 一个只做具名 re-export 的小文件」之后，打包器看得到「只有 9 个符号被用到」，
其余全部摇掉 ⇒ **541.9 KB（−115.3 KB / −17.5%）**，页面总 JS 从 734 KB 降到 619 KB。

**维护约定**：`dna3d.ts` 每多用一个新的 three 符号，就要在 `dna-scene.ts` 补一条导出。
漏了不会报错 —— 运行时 `THREE.XXX` 是 `undefined`，属于静默故障，所以那里刻意不做 `export *`。
回归网在 `tests/build-output.test.ts` 的「首页 DNA：three.js 不许退回整包」（源码扫描 + 产物实测字节两条）。

| `.panel` 控制台 | 原型右下角的调试面板 | 不搬 | 那是原型自己的调试件（播过渡 / 扫视差 / 测帧率），不是页面的一部分 |

**本轮踩到的两个坑（都是测试当场抓的，不是目测发现）**

1. **纸白底上用亮绿 ≠ 合法**。语言占比条第一段我原本照原型写了 `--accent-bright`，
   `tests/tokens.test.ts` 立刻拦下：`#4caf50` 对纸只有 2.66:1，这个 token 只许出现在深色底上。
   改法：占比条走 `--accent-ink → --accent` 同色系渐变（纸上是它该有的颜色）；
   首屏 SCROLL 跑光那道 1px 线**确实**在深墨绿场上，属于正当用途 ⇒ 登记进白名单。
   ★ 白名单要写**产物里的选择器形态**（esbuild 把 `::after` 压成 `:after`），
   写成 `::after` 的例外永远匹配不上 —— 白名单会变成摆设。
2. **`prefers-reduced-motion` 下 `animation: none !important` 会让"靠动画到达终态"的元素永久消失**。
   占比条的初值是 `transform: scaleX(0)`、图例与明细的初值是 `opacity: 0`，
   全靠 `forwards` 停在可见状态 ⇒ 动画一禁就是整块内容凭空不见。
   这是**可用性**问题不是观感问题，所以必须显式写终态（用 `!important` 顶回那条全局规则）。

1. `.band` / `.paper-wrap` 加 `margin-inline: calc(50% - 50vw)`。

### 6.9 撤回「顺手修好/补全」（2026-09-30 第五轮 · 站主指令「以原型为源，照搬原型」）

> ★★ **本轮最大的一条原则（比任何单条改动都重要）**
> **「照搬原型」= 连它写错的 CSS 也照搬。** 不补空格、不补它没定义的变量。
> 原型的样式表里有三类"死"声明（无效的 `clamp()` 算术、引用未定义的变量、引用未定义的变量做 fallback），

#### 第二批（同晚，实测发现）：字体栈也要照抄

站主报的 6 处闭环、推上线之后，用 CDP 的 `CSS.getPlatformFontsForNode` 读**实际渲染字体**
（不是读 CSS —— 这一轮的教训就是"光读 CSS 会漏"），两端同视口复测，又抓出一条**同类**残留：

原型还引用了 `--mono` / `--font-display` / `--font-mono` 三个变量，同样**从未定义**；
但那几处声明**自带 fallback**，所以原型里它们没有"死"，只是落到了 fallback 上 ——
而上一轮我在首页 `:global(:root)` 里把这三个变量定义了，原型的 fallback 在本站**失效**：

| 选择器 | 原型声明 | 原型实际取值 | 本站（改前） |
|---|---|---|---|
| `.marquee-item`（跑马灯大字） | `var(--font-display, inherit)` | `inherit` ⇒ **IBM Plex Sans** | **Archivo SemiBold** ✗ |
| `.marquee-item .num` | `var(--font-mono, monospace)` | `monospace` ⇒ NSimSun | IBM Plex Mono（该元素 color 透明 ⇒ 不可见） |
| `.langbar` | `var(--mono, 'IBM Plex Mono', ui-monospace, monospace)` | `'IBM Plex Mono'` | 同 ✓ |
| `.coord` / `.eyebrow` / `.entry time|.tags` / `.card .k` / `.foot-in` 等 8 处小字 | `'Plex Mono', monospace` | IBM Plex Mono，**中文落 `monospace`** | IBM Plex Mono，中文落 Noto Sans SC |

改法：**删掉这三个变量的定义**，首页 13 处 `font-family` 一律照抄原型那一行的**原文**（连 fallback 一起）。

### 6.10 站主第二轮报修 5 项（2026-09-30 第六轮 · 3 处缺陷 + 2 处文案）

站主给了 6 张截图、5 条指令。**3 条是缺陷**，都不在"照搬原型"的范畴里 —— 其中 2 条是
**原型没有、本站自己长出来的**（结构接驳与动效实现留下的），1 条是照搬漏了过渡。
逐条都先实测定位机制，再改；改动都配了产物级断言（`tests/build-output.test.ts` 第六轮那组）。

#### ① 「身份下面衔接」：`.dusk` 没逃出 `.shell`（**本站特有**）

- **现象**：站主截图里晨昏带左右各露出一条纸白，与上面满宽的深墨绿场/下面满宽的纸白区形成竖向硬边。
- **机制**：原型的 `.dusk` 是顶层元素、天生满宽；本站它被包在 Base 的 `.shell` 里
  （`max-width: --wrap = 82rem = 1312px`）。`.band` 与 `.paper-wrap` 都写了 `margin-inline: calc(50% - 50vw)`
  逃出去，**只有 `.dusk` 漏了**。而 `.shell` 的内边距在首页被清零 ⇒ **窄视口下完全看不出来**，
  一旦视口宽于 1312px 才现形。
- **实测**（1680×900 窗口，CDP `document.elementFromPoint` 逐点）：

  | | `.dusk` 的 x / width | x < 该处命中 |
  |---|---|---|
  | 本站（改前） | 173 / 1312 | `main`（纸白） |
  | 原型（同条件） | 0 / 1658 | `div.dusk` |

- **修**：`.dusk` 补 `margin-inline: calc(50% - 50vw)`（与 `.band` / `.paper-wrap` 同款）。
- **护栏**：断言三条规则的逃逸口**同时**存在 —— 单独钉 `.dusk` 一条，别人把 `.band` 那条删了也看不出来。

#### ② 「百褶 ∞ 突然闪出来」：`.paper-inf` 没有过渡

- **机制**：`.paper-inf` 的显隐由脚本 2 的 `IntersectionObserver` 切 `opacity` 来做，但 CSS 里没有过渡 ⇒ 硬切。
- **修**：`.paper-inf` 加 `transition: opacity 900ms var(--ease-glass)`。
  ★ 初值那次隐藏必须**瞬时**，否则开场会在首屏正中淡出一个幽灵 ∞（它是 `position:fixed` 居中挂视口的）——
  所以 JS 里先 `transition:'none'` → 设 `opacity:'0'` → `getBoundingClientRect()` 强制一次样式计算 →
  再把过渡交还 CSS。这一串是必须的，不能只加 CSS 那一条。

#### ③ 「最近写的有时不 hover 就不显示」：揭示动画是**唯一**的可见性来源（**最严重的一条**）

- **机制**：揭示动画给元素写内联 `opacity:0`，靠 `fill:'both'` 的脚本动画把它拉回 1 ——
  **内联 0 一直留着**。动画一旦被丢弃（返回上一页的 bfcache 恢复、标签页被冻结/回收、
  合成器回收、回调中途抛错……），内联 0 立刻接管 ⇒ 整条内容**永久不可见**，
  而且**没有任何自愈路径**：`io.unobserve` 已经执行，观察器不会再触发。
- **实测复现**（线上 1258×802，CDP）：

  | 步骤 | 内联 | computed | 活着的动画数 |
  |---|---|---|---|
  | A 正常揭示后 | `0` | `1` | 1（**唯一可见理由**） |
  | B 手动 `cancel()` 全部动画 | `0` | **`0`** | 0 |
  | C 再滚走、滚回来 | `0` | **仍是 `0`** | 0（不自愈） |

- **修**：动画播完（`anim.finished`）就把内联 `opacity` 摘掉、并把动画本身 `cancel()` ——
  元素回到"原生无覆盖"状态，**可见性不再依赖任何活着的动画**（动画只负责那 820ms 的入场观感）。
  摘内联与取消写在同一个微任务里（中间不落帧）⇒ 不会闪一下。
  另加 `pageshow` 兜底：从 bfcache 恢复/标签页解冻时，把还卡在 `opacity:0` 且动画已不在的放出来
  （动画还在跑的不碰，别打断入场）。
- **护栏**：内联脚本里必须同时出现 ``removeProperty(`opacity`)`` 与 `pageshow`。
  注意 esbuild 会把引号压成**反引号**（本仓库第三次踩到：断言比的是产物，引号类要写 `` [`"'] ``）。

### 6.11 首屏主标题的绿框（2026-09-30 第七轮 · 站主报「刚进站的这个绿色框框」）

**症状**：一进站，首屏大标题 `North_Cedar's notes` 被一个细绿框套住（站主给的是截图）。

**定位**（先实测、后动手）：

1. 对截图做像素采样 —— 框的四边颜色 ≈ `rgb(41,102,61)`，最接近的站内颜色是
   `--accent-ink: #266b3b`（`rgb(38,107,59)`，JPEG 有色偏）。框的几何恰好等于 h1 的边框盒。
2. `grep` 全站 `outline`：唯一命中绿色的是 `base.css` 的全局
   `:focus-visible { outline: 3px solid var(--accent-ink); outline-offset: 3px }`。
3. CDP 实测（线上）：`document.activeElement` 就是那个 h1。链条是
   `BootIntro.astro` 收尾时 `title.focus()` 交回焦点 → `index.astro` 为此给 h1 挂了
   `tabindex="-1"` → Chrome 把「**脚本聚焦的 `tabindex=-1` 非交互元素**」也判成
   `:focus-visible` ⇒ 绿框。
4. **关键环境坑**：无头窗口默认「没有被聚焦」⇒ `:focus` / `:focus-visible` **恒不匹配**，
   不开 `Emulation.setFocusEmulationEnabled` 就会得出「线上没有绿框」的错误结论
   （本轮第一次跑就是这么被骗的：`focusVisible:false, outline:none`）。
   打开后立即复现：`focusVisible:true, outline: solid 3px rgb(38,107,59) 3px`。
5. **原型没有这一出**：原型 `<h1 class="display">` 既没有 `tabindex`，全文也搜不到
   `tabindex` / `.focus()` / `:focus` ⇒ 又一个「本站自己长出来的」，与第六轮同源。

**改法**（只收程序化聚焦，不动键盘焦点环）：

```css
/* base.css，紧接全局 :focus-visible 之后 */
[tabindex='-1']:focus-visible { outline: none; }
```

- 特异性 (0,2,0) > (0,1,0)，能盖住全局那条。
- `tabindex="-1"` 的元素 **Tab 永远到不了**，只可能是脚本聚焦 ⇒ 收掉焦点环不损可用性。
- **不能**图省事写成全局 `:focus-visible{outline:none}` —— 那是把 a/button/input 的键盘
  焦点环一起砍了（过度修复）。本轮加了反证断言：`a[href]` 聚焦时仍必须算出绿环。
- 保留焦点交接本身（它是站主的 a11y 决定：遮罩收尾别把焦点掉到 `<body>`）。

**护栏**（`tests/build-output.test.ts` 第七轮那条）：一条断言同时钉住两件事 ——
`[tabindex="-1"]:focus-visible` 里必须是 `outline:none`，**且**全局
`:focus-visible` 的 `3px solid var(--accent-ink)` 必须还在。

### 6.12 开场动画整份重做（2026-09-30 · 站主「5 秒内、丝滑、有印象」）

> ⚠️ **本节已被 §6.13 取代**（同一晚，站主看过第一版之后又提了一条要求）。
> 时间轴、层叠结构、资产清单都以 §6.13 为准；本节留作"为什么先做成了那样"的记录。
> 具体作废的点：**覆盖层里那 96 条线已删除** —— 开场那批线现在就是首屏那批（§6.13 的全部内容）。

**站主的原始要求**：开场太长（20.16 s），要「5 秒内能完成、可以摒弃冷静机器感、
做丝滑点能让人留下深刻印象、有创新性，但前提是符合本站视觉」，并给了参考站 `wodniack.dev`。

**为什么是重写而不是剪枝**：旧版是照着上游 RhineLabUI 的 25 fps 原片逐帧复刻的，
六段叙事（ACCESS 打字 → 品牌三行 → ∞ 描边 → 身份验证 → 权限扫描 → 欢迎段）**互相咬合** ——
每一段的起止点都建立在上一段的终态上，删掉任何一段后面全部错位。⇒ 整份重写。

#### 新时间轴（`--dur-boot` = 5300 ms 硬上限，含退场）

| 段 | 起 (ms) | 时长 | 内容 | 动的属性 |
|---|---|---|---|---|
| 落笔 | 180 | 1150 | ∞ 从印刷缺口那端起笔、一笔画完 | `stroke-dashoffset` 1 → 0 |
| 崩解 | 1400 | 1350 | 96 条竖线从 ∞ 上的采样点起飞、展开到各自列位 | `transform` + `opacity` |
| 收束 | 3000 | 1100 | 整片竖线向中央收拢成一条横线 | `scaleY` → .008 |
| 剪幕 | 4150 | 450 | 遮罩 `clip-path` 上下对开 | `clip-path` |
| 退场 | 4600 | 700 | 残余淡出；5300 ms 时时钟 `animationend` 触发 `close()` | `opacity` |

★ **三段时间故意重叠**（崩解尾巴压在收束头上、收束尾巴压在剪幕头上）—— 这是「丝滑」的第一因：
观感是**同一个东西在变形**，不是「一段演完再演下一段」。
★ **全程只有 `transform` / `opacity` / `clip-path` / `stroke-dashoffset`**，不碰 layout ⇒ 不触发重排。

#### 六条设计决定（站主逐条拍板，不是「可优化项」）

1. **方向 B**：∞ 落笔 → 崩解成线 → 收束揭幕。不是「字从下面滑上来」那类常见做法，
   而是**让首屏的流场竖线在开场里就已经存在** —— 观众看到的是同一批线的连续变形。
2. **丝滑主导**（不是炫技主导），靠三件事：① 各段错峰（96 条线按 `min(i, N-1-i)` 从两端向中间错开 7 ms / 5 ms）；
   ② 段落重叠；③ 缓动只用两条曲线 —— `cubic-bezier(.16,1,.3,1)`（进场）与 `cubic-bezier(.65,0,.35,1)`（对称缓冲）。
3. **硬上限 5.3 s** 不是随手定的 —— 它是 **遮罩撤走 + 可交互** 的时刻；
   首屏入场动画延续到 ~6.2 s，**故意与遮罩重叠**（否则会看到「遮罩没了、页面还是空的」）。
4. **刷新不重播**：`sessionStorage` 记一次（进入播放即记，skip 也算）。
5. **skip 保留但不聚焦**：故意的 —— 不让 Tab 一进来就落到 skip 上；
   空格 / Esc 全局都能跳过（`preventDefault` 掉空格的默认滚动）。
6. **手机 ~1.5 s 极简版**：**同一套关键帧** + 另一组 `--bi-*` 变量（`--bi-k: 0.02` 把错峰倍率压到近零）
   —— 不复制一份 CSS，两版就不会各自跑偏。

#### 首屏交接（Q9c / Q10 / Q11 的落地）

**① 线直接变成首屏的竖线（Q9c）** —— `.bi-line` 的 `--k = cos(2πi/N)` 就是它在双纽线上的横向采样点；
崩解的起点 = `50vw - x1 + k · min(23vw, 260px)`（与 `.bi-mark` 的 `min(46vw, 520px)` 对应）。
⇒ 观众能把「∞ 散开的线」和「首屏那片竖线」认成同一个东西。

**② 首屏揭幕抄两条、不抄第三条（Q10）**
- 抄：竖线从两端向中间被「画」出来 ⇒ `.rh-grid` 双层 mask，`mask-size` 从 `0%` 长到 `50%`。
- 抄：内容区揭帘 ⇒ `.band-copy` 的 `clip-path: inset(0 0 100% 0)` → `inset(0)`。
- **不抄**：整体升起、`a-separator`（参考站那套是「整页从下往上推」，会跟本站的滚动视差打架）。

**另给一份 `.display-sr` 完整原文给屏读**，视觉那半标 `aria-hidden`（否则屏读会把标题一个字母一个字母念）。

#### 三条红线（改这块时不许破）

1. **fail-safe 方向**：覆盖层默认 `display:none`，只有 JS 判定该播才挂 `.boot-on`。
   反向（默认显示、靠 JS 隐藏）会在无 JS / JS 报错时把整站盖死。
2. **绝不效仿参考站的「整站 SSR `opacity:0`」**：内容默认可见，入场动画只是「提前把它藏起来」、
   再由 CSS 终态放出来 ⇒ 动画一丢，内容仍然在。这正是第六轮修掉的 bug 类型。
3. **装饰子树 `aria-hidden`，skip 按钮是它的兄弟**（`aria-hidden` 子树里不许有可聚焦元素）；
   且 skip 的类名是 `.bi-skip`（**不是** `.skip` —— `base.css` 已占了 `.skip` 当「跳到正文」，
   照抄会继承 `left:-9999px`）。

#### 本轮踩到的三个坑（都写进了断言）

1. **`<style>` scoped 连 `:global()` 包裹的子选择器也带父作用域** ⇒ `.bi-mark path` 会产出
   `.bi-mark[data-astro-cid-xxx] path`，SVG 子元素命中不稳 ⇒ 必须写 `.bi-mark :global(path)`。
2. **同一个元素上两条动画若都动 `transform` 会互相顶掉** ⇒ `.bi-line` 外层管横向展开

3. **`mask-size` 可以直接插值，不需要 `@property`** ⇒ 用两层 `mask-image: linear-gradient(#000,#000)`
   + `mask-position: left center, right center`，`mask-size` 从 `0% 100%, 0% 100%` 长到 `50% 100%, 50% 100%`。
   （mask 尺寸从 0 长起 = 完全隐藏，与 `mask-position` 无关。）

### 6.14 ∞ 落笔延长一秒（2026-10-01 · 站主「有点突然不够丝滑」）

### 6.15 ∞ 的笔顺：从中心起笔、一笔绕两环（2026-10-01 · 站主「不是先画上半再画下半」）

**站主原话**：「无限符号不是先画上半再画下半，他是8字型画法啊，修」

#### 旧版错在哪：形状对、**笔势**不对

静态看旧 path 就是标准 ∞（§6.13 那版起笔点在**右环顶部** `19.04 2.14`），
但两环**同向**（都是屏幕逆时针）。按弧长把笔尖采样出来：

| 段 | 弧长 | 笔尖轨迹 |
|---|---|---|
| 1 | 0–14.5% | 右环顶部 → 中心 |
| 2 | **14.5–16.5%** | **在中心碰一下、掉头** |
| 3 | 16.5–50% | 左上 → 最左 → 左下 |
| 4 | **64.5–66.5%** | **又在中心碰一下、掉头** |
| 5 | 66.5–100% | 右下 → 最右 → 右上 → 回起点 |

两次经过中心都是**折返**：`(18,2)→中心→(6,2)` 画出一个 ∨、`(6,10)→中心→(18,10)` 画出一个 ∧ ——
两个尖角的顶点重合在中心。形状因此还是 ∞，但 dash 沿路径生长时，读起来就是
**"先撇一个上半、再撇一个下半"**。站主看到的就是这个。

#### 为什么"两环同向"必然是这个结果

∞ 的本质是**两环反向**：lemniscate 的参数式随 t 增加时两环手性相反，两个相切圆的 ∞ 也一样。
- 两环**反向** ⇒ 笔在中心是沿**对角线直穿**，两次穿越分别是"左下↔右上"和"右下↔左上"，合成 X ✓
- 两环**同向** ⇒ 笔在中心是"到达再折返"，形状不变、笔势断掉 ✗

#### 改法：几何一个字没动，只把右环的**段序与绕向**反过来

```
M12 6                              ← 起笔在中心交叉点
c-2 -2.67 -4 -4 -6 -4      → (6,2)    左环上段（出笔方向 左上）
a4 4 0 1 0 0 8             → (6,10)   左环左侧（经最左 x=2）
c2 0 4 -1.33 6 -4          → (12,6)   左环下段（进中心方向 右上）
c2 -2.67 4 -4 6 -4         → (18,2)   右环上段（出笔方向 右上 ← 与上一条同向 ⇒ 直穿）
a4 4 0 0 1 0 8             → (18,10)  右环右侧（经最右 x=22）
```

### 6.16 流场线的时间基准：**毫秒**，不是秒（2026-10-01 · 站主「那些线在缓慢移动」）

站主原话：「做一个像 wodniack.dev 一样的视觉感官上那些线在缓慢移动」。

#### 症状：参数全对、画面全对，唯独"不动"

首屏那批流场线从第七版起就是**冻住的**。不是参数错、不是动画被关掉 ——
是**单位错了 1000 倍**。

| | 顶点平均位移 | 峰值 | 帧率 |
|---|---|---|---|
| 改前（本站，`T = now / 1000`） | **0.006 px/s** | 0.05 px/s | — |
| 改后（本站，`T = now`） | **2.7–4.6 px/s** | 9.4–12.7 px/s | 58 fps |
| 参考站 wodniack.dev（实测） | 4.1 px/s | 10.5 px/s | — |

#### 根因：参考站喂毫秒，移植时写成了秒

```js
// 参考站 hoisted.*.js —— 自定义 ticker 的 emit
$.emit("tick", t * 1e3)     // ← GSAP ticker 的 t 是**秒**，它自己乘了 1000
                            //   a-waves 订阅：$.on("tick", this.tick, this)
// 所以参考站 movePoints(t) 收到的 t 是**毫秒**
```

本站第七版移植成了 `T = now / 1000`（秒）⇒ 噪声项 `t * WAVE_TX` 慢 **1000 倍**。
噪声坐标是 `(x + t·WAVE_TX)·WAVE_SC` —— 加号两侧同乘缩放，所以 **t 每推进 1 ms
等于整片场沿 x 后移 WAVE_TX px**：喂毫秒 = 12.5 px/s，喂秒 = 0.0125 px/s
（一小时走 45 px，肉眼等于静止）。纵向同理 `WAVE_TY` = 5 px/s。

#### 改法：一行

```ts
T = now;   // tick(now) —— now 本身就是毫秒（rAF 参数），本来就是毫秒
```

`T` 只喂给 `move()` 的噪声项，鼠标弹簧那套是从鼠标位移算的，与 `T` 无关 ⇒ 换单位
不影响交互手感；开场时间轴在 CSS 里，也不受影响。

#### 这类 bug 的教训（可复用）

**"参数全对但效果没有"要量的是「同一个点在时间里的位移」，不是任何形状/时长读数。**
本轮之前所有探针（`cdp-boot` 量时序、`cdp-lines` 量几何、`cdp-path-order` 量笔顺）
都读不出它 —— 因为形状、条数、透明度、帧率**全部正常**，唯一不对的是"它们没在动"。

为此新建 `_probe/cdp-flow-drift.mjs`（本站与参考站通用，`--sel` 换目标元素）：
按**弧长**采样每条线的 N 个点（`getPointAtLength`），两次采样求逐点位移，
输出 `② 运动`（px/s）· `③ 弹性`（横向摆幅 / 相邻转角 / 走向反向次数）· `④ 帧率`。
★ 它自己的两条硬规矩也写在文件头：注入脚本里**不能出现反引号**；
**不要用正则解析 `d` 属性**读第 k 个顶点（路径一旦改成曲线，编号就不再对应真实顶点）。

#### 静态契约（`tests/flow-field.test.ts`，4 条）

1. `T = now` 存在，且**不许** `T = now / …`；
2. 源文件里要留着参考站的依据（`t*1e3`）与 `wodniack` 字样 —— 否则 `T = now` 会被
   后来人当成"漏了 /1000 的单位 bug"**顺手修回去**（这正是它最危险的地方）；
3. 流速带：`WAVE_TX × 1000` 落在 5–25 px/s、`WAVE_TY × 1000` 落在 2–12 px/s
   —— 钉"性质"不钉"数值"，允许按手感调、挡住量级错；
4. 降级路径仍在（`reduce` 只画一帧、`IntersectionObserver` 出视口停帧）。

第 1 条的判据**验证过会红**：把 `T = now` 改成 `T = now / 1000` 后单跑该文件，
`Tests 1 failed | 3 passed`，恢复后 4 passed。

#### 未动

`.band` 底色 / `.rh-grid__svg` 暗角 / 鼠标三约束（clamp ±100 · 阻尼 .925 · 回弹 .005）/
开场揭幕（`rh-bloom`）—— 本轮只动时间基准。观感层面「更有弹性」是下一版的题目。

### 6.17 流场线的"弹性"：两层，以及为什么"全场统一"的改动看不见（2026-10-01 · 站主「更有弹性一点，不要太多」）

紧接着 §6.16 那条。站主要求原话：「把本站的线改的更有弹性一点，不要太多」——
所以观感上的"更有弹性"在这一版落地。

#### 第一轮：只加"跟随弹簧" ⇒ 固定种子实测**完全不可见**

做法：`pt.wave` 不再直接等于噪声目标，改用二阶弹簧去"追"：

```
v += (target - x) * WAVE_S      # 刚度/帧²
v *= WAVE_D                     # 阻尼/帧
x += v
```

固定噪声种子扫了三档（`_probe/cdp-flow-drift.mjs --seed 0.4242 --reps 4`）：

| ω₀ (rad/s) | 横向摆幅 | 相邻转角 | 最大转角 |
|---|---|---|---|
| ∞（无弹簧） | 38.22 ± 2.18 | 3.68° | 22.22° |
| 1.04 | 38.95 ± 1.76 | 3.75° | 23.20° |
| 0.70 | 38.90 ± 1.16 | 3.76° | 23.62° |

**三档的差别全落在 ± 之内** —— 也就是"没做"。两个原因叠在一起：

1. **全场统一 ⇒ 没有参照物。** 弹簧对整片场产生的是"一起晚一拍 + 一起缩一点"。
   人眼只能看出**差异**，看不出"一起晚了"。
2. **噪声频谱很窄。** 场是匀速平移的 ⇒ 时间频率 = 空间频率 × 流速，所以"滤时间高频"
   就是"滤线的细节褶"。而这批噪声场的能量几乎**全在 λ > 170 px**（实测每条线弧长
   881 px、走向反向 5.2 次 ⇒ 平均褶长约 170 px）。截止波长真要压到它之下时，滤掉的
   就是**主起伏本身**（观感 = 线变平），不是"弹性"。

⇒ 结论：**可见的弹性必须来自空间上不均匀的响应。**

#### 第二轮：加"横向呼吸"

```
breath = 1 + WAVE_BR * sin(2π * (t / WAVE_BR_MS - 列位x / WAVE_BR_WL))
最终形状(pt.wb) = 弹簧输出(pt.wave) × breath
```

沿 x 带波长（1600 px）⇒ 同一时刻"左边弯得开、右边收着"，并缓慢此消彼长 ⇒ **有了参照**。

#### ★ 关键坑：呼吸乘在**弹簧输入**上等于没做

第一版把 breath 乘在目标上（`tx = cos(o) * WAVE_AMP_X * breath`）。同种子同 t 实测：

| | 摆幅起伏（10 帧极差） |
|---|---|
| 无弹性（线上 `7f7bbeb`） | 12.3% |
| 弹簧 + 呼吸（**乘在输入上**） | **8.5%** ← 反而更小 |
| 弹簧 + 呼吸（**乘在输出上**） | 16.1% |

因为弹簧在 r≈1（呼吸周期 9 s、ω₀ = 0.70 ⇒ r ≈ 1.0）处 |H| ≈ 0.83 且滞后 90°：
先把呼吸衰减掉一大半，剩下的又与场的自然波动（±12%）相位抵消。
⇒ **呼吸必须绕过弹簧**（乘在输出上），接线见 `move()` 里的 ②，断言见下。

★ 附一条：**呼吸深度不能凭感觉定**。场自身的摆幅起伏就有 ±12%，呼吸比它小就淹没在里面。
±13%（≈ 能测出来的下限）只把起伏抬到 14.7%，10 个样本下仍不显著；最终取 **±20%**
（预期叠加 ≈23%）。这一条是"不要太多"和"能看见"之间的实际边界。

#### 验收：同种子 + 同 `performance.now()` 逐点比对（`_probe/cdp-flow-sync.mjs`）

两次运行的场必须逐点相同才谈得上"比版本"。做法：`Page.addScriptToEvaluateOnNewDocument`
在页面脚本执行前固定 `Math.random`；再让两次运行都**在页面内 performance.now() ≈ 同一个值**
采样 —— `T = now` 就是页面相对时间，所以 t 也对齐了。

| 对比 | RMS 逐点差 |
|---|---|
| 同一版本跑两次（**噪声底**） | **0.038 – 0.402 px** |
| 无弹性 vs 弹簧+呼吸 | **10.1 – 13.1 px**（10 帧） |
| 平均 Δx | ≈ 0（**不是整体平移，是形变**） |

左右半（各 6 条抽样线）摆幅比：

| | 左/右 摆幅比的范围 |
|---|---|
| 无弹性 | 0.97 ↔ 1.29 |
| 弹簧 + 呼吸 | **0.89 ↔ 1.53**（明显此消彼长 ✓） |

形状叠图（`_probe/_shapediff.mjs`）：两版基本重合、只在波浪上轻微错开（几 px），
走向与褶的位置都对得上 ⇒ 是"线在缓缓呼吸"，不是畸形。

#### 静态契约

`tests/flow-field.test.ts` **8 条**：`T = now`（不许 `/1000`）/ 源文件留着 `t*1e3` 与
wodniack 依据 / 流速带 5–25 px/s / 降级路径 / 弹簧积分式 + `pt.ini` 首帧落位 /
ζ ∈ (0.45, 0.75) / ω₀ ∈ (0.4, 3.0)（截止波长 = 流速 × 2π/ω₀）/ 呼吸的 sin 调制与列位相关 /

#### 6.17.1 补丁：弹簧必须**帧率无关**（2026-10-01，同日）

上节落地后做线上验收，发现**同版本跑两遍**（同种子、同 t）逐点差 **7.4–12.3 px** ——
而无弹性版本的噪声底只有 0.04–0.40 px（形状本该是 `seed + t` 的确定函数）。

**根因**：第一版弹簧用的是"**每帧**固定系数"（`v += (T−x)*S; v *= D; x += v`），
看着最自然，实则把 **dt 当成恒定的 1/60 秒**。等效固有频率 `ω₀ = √S × 实际帧率`
⇒ 帧率一变，滤波器就变：

| 实际帧率 | 等效 ω₀ | 对 18 s 主起伏的增益 / 相位 |
|---|---|---|
| 60 fps | 0.700 rad/s | 1.041∠−38.7° |
| 39 fps | 0.455 rad/s | 0.991∠−66.0° |

相位差 27°、幅度 32 px ⇒ 两帧之间差 **≈15 px** —— 与实测的 7–12 px 同量级，根因确凿。

**这条的严重性有两层**：

1. **观感随设备变**：120 Hz 屏上 ω₀ ≈ 1.40 rad/s（弹性快一倍、过冲更大），
   掉帧时又变慢。站主要的是"不要太多"的手感，结果手感取决于用户显示器 —— 不可接受。
2. **验收直接失效**：抖动幅度**正好等于**要测的"弹性效果本身"（10–13 px）
   ⇒ 任何"加了弹性有没有效果"的结论都站不住。

**修法**：换成物理量 + **真实 dt** 的半隐式欧拉（`v` 的单位从 px/帧 变成 px/s）：

```
a = ω₀²·(target − x) − 2ζω₀·v      v += a·dt      x += v·dt
```

两个常量**由原系数推导**（60 fps 行为不变，站主看到的手感不动）：

```ts
const WAVE_W2 = WAVE_S * 3600;      // ω₀²  ≈ 0.4896
const WAVE_Z2 = (1 - WAVE_D) * 60;  // 2ζω₀ ≈ 0.8400
const DT_MAX = 0.05;                // dt 上限：切回标签 / 长卡顿后别让弹簧"跳"过头
```

`tick()` 里 `const dt = Math.min(DT_MAX, Math.max(0, (now - lastNow) / 1000))`，
`move(t, dt)`；首帧 / resize 重建 / `dt === 0` 一律**直接落位**（并清零 `wv`）。

**护栏**：`tests/flow-field.test.ts` 第 8 条「弹簧帧率无关」——
钉住两个**推导式**（不是魔法数字）、钉住"不许再出现 `v *= WAVE_D`"、钉住 `dt` 确实由 rAF 算出并传进 `move`。
**验过会红**：拿 `7a4f760` 的旧文件跑同一组判据，5 条全落在"会红"状态。

**线上判据**（压缩后）：chunk `index_astro_type_script_index_1_lang.<hash>.js` 内含
`Math.min(.05,Math.max(0,(e-_)/1e3))` 与 `.wv.x+=(a*(v-p.wave.x)-o*p.wv.x)*t`。

#### ★★ 密度场（第六轮把渲染内核整个换掉了）

上一版是「**离屏 alpha 蒙版** + 乘性衰减」：每帧 ① 整版 `destination-out` 乘性衰减
② 在指针处盖一个有机形状的笔触，最后 `destination-in` 把照片抠出来。
**这套做法做不出"像水一样"** —— 它只能"抹出一块、然后整块淡掉"（站主第六轮的反馈正是这个）。

⇒ 换成参考站那套**密度场**（`Float32Array`），每帧三步，全部照抄它的 sim shader：

| 步 | 参考站原文 | 本站 |
|---|---|---|
| ① 流场 | `flow = vec2(a,−b)*.5`（curl noise）+ `velocity*influence*.18` | 在 **FW/4** 分辨率算（p*5 只有 5 个周期，够了） |
| ② **输运** | `sampleUv = uv − flow·dt; density = texture(field, sampleUv)` | 半拉格朗日回溯 + 双线性采样，**双缓冲 ping-pong** |
| ② 衰减 | `density = max(0., density − dt/life)` | **线性** `− ds/LIFE`，夹到 0 |
| ③ 笔触 | `density = max(density, brush*down)` | 只在指针**包围盒**内算（盒外 brush 恒为 0） |

display 照抄它的显示阶段：采样点先被一个**低频**噪声推歪（域扭曲），再叠一层**高频** fbm，
最后过一条**带宽只有 0.025** 的 `smoothstep` ⇒ 边界是**硬的**，破碎感来自噪声不是渐变。

**★ 为什么"线性衰减 + 硬阈值"才读成"水退回去"**：
线性衰减让整块 density 一起匀速下降，而阈值是一条**等值线** —— 笔触边缘本来就低，先降到阈值
以下就先消失 ⇒ 边界**往里收缩**。乘性衰减 + 软边渐变则相反：整块一起变淡，没有"收"这个动作。

**★ 顺带解决上一版那个 α 下限**：8 位 alpha 的**乘性**衰减有下限（α 越小、每帧减量 `α·αs`
越小，减到不足 0.5 就四舍五入原样留下 ⇒ 实测卡在 42，一道 17% 的鬼影僵两秒）。
Float32 的**线性**衰减减到 0 就是 0 ⇒ 蒙版**不再需要平方**。

#### ★★ CPU 跑 GPU 的场：三处**不改变结果**的优化（这是能不能上线的关键）

参考站用 WebGL 跑这个场，本站用 CPU。**直接照搬它的场分辨率跑不动**：
实测（`_probe/bench-field.mjs`）512×360 要 **37 ms/帧**（27 fps）、384×270 要 21 ms。

| 优化 | 为什么成立（结果不变） | 效果 |
|---|---|---|
| **flow / q 降分辨率**（FW/4） | 它们是**低频**场（p*5 / p*7，跨屏只有 5~7 个周期）⇒ FW/4 下每周期还有 16+ 采样，双线性采回来与全分辨率无差别 | 4 次 noise/像素 → 1/4 |
| **空块跳过 edge** | 块峰值 < `DEAD = REV0 − EDGE_A/2` 时，无论 edge 噪声怎么抖都**不可能**显 ⇒ 直接写 0 | display（全场最贵的一步）在空区域几乎免费 |
| **笔触只算包围盒** | `brush` 只在 `\|off\| < 1.2·radius·1.22` 内非零，盒外恒为 0 | 省掉整版最贵的 `atan2 + 2×sin` |

⇒ **320×225 满场 9.1 ms / 空场 6.0 ms**（`_probe/bench-field3.mjs`）；线上实测**满帧 60 fps**。
★ 场分辨率**只决定输运/衰减的细节**，不再决定边缘的清晰度 —— 见下面「矢量等值线」（第七轮）。

#### ★★★★ 第七轮：边缘改成**矢量等值线**（站主：「边缘好粗糙，分辨率好低」）

★★ 根因（把参考站的 display shader 逐行扒出来才看清）：**它的 display 是逐屏幕像素跑的**
（`vec2 p = uv*vec2(aspect,1.)`，那条极窄的阈值带 `smoothstep(.19,.215, d+(edge-.5)*.15)`
也在屏幕像素上）⇒ 它**只有 `d`** 是从 512 的低分辨率场双线性采样的，**高频细节是屏幕分辨率的**。
本站第六轮把整段 display（**含**决定"破碎水渍边"的 `edge` fbm）都跑在 320 的场上，再
`drawImage` 放大 4× ⇒ 高频噪声被降采样到 320、阈值带也被摊成 4 px ⇒ 又糊又有块。

⇒ 解法不是提高场分辨率（实测 512×360 要 37 ms/帧；把场从 1/4 提到 1/3 本地就掉到 **29 fps**），
  而是**把两件事分开**：

| | 分辨率 | 理由 |
|---|---|---|
| `d`（输运 / 衰减 / 笔触） | **场分辨率 320** | 低频，再高就跑不动 |
| **边界** | **矢量（dpr 全分辨率光栅化）** | 高频噪声在**屏幕坐标**上采样 |

四步：① 场算 `d` ⇒ `DD`；② **marching squares** 提 `d = TH` 的等值线（**线性插值 ⇒ 亚像素**，
不再是 4 px 台阶），含两个鞍点 case；③ 每个顶点按参考站的 `edge` fbm 沿法线位移
`δ = −Δ·∇d/|∇d|²`（Δ = (edge−.5)*EDGE_A）—— **不是"直接乘一个常数"**：场被衰减得越平，
边界该抖得越厉害，那正是"水退回去"时的样子；④ 环串起来后用**二次曲线过中点**填进 canvas
（C1 连续），`evenodd` 填充（绕向无关地挖洞）。

★ 关键收益：`edge` 那层 fbm 从"每格一次（7 万次）"搬到"每个**顶点**一次（几百~几千次）"
  ⇒ 边界做成矢量**反而更省**（contour 2.5 ms，比上一版 display 便宜），60 fps 不变。

**实测对照（本地 1280×900，`_probe/cdp-bath-edge.mjs`）**

| | 第六轮（位图放大） | **第七轮（矢量）** |
|---|---|---|
| 过渡带宽度 | **2.97 px** | **0.84 px** |
| 平均转角 | 14.24° | **10.29°** |
| 最大转角 | **68.5°** | 52.4° |

⇒ 旧版是"又糊（3 px 斜坡）又毛（68° 硬折角）"，新版是平滑曲线 + 10° 的水渍起伏。

**走过的弯路：fbm 预生成 LUT 不可行。** 想用一张 LUT 把 3 次 noise 换成 1 次查表，但 LUT 覆盖
32 个单位、而 hash 的周期是 256 ⇒ **wrap 处跳变**（接缝）。⇒ 直接算 noise：本站的 hash 用
`& 255` 周期化，格点 255 → 0 是**相邻格插值，天然平滑**，没有接缝。

#### ★★ 「只抽横幅」踩出来的数据坑：manifest 的 `w` **不是实际宽**

`public/gallery/manifest.json` 每条 `files[i]` 的 `w` 是**请求的目标宽**，不是产物实际宽度：
`scripts/gen-gallery-webp.mjs` 用 `sharp(src).resize({ width: w, withoutEnlargement: true })`，
源图窄于目标宽时不会放大 ⇒ 文件停在源宽上，但登记进 manifest 的仍然是 `w = 目标宽`。

逐帧读真实像素核对（82 帧 × 2 档）：**`h` 永远是真的；`w` 在 1280 档有 19 条是假的、800 档有 4 条**。

后果：**照 1280 档判横竖会有 6 张判反** —— 例：「苏州的美」manifest 记 `1280×1184`（看着是横幅），
实际 1280 档文件是 **896×1184（竖幅）**；「电话亭」「蓝调二分」「舞」「花海」「青春的结束」同理。
**照 800 档判一张都不反**（同一批逐帧验过）。

⇒ 本站硬规矩：**判横竖一律用 800 档（网格档）的尺寸**。这同时是脚本端的口径 ——
`develop.ts` 读的就是 `<img>` 上那对 800 档 `width`/`height` 属性。
两边口径必须一致，否则"脚本没跑完的那一瞬间"会露出一个对不上的分母。
护栏：`tests/develop-bath.test.ts`（SSR 必须取 800 档 + `w > h`）。

★ 顺带记录（**未动**）：网格 `<img width={g.w} height={g.h}>` 用的也是 800 档，那 4 条假 `w` 会让这张图的
**加载前占位比例**略有偏差（`width:100%; height:auto` ⇒ 图到了会自己纠正，肉眼看不到）。
要根治得让生成脚本登记真实宽。

#### 技术选择：Canvas2D，不是 SVG `feTurbulence`

滤镜方案代码更少、"液体"味更足，但大尺寸滤镜是性能杀手。
Canvas 里形状完全可控、每帧只做「96 个点的多边形 + clip + 一次 drawImage」，实测 **62 fps**。

#### 六个关键实现决策（每条都对应一个坑）

| 决策 | 为什么 |
|---|---|
| **板底不由 canvas 画** | canvas 是**透明的**，只在擦痕里画照片 ⇒ 形状外"没有像素"，自然露出容器的 CSS 深墨绿背景。好处三条：每帧少一次全屏 `fillRect`；降级时板底照旧在；**探针可以直接读 alpha 通道** —— ★ "没有指针 = 纯色"这条口径，探针一读 `α` 整版为 0 就验完了（`_probe/cdp-bath.mjs` 一行 debug 钩子都不用加）。 |
| **颗粒走 CSS 层，不进 canvas** | 站主要"照片加一点噪点颗粒感"。进 canvas 有两个坏处：① 撒随机噪点会**掺进随机源** ⇒ 那条硬规矩「形状必须是 `t` 的确定函数」（同 t 逐点比对）直接失效；② 静态噪点走 CSS **每帧零成本**（只栅格化一次并平铺），canvas 每帧重画整屏噪点在整屏尺寸下是实打实的开销。实现 = `.bath::after` + 内联 SVG `feTurbulence` 的 data URI（`fractalNoise` + `saturate 0` + `feFuncA` 拉平 alpha + `stitchTiles='stitch'`）+ `mix-blend-mode: overlay`，`opacity: 0.42`，自包含不发请求。 |
| **花体字是 DOM，不是 `fillText`** | 参考站的画面文字压在显影层之上、不参与显影 ⇒ 本站照做：`.bath-mark` 是 canvas 外面的 `<span>`（`z-index: 2`，压在颗粒层之上）。★ 好处是"擦不掉"这条**不需要任何脚本配合**，天然成立。护栏钉「脚本里不许出现 `fillText`」。 |
| **笔触分两档，按「板的短边」选** | 参考站那档是按**整屏**定的（板高 800 ⇒ 一笔 295 px），照搬到手机那块 ~160 px 高的小板上只有 25 px —— 手指根本擦不动。⇒ `RADIUS_SMALL_K = 0.19`（按"可见直径与上一版小板持平"反推），`SMALL_PLATE = 420`。★ 判定用**板的短边**，不是视口：同一个视口下两种版面尺寸差 4 倍，按视口分会判错。★ 半径本身一律按**板高**算（参考站是 `/height`）。 |
| **跟随 = 一阶指数平滑**（`FOLLOW_K = 18`） | ★★ 照抄参考站：它的 `advance()` 是 `const n = 1 - Math.exp(-t*18); point += (target-point)*n` ⇒ 速率 18/秒（时间常数 ≈56 ms）、**一阶 ⇒ 不过冲**。上一版那个二阶弹簧（ζ=0.65）有约 6% 过冲 ⇒ 涂抹时读成"笔尖抖一下"。★ 稳态滞后 = v/18（500 px/s 落后 ≈28 px）。★ 必须吃**真实 dt 的秒**（18 的单位是 1/s）。 |
| 噪声**在圆环上采 2D**，不做 1D 周期化 | ★ 初版走「1D 噪声 + 在 u 与 u−K 之间插值」那套周期化技巧，形状**左上角一直有一根"拉丝"尖角**：值噪声要周期化，周期 K 必须是**整数**、而且**哈希索引也得模 K**，两处漏一处就在接缝留下折痕。换成在半径 R2 的圆上采 2D 噪声 ⇒ θ=0 与 2π 是**同一个点**，根本不存在接缝。 |
| 轮廓用**二次曲线过中点**平滑，不是 `lineTo` | 直接连线会出锯齿：形状被压扁的区段里相邻顶点 dy 只有 2~3 px，而噪声让 dx 能差 3 px ⇒ 折线在横向来回跳（肉眼就是边上一圈小毛刺）。同样 96 个点，过中点画二次曲线 ⇒ 一条连续的液体曲线。 |

#### 互动三层

1. **涂抹擦痕**（唯一让板动起来的输入）：指针进板 ⇒ 在指针处盖一个有机形状的笔触，
   笔触**每帧变形**（噪声相位跟着 `t` 走）⇒ 划一道出去，带子两边是起伏的，**不是一条等宽的规整笔道**
   （站主原话「被擦除的部分不能太规整」）。笔触软边（径向渐变，实心到 0.70R、外围渐隐）
   ⇒ 边界像"雾被擦开"。擦痕停留 ≈2.9 s 后褪回纯色。
2. **与页面互动**：划过网格里任意一张**横幅**照片 ⇒ 板里交叉淡入那一张（700 ms）。
   ★ 竖幅不接（站主：「只要横着的照片」）。
   ★★ 图源走**网格档（800）**（`img` 的 src），**不是**灯箱档（1280）：1280 档单张能到 **486 KB**，
   线上实测某张 842 ms 才到、更重的要好几秒 —— **那几秒里指针擦不出任何东西**
   （`drawCover` 看 `complete`）。★ 整屏了也**不换**回大图：擦出来的只是一条一两百 px 宽的带子。
3. **每次打开随机一张**（只从横幅里抽）：★ 本文件**唯一**允许的随机源
   （形状本身必须是 `t` 的确定函数，否则"同 t 逐点比对"这个唯一的形状验收手段失效）。
   ★ bfcache 回来的页面**不会重新执行脚本** ⇒ 补 `pageshow`（判 `persisted`），
   否则"每次打开随机一张"在"从文章返回相册"那条路径上不成立。

#### 降级四态（都实测过）

| 状态 | 行为 | 实测 |
|---|---|---|
| `prefers-reduced-motion` | **静止整张照片**（不裁形、不响应指针、不跑 rAF） | 三次采样面积**完全相同**、位移 **0.0 px/s** |
| 无 JS | 整块不出现（SSR 就带 `hidden` + `aria-hidden`），**不是"藏起来"** | 板是装饰，内容在网格里已完整存在 |
| ≤767px | **回到页头右侧小板**：页头变回左右两栏（标题 `order:1`、板 `order:2`）⇒ 一个 DOM 两副版面；高走照片原比例（`--bath-ar`）；笔触走小板那一档 | 390 视口实测板 `min(56%,240px)`、**无横向溢出** |
| 视口外 / 切标签 | 停帧（★ 整屏装置的耗电只发生在它可见时） | `IntersectionObserver` + `visibilitychange` |

★★ **小板必须 `flex: 0 0 auto`**：flex 子项默认可收缩，不写的话标题一挤就把板压扁
（实测 390 视口下被压到 133 px，而 CSS 写的是 179 px）。已写进 `AGENTS.md` 事故表。

★ **露面不等首图下载**：静止态本来就一个像素都不画（纯色），等图只会让板在慢网络下晚好几秒才出现
—— 线上实测 t≈4.1 s 时 `host.hidden` 仍是 true（板根本没露面）。照片迟到没有副作用：
指针进来时 `drawCover` 自己会看 `complete`。护栏钉「源码里**不许**出现 `await ready(` / `addEventListener('load'`」。
★ 唯一例外：reduced-motion 是静态整张且**不跑 rAF** ⇒ 图晚到就再没重画机会（静止用户看到一块空板）
⇒ 那里补一次 `onceImg` 的 one-shot。

★ 为什么 reduced-motion 给"整张"而不是"留一块纯色"：静止用户没有搅动可得，纯色块就只是个空方块；
而「显影完成」是这块装置**静止时最有信息量的那一帧**，且零运动。

#### 探针 `_probe/cdp-bath-water.mjs`（第六轮新增：量"像水一样"这三件事）

`node _probe/cdp-bath-water.mjs <url> [--w 1280] [--h 900] [--hold 3200]`
—— 慢划一道 → **把指针移出板** → 每 200 ms 采一次，输出一条时间序列：

| 列 | 量什么 | 怎么读 |
|---|---|---|
| 面积 | alpha>8 的像素数 | 单调下降 = 在褪 |
| **质心** | 显影区域的重心 | 只衰减 ⇒ 不动；被水流推 ⇒ 会漂 |
| **硬边比** | alpha>192 的像素占显影面积的比例 | 一直 0.9+ = **双峰**（边界在收缩）；中段掉下去 = 整块一起淡 |
| **差异% / 大变%** | 与上一帧相比 alpha 变化 >8 / >64 的像素比例 | 活着期间持续 >0 = **边界一直在动**（冻结后整体淡出的话这一列会是 0） |

★ 两个"量法陷阱"：
· **不能用面积判断"边缘在动"** —— 面积只会单调下降，冻住和流动都长这样；
  ⇒ 必须看**相邻帧的差异像素比例**（边界在移动 ⇒ 那一圈像素会大幅翻转）。
· **质心漂移要分方向读**：沿划动方向的漂移主要来自"早擦的那段先褪"（这是**对**的）；
  垂直于划动方向那一份才是水流输运真正的读数。

#### 探针 `_probe/cdp-bath.mjs`

按行扫 canvas 的 alpha>128 区间即得轮廓（因为板底是 CSS、canvas 只有擦痕中有像素）。

- `--at` 采样时刻 · `--rows` 扫描行数 · `--moments` 打印逐行左右端点 · `COV` 整版覆盖率
- `--hold x,y` 把指针**按住**在板的相对位置（0..1）· `--wipe` 慢划一道 + 划完把指针**移出板** + `--after` 衰减采样
- `--drag a,b,c,d` 从 A 快速划到 B，量**洞心滞后指针多少 px**（读整版 α 质心）
- `--hover-fig N` 把指针移到网格第 N 张可见图 ⇒ 验"与页面互动"
- `--reduce` 模拟 `prefers-reduced-motion: reduce` · `--dsf N` 抬设备像素比 · `--shot` 截图

**探针自身的坑**（都踩过）：
1. **窄视口必须用 `Emulation.setDeviceMetricsOverride`**，不能只靠 `--window-size` —— Windows 上 Chrome
   窗口有**最小宽度**（要 390 时得给到 512）⇒ 量出来的其实是 512 宽的桌面窗口，白测。
2. `--hover-fig` 会把页面滚下去，而截图 clip 用的是**文档坐标** ⇒ 不回顶会截到一块空白。
3. 拼接注入脚本时两块之间**必须**有分号（`'}; 1'` + `'window.__x = …'` ⇒ `1window` 是非法记号）。
4. 板宽由 CSS 定 ⇒ 放大视口不会把板放大，要看形状细节只能抬 dpr，截图 clip 的 `scale` 得一起改。
5. **判"换片了"必须先 `Network.setCacheDisabled`** —— 否则 `new Image()` 命中内存缓存，
   `performance` 资源条目不增加 ⇒ 误判"没换片"。
6. **量"停留"时划完要先把指针移出板**：指针留在板上会每帧原地补一笔 ⇒ 量到的停留偏大。

#### 现行实现（`src/scripts/time-slice-scene.ts` / `time-slice.ts`）

* **切片链**：76 片 = 一块无边框玻璃片（`PANE_W=1.8`，纹理只有一小团极淡的玻璃芯）
  + 一只静止蝶（`SLICE_SCALE=0.8`，全链共享一份几何）+ 右下角 FRAME 芯片。
* **「实 / 虚」判据**（本轮核心，别改坏）：
  ```
  dist = CAM_BACK − (s.z − live.z)       // 这一片到镜头的轴向距离
  dd   = (s.z − live.z) / 片距           // 镜头已越过这一片几片（连续值，负 = 还没到）
  op   = (0.26 + 0.74·e^(−|dd|·k)) · smoothstep(CAM_NEAR, CAM_CLEAR, dist)
         k = K_AHEAD(0.85) 未走到 / K_PASSED(2.6) 已走过
  ```
  **为什么要分档**：镜头在连续推进，任意时刻总落在两片之间；对称衰减会让两片等距、
  同时最亮 ⇒「只有一片是实的」在数学上不成立。分档后「正前方还没走过的那片」永远是
  唯一最亮的（实测 maxOp 0.69~0.94 恒为 1 片），且在 `dd=0` 处两档都趋近 1 ⇒ 切换点
  无跳变（不闪）。**让位**那一段保证被走过的片在贴到近裁剪面前淡完（否则放大成满屏糊块）。
* **隧道**：一圈圈**开着的**方框（`HALF=1.35`、`bar=0.12`，间距 3.1，铺满 165 单位）。
  框内是空的 —— 早先填过面，76 层片 + 54 层面片一路累加到 ~97% 白，整条隧道被洗成白雾。
* **环绕蝴蝶群**：`InstancedMesh` 360 只（3 圈壳层 × 10 × 12 站），位置/姿态全由
  `tslHash` 确定（零随机源），透明度由 `amb` 驱动 ⇒ **不转视角完全看不见**。
* **尽头背光**：三个加色精灵**恒定跟在镜头前 58 单位**（点光口径，屏幕尺寸恒定），
  中间几十片玻璃/方框把它滤成一圈圈光带。
* **模型**：Poly Pizza CC-BY「Monarch Butterfly」（Paul Spooner），本地把贴图重打成
  浅象牙（保留黑脉 ⇒ 真实感）+ 抽稀到 3552 面，落成 `public/butterfly.glb`（249 KB）。

#### 本轮踩的坑（都要记住）

1. **★★ 共享层的弹簧在低帧率下发散**（`rl-core.ts`）：半隐式欧拉一帧一大步的稳定域是
   `dt < 2/c`，`k=110 / c=23` ⇒ **87 ms**，而 `startLoop` 把 dt 钳在 100 ms ⇒
   **低于 11.5 fps 就发散**成 Infinity→NaN。挂在上面的滚动进度跟着 NaN ⇒ 装置跳到 0/1
   极端态。**软件渲染（≈3 fps）下必现**，所以这个坑是在探针里先炸出来的。
   ⇒ 改成**定步长子步（1/120 s）**，并把「大 dt 不发散」写成测试。
2. **★ 纹理里任何「铺满整片」的元素都会逐层累加**：0.05 的掠光叠 76 层 = 98% 白。
   隧道/玻璃的质感只能靠**边框**（每片落在不同半径上）与极小的居中玻璃芯。
3. **★ 尽头背光不能钉在链尾**：镜头一靠近它就等比放大，走到链尾糊满整屏

4. **★ 探针不能 sleep 定长就读数**：`dt` 被钳到 64/100 ms 之后，「模拟时间」远慢于
   真实时间，弹簧还在半路 ⇒ 读到自相矛盾的中间态（这一版第一轮探针的 `z` 在 −3 与

#### ★ 玻璃「毛玻璃」的画法（`makeGlassTexture`）

同一圈**圆角**轮廓上叠 14 道「由细到宽、由亮到淡」的描边（`lineWidth = 2.5 + t*44`，
alpha ∝ `(1−t)^1.7` 峰值 0x0d）：最亮的一笔压在轮廓线上，往外一层比一层宽、比一层淡
⇒ **边是雾带不是线**，而且越往片内越化开，正是磨砂倒角的样子。面上只留一圈贴边的
极淡雾（**radial**，中心透亮 —— 蝶不被糊）。76 片叠着看就是参考图2 那圈往里收的软边方框。

**为什么不能用 linear**：`createLinearGradient` 扫过的是一整片，76 层累加 = 98% 白，
整条隧道洗成白雾、蝶面跟着糊掉（第四轮实测踩过）。radial 只在贴边一圈有值，中心恒为 0。

#### ★ 蝶的「实 / 虚」判据（本轮重写，别改坏）

```
cur  = argmin{ dist_i | dist_i > 0 },  dist_i = 镜头 z − z_i     // 唯一
k    = i − cur
near = smoothstep(FADE_NEAR 0.35, FADE_FAR 1.0, dist_i) ^ 0.6    // 让位：镜头正穿过它
op   = e^(−k · K_AHEAD 0.72) · near                              // 玻璃片把 K 换成 K_PANE 0.10
```

* **为什么必须「选唯一那片」而不是对称衰减**：镜头连续推进，总会有两片等距的瞬间，
  对称衰减会让两片同时最亮 ⇒「只有一片是实的」在数学上根本不成立。改成筛选后
  `k=0` 恒为 1（实测 `maxOp=1.00`、`solid=1`），往后严格递减。
* **为什么要有 `CAP_DIST` 缩放**（`wing.scale = SLICE_SCALE · min(1, dist/1.5)`）：
  镜头是**连续**推过去的，「最前那片」必然一路逼近到 0 距离 —— 不缩的话它在屏上会涨到
  100%+，实测 `_bvts-k-p050` 就是一大团半透明糊满整屏，恰好把「只有一片是实的」毁掉。
  缩了之后它从 24% 长到 40% 封顶，再让位淡出；缩放函数在 `dist = CAP_DIST` 处正好等于
  透视值 ⇒ 封顶点**不跳**。
* **让位段**：`dist < 0.35` 完全消失（否则贴在近裁剪面上放大成糊块）；零点接上 `k=1`
  的 `e^(−0.72)=0.49` ⇒ 交接点不闪。

#### ★ 烘焙翼相（`makeFlapGeos`）—— 轴选错会把蝶折成楔形

* 主轴 = **背轴（Z，指向镜头）**：两翼反号绕它转 ⇒ 翼尖在画面里一起抬/落，两翼张成
  **V 字**，一眼就是扑扇。
* ★ **为什么不是体轴（Y）**：归一后翼展沿 ±X、头朝 +Y，绕 Y 转只会在正投影里把翼面
  **横向压扁** —— 60° 时只剩一半，整只蝶折成一个楔形（把 16 档翼相并排渲出来看的，
  `_probe/_bvm-flap-zoom.png`），完全不像在飞。
* 上抬全量 / 下压一半（`raw >= 0 ? raw : raw*0.5`）；再叠一个 0.3 的体轴后掠，翼面
  不贴正投影、少些「纸片感」；翼根 `smoothstep((|x|−0.03)/0.13)` 加权到 0 ⇒ 不撕胸节。
* 振幅 0.62 rad（36°）⇒ 任何一档的横向展幅 ≥ cos(36°) = 0.81，永远是「一只张着翅的蝶」。

#### ★ 蝶的调色（第五轮）

原片里那只蝶（`_probe/_bvt-video-bf.png` 放大到 840×640 读的）是**浅奶油带细灰脉、
通体发光**，而我第四轮那版**黑脉太厚、整只偏深**。改成逐像素调色（`_probe/_bv-grade.mjs`）：

```
① 提亮曲线  v = 255·(1 − (1 − c/255)^4.0)     // 把黑脉整条抬起来
② 线性      v = 112 + 0.58·v                  // 暗端抬到 ~112（原片里的脉是浅灰不是黑）
③ 去色相    out = lerp(v, L·(1.00, 0.945, 0.70), 0.97)   // 同亮度换成暖象牙
```

四档并排比过（`_probe/_bvm-grade2-zoom.png`：C/D/E/F），**取最浅的 F**。体量不变
（229 KB / 3552 面，`public/butterfly.glb`）。

#### ★★ 1) 「唯一实」必须是**硬切** —— 软窗口本身就是双影的来源

第六轮那版用 `hero = ss(COMP_HI, COMP_LO, score)` 做「软重叠」。窗口半宽 1.1、
两片距离恒为片距 2.2 ⇒ 相邻两片**可以同时落在窗口里**（一个 au=0.84、一个 au=0.93），
于是两只蝶同时 0.80 / 0.93 —— 肉眼看就是**双影**（证据帧 `_probe/_bvts-6b-p050.png`：
一只在左下、一只在中央，取样 `(392,636)=243,239,206` 与 `(380,600)=254,254,254`）。

第七轮改成**硬切**：

```
const au = Math.abs(dist - FOCUS_DIST);
// focusI = au 最小的那一片（先扫一遍选出来）
const op = i === focusI ? 1 : SIDE_OP * wingFade;   // hero ∈ {0,1}，没有中间态
```

相邻两片的 au 相差**恰好一个片距**（2.2）⇒ 不可能两片同时取到最小值 ⇒ **任一瞬刻
恰好一片是实的**，既不会双影、也不会「谁都不亮」。硬切同时就是「时间切片」的语义：
一帧就是一帧（参考片 76 帧 / 14.03s ≈ 5.4fps，本来就是频闪的），滚动 = 逐帧换掉。
`_probe/_bvts-6c-p050.png` 复检：只剩一只，且落在画面中央。

#### ★★ 2) 其余蝶的透明度：**亮度另给一档、可见度曲线与玻璃完全同一条**

站主第七轮把它说了两遍（第 1 条 + 补充）。关键在于**玻璃贴图峰值 alpha 只有 0.2**
（`GLS_PEAK`，见 `makeGlassTexture`，通体极淡）⇒ 玻璃「看上去」的不透明度是
`PANE_OP × GLS_PEAK = 0.9 × 0.2 = 0.18`，而不是 `PANE_OP` 本身：

```
const paneFade = Math.exp(-au * K_PANE) * paneNear;
const wingFade = Math.exp(-au * K_WING) * paneNear;   // K_WING = K_PANE
const paneOp = PANE_OP * paneFade;
const op = i === focusI ? 1 : SIDE_OP * wingFade;
const SIDE_OP = (PANE_OP * GLS_PEAK) / STACK_DAMP;    // 0.18 / 4 ≈ 0.045
```

两件事必须分开看，混在一起就会两头不讨好：

* **可见度曲线 = 玻璃那条**（`K_WING = K_PANE = 0.1`）。这是补充那条硬要求
  「转动视角时看到的其他切片上加一个透明蝴蝶」⇒ **有玻璃的片就必须有蝶**。
  ⚠️ 中途曾为了压亮度把蝶的衰减单独改陡到 `K_WING = 0.35`，实测环视时
  `vis=10 / panesLoud=26` —— 16 片玻璃上没有蝶，**违反补充那条**，已回退。
* **单只不透明度 = 玻璃那一档再除以 4**。原因是几何上的不对称，不是审美：
  玻璃片是**薄框**，各片框线落在不同半径上、几乎不叠；蝶是**实心剪影**，而所有
  残影的屏上位置都挤在链轴附近（离轴摆动只有 ±0.34 世界单位）⇒ 十几只叠在同一
  小片区域里。实测（`_probe/_bvts-7e-p050.png`，单只取 0.06 那一版）中轴残影云
  合成峰值 **157/255**，比玻璃框（取样 55~63）亮出一大截；`_bvts-7f-p050.png`
  （单只 0.045）降到 **75~80/255**，与玻璃同档 —— 这才叫「和玻璃片一样透明」。
  同时单只仍有 `0.045 × 255 ≈ 11/255`，环视时落在玻璃片上是**看得出的**
  （`_bvts-7f-chk060.png` 左片那只透蝶把背景 11~22 抬到 31~71）。

> 量测提醒：实的蝶本体覆盖 x≈500~680、y≈310~500，`(640,400)=255`、`(660,400)=148`
> 都是**实蝶自己的**读数，不是残影云。残影云要取实蝶轮廓之外的柔雾区
> （如 `(408,489)`、`(699,443)`），否则会把 148 误当「残影过亮」。
>
> 结论：**唯一实**的客观判据仍是探针那两条 —— `solid` 恒为 1、`half` 恒为 0
> （11 个落点全绿）；补充那条的判据是 `vis` 追平 `panesLoud`（实测 22 vs 26，
> 差的那几片是尾端 op 刚好压线的，肉眼已是全黑）。

#### ★★ 3) 场景**全静止**：update() 里一个 `position` 都不写

站主第七轮给了两句几乎同义的话：「蝴蝶是固定在切片上的，不要变位置」「整个场景中
蝴蝶，切片等等位置都不要变幻，只有摄像机的位置在变」。上一轮为了实现「交接完全
重合」，把蝶的位置每帧按 `k = 1 − hero` 收回链轴 —— **那就是在动场景**，删掉。

落法：每片起一个**锚在链轴上的 `Group`**（`holder`）：

```
holder.position.set(p.x, p.y, p.z);   // 建场景时写一次，之后一辈子不动
wing.position.set(sway.x, sway.y, 0); // 该片自己的摆动，也是常量
holder.add(wing);
```

`update()` 只写 `opacity / visible` 与 **`holder.scale`**。那个 scale 是**投影补偿**：

```
s.holder.scale.setScalar(Math.max(0.05, dist / FOCUS_DIST));   // ★ 全链一律
```

* 视张角 = (SLICE_SCALE·comp)/dist = SLICE_SCALE/FOCUS_DIST ⇒ **与距离无关**；
  离轴位移也按同一个 comp 放大 ⇒ 屏上位置同样与距离无关。于是实蝶在它整个任期
  （dist 2.3→4.5）里既不胀大也不缩回，交接处更不跳。
* ⚠️ 补偿必须**对全链一律生效**。中途曾把它收窄成「只在焦点附近」
  （`w = ss(3.0, 1.2, au)`），结果镜头**正在穿过**的那几片（dist 0.2~2.0）保持原始
  世界尺度 ⇒ 视张角涨到一屏以上，糊满整条隧道（证据帧 `_probe/_bvts-7-p050.png`
  里那只「比屏幕还大的整屏灰蝶」）。现在一律缩。
* 下限取 `0.05`（不是 0.25）：`dist < 0.85` 的片若按 0.25 兜底会重新涨大，
  0.05 让身后那些片老老实实缩成一点，读作「频闪拖尾」而不是「一堵墙」。

#### ★★ 4) 虚实只认滚动位置；滚轮**任何方向**都不许动视角

* **虚实**：`dist` 原来取 `camera.position.z`。环视是绕当前切片公转 ⇒ 机位 z 会变
  （拖动到 47° 时实测 camZ 漂了 0.8）⇒ **转视角会顺手改掉「哪一片是实的」**，正是
  站主第 4 条骂的。改成取**链锚** `const eyeZ = camZ;`（纯滚动量）。
* **滚轮**：第 6 条带了六个感叹号。上一轮我把它读成「滚动两个方向都**复位**视角」，
  并在 base 方位角里留着 `+ 0.1 * se` —— 那等于「滚一下，视角跟着转最多 5.7°」。
  第七轮全部删净：`const azBase = AZ_BASE;`（纯常数），且 wheel 监听器里
  **一个赋值都没有**，只剩「链尾之后再往下滚就别滚了」那条守卫。于是向上滚与向下滚
  在同一个滚动位置给出**逐像素相同**的画面。
  * 代价（有意为之）：拖动过之后周围切片不再被滚动熄灭。此前那句「向下滚 ⇒ 周围
    切片不再显示」属于第二轮口径，与第七轮「滚轮不要变视角」直接冲突，以后者为准。

#### ★ 5) 实的蝶离镜头远一点 + 扇动幅度大一点

* `FOCUS_DIST 1.9 → 3.4`。1.9 时焦点片自己那扇玻璃就胀到比屏幕还大（55° 竖直 FOV
  下边长 2.6 的方框在 1.9 处占 1.37 个屏高）⇒ 实蝶等于贴在镜头上、画面里没有边框
  托它。3.4 处那扇窗占 0.76 个屏高，正好「框住」。
* 尺度必须同步：视张角 = SLICE_SCALE / FOCUS_DIST ⇒ `SLICE_SCALE 0.62 → 1.11`
  （× 3.4/1.9），实蝶仍占屏宽 ≈20%（与参考图同比例）。改 FOCUS_DIST 就必须改它。

  `cos(49°) = 0.66`，仍是一只张着翅的蝶，不会收成一条。

#### 本轮踩的坑

9. **`not.toMatch(/=/)` 这种「禁止一切赋值」的写法必踩箭头函数**：`(e) => {` 里就有
   `=`。改成「把函数体切出来 + 长度上限」才稳（见 `tests/time-slice.test.ts`）。
10. **改常量要顺着「派生常量」一路改**：`SLICE_SCALE` 与 `FOCUS_DIST` 是绑死的
    （观感 = 比值），只改一个就会让实蝶要么贴脸要么缩成一点。
11. **`SLICE_SCALE` 一度被我在 update 区重复声明**（原有的定义在切片构建区）——
    TS 会直接报「Cannot redeclare」。常量只有一个家，改值就回去改那一个。
12. **读数必须等 z 也收敛**：只等 `amb` 收敛就拍照，会拍到弹簧还在飞行途中的
    「两片都半亮」瞬态，误判成静止态双影 —— 这是上一轮把 `_bvts-6c-reset.png`
    看成双影的原因。探针已加 `converge([...])` 助手。

13. **「压亮度」要压对地方**：压亮度有两个旋钮 —— 单只的不透明度（`SIDE_OP`）和
    可见度衰减（`K_WING`）。改前者只动亮度，改后者会**顺手删掉远处的蝶**。
    为了消掉残影云，我第一反应是拧 `K_WING`（0.1 → 0.35），亮度是下来了，但
    站主要求的「每片可见玻璃上都有蝶」也被一起拧掉了（`vis` 26 → 10）。
    **要亮度就拧 `SIDE_OP`，要覆盖就守 `K_WING = K_PANE`。**
14. **量测点要避开主体**：实蝶本体就覆盖 x≈500~680 / y≈310~500，随手取的
    「中央偏右」取样点其实落在它的翼缘上（`(660,400)=148`），会把实蝶的边缘
    误判成「残影云过亮」。取样前先在证据帧上确认那个点在图里是什么。
15. **★★ 没有阴性对照的量测可能是「永远通过」**：为了给第 8 条（删滚动条）留证据，
    我量了 `documentElement.offsetWidth − clientWidth`，主页读到 **0** —— 看着是完美通过。
    但**同一个 Chrome 加载一个没有滚动条 CSS 的裸页面，这个数也是 0**：
    `--headless=new` 用的是**覆盖式滚动条**（overlay scrollbar，不占布局宽度）。
    ⇒ 这个量测在本机**恒为 0**，什么都证明不了（假阳性）。
    **教训：任何「应该变 0 / 应该消失」的量测，都要先拿一个「应该非 0」的对照组跑一遍。**
    最终第 8 条的证据只能靠产物 CSS + `tests/build-output.test.ts` 那条用例，
    而不是这个读数。（对照脚本见 `_probe/_bv-home.mjs` 的 `BV_CTL=1` 模式。）
16. **开机遮罩期的滚动会被 focus() 顶回顶部**：`_bv-home.mjs` 第一次跑时
    `scrollTop` 怎么写都回 0，一度以为是「删滚动条把滚动也关掉了」（过度修复的嫌疑）。
    实为 `BootIntro` 收尾 `title.focus()` 触发的滚动重置（`_bv-ts.mjs` 早就踩过同一个坑）。
    探针加「整屏遮罩计数 + 重试」后才稳定通过（`scrollTop = 6766`）。

#### 探针新增（可量化，不靠肉眼）

* dump 增加 `half`（0.35 < op ≤ 0.9 的「第二片半亮」计数）与 `panes / panesLoud`
  （玻璃片的渲染数 / 其中 op > 0.05 的「看得出是块玻璃」数）。
  * 判据 A（第六轮 → 第七轮）：「唯一实」⇒ 静止态 **`solid` 恒为 1 且 `half` 恒为 0**。
    这是「双影」唯一的客观指标。
  * 判据 B（第七轮补充）：「每片可见玻璃上都有透蝶」⇒ **`vis` 追平 `panesLoud`**。

#### ★★ 1) 「滚轮往上滚不要变视角」的**真因** —— 第三次返工才找到

第 4 条是**第三次**返工（第七轮我甚至专门为它写过一轮）。前两次都改在**参数**层：

* 第六 → 第七轮：把 wheel 监听器删到「一个赋值都不写」；
* 第七轮：把基础方位角常量化（`azBase = AZ_BASE`，删掉 `+ 0.1 * se`）。

这两处**都是对的**，但它们都不是真因。真因在 `time-slice-scene.ts` 的机位段：

```
机位  pz  = camZ + (R·cos az·cos el − CAM_BACK) − 2.9·exit   ← camZ 是**二次平滑**后的值
注视点 az2 = live.z − 1.7                                     ← 即时值
```

控制器那边的 `p` 已经过弹簧了，场景里又对 `camZ` 做了一次 `dt/190` 的一阶平滑。
于是 **机位滞后于注视点**，滞后量记 L：

* 向下滚：L > 0 ⇒ 注视点落到相机更远处 ⇒ 视线被**压平**；
* 向上滚：L > 0 但方向相反 ⇒ 注视点甚至跑到相机**身后** ⇒ 画面**朝后翻**。

实测（`_probe/_bv-look.mjs`，**改前**，拖动转开视角后各滚 8 档）：

| 量 | 起点 | 向下滚途中 | 向上滚途中 | 滚回原位 |
|---|---|---|---|---|
| `az`（参数） | 47.01° | 47.01° | 47.01° | 47.01° |
| **`camera.rotation.y`（观测量）** | 28.20° | 9.92° | **143.24°** | 28.31° |

`|Δyaw|max = 116.45°`、`|Δpit|max = 3.09°`。**而 `az / el / amb` 一动不动** ——
所以老探针每次都「全绿」，站主每次都还在骂。

**修法（结构性，不是调参）**：机位与注视点改用**同一个锚**（链参数点 `live`）、
放在锚的**两侧**（机位在后方 `R`、注视点在**前方** `R2 = R + LOOK_DIST`）：

```
const LOOK_DIST = 1.7;
const tx0 = live.x − R2·sin az·cos el;      // ★ 三项都要取负号，见下面的坑
const ty0 = live.y − R2·sin el + 0.03;
const tz0 = live.z − R2·cos az·cos el − 2.9·exit;
camera.lookAt(ax, ay, az2);                 // se 段再混向标本
```

⇒ 视线方向 = **−u**（`u = (sin az·cos el, sin el, cos az·cos el)`），只由 `az / el`
决定，与滚动位置、与任何弹簧滞后**完全无关**。同时把机位那层二次平滑 `camZ`
**删净**（「轻惯性」由控制器那一层弹簧负责，一层就够）。

改后实测：**`|Δyaw|max = 0.00°`、`|Δpit|max = 0.00°`**，同一位置滚动往返
`yaw −132.99° → −132.99°`（Δ0.00°）。

> ⚠️ **符号写反过的坑（探针没抓到，靠目检抓到的）**：第一版把注视点写成
> `live.z + R2·cos`。机位在链锚**后方**（z 更大），注视点于是落到**相机身后**
> ⇒ 相机转身朝后看 ⇒ 画面里只剩被甩到身后的那几片，而它们的 `holder.scale`
> 取 `0.05` 下限 ⇒ **蝶缩成一个小十字、整屏发黑**（`_probe/_bvts-8a-p050.png`）。
> 而当时 `_bv-look.mjs` 的 ①②③ 判据**全绿** —— 因为它们比的都是「滚动前后
> 一致」，而**整体朝后看同样能前后一致**。⇒ 补了一条**绝对判据**：朝前方的
> 相机，`yaw` 归一化到 (−180, 180] 后 `|yaw|` 必须 < 90°。

#### ★ 4) 开场整体缩放（第 1 条「里面的场景一开始小一点，随着慢慢进窗口的同时恢复原来大小」）

拆成两件事：

* 「**这个窗口**大一点」—— 截图里的绿框是**入口菱形窗**（`.tsl-ring path`，
  `stroke: var(--accent)`），不是玻璃片的框。基准半宽在控制器里：
  `baseHalf = Math.min(W, H) * 0.14` → **`* 0.19`**。
* 「里面的场景一开始小一点 …… 恢复原来大小」—— 中央链（蝶 / 玻璃 / 读数）乘一个
  由 **`zoom`（入口菱窗张开进度）** 驱动的整体缩放：

```
const GROW_MIN = 0.6;
const grow = GROW_MIN + (1 - GROW_MIN) * ss(0, 1, zoom);
```

  * 驱动量选 **`zoom`**：站主说的「进窗口」就是窗口张开那一段（`zoom: 0 → 1`，
    落在 `p ∈ [0, 0.30]`）。挂 `t`（飞行进度，从 `p=0.30` 才开始）的话恢复会推迟
    到飞行开始之后；挂 `zoom` 则**飞行全程 `grow` 恒为 1**，飞行段的观感与已经
    验证过的那一版完全一致。控制器要把它传下去（`zoom: tl.zoom`）。
  * 不是「近大远小」的透视：站主要的是「一开始小 → 慢慢恢复」这段**开场过渡**。
  * **只缩中央链**（`s.holder.scale` 乘 grow、`s.pane.scale.setScalar(grow)`、
    读数 sprite 同类）。柱阵（`grid`）**不参与** —— 它的实例位置铺在整条链上，
    跟着缩会被甩到相机身后。柱阵本来也只在转视角后才可见。
  * ★ 只写 `scale`，**位置仍然一个字节都不动**（第七轮契约不变；
    `tests/time-slice.test.ts` 里那三条 `not.toContain('s.….position.set(')` 继续守着）。

#### ★ 5) 蝶列玻璃放大 + 轨迹成**曲线**（第 5 条）

* 「有蝴蝶的这一列切片玻璃可以大一点」：`PANE_W 2.6 → 3.6`。**但柱阵仍吃 2.6 那份

  （第六轮要的正是「一格一格整齐等距」）。
* 「运动轨迹不要是一条直线 …… 可以是一条曲线」：`swayOf` 从「两个正弦相加」
  （近似直线，峰值 0.34）改成 **x / y 相位差 π/2 的椭圆 + 次级谐波**：

```
const TRAIL_TURN = 0.21;  // 沿链的相位步长（76 片 ≈ 2.5 圈）
const TRAIL_A = 1.05, TRAIL_A2 = 0.3;
const TRAIL_B = 0.6,  TRAIL_B2 = 0.22;
x = taper·(TRAIL_A·cos th + TRAIL_A2·cos(th·0.37 + 1.9))
y = taper·(TRAIL_B·sin th + TRAIL_B2·sin(th·0.53 + 0.7))
```

  峰值 0.34 → **≈1.35 世界单位**（在焦点处 ≈ 20% 屏高，一眼是条曲线）。
  * 蝶与它那扇玻璃用**同一个 sway**（`sx = p.x + sway.x` 与
    `wing.position.set(sway.x, sway.y, 0)`）⇒ 摆幅再大，蝶也**永远停在框心**。
  * `taper` 两端归零不变 —— 入窗那一片与出窗那一片仍老实居中。

#### ★★ 6) 量测纪律：判据要落在**观测量**上（本轮最值钱的一条）

第七轮的探针把自己的「视角不变」判据写成 `az / el / amb` 三个**参数**。这三个确实

输入不变而输出变了（因为中间多了一层滞后），探针就**全绿地骗了自己三轮**。

**规则**：断言「用户看到的东西」，不要断言「我以为的中介量」。
能落到像素就落像素；落不到像素就落在**渲染层会读的那个量**（这里是 `camera.rotation`），
并且**在运动过程中采样** —— 漂移是**瞬态**，等收敛后再读是读不到的（本轮实测：
收敛后往返都能回到 28.20 / 28.31，看着像「只差 0.11° 的浮点尾差」）。

同类前科（§6.18 坑 15）：量滚动条宽度量到 0，看着是大成功，结果**裸页面也是 0**
（`--headless=new` 用覆盖式滚动条）⇒ 恒为 0 的假阳性。**同一个病**：没问「这个量
真的能区分对错吗」。

#### ★ 2) 滚滚轮 = 「收回临时环视」（第 2 条）

站主要有两件事同时发生：**回到原始视角** + **周围切片消失**。

先把「视角」拆成两层（这是本轮最要紧的一刀）：

| 层 | 谁写 | 什么时候变 | 滚动时 |
|---|---|---|---|
| **基础朝向** `AZ_BASE` | 常数 | 永远不变 | **不动**（第七/八轮钉死的那条） |
| **临时环视** `obxT / obyT` + 环绕柱阵开关 `ambT` | 拖动 / 指针视差 | 读者拖的时候 | **一滚滚轮就归零** |

于是 wheel 监听器里就三行赋值（外加两条**原有**的链尾守卫）：

```ts
window.addEventListener('wheel', (e) => {
  if (atTail && e.deltaY > 0) { e.preventDefault(); return; }  // 链尾之后：滚动到此为止
  obxT = 0;   // 环视：回到原始视角（目标恒为 0，不随滚动方向变）
  obyT = 0;
  ambT = 0;   // 周围切片：收起
}, { passive: false });
```

三个要点：

* **目标是常数 0，不读 `e.deltaY`、不读方向** ⇒ 向上滚与向下滚在**同一位置**仍然
  给出**同一个朝向**。这正是第八轮那句「视角和滚轮往下时一模一样」的**结构性**延续：
  第七/八轮钉的是「不带入滚动量」，第九轮加的是「带入的只是**归零**这个动作」。
  （写死 0 而不是「恢复拖动前的值」，站主说的是「回到**原始**视角」= `AZ_BASE` 那一档。）
* **是「缓缓转回」不是硬切**：赋值只是**目标**，`render` 里那两条一阶指数负责行程
  （`obx/oby` τ=140ms、`amb` τ=260ms），仍是「滑而不弹」。
* **周围切片消失 = `ambT = 0` 的副产物**，不需要单独一段代码：柱阵不透明度就是由
  `amb` 驱动的（`gridMat.opacity`）。这也是站主第 2 条的「且周围切片消失」——
  与「回到原始视角」**同一根因**（都是环视量归零），不是两个 bug。

> ⚠️ 与第七轮 §6.21「wheel 里一个赋值都不写」的关系：那条针对的是**基础朝向**
> （当时 wheel 里写着 `azBase = AZ_BASE + 0.1 * se` 之类把滚动量带进朝向的写法）。
> 本轮写的是**临时环视的归零**，方向无关、不读滚动量 ⇒ 两条不冲突。

#### ★ 3) 收尾简化：绿幕满屏即入相册（第 3 条）

三件事一起做：

**(a) 删「进入相册」按钮**（`.tsl-cta` / `.tsl-go` 整块 + 它的驻留进度线
`.tsl-cta::after` + 全部 CSS 一族）。它的两个旧职责都有人接手：
* 「尽头出口」→ 绿幕满屏自动切页（下面 (b)）；
* 「无 JS / 手机 / reduced-motion 的相册入口」→ **静态回退层里那个真链接
  （`.tsl-static a`）一直都在**，不依赖这一块。脚本里 `goLink` 也顺势改成
  **读静态层那个真链接**（`host.querySelector('.tsl-static a')`）—— 跳转地址
  因此只写在 HTML 一处，不在 JS 里再写死一份。

**(b) 删出口那一扇绿色菱形框**：菱形轮廓环**只剩入口那一扇**。
第八轮里出口环的半径本来是 `Math.pow(exit, 1.7)` 那套逐帧缩放，本轮整段删掉，
只留入口环：`ringPath.parentElement.style.opacity = tl.zoom > 0.985 ? '0' : '1'`。

**(c) 跳转判据从「时间轴走完」改成「绿幕自己满屏」**：

```ts
const gx = Math.min(1, Math.max(0, (exit - 0.45) / 0.5));
const greenOp = gx * gx * (3 - 2 * gx);      // smoothstep：绿幕自己
green.style.opacity = String(greenOp);
if (navOk && greenOp >= 1) beginNav();       // ★ exit ≥ 0.95 就算「满了」
else cancelNav();
```

```
beginNav(): setTimeout(…, NAV_HOLD_MS = 90) ⇒ sessionStorage['tsl-nav']='1' ⇒ location.assign(dest)
```

* **为什么这是「别卡」的药**：旧写法是 `tf >= 1`（收尾时间轴走完，`TAIL_MS=1900`）
  再 +260ms。`exit` 到 1 的那一刻约在 `tf ≈ 0.95 ÷ …`，而 `tf` 还要继续走到 1 ⇒
  **满屏绿之后还要干等 ≈0.7 s** 才切页 —— 读者看到的就是「绿了，卡一下，才走」。
  现在绿幕一满就走，`NAV_HOLD_MS=90` 只用来保证这一帧**真的上屏**。
* `cancelNav()` 是必需的：滚回链尾以上会重置收尾（`tailT0 = 0`），若计时器还挂着
  就会在半路把读者带走。

**(d) 「有时进不去」的真因 = 旧的 15 s 冷却窗**（本轮删净）。第六轮为了防
「从相册返回 → 又被弹回相册」的死循环，用了一个 `sessionStorage` 时间戳、
**15 秒内不许自动跳**。代价正是站主遇到的：刚看完相册按返回回来，**再滚到底，
十几秒内怎么都不进相册**。本轮换成**看读者的动作**：

```ts
const navType = performance.getEntriesByType('navigation')[0]?.type ?? 'navigate';
let navOk = navType !== 'back_forward';          // ① 整页重载式返回：先闸住
window.addEventListener('pageshow', (e) => {     // ② bfcache 恢复不重跑脚本
  if ((e as PageTransitionEvent).persisted) navOk = false;
});
if (pRaw < lastP - 1e-3) navOk = true;           // ③ 唯一重新武装判据
lastP = pRaw;
```

* 闸门只关「刚回来的那一下」；读者**只要自己往回滚过一点**（`pRaw` 在往回走）
  就重新武装，没有任何时间惩罚。
* **重新武装判据为什么不能写成「pRaw 已在链尾线以下」**：从相册返回时滚动位置是
  浏览器恢复的，而恢复可能落在**首帧之后**（本站首屏遮罩还会把滚动重置回顶部，
  第七轮实测过）⇒ 位置判据会在恢复那一瞬间把闸门打开，然后立刻把读者弹回相册
  （死循环，后退键形同虚设）。「往回走」是恢复**装不出来**的 —— 恢复只有
  「停在上次离开的地方」一种形态。
* `lastP` 初值 0 与首帧 `pRaw ≥ 0`：首帧不会误判成「往回走」。
* 被否掉的两版（记录在案，别回头再写）：① 用 `!atEnd` 当判据 —— 在链尾线以下
  恒为假，收尾压根不启动，永远武装不回来；② 用 `tailT0` 当判据 —— 但 `!atEnd`
  会先把 `tailT0` 清零，同样恒假。

#### ★ 4) 「相册页内容缓缓浮上来」（第 3 条后半）

技术问题只有一个：**跳转那一下，目标页的第一帧必须已经是同款深绿**，否则会闪
一帧纸白（本站的页面过渡墨色浸染是「站内点链接」那条路才有的，`location.assign`
是**整页导航**，走不到那条路）。

* **交接标记**：`<head>` 里那段**同步 inline 脚本**（在 CSS 之前执行）读掉
  `sessionStorage['tsl-nav']` 并给 `<html>` 挂 `.tsl-in`：
  ```js
  if (sessionStorage.getItem('tsl-nav')) {
    sessionStorage.removeItem('tsl-nav');     // 标记用完即删：刷新回来的不该再播
    document.documentElement.classList.add('tsl-in');
  }
  ```
  ★ 必须同步、必须在 head：晚一步（比如挪进 `DOMContentLoaded`）就是**先画一帧
  纸白再补绿** —— 那正是「闪」。这与第六轮 `'pt'`（墨色浸染）用的是**同一手法**。
* **相册页**（`gallery/index.astro`）：`<Base>` 内首子元素加一层交接幕
  `<div class="tsl-veil" data-tsl-veil aria-hidden="true">`，`.tsl-veil` 默认
  `display:none`；只有 `.tsl-in` 下才现形，背景是**同款 178deg 深绿渐变**
  （与剧场绿幕逐档实测误差 ≤2/255），并播 `@keyframes tsl-veil-out` 淡出：
  ```css
  @media (prefers-reduced-motion: no-preference) {
    .tsl-in .tsl-veil { display: block; z-index: 46; animation: tsl-veil-out 620ms var(--ease) both; }
    .tsl-in .bath-mark, .tsl-in .bath-hint,
    .tsl-in .pagehead-main, .tsl-in .filters { animation: tsl-rise-in 820ms var(--ease-glass) both; }
  }
  ```
* 「缓缓浮上来」= `tsl-rise-in`（`translateY` + 淡入）只挂在**内容那几块**上，
  幕布自己淡出 ⇒ 读起来是「绿幕还在，内容从下面浮上来」，而不是「白屏 → 内容
  齐刷刷弹出」。
* 全部包在 `prefers-reduced-motion: no-preference` 里：降低动效的读者得到的是
  **不做动画的绿幕**（本来就 `display:none`，即直接看到内容），不会有位移。

#### 本轮的坑

1. **探针尾部重写时把 `snap / sameView` 一起删掉了**（它们原本定义在尾部），
   跑起来第一刀就 `ReferenceError: snap is not defined`。⇒ 重写一段时先
   `grep` 一遍「这段里引用了哪些外部符号」，别只看被删的那几行。
2. **「回到原始视角」不能写成「恢复拖动前的值」**：站主说的是「原始视角」，
   也就是 `AZ_BASE` 那一档常数 ⇒ wheel 里的目标是写死的 `0`（环视量本身相对
   基础朝向），而不是「记下拖动前那一帧、回滚过去」。后者的观感是「松开就弹回
   上次的位置」，与「一滚滚轮就回正」不是一回事。
3. **`opacity:0` 不等于「不显示」**（第 1 条）：看不见的元素照样可点、可 Tab 聚焦。
   「进窗口后不展示」必须落到 `hidden`（或 `visibility`/`display`），否则会留下
   一个**能点中但看不见**的 CC 外链。测试因此断言的是 `hidden` **并且**
   `opacity === 0`。
4. **降级路径要记得把署名放回来**：`hidden = true` 是运行时状态，`disable()`
   （reduced-motion / 手机 / WebGL 挂了）如果不显式复位，降级页面上署名就永久
   消失了 —— 而许可要求恰恰要求它在**所有**路径下可见。
5. **跳转判据换成「绿幕满屏」后，落点探针必须停在链尾线以下**：一进收尾就会
   自动播到绿幕并切页，把 `p=0.9` 放进「静止态体检」循环会让页面在体检途中
   跳走（读数全成 `(无 dump)`）。静止态体检的落点上限因此定在 `p=0.8`。
6. **★★ Astro 作用域会给选择器里「每一段元素级选择器」都补 `data-astro-cid-*`，
   不只是最后那段** —— 于是「祖先是别人家组件里的元素」这类规则会静默失效。
   本轮最贵的一条坑：
   * 源码写 `.tsl-in .tsl-veil { display: block; animation: … }`，一字不差；
   * 编译出来是 `.tsl-in[data-astro-cid-wiaw4zal] .tsl-veil[data-astro-cid-wiaw4zal]`；
   * 而 `.tsl-in` 挂在 `<html>` 上，`<html>` 是 **Base 组件**渲染的（另一个 cid）
     ⇒ 属性对不上 ⇒ **规则一次都没生效过**；
   * 探针实测：落点 `<html class="tsl-in …">` 明明挂上了标记，但
     `getComputedStyle('.tsl-veil').display === 'none'`、两个 `animationName`
     都是 `none` —— 交接层与内容上浮**双双静默失效**，而**源码级断言全绿**。
   * 修法：前导那段一律 `:global(.tsl-in) …`（只让最后那段吃作用域）。
   * 配套：测试补了一条**产物级**断言（`distCss()` 里 `\.tsl-in .tsl-veil\[data-astro-cid-…\]`
     必须存在、`\.tsl-in\[data-astro-cid-…\] .tsl-veil` 必须不存在）。
   > 一般化的教训：**「我写了这条规则」和「这条规则真的匹配得上」是两件事**。
   > 只要选择器里出现了「由别的组件渲染的祖先」（`<html>` / `<body>` / 布局层的
   > 包装元素 / 全局状态类），就必须在**产物里**确认它的落形，光看源码不算数。
7. **深底上的链接会被全站兜底规则「吃掉对比度」**：`links.css` 那条
   `a { color: var(--accent-ink) }` 兜的是**纸**上的链色（`#266b3b`）。署名这一格
   是深底 ⇒ 首轮探针截图里 `CC BY 4.0` 糊成一片、几乎读不出来 —— 而「可见的署名」
   正是 CC-BY 的全部要求（一条看不见的署名等于没署名）。修法：`.tsl-hud a`
   用站内既有的深底绿 token `--accent-bright`（`#4caf50`，注释明写「只许用在
   深色底」）+ 下划线；探针把 `linkColor` 也纳入观测量（实测 `rgb(76,175,80)`）。
   * ⚠️ `--accent-bright` 是**受控 token**：`tests/tokens.test.ts` 扫产物 CSS，
     裸用它必须登记进 `ALLOWED` 完整选择器白名单（该断言曾经写成 `'a:hover'`
     这种片段，把页脚小字的越界用法一起放行了 ⇒ 白名单必须写全选择器）。
     本轮登记 `.tsl-hud a`，理由：对 `--dusk-1`(`#0b100e`) 实测 **6.76:1**，
     小字达标，属深色底上的正当用途。

8. **导航期间 `Runtime.evaluate` 会丢响应 ⇒ 探针静默卡死**：`location.assign`

   6 分钟，而页面其实早就跳到 `/gallery/` 了。⇒ 跨导航只用两个助手：
   `navPath()`（走 CDP `Page.getNavigationHistory`，完全不碰页面）与
   `evT()`（给 evaluate 套超时，丢了也只是拿到 fallback）。
   ★ 顺带一条：量「进收尾 → 绿幕满屏」这两个时长时**不能用 `setP()`**
   （它会等到收敛，而收敛就已经包含收尾整段 ⇒ 两个数都量成 0），要直接滚过去
   立刻开秒表。

### 6.24 第十轮：触角与肢体不许乱动、不许交叉 —— 翅膀掩膜（2026-10-02）

> 站主原话：「触角和肢体不要乱动，不要交叉」。

#### 病根

第九轮及之前的烘焙扑翼（`makeFlapGeos`）把形变权重挂在 **|x|** 上
（`ease((|x| − 0.03) / 0.13)`，翼根 0、翼尖 1）。但 GLB 是**单个 mesh、无骨骼、
无动画、顶点未焊接**（按位置哈希后有 681 个碎片块），触角与六条肢体跟身体、
翼根**同处 |x| ≤ 0.233 一档** —— 其中 |x| ∈ [0.10, 0.23] 的部分权重已经吃到
0.5～1 ⇒ 每档翼相都被绕 Z 轴拧一遍，**触角跟着翼相摆动、两根在多数翼相里
交叉**；「翼根不动」只保护到了 |x| < 0.10 的胸节。

#### 修法：加载时算出「翅膀掩膜」（`splitWings()`，在 `time-slice-core.ts`）

单 mesh 无骨骼 ⇒ 无法按节点分；未焊接 ⇒ 按顶点也分不开。于是**先按位置焊接
（三点哈希），再做连通块**（共享顶点即连通），最后按块的几何范围判膜：

* 判据：一块的 `max|x| ≥ WING_MIN_X (0.25)` ⇒ 翅膀膜。**0.25 落在真实间隙里**：
  实测 10 个膜块 `max|x| ∈ [0.271, 0.50]`，而触角 / 肢体 / 身体全部 `≤ 0.233`
  —— 中间有 0.038 的空档，阈值不用猜。
* 产出 `mask: Uint8Array`（逐顶点 0/1）+ 自检数字（`comps / wingVerts /
  minWingX / maxOtherX`）。`makeFlapGeos` 多收一个 `mask` 参数，逐顶点权重
  `w *= mask[i]` ⇒ 掩膜外的顶点**一步到位**地不动。
* 为什么不能只按 |x| 一刀切 —— 见 `splitWings` 的长注：翼根的膜在 |x| 0.27
  附近与肢体 0.233 只差 0.038，而触角尖端 |x| 与前翅后缘**重叠**，任何纯
  坐标判据都会把触角拧进翼相里。

#### 「不许乱动」的客观判据（不靠肉眼）

`?tsl-dump=1` 时一次性算好 `__tsl.wing` 自检：

* `restSpread` —— 非翅膀顶点在 16 档翼相间**位移的极差**。整只蝶的「浮」是
  均匀平移 ⇒ 极差理论上恒 0，任何一丝旋转/形变都会让它冒出来。实测
  **1.5e-8**（纯浮点噪声）。
* `wingMove` —— 翅膀顶点最大位移，必须明显大于 0。实测 **0.404**（翅膀在扇）。
* `comps=10, minWingX=0.271, maxOtherX=0.233` —— 掩膜本身与间隙都在。

#### 验收

* 放大帧 `_bvts-10z-focus.png`：触角两根呈对称 V 字、无交叉，肢体收在身体下。
* 环视帧 `_bvts-10z-sweep.png`：各切片翼相依旧各异（扑翼没被误伤）。
* 第九轮探针（环视归位、署名、绿幕直入相册）在掩膜改动后**全部保持**。
* 测试：掩膜断言进 `tests/time-slice.test.ts`（`splitWings` 导入、`WING_MIN_X`、
  `restSpread`、`w *= mask` 等）。

#### 本轮的坑

1. **CDP 的视口覆盖是按浏览器会话存的**：SVG 截图脚本（`_bvsvg.mjs`）给
   Chrome 设过 `DeviceMetricsOverride 660×660`，之后复用同一个调试端口跑装置
   探针 ⇒ 页面被判成手机档、**装置整个停用**，读数全是 `null`。⇒ 每个 CDP
   脚本用完（或起手）都 `Emulation.clearDeviceMetricsOverride`；不要让两个
   脚本共用一个浏览器实例而不清场。
2. **`__tsl` 探针读数要等场景写第一帧**：页面 `load` 之后立刻 evaluate
   `(window.__tsl).wing` 是 `undefined`（three.js 异步加载 GLB、首帧还没跑）。
   探针要轮询等键出现，而不是假定它已在。
3. **CDP `Page.captureScreenshot` 的 `clip` 用的是文档坐标不是视口坐标**：
   页面能滚（装置锚在首页很深处）时按视口算出来的 clip 会截到文首的白纸。
   先 `Runtime.evaluate` 拿 `scrollY`，clip.y 加上它。

### 6.25 归档页「索引卷尺」（INDEX TAPE）—— 内页第二台装置（2026-10-01，提交 `4a42f3f`）

**形态**：右侧贴边一条**竖向**刻度尺（不是站主草案里写的横向卷尺 —— 横向要占正文宽度，
而归档列表是通栏的；竖向贴在右侧留白里不推挤内容，是同一意象的另一形态，站主 2026-10-01 认可）。
结构：`aside.tape`（`position: fixed` / `right: var(--gutter)` / 宽 44px / 高 `min(60vh, 460px)`）
里放读数区 + 刻度轨道 + 游标。

#### ★ 机制必须与显影板**对立**（口径 #5：每页一个机制上不同的互动）

| | 相册 显影板（§6.18） | 归档 索引卷尺（本节） |
|---|---|---|
| 物理形态 | 连续介质（密度场） | 离散刻度（刚性齿） |
| 边界 | 矢量等值线（marching squares） | 直线段（1px 高的横线） |
| 位置语义 | 密度值 →阈值 | 滚动进度 → 等距年份 |
| 跟随手感 | **一阶**指数平滑（无过冲，笔触"干净贴上"） | **二阶**欠阻尼弹簧（有过冲，机械"咔哒"） |
| 驱动源 | 指针轨迹（累积擦痕） | 页面滚动位置（无状态） |

⇒ 因为手感方向相反，**弹簧没有抽进共享层**，两页各自实现（见下）。

#### 刻度：构建期算好，输出纯 HTML

- **年份 = 大齿**（`.tape-tick.is-year`），等距分布 `i/(n-1)`，单年时居中 50%；
  位置以**百分比**打进 `data-pos`（等距刻度的计算值，不是写死的文案/色值，不触红线）。
- **月份 = 小齿**（`.is-month`，8px 短横），散布在「本年刻度 → 下一年刻度」之间；
  最早一年下方没有空间 ⇒ 省略它的月份刻度。
- ★ **从内容推导，不写死年份**：`groups` 来自 `getArchive()`，明年发文自动多一根 2027 刻度。
  测试 `tests/index-tape.test.ts` 的判据是**解析 `content/posts/` 真数已发布文章**，
  比对刻度 `data-count` 与年份分组 —— 不硬编码任何年份。
- 颜色全 token：未卷过 `--hair`、卷过 `--accent-ink`（脚本加 `.past`）、游标 `--accent-ink`、
  读数 `--ink`/`--muted`。读数用等宽字体 + `tabular-nums`（延续仪器语汇）。

#### 交互与降级四态

- 滚动 ⇒ 游标目标 = 滚动进度 × 轨道高，弹簧自己追（松手后从当前速度继续 ⇒ 过冲）。
- 跨过年份刻度 ⇒ 读数区换「年份 · N 篇」，卷过的刻度加 `.past` 留墨。
- **点击年份刻度 / 拖动轨道** ⇒ `scrollIntoView({behavior: animate ? 'smooth' : 'auto'})`
  跳到对应年份分组。拖动期间游标直接贴手（不弹），松手才跳。
- ① **reduced-motion** ⇒ 不跑 rAF，直接贴目标（落到最终态）；
  ② **无 JS** ⇒ 装置不存在（`[hidden]` + `aria-hidden`，脚本到位才摘 `hidden`），
  归档列表服务端已渲染完整；③ **≤767px** ⇒ CSS `display:none`（口径 #9，本轮拍板"完全不渲染"）；
  ④ **视口外/ 切标签** ⇒ `rl-core` 的 `activityGate` 停帧。

#### 共享工具层 `src/scripts/rl-core.ts`（约 1.4 KB，第一版）

刻意**只抽真正通用且实现一致的三样**，硬抽是假共享：

- `startLoop(cb)` —— 喂**真实 dt**（`Math.min(now-last, 100)`）的帧循环外壳；
- `createActivityGate(el)` —— IntersectionObserver（`rootMargin` 预载 160px）+ `visibilitychange` 合并；
- `prefersReducedMotion()` / `shouldAnimate(mql)` —— 降级开关（`matches` 是活的，别缓存成布尔）；
- `createSpring(target, {stiffness, damping})` —— 二阶欠阻尼弹簧。

★ **弹簧必须定步长子步积分**（`SPRING_H = 1/120`），这是实测踩到的坑：
一帧一大步的半隐式欧拉稳定域是 `dt < 2/c`（k=110 / c=23 时≈ 87ms），
而 `startLoop` 把 dt 钳在 100ms ⇒ **低于 11.5fps 就发散**，慢机器上弹簧炸成
`Infinity→NaN`，挂在上面的滚动进度跟着变 NaN ⇒ 装置直接跳到 0/1 极端态。
定步长后 `ω·h ≈ 0.087`、`c·h ≈ 0.19` 恒在稳定域内，且**真正**帧率无关。
护栏：`tests/index-tape.test.ts`「大 dt 不发散」+「帧率无关」两条。

#### 页面侧的三个坑（写在这里，别重犯）

1. **归档页路径是 `src/pages/archive.astro`（单文件），不是 `archive/index.astro`** ——
   全站只有 `gallery/`、`tags/`、`posts/` 是目录形式。
2. **页头不能写 `max-width: var(--measure)`**（与其他内页不同）：归档**没有正文列**，
   内容列是 `PostIndex` 的**通栏列表**（只有 `.title` 限 22em、`.summary` 限 40em）。
   页头若收成 34em，下缘实线会短于列表的上缘线 ⇒ 两条线错位。
   **版心要对齐的是内容，不是习惯。**
3. **必须先摘 `[hidden]` 再量尺寸**：`display:none` 时 `clientHeight` 是 0，
   刻度位置会全算成 0（同 `develop.ts` 的"必须先露面再量尺寸"）。

#### 静态契约与护栏

`tests/index-tape.test.ts` 14 条（9 条装置 + 5 条弹簧）。装置侧判据：
`<aside class="tape">` 带 `hidden` + `aria-hidden="true"`、刻度年份 == 分组年份、
`data-count` == 内容层真值、`data-pos ∈ [0,100]` 且年份等距、≤767px 有 `display:none`、
零 `Math.random`、`spring.step(dt)`、reduced-motion 分支 `setCursor(targetFor())`、
脚本只 `querySelector` 不 `innerHTML`。

| `ref-dial` | 圆盘 + 星芒 + 直尺 | 右下角 |

★ 全部取自**白底段**。d 图虽有罗马雕像但**底是蓝色** ⇒ 蓝底转绿与「白底+ 墨绿」打架，

#### ★★★ 核心认知：CSS 裁切不能裁文件

第一版用 `overflow:hidden` + 绝对定位偏移在浏览器里"取景"。**浏览器仍会下载整张原图** ——
参考图 1080×1791~2355、3–4 MB 三张 ⇒ 关于页 10 MB+。**这版不能上线。**

正解：**构建期裁文件**。工具是 `sharp` —— ★ **它是 astro 自带的依赖**
（`node_modules/astro/package.json` 里 `"sharp": "^0.35.4"`），
**不是新增运行时依赖**，不违反「只允许 astro / @astrojs/rss / @astrojs/sitemap」。
产物走 `astro:assets`（`import.meta.glob` 拿 `ImageMetadata` + `<Image widths sizes>`）
⇒ 构建期出 WebP + 多档 srcset。

体积：进仓源图四张共 **482 KB**；`about/index.html` 引用的 webp 合计 **< 2.5 MB**（含头图与签名）。

#### ★ 裁切与转色：三个错都踩过（脚本 `_probe/_ref-plate.mjs`）

| 错 | 症状 | 正解 |
|---|---|---|
| **取景框跨段** | 百分比相对**整张图**算，而原图先切了四段 ⇒ 框跨了c0/c1，混进深色区 ⇒ 整块发灰 | 在**段文件**上裁，坐标只在段内表达 ⇒ 物理上不可能跨段 |
| **alpha 阈值固定** | 原图那些段本就有大量**中灰纸纹/ 水墨**，实测导出图 alpha 均值 **127/255** ⇒ 整块半透明、呈浅绿雾 | 用**白点分位数**（该段里多少比例的像素算「纸白」），本项目取 **0.45 / gamma 1.0** |
| **alpha 映射方向** | 初版按「与白的亮度差 → alpha、颜色给墨绿」，但原图元素本身是**深色** ⇒ 元素处 alpha最高、白底处近 0 ⇒ 出来是「浅绿底 + 深绿元素」，与「白纸 + 墨绿元素」**正好相反** | 颜色**恒为墨绿**（不随像素变），alpha = f(亮度差) ⇒ 白底天然透明、越深越显 |

★ 参数是**扫出来的**不是猜的：`_probe/_scan-params.mjs` 一次导出六组
（white 0.40–0.80 × gamma 0.7–1.2）拼成对照图逐张比。0.45 时月相环的深浅层次与
四周放射线全在、白底干净；0.80 太满（整块绿雾）、0.40 太狠（浅描线断掉、雕像只剩黑影）。

#### 运行时没有 filter

第一版靠 CSS `grayscale + sepia + hue-rotate` 现场染色（因为当时是原图）。
现在图在构建期已转成带 alpha 的墨绿小图 ⇒ 那套 filter **全是白做的算力**，已删。
护栏：`tests/about-ref-plate.test.ts` 断言 `.ref` 的样式块里不许再出现 `filter:`。

#### 摆位原则：四块全部待在版心之外

目检踩过**两轮**：月相按「右上角」放 ⇒ 盖住右栏社交清单；飞鸟放左侧中段 ⇒
压住头像与正文第一行。⇒ 改成按**视口百分比贴边**（负偏移滑出视口），
