## 2. 技术栈 ✅ Astro 7

**版本事实（已核实）**：稳定大版本 7.x，最新 `astro@7.3.5`，要求 Node ≥ 22.12.0。

选它的理由，按权重：

1. 冻结契约里的 6 条 frontmatter 校验规则，在 Astro 里就是一个 zod schema（约 20 行）；在 Eleventy 里是一套要自己维护的脚本。
2. `glob({ base: './content' })` 是官方支持的选项 —— 契约要求「`content/` 放仓库根」，这条直接成立，不需要 hack。
3. 图片与正文同目录 + 构建期优化是原生能力（`<Picture>` 出多格式 srcset），不引额外插件。
4. C 方向（高对比编辑风）要精细的版面控制，组件化比模板拼接更扛得住后续改动。

**已核实的代价（不是听来的，是我查到的）**：

- Astro 7 把 Markdown 处理器换成了 Rust 的 Sätteri，**recma 插件不再支持**。→ 我的对策：TOC 自研（解析 headings），不依赖 remark/rehype 生态。
- `sharp` 是 optionalDependency 且为 native 二进制；包管理器严格模式下可能要显式安装。
- Astro 本体直接依赖 53 个 vs Eleventy 的 33 个。**这只影响构建机，不影响产出物** —— 两边产物都是纯静态 HTML，这也是我没把依赖数当决定因素的原因。

### 依赖预算

| 包 | 状态 | 理由 |
|---|---|---|
| `astro` | 必须 | 框架本体 |
| `sharp` | 必须 | 图片优化（Astro 的默认图片服务） |
| `@astrojs/rss` | 计划加 | 你选了要 RSS。官方包，非零配置（要写一个 `rss.xml.js` 端点） |
| `@astrojs/sitemap` | **待你同意** | SEO 用。不是必须 —— 但站点要能被搜索引擎收录，这个包比手写 sitemap 划算 |
| `@astrojs/mdx` | **不加** | 你选了纯 Markdown |
| 其它 | 一律自研 | TOC、代码复制按钮、阅读时长、标签页、归档页、404 —— 都是几十行的活，不值得引包 |

## 3. 部署 ✅ Cloudflare Pages（先用免费 `*.pages.dev` 子域）

**你的前提**：无域名、无 ICP 备案、读者以中国大陆为主。

**我没有根据地能给你的承诺**：大陆访问速度这块，除了 Vercel（官方自己承认可能缓慢或失败），Cloudflare Pages 和 GitHub Pages 我**只有第三方经验帖，没有官方数据**。所以下面是路线选择，不是性能承诺。

选择 Cloudflare Pages 的理由：¥0、零运维、不需要备案；产出是纯静态 HTML，**托管商不锁死** —— 以后想搬到国内云或 VPS，成本是"改 DNS + 传文件"。

**已知代价**：大陆访问可能不稳定。等你决定买域名（约 ¥50/年）后，把自定义域绑上去通常比 `pages.dev` 子域略好，但**同样不保证**。真要把大陆速度当硬指标，唯一的路是域名 + ICP 备案 + 国内云，约 2–4 周流程。

> **推送到 GitHub 时踩到的环境事实**（下次会再遇到）：这台机器的 `hosts` 里有 27 条 GitHub 域名指向 `127.0.0.1`，
> 由 **`Steam++.Accelerator`（Watt Toolkit）** 在 443/80 上反向代理 —— 那是加速工具，不是屏蔽。
> 所以 `github.com` 能连上（经它转发），推送失败的真实原因只可能是**凭据**。
> 排查时**不要**用 `GIT_TERMINAL_PROMPT=0` / `GCM_INTERACTIVE=never`，那会把「缺凭据」伪装成「推不上去」。
>
> **另一个坑**：`curl` / `Invoke-WebRequest` 走 github.com 时可能返回 `HTTP 000`（加速器的 HTTP 转发路径会抽风），
> **而同一时刻 `git ls-remote` 却是通的**。所以判断仓库可见性不要用 HTTP 请求，用下面那条命令。

### 仓库可见性：已转私有（2026-09-25）

站主决定把仓库转为私有。原因是：**草稿的保密性等于仓库的保密性** ——
`draft: true` 的文章不会发布到网站，但它的 `.md` 原文就在仓库里；
仓库公开时，任何人翻仓库都能读到未发布的草稿。

**怎么验证它确实是私有的**（不依赖 HTTP，绕开加速器抽风）：

```powershell
git ls-remote --heads origin                                              # 带凭据：应当成功
git -c credential.helper= ls-remote --heads https://github.com/NorthenCedar/personal.git
```

实测（2026-09-25）：第一条成功读到 `refs/heads/main`；第二条报
`fatal: could not read Username for 'https://github.com'` ——
**服务器拒绝匿名访问，确认为私有。**

**"不加第三方脚本"这条值得说清**：以上全部不加载任何第三方 JS/CSS —— 没有统计、没有字体 CDN、**评论也不用第三方**。这是大陆访问友好度最直接的一招。

### 变更记录：评论从「不做」改为「自建」（2026-09-26）

**为什么改**：站主提出想要评论功能。

**为什么是自建而不是现成方案**（这是这次变更的核心判断）：

| 方案 | 为什么没选 |
|---|---|
| Giscus / utterances | 依赖 GitHub Discussions 加载 —— 大陆读者不稳；**读者必须有 GitHub 账号才能留言**，门槛过高；且是 iframe，**样式无法与站点设计语言一致**（站主的明确要求） |
| Waline / Twikoo | 要自己长期维护一个后端 + 数据库，且多在境外 |
| **自建 Functions + D1** | ✅ 同域名、无第三方、**样式完全可控**、数据在自己的 Cloudflare 账号里 |

**代价（写清楚，不藏）**：

1. 部署形态从**纯静态**变成**带 Functions**；本地调评论要用 `wrangler pages dev`（写文章仍用 `npm run dev`）
2. 新增一个依赖：`wrangler`（devDependency，不发给浏览器、不进产物）
3. 需要站主在 Cloudflare 侧做两步：创建 D1 数据库、把 binding 绑到 Pages 项目（生产 + 预览）
4. 全站 `<script>` 从 1 个变 2 个；JS 预算从 < 1 KB 放宽为「复制脚本 ≤ 1 KB + 评论脚本 ≤ 4 KB」
5. 要自己处理垃圾评论：**蜜罐字段 + 同 IP 频率限制**（零第三方、零读者负担），必要时手动删

**没变的**：零第三方资源、零网络字体、内容层只读、草稿语义、对比度与视觉 token —— 这些一条都没松。

> 未被选中的 A / C 仍留在 `prototype/` 作为备选与反例，不进入实现。

- **排版**：强网格；超大粗体标题 + 大字号跳跃；章节编号只当锚点，不当装饰。
- **字体**：标题 grotesk（Archivo / Space Grotesk），正文与 UI 无衬线（Public Sans / IBM Plex Sans）、中文思源黑体。
- **字体加载（我的提议，你没反对）**：一律自托管裁剪后的 WOFF2 子集，**不用 Google Fonts**（国内不可达 + 多一跳请求）。中文字体必须按实际用字裁剪，否则一个思源全字重就是几 MB。

这些在阶段 4 会被细化成可查的规范文档（字号阶梯、行高、间距系统、配色 token、动效时长与缓动）。
