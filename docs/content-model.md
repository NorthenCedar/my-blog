# 内容模型（阶段 0 · 冻结）

> 状态：**已冻结（v1.1）** — 本文件是内容层的唯一契约。文章文件与主题实现都必须服从它。
> 首次冻结：2026-09-25 ｜ 最近修订：2026-09-25
> 项目根目录：`<博客仓库>`（独立 git 仓库，与 `<本机工作区>\dsh-routing-suite` 无关）
> 相关文档：`docs/site-decisions.md`（阶段 1 的技术栈/部署/页面/视觉决策）

本文件只定"内容长什么样、放哪里、叫什么"。
**不涉及**：框架配置、模板语法、页面布局 —— 那些属于阶段 4 的设计规范。

技术栈已于阶段 1 定为 **Astro 7**；本契约不依赖具体框架，`content/` 目录位置由框架侧配置指过来。

## 1. frontmatter 字段

字段总数 **9 个**（5 必填 + 4 可选）。不允许随手加字段；要加就走本文档末尾的变更流程。

| 字段 | 必填 | 类型 | 示例 | 说明 |
|---|---|---|---|---|
| `title` | ✅ | string | `用 Astro 重构这个博客` | 页面 `<title>`、列表页、RSS 标题。建议 ≤ 60 字。 |
| `date` | ✅ | `YYYY-MM-DD` | `2026-09-08` | 首发日期。列表排序、归档分组的唯一依据。 |
| `summary` | ✅ | string | `把 300 行的构建脚本换成…` | 列表页摘要 + `<meta name="description">`。**≤ 80 字，纯文本，不写 Markdown。** |
| `tags` | ✅ | string[] | `[成长, 随笔]` | **1–3 个**，且必须已登记在第 4 节的标签表里。 |
| `draft` | ✅ | boolean | `false` | 草稿开关。语义见第 5 节。**必须显式写，不写视为错误并在构建时报错。** |
| `updated` | ⬜ | `YYYY-MM-DD` | `2026-03-01` | 有则在详情页显示「更新于」；须 ≥ `date`。**写作台（桌面端与云端）在你改过正文或其它字段时会自动把它往前推，只进不退**；没有该字段的文章不会被自动加上，见第 6.1 节。 |
| `cover` | ⬜ | string | `./cover.jpg` | 头图。**相对本文所在目录**，不是站点绝对路径。 |
| `coverAlt` | ⬜ | string | `终端报错截图` | 图片替代文本。**有 `cover` 就必须有 `coverAlt`**（无障碍硬约束，构建期校验）。 |
| `slug` | ⬜ | string | `camera-in-gaosan` | 覆盖文件夹名生成的 URL 片段。中文标题必须写。 |

### 完整示例

```yaml
---
title: 用 Astro 重构这个博客
date: 2026-09-08
updated: 2026-09-20
summary: 把 300 行的构建脚本换成一个内容集合，顺便扔掉了 6 个依赖。
tags: [建站, 工程实践]
draft: false
cover: ./cover.jpg
coverAlt: 新首页在桌面端的截图
---
```

### 校验规则（阶段 6 落地为测试）

1. 5 个必填字段缺任意一个 → 构建失败，报出文件路径与缺失字段名。
2. `date` / `updated` 不符合 `YYYY-MM-DD` → 构建失败。
3. `updated < date` → 构建失败。
4. `tags` 为空数组、长度 > 3、或含未登记标签 → 构建失败。
5. 有 `cover` 无 `coverAlt`（或 `coverAlt` 为空串）→ 构建失败。
6. 出现未登记字段 → 构建警告（不失败），提示"是否该走内容模型变更流程"。

## 2. 目录结构

原则：**`content/` 是纯文本与素材，`src/` 是主题。换主题只允许动 `src/`。**

```
<博客仓库>\
├─ content/                      # ← 内容层：只有正文与素材，不含任何模板
│  ├─ site.md                    #   站点文案：站名 / 英文副标 / 首页简介 / meta description / 页脚联系方式
│  ├─ posts/                     #   一篇文章 = 一个文件夹
│  │  ├─ ai-built-this-blog/
│  │  │  └─ index.md
│  │  ├─ camera-in-gaosan/
│  │  │  ├─ index.md
│  │  │  └─ Image_1790268606244_504.jpg   # 该文专属图片，与正文同目录
│  │  └─ piano-eight-level-and-after/
│  │     └─ index.md
│  └─ pages/
│     └─ about.md                #   「关于」页正文，与文章同一套解析方式
├─ src/                          # ← 表现层：布局、组件、样式
│  ├─ layouts/
│  ├─ components/
│  └─ styles/
├─ public/                       # ← 静态直出（favicon、robots.txt 等），不走处理管线
└─ docs/                         # ← 本项目的过程文档（内容模型、设计规范、计划）
```

**为什么 `content/` 放在仓库根，而不是框架默认位置**
内容层不该被任何框架的目录约定绑死。把 `content/` 放在根，换栈时内容零迁移；框架侧用配置指过来即可 —— Astro 7 的 glob loader 提供官方 `base` 选项，直接支持这种布局（写法见 Astro 文档 `content-loader-reference`）。代价：配置里多写一行。**这个代价是故意付的。**

**`content/site.md` 为什么算内容层**
站名、首页那句简介、meta description、页脚邮箱与 GitHub —— 这些是**文字**，不是版式。
它们一度硬编码在 `src/pages/index.astro` 与 `src/components/SiteFooter.astro` 里，那破了「换主题不该动文章文件」的对称原则：
改一句简介要去改 `.astro`，而改一篇文章只需改 `.md`。现在它们和文章一样在 `content/` 下，
`tests/content-invariants.test.ts` 里有一条断言守着 `src/` 不许再出现这些文字。

**图片为什么与正文同目录**
一篇文章的全部素材在一个文件夹里，删除/备份/迁移都是一次拖拽；正文写 `![](./screenshot.png)`，不依赖任何全局路径约定。同时同目录图片能进构建期优化管线（生成多尺寸 + 现代格式），集中放 `public/` 的图片不能。

## 3. slug 规则

**文件夹名即 slug。URL 形如 `/posts/<slug>/`。无日期前缀。**

- 允许字符：`^[a-z0-9]+(-[a-z0-9]+)*$`（全小写、数字、单个连字符分隔；不允许下划线、空格、大写、连续连字符、首尾连字符）。
- 长度 1–60 字符。
- 中文/非 ASCII 标题 → **必须**在 frontmatter 写 `slug`；文件夹名仍用该 slug（两者保持一致，校验器会比对，不一致则告警）。
- 一旦发布，**slug 不得修改**（改了就是死链）。需要改标题时只改 `title`。

**为什么不要日期前缀**
日期是元数据，不是身份。补发旧文、改标题、把草稿转正，都不该让 URL 变化。

**当前已占用的 slug（发布后不得再改）**

| 标题 | slug | URL |
|---|---|---|
| 钢琴八级之后：我学了那么多东西，为什么只有几样留在了我身上 | `piano-eight-level-and-after` | `/posts/piano-eight-level-and-after/` |
| 我用手机 AI 指挥电脑 AI，从零搭了这个博客 | `ai-built-this-blog` | `/posts/ai-built-this-blog/` |
| 高三那年我买了台相机 | `camera-in-gaosan` | `/posts/camera-in-gaosan/` |

## 4. 标签体系

**当前状态（2026-10-09）：本节的表格是 `src/tag-registry.ts` 的**人类可读镜像**。**
标签的**唯一事实来源**是那份注册表（`src/lib/schema.ts` 拿它校验每篇的 `tags`）。
新增标签时，写作台会**自动在本表末尾补一行** —— 「含义边界」那列只能人写，所以补进来的行先落一个「（待补：什么算、什么不算）」占位，等你填。删标签仍要站主同意。
★ 这里**不再写数字**：原先那句「（6 个）」早就和注册表对不上了（实际是 8 个）。
数量以注册表为准，别再在这儿抄一份。

规则：

- 数量控制：新增需在本文件登记；**每个标签必须至少有 1 篇文章**（否则标签页是空的）。
- 形态：短中文词（2–5 字），**不加层级**（不用 `前端/Astro` 这种子标签）。
- **同义词只留一个**：出现"前端"就不再新增"前端开发"或 "frontend"。
- 每篇 1–3 个标签（见第 1 节校验规则）。

| 标签 | 含义边界（什么算、什么不算） | 现有文章 |
|---|---|---|
| `AI` | 用 AI 做事的过程、提示词、工具链；**不写**行业新闻与模型评测 | ai-built-this-blog |
| `建站` | 这个博客本身的构建、部署、设计决策 | ai-built-this-blog |
| `摄影` | 照片，以及拍照这件事 | camera-in-gaosan |
| `成长` | 回看自己经历、清账式的长文 | piano-eight-level-and-after |
| `随笔` | 没有明确主题归属的日常记录 | piano-eight-level-and-after |
| `钢琴` | 与弹琴有关的记忆与手感 | piano-eight-level-and-after |
| `教程` | 手把手的操作步骤，照着做完就能得到同一个结果；**不写**纯观点、感想与新闻 | tutorial-on-using-genuine-typora-for-free |
| `工具` | 某个软件 / 服务本身：怎么选、怎么配、值不值得用 | tutorial-on-using-genuine-typora-for-free |
| `项目` | 我自己做的、能拿出手的东西：成品是什么、怎么做的、踩了哪些坑；**不写**给别人用的教程 | blog-desk |
| `个人` | （待补：什么算、什么不算） | — |
| `备忘` | （待补：什么算、什么不算） | — |

**两个被裁掉的词，以及为什么**

长文原本还打了 `街舞` 和 `合肥`。因为每篇上限 3 个（已确认），它们被裁掉了。现在这两个词**不是标签**，也就没有标签页。

要启用它们，正确做法是：先在本文档登记，并确保至少有 1 篇文章打上它。不要为了"让这个词能被点"而临时放宽上限。

## 5. 草稿机制

**草稿靠字段隔离，不靠目录。** 同一份文件从草稿转为发布，只改一个字段，不搬文件、不改图片相对路径。

`draft: true` 的文章：

| 场景 | 行为 |
|---|---|
| 生产构建：文章列表 / 首页 / 标签页 / 归档 | 不出现 |
| 生产构建：RSS / sitemap / 站内搜索索引 | 不包含 |
| 生产构建：直达 URL `/posts/<slug>/` | **不生成页面**（404，而非"生成了但没入口"） |
| 本地开发（dev server） | 正常渲染，标题旁显示「草稿」标记 |
| 本地开发：列表页 | 出现，带「草稿」标记（便于整体检查排版） |

**为什么直链也不生成**：草稿一旦产出静态文件，就可能被爬虫抓到或被人转发，SEO 与隐私都不可控。宁可预览时用 dev server。

**当前状态（2026-09-25）**：三篇文章**全部已转正**（`draft: false`），站主明确决定上线。
`draft` 字段的机制不变，只是现在没有处于草稿态的文章。
转为发布 = 把 `draft` 改成 `false`，并确认 `summary`、图片 alt 都已就位。
**改 `draft` 是站主的发布决定 —— 任何工具、脚本或代理都不得代办。**

## 6. 变更流程

本文件冻结后：

- 加/改字段、改目录结构、改 slug 规则、增删标签 → 必须由站主**明确同意**后修改本文件，并在下方追加变更记录。
- 内容文件必须服从本文件；若某篇文章想要新字段，正确做法是改契约，不是让渲染器兼容特例。
- 表层的视觉/主题变更**不需要**动本文件，也不允许动 `content/` 下的任何文件。

### 6.1 `updated` 的自动推进（2026-10-27）

`updated` 是手填字段，而改正文的人不会记得同步它 —— 实测
`my-python-memorandum` 当天加了 106 行，页面仍印着「更新于 2026-10-25」。
所以两端的写作台都**自动推进**它，并且**只进不退**：

| 情形 | 行为 |
|---|---|
| 改过正文或其它字段 | 推到 `max(今天, 当前值)`（北京日期） |
| 你手填一个**更晚**的日期 | 用你的值 |
| 你手动清空 `updated` | 保持为空，不写回（想藏掉「更新于」就这么做） |
| 只是打开又保存、什么都没改 | 不动 |
| 原文没有 `updated` | **不主动添加**。想让某篇显示「更新于」，手填一次，之后自动维护 |
| 新建文章 | 不写 `updated`（`date` 就是今天） |

**为什么不做"手填优先"**（`updated` 是单调字段）：

1. 客户端的编辑器可能还停在上一次推进之前的日期，把"提交值早于原文"当成手填，
   就会把刚写好的日期顶回去 —— 27 → 25 → 27 来回跳。实测这个坑要真跑两次保存才看得见。
2. 代价是**不能把 `updated` 往回改**：填一个更早的日期会被改回原文值。
   要彻底隐藏「更新于」，清空字段即可（清空是被尊重的）。

**`date` 永远不动。** 它是首发日，归档分组、列表排序、RSS 都按它。
§6.60.2 那次「把 `date` 改成今天」是针对单篇文章的一次性要求，不是常态口径 ——
想让一篇文章冒到最新，就手改 `date`，两者互不代劳。

实现落点：桌面端 `blog-desk/lib/content.py` 的 `sync_updated()`（自检 `_t16.py`，8 条变异全部咬住），
云端 `src/lib/writer/content.ts` 的 `advanceUpdated()`（判据在 `tests/writer-content.test.ts`，3 条变异全部咬住）。
两处规则必须同时改，否则两端保存出的文件会不一样。

## 8. 相册内容（2026-10-13 补充）

相册位于 `content/gallery/<册名>/index.md`，图片与其同目录；内容集合契约在 `src/lib/schema.ts` 的 `gallerySchema`，构建产物清单由 `scripts/gen-gallery-webp.mjs` 生成。

| 字段 | 必填 | 含义 |
|---|---|---|
| title | 是 | 中文相册标题，不改变已发布文件夹名 |
| date | 是 | 日期，决定相册编目顺序 |
| images | 是 | 非空 `{src, alt}` 数组，源图不能重复，顺序由作者维护 |
| titleEn | 否 | 英文展示名；省略时回退 title |
| layout | 否 | scatter、slices 或 wall；省略时默认 scatter，不按数量自动切换 |
| draft | 否 | true 为未完成相册草稿，可暂缺标题、日期和照片；缺省为已公开，发布时完整校验 |
| cover | 否 | images 中某一项的 src，独立于照片顺序；省略时仍取第一张 |
| presentation | 否 | 封面 arrangement（left/right/wide）、transition（slide/reveal/perspective）、stroke（arc/loop/corner）、weight（regular/bold） |

两档图片和原图不部署的规则保持。生成地址为序号、源图字节及编码参数的内容摘要、档位宽组成；变更内容就变更地址，兼容静态资源 immutable 缓存。相册可选字段同时进入清单和内容集合，页面不硬编码相册标题与布局名单。

2026-11-01 写作台相册配置扩展：封面编排只允许上述固定选项，不接受脚本、任意 SVG 路径或自定义样式。旧册缺字段时保持已上线构图；两端首次保存时将推荐值固定，主动“重新推荐”才重新计算。既有中文目录名与 URL 不变，相同日期按目录代码序稳定排列。照片可为一两张；首页槽位按已有照片循环取图，真实张数保持。图源仅限当前册平铺图片；发布时要求真实文件、有效日期、标题、非空图注及无重复图源。未知字段与正文不因编辑这些配置而丢失。

本地草稿不进入公开清单，构建同时移除该册历史生成的公开图片；正文草稿独占素材沿用构建后清理。云端相册草稿与现有文章/说说等共用私密存储，图片使用 writer-asset 引用，发布快照再解析为本册相对路径；新类型需先安全执行 0009 增量迁移。整个相册的显影板、螺旋盘和胶片底纹仍属于整页，不是每册配置。

## 9. 站主视频（2026-10-20）

视频原件存放在 `content/videos/<64 位小写 SHA-256>.mp4|webm`。公开地址为 `/videos/<同名文件>`；这是原件的内容地址，不是独立发布指令。仅当已生成的公开 HTML 中有视频引用，构建才将原件复制至 `dist/videos/`。草稿独占或没有被引用的原件不部署。

- 格式为 MP4 / WebM，单个不超过 25 MiB，上传保留原字节，不自动转码。
- 文章在正文内用原生 `<video controls preload="none" playsinline src="/videos/..." aria-label="说明">…</video>`，不增加文章 frontmatter 字段。
- 说说增加可选 `videos` 数组，每项为 `{src, alt}`，`src` 使用上述公开地址，`alt` 为非空的视频说明。界面播放须由访客主动触发。
- 说说的可选 `id` 是赞和评论的稳定归属。写作台读取旧数据时按原页面的日期、当日顺序生成原有标识，保存时持久化；新说说使用独立标识，不再改变旧评论的归属。
- 原件缺失、摘要不符、扩展名与格式不符、超限或引用越界时，上传或生产构建失败，不能带着破损播放器上线。

## 10. 造物台的公开项目（2026-10-26）

一件作品存放在 `content/projects/<英文短名>/index.md`，图片与正文同目录。短名是稳定标识，对应 `/forge/<英文短名>/`；列表位于 `/forge/`。集合契约见 `src/lib/project-schema.ts`。这些条目全部是已决定公开的内容，没有文章的 draft 开关；未公开的材料不要放入此目录。

| 字段 | 类型 / 默认值 | 用途 |
|---|---|---|
| title / summary / tagline | 必填字符串，分别不超过 60 / 160 / 60 字 | 名称、简介、一句话说明 |
| category / status | 必填字符串 | 项目类型与当前状态；硬件和手工作品同样适用 |
| order | 必填非负整数 | 越小越靠前；相同时按短名排序 |
| tags | 必填数组，最多 4 项，可为空 | 项目自己的展示标签，不占用文章标签注册表 |
| visual | `image`（默认） / `site` / `desk` | 普通图片或现有两件作品的界面模型 |
| effect | `auto`（默认）、`lift`、`tilt`、`stack`、`zoom`、`scan`、`develop` | 统一动效模板；不存放任意脚本 |
| images | 最多 6 项 `{src, alt, darkSrc?}` | 相对路径，说明不能为空；image 模板至少一张图；暗色图可选 |
| links | 最多 4 项 `{label, href}` | 站内路径或无凭据的 HTTPS 链接 |
| preview | 字符串字典，可省略 | site / desk 模型里的文案，普通照片无需填写 |

正文使用 Markdown，在详情层与独立项目页中展示。第一张图片是主封面；叠片模板最多使用前三张，详情保留所有图片。没有暗色替图时保留照片原色，仅切换底板和边框；提供 darkSrc 后两处展示均切换替图。

动效由主题实现。auto 按稳定短名选择，刷新不变；叠片不足两张时退回轻抬。手机和减少动态效果保留可阅读、可点击的静态展示。

本地和云端写作台现均提供项目维护与页面文案编辑。新项目默认 image / auto，已有 site / desk 及 preview 不重写；英文短名不超过60字符，创建后固定。图库最多6项，每张主图与暗色替图共用说明，配图只限当前项目同目录的合法文件。项目标签独立于文章标签。修改项目不添加文章的 draft 或 updated 字段。

云端以 project / forge 两种私密草稿复用版本、恢复和发布任务；forge 的目标只允许固定 key=forge，保存私密草稿不会上线。明确发布后才把项目落入公开目录，或定点修改 content/pages/forge.md 的文案；原未知字段、未改正文和并行更新保护继续保留。页面文案的可编辑字段及长度见 src/lib/forge-fields.ts，滚动提示固定3项，工作手记最多12项。新增0008只扩展类型约束，0007不得在已有生产环境重跑。
