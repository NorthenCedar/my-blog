# 独立云端写作台 · 第一版设计

日期：2026-10-22。状态：2026-10-23 站主要求按此方向开始，进入实施计划审阅；尚未实施。

本设计基于博客本地提交 `29e17b523ee4e321225102a61f31d40f3a15a983`、现有访客账户及 Windows 写作台。该提交与本地记录的 `origin/main` 相同；本轮没有通过网络刷新远端引用，因此不把它当成远端此刻状态的证明。

## 1. 目标与已确认的约束

站主希望电脑关机、人在外面使用手机流量时，也能写文章、发说说、上传配图并发布。手机和电脑浏览器使用同一个云端写作台，共享草稿。已发布的内容继续以 GitHub 私有仓库 `NorthenCedar/personal` 的 `main` 为准，由现有 Cloudflare Pages 部署。

站主明确选择：**优先不新增计费服务**。第一版不启用 R2、不增加服务器、不升级套餐。利用现有 Pages Functions、D1 和 GitHub Actions 的账户额度；超限或服务不可用时明确停止相应操作，不自动购买额度。

保留 `<工作区>/blog` 和现有桌面写作台。云端发布不会自动修改电脑文件，也不会重写 Git 历史。任何由代理执行的 `main` 推送仍需站主当次明确授权；产品上线后，站主在写作台点击“发布”就是对该次产品发布的操作授权。

## 2. 路线比较与选择

| 路线 | 对本需求的影响 | 决定 |
|---|---|---|
| 现有 D1 存私密草稿和小体积配图，发布时写入 Git | 无须开通新存储订阅；需要严格限制图片体积和草稿占用 | 第一版采用 |
| D1 存文字、R2 私有桶存图片 | 适合更多图片及大文件，但需开通 R2 订阅并处理超额计费 | 按站主选择不采用 |
| 在博客仓库的草稿分支存全部未发布内容 | 保存即产生 Git 历史，且必须另行关闭或保护 Pages 分支预览，才能保证草稿私密 | 第一版不采用 |

D1 支持 BLOB，单行上限为 2,000,000 字节；Free 单库上限为 500 MB。第一版将单图控制在 300 KiB、写作台总有效数据控制在 96 MiB，远低于单行和单库上限。这个选择适用于单站主、小体积配图；大量原图和视频不属于本版目标。[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)

## 3. 第一版范围

包含：

- 站主认证、手机与电脑浏览器的独立写作界面。
- 文章列表、新建、编辑、私密草稿、Markdown 预览、发布新文和更新旧文。
- 说说列表、新建、编辑、配图排序、发布新说说和更新旧说说。
- 图片选择、粘贴上传、压缩后确认、替代文本、上传进度和失败重试。
- 云端自动保存、当前设备的恢复副本、跨设备编辑冲突提示。
- 发布前查看本次内容变更，云端完整校验、普通 Git 推送、部署状态显示。
- 导出草稿与配图、清理选中的私密草稿和未引用上传。

后续单独扩展：日志编辑、相册编排、标签增删、站点设置、视频上传、定时发布、多人写作、已发布内容删除或撤回、桌面应用自动同步。

第一版读取和保存旧内容时，必须保留已有视频字段、未知 frontmatter 字段、说说稳定 ID 以及未编辑的其他条目。不能因为编辑器暂不提供某个控件，就把原内容对应字段删掉。

## 4. 入口、部署与界面

入口为 `https://northcedar.top/write/`。这里的“独立”指独立写作界面、私密存储和云端发布流程，运行不依赖本机应用。第一版沿用现有 Pages 项目及同源地址，以便复用现有 `__Host-nc_session` 登录 Cookie，不引入跨子域登录协议。

新增写作专用外壳，使用本站字体及纸白、墨绿、铜橙 token；暗色背景采用现有中性深色 token。手机以单栏为主，文章/说说/草稿/发布作为清晰入口，编辑与预览切换显示；电脑可以并列显示列表和编辑区。保存状态始终可见，发布操作与“保存草稿”分开。

写作区保留原生文字光标，不加载博客的开场、流场、WebGPU 开关或全站自定义光标。按钮有明确文字，输入框有可见标签；软键盘打开时仍能编辑和查看保存状态。页面设置 `noindex` 并从 sitemap 排除，普通访客导航不增加写作入口。

静态 HTML 仅包含空界面和加载提示，不嵌入草稿、文章源文、站主 ID、私有仓库数据或密钥。只有鉴权成功后才请求私密数据。

## 5. 登录、权限与私密性

浏览器接口使用现有站主账户。每一个私密读取、保存、上传、导出、清理、发布和状态接口都在服务端验证：

1. 请求是正式站点同源请求，或者显式启用的本地测试环境请求。
2. 会话有效，账户存在，`auth_version` 与当前账户匹配。
3. `OWNER_USER_ID` 已配置，且与账户完整 ID 一致。

缺少站主绑定、数据库表或必要服务配置时关闭相应能力，不能退化成“任意已登录用户可写”。不信任浏览器提交的 `isOwner`、昵称、用户名或 owner ID。写入采用现有活跃会话证明，在 SQL 条件中再次核对，避免鉴权后退出仍然写入。

浏览器写入要求同源 `Origin` 和现有自定义请求标记；不开放跨站 CORS。所有私密响应及错误返回 `Cache-Control: no-store`。私有图片也逐次鉴权，不使用可公开访问的图床、R2 公共地址或静态预览目录。Pages 预览域名不能调用生产写作接口。

登录过期时保留编辑内容并提示重新登录。切换或退出账户时清理私密列表、图片 Object URL 和浏览器恢复缓存；不将文章内容放入 URL、埋点或普通错误日志。

预览复用现有桌面版支持的基本 Markdown 语法，但作为独立模块重新验证安全边界：原始 HTML 转义；链接仅接受允许的协议；图片只解析受控素材引用；脚本、事件属性、`javascript:` 和任意 iframe 不执行。预览是排版参考，最终网页以现有 Astro 构建为准。

## 6. 草稿、版本与同步

### 6.1 两种权威来源

- 未发布内容：D1 中的站主私密草稿。
- 已发布内容：GitHub `main` 中现有 Markdown 和素材文件。

首次编辑已发布文章时，读取一个确定的远端提交及目标文件，记录文件 blob SHA 和原文作为基线，再创建 D1 草稿。首次编辑说说时还记录目标 `id` 和原条目指纹。读取列表使用确定的提交，避免同一次读取跨越两个远端版本。

私密草稿没有进 GitHub 内容分支，也不会触发 Cloudflare 构建。“保存草稿”不能等价于推送 `draft: true` 到 `main`。

### 6.2 自动保存与恢复

正文输入停止 2 秒后保存，持续输入时至多每 15 秒发起一次保存；另有显式“保存”按钮。每次携带读取到的 revision，服务端以比较并交换方式更新。只有收到成功响应才显示“已保存到云端”。

保存请求包含稳定的请求标识及内容摘要。成功响应丢失后，先查询该标识对应结果，确认原请求是否已经保存；相同请求不得重复增加 revision，也不能把它误判成另一设备冲突。

浏览器维护按账户、草稿 ID 和基线版本隔离的 IndexedDB 恢复副本。写入恢复副本失败时明确提示；上传中的图片不能只依赖内存。离线时显示“仅保存在本设备”，恢复网络后正常执行版本检查，不自动覆盖另一设备的新版本。

两台设备基于同一 revision 保存时，只允许一个成功，另一个收到 409 并保留其输入。冲突界面提供当前输入与云端版本的对照、复制和另存草稿，不提供默认覆盖按钮。首次打开内容时发现恢复副本，也先展示恢复选择，不静默替换。

### 6.3 发布时冻结

点击发布后保存当前内容，创建不可变快照。快照包括正文、元数据、素材摘要及版本；后续上传或自动保存不能改变正在校验的快照。校验期间可以继续编辑，新的 revision 留作下一次发布。

发布完成时，仅标记快照对应的 revision 已发布。如果草稿已经有后续编辑，保留新输入，同时将本次发布快照更新为它的比较基线，显示“仍有未发布修改”。发布回执重放不能回滚较新的草稿状态。

## 7. 图片与额度

第一版接收浏览器能解码的 JPEG、PNG、WebP 静态图片。原选择文件最多 20 MiB、解码像素最多 40,000,000；不支持的 HEIC、动画 GIF、SVG 或视频明确提示，不静默丢帧或换格式。浏览器按 EXIF 方向显示并重绘，去除定位等原始元数据，转为 WebP，长边最多 1920 像素、最终单图最多 300 KiB。压缩前后体积和成图可查看，超过上限可调整后重新选择。

服务端不相信客户端声明：检查实际接收字节、文件签名、图像尺寸和 SHA-256，再保存 BLOB。上传正文上限为 320 KiB，拒绝超大或异常格式；服务端不执行任意格式转换程序。第一版不提供原图保留承诺。

- 每篇文章最多新增 20 张配图，每条说说最多新增 9 张。读取旧内容时已有素材不因本版上传限制而被删除。
- 同一站主相同压缩图按摘要去重；配图顺序及 alt 属于草稿元数据。
- 待发布图片 BLOB 总量最多 64 MiB；草稿、快照和图片等写作数据总有效载荷最多 96 MiB；最多 100 份可编辑草稿。
- 大小统计为有效载荷，不冒充 SQLite 文件实际大小。上线前另查数据库实际占用；应用限额不能保证整个账户所有服务都不超额。
- 额度占用与插入操作在事务中一致更新，并发上传不能超卖。删除时检查草稿及发布快照引用；仍被引用的素材不能清理。
- 不自动删除长期未发布草稿。提供占用显示、导出和选中清理；达到上限后停止新增或扩大的操作，仍允许读取、导出、清理和不增加占用的保存。

发布时，文章图片写入 `content/posts/<slug>/writer-<sha256>.webp`，正文使用相对引用；说说图片写入 `src/assets/talks/writer-<sha256>.webp`。因此本地拉取后拥有实际图片文件，原有 Astro 优化管线仍然生效。发布成功不意味着立即删除云端草稿或其图片。

## 8. D1 数据边界

继续绑定现有 `COMMENTS_DB`，以增量迁移新增 `writer_` 前缀表，不改评论、账户、会话的既有结构：

| 表 | 职责 |
|---|---|
| `writer_drafts` | 类型、目标标识、原始基线、编辑内容、revision、最近发布信息 |
| `writer_assets` | 站主 ID、摘要、尺寸、MIME、字节数、图片 BLOB |
| `writer_draft_assets` | 草稿对素材的引用及顺序，阻止误清理 |
| `writer_jobs` | 发布请求、不可变快照、幂等键、状态、远端提交及工作流关联 |
| `writer_job_assets` | 发布快照的固定素材引用 |
| `writer_usage` | 站主写作数据的配额及并发占用 |

单份 Markdown 的 UTF-8 正文上限为 128 KiB，原始 frontmatter 和正文基线也有同量级限制；不能把整仓库或所有图片塞进一个 JSON 行。读列表不选择 BLOB；图片通过独立接口逐张读取。查询使用索引及绑定参数，不拼接任意 SQL。

新表的数据隔离不依赖昵称。账户注销时级联清除其私密写作数据，Git 中已发布内容不随注销删除；在账户注销说明中新增这项行为，并覆盖并发发布中的注销情况。

## 9. 发布链路与丢失保护

一次只接收一个活动发布任务，重复点击通过幂等键返回同一个任务。允许编辑其他草稿，但不排出不可见的长发布队列。

1. 浏览器显示本次文章或说说及配图的变更摘要，站主点击发布。
2. 服务端保存不可变快照，记录站主账户和凭据版本，触发固定的 GitHub Actions 工作流。浏览器拿到任务 ID 后即可离开，不必保持网页在线。
3. 工作流以受控 runner 在临时检出中获取最新 `main`；它只能取到指定任务快照，不取得任意 D1 管理权限。
4. 检查草稿目标的原始基线。文章文件未变时可以直接应用；同篇已变则冲突停止。说说按稳定 ID 比较原条目，允许保留别人的新说说、只插入新条目或修改目标条目；目标条目已变化或已被删除则停止。
5. 产生候选变更，重新验证所有路径和素材摘要。文章只写当前文章目录；说说只改 `content/pages/talks.md` 的目标条目及本次新增配图。旧条目的 ID、视频、说明注释及其他内容保持。
6. 在临时检出中运行 `npm ci` 和完整 `npm run verify`。使用仓库 `.node-version` 指定的 Node，避免本机与云端安装差异。不能只运行 `astro build`，不能跳过测试发布。
7. 校验后检查候选修改集没有新增越界文件、构建没有改写内容，再创建内容提交；生成物如 `_generated/comment-targets.json` 仍保持忽略。
8. 再检查任务有效性和远端 `main`，以普通非强制 Git 推送发布。若远端已变化，停止并提示基于新版本重新校验，不复用旧验证结果、不强推、不自动重置。
9. 记录准确的提交 SHA。继续查询该提交的 Cloudflare Pages 检查结果，区分“已推送，部署中”“已上线”“部署失败”。不能把 Git 推送成功直接显示成网站上线。

工作流失败或额度不足时，草稿和配图仍在 D1。工作流关闭、密钥缺失或触发请求超时，必须显示具体阶段；触发结果不确定时先按任务 ID 查询是否已经运行，不能盲目重复派发。

推送结果不确定时，检查远端是否已包含该任务提交；任务 ID 写入提交说明，作为恢复依据。不仅凭一次旧 ref 回读就判定失败。已经推送的任务不再创建第二个内容提交。

Cloudflare 构建失败时，Git 中仍保留已推送的提交，线上继续使用上次成功部署。界面引导查看该次部署日志，不谎称内容已回滚，不为重试界面而重复发布正文。

## 10. 云端任务认证与密钥

浏览器不接收 GitHub token、`ADMIN_TOKEN` 或 runner 凭据。继续保留现有留言管理接口的 Bearer 鉴权，新增浏览器写作接口使用 `/api/writer/`，不放宽 `/api/admin/` 的规则。

第一版使用分离的服务端凭据：

- Pages Secret `WRITER_GITHUB_TOKEN`：仅授权当前私有仓库；Contents 读取、Actions 读写，用于读取内容、触发固定工作流和读运行状态。2026-10-23 核实细粒度 PAT 不支持 Checks API：部署检查交给工作流自带的 Contents/Checks 只读临时令牌，再经运行身份、任务租约和准确提交核对后回传。等待超时保留未确认，提供只查原提交的重新检查，不再次提交正文。
- GitHub Actions Secret `WRITER_PUBLISH_TOKEN`：仅当前仓库的 Contents 读写，供 runner 普通推送。使用受限凭据使这次推送正常触发现有 Git 集成，并在验收时实测。
- Pages 与 Actions 各保存同一 `WRITER_RUNNER_SECRET`：至少 32 字节随机值，只供 runner 读取活动任务、申请发布许可及回传状态；不允许枚举私密草稿、任意文件写入或直接操作数据库。

runner 接口使用独立鉴权及租约，固定仓库、工作流和 `main`；状态转换带任务版本、run ID 和当前租约，旧运行或旧回调不能覆盖新结果。申请推送许可时再次检查站主账户是否仍存在、凭据版本是否一致；取消、改密、注销后的任务不再获得新许可。已经开始的跨服务 Git 操作不能承诺与账户注销全局原子，需要在界面明确区分“已提交”与“已取消”。

工作流不接受任意 shell 命令、仓库、分支、文件路径或 token 作为浏览器输入。标题、正文、图片名称、提交说明通过结构化数据传递，不能插入 shell 字符串。凭据与草稿全文不写入 Actions 控制台；不上传包含私密快照的公共构建产物。

检出使用 `persist-credentials: false`，发布 token 只传给最后的推送步骤；安装依赖和运行测试时不提供发布凭据。第三方 Actions 固定到完整提交 SHA，工作流仅开放读取内容所需的默认权限，不运行来自草稿分支或任意 ref 的工作流。

GitHub 原生 `GITHUB_TOKEN` 触发后续工作流有递归抑制规则；不能以“本地 push 成功”代替对现有部署集成的实测。[GitHub 工作流触发规则](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)

## 11. 与电脑本地仓库的关系

手机发布更新 GitHub，电脑本地目录保持原样。电脑日常写作推荐直接进入同一个 `/write/`；本地仓库继续用于开发、离线编辑和备份。

本地代码发布前先获取远端更新。工作区干净且没有分叉时可以快进同步；本地有未提交改动或本地提交时先保护这些改动，再显式合并。第一版不修改桌面写作台，也不承诺它自动拉取。

验收必须演练：云端新增多篇文章 → 本地旧版本提交代码 → 普通推送被拒绝 → 合并远端 → 文章和代码都存在 → 再推送。另演练反方向：本地先推代码，云端旧草稿发布时采用最新代码重新验证。双方修改同一目标时停止并保留版本。

任何路径都不通过 force push、`reset --hard`、自动 stash 或“用本地目录替换远端”来解决分叉。

## 12. 模块及接口边界

| 模块 | 对外职责 | 主要依赖 |
|---|---|---|
| 写作界面 | 编辑、恢复、预览和显示服务状态 | 同源 writer HTTP 接口 |
| 站主权限模块 | 请求边界、当前站主、会话有效性 | 现有账户存储 |
| 草稿/素材存储模块 | 版本保存、额度、引用、快照 | D1，不直接操作 Git |
| 仓库读取模块 | 按确定提交读取文章和说说 | 受限 GitHub API，不接受任意路径 |
| 内容转换模块 | 结构化草稿与现有 Markdown 格式互转 | 明确的 YAML 解析器及内容契约 |
| 发布任务模块 | 幂等派发、租约、状态与恢复 | D1、固定 Actions 工作流 |
| runner 发布脚本 | 检查基线、应用内容、校验、普通推送 | 临时 Git 检出、现有 verify |

建议接口族为 `/api/writer/session`、`content`、`drafts`、`assets`、`publish`；runner 使用独立的 `/api/writer/runner`。路径只是固定受控动作的入口，不能提供“传文件系统路径就读写”的通用接口。

YAML 采用显式声明的 `yaml` 依赖，限服务端及发布脚本使用。保留源结构和注释，禁止用全文件 load/dump 消掉说明；禁止解析时执行类型扩展。该依赖需在实现时同步仓库依赖白名单及锁文件，并验证访客页面的下载路径不包含它。Markdown 预览优先抽取现有桌面版的基本能力，第一版不引入富文本编辑器框架。

## 13. 状态、故障与反馈

编辑状态：未保存 → 保存中 → 已保存到云端；另有仅存本设备、保存失败、版本冲突。进入新页面前不谎报已保存。

发布状态：等待运行 → 校验中 → 准备推送 → 已推送、部署中 → 已上线。终止状态分别为内容冲突、校验失败、触发失败、额度不足、已取消和部署失败。每个状态保留可操作的下一步。

工作流总时长上限 10 分钟。后端操作有超时和有限重试；前台发布状态只在可见页面递增间隔查询，不依赖长连接。回调丢失或浏览器关闭后再次进入，按记录的 run ID 和提交 SHA 恢复状态，不能把“没有新回调”直接认定为没发布。

GitHub Actions 的费用和免费额度按仓库所有者账户计算；本站私有仓库不享有“公开仓库标准 runner 无限免费”的前提。上线前核对账户额度，并由站主保持新增付费使用预算为 0；没有额度时保留草稿、停止发布，不自动启用付费 runner、购买额度或上传大型 Actions 缓存。[GitHub Actions 计费说明](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

## 14. 验收与测试

先对关键接缝建立能失败的用例，再实现对应能力。不能只检查源码字符串是否存在。

| 验收面 | 必须覆盖的场景 |
|---|---|
| 权限 | 未登录、普通访客、伪造 owner、过期/撤销会话、漏配 owner、跨站请求、预览域名、私有图片和导出都不能绕过 |
| 草稿 | 重开浏览器恢复、手机和电脑同改、请求乱序、离线重连、登录过期、IndexedDB 不可写、成功响应丢失 |
| 图片 | 合法二进制字节不变、伪造 MIME、尺寸异常、超限、透明图、重复上传、并发配额、仍被快照引用时清理被拒绝 |
| 内容 | LF/CRLF、中文标点和 YAML 冒号、注释/未知字段/视频不丢、文章 slug 不变、说说旧 ID 与评论归属不漂移 |
| 发布 | 重复点击、触发超时、重复回调、不同旧租约、校验期间继续编辑、任务取消、runner 失败、不确定推送结果 |
| Git | 云端多文与本地代码双向合并、同目标冲突、校验期间 main 更新、越界路径/符号链接、无强推、素材和正文原子提交 |
| 隐私 | 未发布正文和图片不进入 dist、RSS、sitemap、公开分支预览或构建日志；预览不能执行脚本 |
| 页面 | 320/390/768/1280 宽度、亮暗主题、软键盘、长标题/长代码块、触摸上传排序、原生焦点与键盘导航 |
| 全站 | 完整 npm run verify、实际 Pages Functions 打包、干净安装、普通访客页面未新增写作脚本/大分片 |

上线验收必须实际跑一次云端“草稿 → 校验 → 推送 → Cloudflare 部署”，并从另一浏览器确认未发布内容不可读、已发布内容可见。本地模拟通过不等于云端已经可用。

## 15. 部署准备与回退

实现及本地验收完成后，再整理服务端配置及站主操作清单：核对现有 D1/Actions 配额、设置仅限仓库的凭据、备份 D1、执行增量迁移、部署和验证。

远端数据库迁移前导出备份并验证可读；不删除旧账户或评论。配置文件修改前按工作区规则备份到 `<工作区>/work/`，密钥通过 Secret 工具或平台后台设置，不在聊天中索取明文、不进 Git，不修改 Codex 的 `config.toml`。

生产写入仅正式域名启用。发布前检查所有必要绑定与工作流可用性；生产迁移和首次 main 推送在取得当次授权后执行。权限被拒绝时停止对应操作并按用户约定说明需要的配置位置、命令、影响和替代方案。

回退通过关闭写作入口/发布能力及 Git revert 完成；新增表保留私密草稿供恢复，不因代码回退就清空数据。已经推送的内容回滚仍用新的撤销提交，不重写历史。
