## 1. 设计计划

### 1.1 配色：5 个值，两类底

| 名字 | 值 | 角色 | 实测对比度 |
|---|---|---|---|
| `--paper` | `#FFFFFF` | 页面底 | — |
| `--ink` | `#0E0E0E` | 主文字；**也是黑带的底色**（同一支墨） | 对纸 **19.3:1** |
| `--muted` | `#5C5C5C` | 次级文字：摘要、元信息、图注 | 对纸 **6.69:1** ✅ |
| `--hair` | `#D6D6D6` | **纯装饰线**，永不承载文字 | 对纸 1.45:1（不适用） |
| `--accent` | `#E4572E` | 信号橙：hover、图形、≥24px 大字 | 对纸 **3.68:1**（大字门槛 3.0 ✅ / 正文 ✗） |
| `--accent-ink` | `#C2410C` | 小字专用橙 | 对纸 **5.18:1** ✅ |

**底反了，橙也要跟着换**（这条最容易被忽略）：

| 在黑带上 | 实测 |
|---|---|
| `#FFFFFF` 文字 | 19.3:1 ✅ |
| `#DEDEDE` 简介 | 14.35:1 ✅ |
| `#B4B4B4` 元信息 | 9.31:1 ✅ |
| `#E4572E` | **5.24:1** ✅ ← 黑带上就用它 |
| `#C2410C` | 3.73:1 ✗ ← **黑带上不能用小字橙** |

> **为什么是 `#0E0E0E` 而不是纯 `#000`**：这不是"习惯性用近黑代替黑"。首屏是一块 74vh 的满幅黑，
> 在非 OLED 屏上纯 `#000` 与大面积白之间会出现边缘振颤；`#0E0E0E` 保留 19.3:1 的对比度同时缓解这一点。
> 而且它与代码块底色**是同一个值** —— 全站只有一支墨。要改成纯黑只需动一个变量，但需要重新看一遍首屏。

### 1.2 字体：拉丁自托管，中文走系统栈

| 角色 | 字体 | 加载方式 |
|---|---|---|
| 显示 / 标题（拉丁） | **Archivo Variable** | 自托管 WOFF2，latin 子集，约 20–30 KB |
| 正文 / UI（拉丁） | **IBM Plex Sans** 400 / 600 | 自托管，约 40 KB |
| 代码 | **IBM Plex Mono** 400 | 自托管，约 20 KB |
| 中文（全部） | **系统栈**：PingFang SC → Microsoft YaHei → Noto Sans SC → Source Han Sans SC | **不加载字体文件** |

**中文字体不下载，这是刻意的取舍，说清代价**：中文全量字体 5–10 MB，对大陆读者是灾难性的首屏成本；
系统栈在三端的覆盖率极高（苹果苹方 / Windows 微软雅黑 / 安卓思源黑体）。
代价是不同系统上字形略有差异 —— 换来的是 0 KB 和更快的首屏。**这个交换值得。**

**正文字族与等宽同源**（Plex Sans + Plex Mono 是同一个超家族），所以代码块与正文并排时不打架。
标题族（Archivo）与正文字族（Plex Sans）是**两族但气质可分**：前者偏宽、几何、有海报感，后者偏人文。
—— 不用第三族，这是克制。

**字体加载**：`font-display: swap`；拉丁字体 `preload`；黑带标题的首屏文字先用系统字体渲染，避免文字闪烁后跳版。

### 1.3 布局

```
首页（桌面）
┌──────────────────────────────────────────────────────────────┐
│  北杉札记           NORTH_CEDAR'S NOTES      文章 标签 关于 RSS │ ← 黑带顶行
│                                                              │
│            黑带 min-height: min(74vh, 42rem)                  │
│                                                              │
│  北杉札记                                        ← 站名，压底左对齐
│  你好，我是郑云嘉，合肥人，安徽大学大一在读。……      ← 简介，max 33em
└──────────────────────────────────────────────────────────────┘
   最近写的                                          ← h2，22px，正常字距
   ─────────────────────────────────────────────────
   2026-09-24   草稿
   高三那年我买了台相机                              ← 条目，超大标题
   高三最忙的那年，我买了人生第一台相机，从此看世界多了一个借口。
   摄影
   ─────────────────────────────────────────────────
   （下一条目……）

文章详情（桌面）—— 只有首屏换内容，正文骨架与首页一致
┌──────────────────────────────────────────────────────────────┐
│  北杉札记           NORTH_CEDAR'S NOTES      文章 标签 关于 RSS │
│  我用手机 AI 指挥电脑 AI，从零搭了这个博客          ← 标题压进黑带
│  2026-09-16    2,431 字    约 6 分钟    草稿    AI   建站        │
└──────────────────────────────────────────────────────────────┘
   本文目录
   ─────────────────────────────────────────────
   这套流水线的分工              第一步：把弹药从电脑搬到手机        ← 两栏
   ─────────────────────────────────────────────
   先说清楚这件事有多离谱：……                                    ← 正文 34em
```

- **对齐**：一律左对齐。不用居中标题、不用两端对齐（中文两端对齐会产生难看的字距）。
- **正文行宽 34em**（≈578px @17px）。中文一行约 34 字、拉丁约 75–80 字符，两者都落在舒适区。
  （阶段 2 调研里「中文该用 34–38em」是推断、无硬数据；34em 是保守取值，阶段 7 用真草稿目视复核。）
- **栅格**：列表是单列堆叠，不用多栏。黑带满幅出血，正文回到 34em —— 这个"宽—窄—宽"的节奏是本设计的骨架。

### 1.4 原则（三条）

1. **记忆点只有一个：首屏那块满幅黑。** 除此之外全站保持安静 —— 没有卡片、没有阴影、没有圆角、没有第二块彩色区域。
2. **层级靠字号与留白，不靠容器。** 需要区分两块内容时，先加空白或一条 1px 线，而不是加一个框。
3. **橙色是信号，不是装饰。** 静止画面上橙色出现 0–1 次；它出现的位置必须意味着"这里可以点"。

## 3. Token（可直接抄进 `src/styles/tokens.css`）

### 3.1 颜色

```css
--paper:#FFFFFF; --ink:#0E0E0E; --muted:#5C5C5C; --hair:#D6D6D6;
--accent:#E4572E; --accent-ink:#C2410C;
--on-band:#FFFFFF; --on-band-sub:#DEDEDE; --on-band-meta:#B4B4B4;
--code-bg:#0E0E0E; --code-fg:#EDEDED;
```

### 3.2 字号阶梯（11 档）

| token | 值 | 用途 | 配套行高 |
|---|---|---|---|
| `--fs-display` | `clamp(2.8rem, 13vw, 8.5rem)` | 首屏站名 | .90 |
| `--fs-title` | `clamp(1.9rem, 1.1rem + 3.6vw, 3.8rem)` | 文章标题 | 1.02 |
| `--fs-item` | `clamp(1.6rem, 1rem + 4.2vw, 3.4rem)` | 列表条目标题 | 1.03 |
| `--fs-h2` | `clamp(1.45rem, 1.05rem + 1.5vw, 2.1rem)` | 正文二级标题 | 1.18 |
| `--fs-h3` | `clamp(1.15rem, 1rem + .7vw, 1.4rem)` | 正文三级标题 | 1.25 |
| `--fs-lg` | `1.375rem` (22px) | 区块标题 | 1.3 |
| `--fs-lede` | `1.125rem` (18px) | 首页简介 | 1.75 |
| `--fs-body` | `1.0625rem` (17px) | 正文 | 1.75 |
| `--fs-sm` | `.875rem` (14px) | 摘要、图注 | 1.7 |
| `--fs-xs` | `.8125rem` (13px) | 元信息、标签 | 1.6 |
| `--fs-mono` | `.85rem` (13.6px) | **仅代码与代码语言标注** | 1.72 |

负字距随字号递增：`--ls-display:-.045em` / `--ls-title:-.035em` / `--ls-item:-.032em` / `--ls-h2:-.012em` / 正文 `0`。

### 3.3 间距（4px 基准，8 档）

`--sp-1:.25rem` · `--sp-2:.5rem` · `--sp-3:.75rem` · `--sp-4:1rem` · `--sp-5:1.5rem` · `--sp-6:2rem` · `--sp-7:3rem` · `--sp-8:4.5rem`

规则：**组内用 1–4，组间用 5–8。** 不允许出现不在这个阶梯上的间距值。

**一条明确的例外**：正文内部的**排版节奏**（段落间距 `1.15em`、列表缩进 `1.35em`）用 `em` 而非 token。
理由：它们必须随字号缩放，而 token 是 `rem`（不随字号缩放）。这不是"随手加的间距"，
而是排版学上的基线节奏 —— 布局间距仍然只走上面这八档。

### 3.4 版心与断点

```css
--wrap:82rem;        /* 最大 1312px */
--measure:34em;      /* 正文行宽 */
--gutter:clamp(1rem, 4vw, 3rem);
--band-h:min(74vh, 42rem);
```

断点（移动优先，`min-width`）：**640px**（列表条目加标签列）· **860px**（导航一行放下）· **1200px**（黑带内简介分两栏？不 —— 全站不做多栏）

### 3.5 动效

```css
--dur-fast:120ms;   /* hover / focus 的颜色与下划线 */
--dur-enter:320ms;  /* 唯一一次入场 */
--ease:cubic-bezier(.2,0,0,1);
```

- **唯一允许的非交互动效**：首屏黑带里的站名 + 简介，加载时做一次 `translateY(12px) → 0` + 淡入，320ms，一次性，不循环。
- **明确禁止**：区块逐个淡入、卡片 hover 抬升、视差、滚动驱动动画、loading 骨架。
- `@media (prefers-reduced-motion: reduce)` 下：入场的位移与时长全部归零（只保留瞬时显隐）。

## 4. 组件规范

| 组件 | 关键尺寸 | 交互 | 无障碍 |
|---|---|---|---|
| 黑带 `Band` | `min-height:var(--band-h)`；内容压底 | 无 | 内部的 h1 是页面唯一的 h1 |
| 站名 `Display` | `--fs-display` / `--lh .90` / `--ls -.045em` | 首页是链接，hover 不改色（只加下划线） | 链接文本即站名，不需 aria-label |
| 顶行 `Brandline` | 13px；wordmark 与导航一行，窄屏折行 | 导航 hover 用 `box-shadow: inset 0 -2px 0 var(--accent)`（≥24px 规则的例外：这是**图形**不是文字色） | `<nav aria-label="主导航">`，当前页 `aria-current="page"` |
| 列表条目 `PostIndex` | 标题 `--fs-item`；上下 `--hair` 1px 线 | hover 标题变 `--accent`（字号远大于 24px，3.68:1 合法） | 整条是一个 `<a>`，焦点环覆盖整块 |
| 元信息 `Meta` | 13px / `--muted` / `tabular-nums`；**无分隔符**，靠 `--sp-4` 间距分组 | 无 | 用 `<time datetime>` |
| 标签 `TagChips` | 13px；1px `--hair` 边框；无圆角 | hover 边框与文字转 `--accent-ink` | 是链接就进 Tab 序；标签数量多时用 `<ul>` |
| 草稿标记 `DraftBadge` | 12px；1px `--accent-ink` 边框 + 同色文字 | 无 | 需要可见文本"草稿"，不能只靠颜色 |
| 目录 `Toc` | 14px；860px 以上两栏 | 锚点跳转；`scroll-margin-top` 留出 1.5rem | `<nav aria-label="本文目录">` |
| 代码块 | 黑底 `--code-bg`；顶部一条：语言标注（`--fs-mono`，`--on-band-meta`，**不做全大写、不加字距**）+ 复制按钮 | 复制按钮 hover 反色 | `pre > code`；复制按钮有可读文本；**JS 关闭时不出现** |
| 超长代码行 | `pre{overflow-x:auto}` + `white-space:pre` | 横向滚动 | 不把 `overflow-wrap:anywhere` 用在 `pre` 上（会毁缩进） |
| 表格 | 表头 2px `--ink` 下线，行 1px `--hair`；外层 `overflow-x:auto` | 无 | 真 `<table>` + `<th>`；表头 `white-space:nowrap` |
| 正文图片 | 通栏（`--measure` 宽）；上下 `--sp-6` | 无 | **`alt` 必填且要写成人话**（基准：craigmod 那种整句描述） |
| 引用块 | 左侧 4px `--ink` 实线；无底色；不斜体 | 无 | 真 `<blockquote>` |
| 焦点环 | `3px solid var(--accent-ink)`，`outline-offset:3px` | — | **只在 `:focus-visible`**，不用 `:focus` |

### 4.1 评论组件（2026-09-26 新增 — 自建 Functions + D1）

**设计原则：它是正文的延续，不是一块 UI 面板。** 同宽（`--measure` 34em）、同字号、同一套细线；
全站唯一的"界面感"来自那个「发表」按钮。

**配色：不新增任何颜色**，全部复用 §3.1：

| 用途 | token | 实测对比度 |
|---|---|---|
| 评论正文、留言者名字 | `--ink` | 对纸 19.3:1 |
| 时间、空状态提示 | `--muted` | 对纸 6.69:1 |
| 条目分隔线、输入框边框 | `--hair` | 装饰线，不承载文字 |
| 输入框聚焦边框 | `--ink` | — |
| 「发表」按钮底 / 字 | `--ink` 底 + `--paper` 字 | **19.3:1** |
| 「发表」按钮 hover 底 | `--accent-ink` 底 + `--paper` 字 | **5.18:1** |
| ~~`--accent`~~ | **刻意不用** | 对纸仅 3.68:1，按钮文字是小字，**不达标** |

**字体**：全部复用现有栈（正文族 + 系统中文字体）。**不引入等宽** —— §2 已禁止把等宽用于数据标签；
时间用 `font-variant-numeric: tabular-nums`。

**布局**（与正文同宽、左对齐；移动端同构，不需要单独断点）：

```

写得真好。                                ← --fs-body / --lh-body / max-width 34em
──────────────────────────────────────  ← 1px --hair
小红
…
──────────────────────────────────────  ← 1px --ink，评论区结束

留个言                                    ← h2（--fs-lg / 700）
名字
┌────────────────────────────────┐
└────────────────────────────────┘      ← input：1px --hair，无圆角；focus → 1px --ink
留言
┌────────────────────────────────┐
│                                │      ← textarea rows=4
└────────────────────────────────┘
[ 发表 ]                                 ← --ink 底 / --paper 字；hover → --accent-ink 底
```

**第二遍：对照「生成的页面」默认值复查**（§2 那张表的同一套判据）：

| 检查项 | 结论 |
|---|---|
| 每条评论套一个圆角卡片 | ❌ 用 1px 细线分隔，和 `PostIndex` 一致 |
| 头像 + 名字 + 时间的社交卡片 | ❌ **不用头像** —— 它会导致请求 gravatar（= 第三方域名），直接违反约束 |
| 中点/斜杠连接元信息 | ❌ 换行排布（§2 已禁止） |
| 全大写 eyebrow「COMMENTS」 | ❌ 用中文 h2「评论」 |
| 阴影 / 渐变 / 玻璃拟态 | ❌ 全无 |
| 装饰性编号 | ❌ 无 |
| 模糊按钮文案「提交」 | ✅ 用「**发表**」；成功后按钮短暂变「已发表」 |
| 空状态「暂无数据」 | ✅ 改成邀请式：「还没有人留言。你可以是第一个。」 |

**状态设计**（不是只画静态图）：

| 状态 | 表现 |
|---|---|
| 空 | 评论区只有一条细线 + 「还没有人留言。你可以是第一个。」（`--muted`） |
| 加载中 | 列表位置显示「正在加载留言…」（`--muted`），不显示骨架屏（禁止项） |
| 加载失败 | 「留言没能加载出来。刷新页面再试一次。」**不清空已加载的内容** |
| 校验失败 | 字段下方显示「名字还没写」/「留言不能超过 1000 字」，`role="alert"` |
| 提交中 | 按钮文案不变但 `disabled` + `aria-busy="true"` |
| 提交成功 | 清空表单；新评论追加到列表底部并标「**刚发表**」（用文字，不用颜色）；**不跳转、不刷新页面** |
| 提交失败 | 「留言没提交成功。可能是网络问题，请稍后再试。」+ **保留用户已输入的内容**（不能让他白写一遍） |

**无障碍**：

- 真 `<form>` + `<label for>`；错误用 `aria-describedby` 关联到字段
- 错误容器 `role="alert"`（屏幕阅读器会播报）
- 评论列表用 `<ol>`（有序 = 时间序）；时间用 `<time datetime>`
- 蜜罐字段：`aria-hidden="true"` + `tabindex="-1"` + **绝对定位移出视口**（不能用 `display:none` —— 部分机器人会跳过隐藏元素）
- 提交按钮有可读文本（不是只有图标）
- 焦点环沿用全局 `:focus-visible` 规则

**API 契约**（UI 依赖它，所以属于设计的一部分）：

```
GET  /api/comments?slug=<slug>
     → 200 { comments: [{ id, name, body, createdAt }] }   // 按 createdAt 正序

POST /api/comments
     body: { slug, name, body, website }   // website 是蜜罐字段，正常用户永远为空
     → 201 { comment: { id, name, body, createdAt } }
     → 400 { error: '名字没写' | '留言为空' | '名字太长' | '留言太长' | '页面标识不合法' }
     → 429 { error: '发表太频繁，请等一分钟再试' }
```

限额：`name` ≤ 40 字、`body` ≤ 1000 字、`slug` 只校验格式 `^[a-z0-9-]+$`（**不校验文章是否存在** ——
垃圾评论填个不存在的 slug 也不会显示在任何页面上，为它去读已发布列表是过度设计）。

**JS 预算修订**：评论脚本为原生 JS，目标 **≤ 4 KB**；文章页 `<script>` 数量由 1 变 **2**。
（§6 第 4 条同步修订。）

## 6. 可测的验收标准

阶段 7 逐条跑，不接受"看起来没问题"：

1. **无横向滚动**：360 / 768 / 1440 三个宽度下 `documentElement.scrollWidth === clientWidth`。
2. **对比度断言**：一个脚本读 `tokens.css`，对 §5 的取值表逐项复算并断言。
3. **橙色越界断言**：构建产物里，包含 `--accent`（非 `--accent-ink`）的选择器只允许出现在白名单里（列表条目标题 hover、导航当前项下划线、首屏入场）。
4. **JS 预算**（2026-09-26 修订，因新增自建评论）：文章页 **≤ 2 个 `<script>`**，**内联合计 ≤ 4 KB**；
   必须内联或同域名，**不得引入任何外部域名**。
   > 实测修正：计划里预测「加评论会让 script 从 1 个变 2 个」——**错的**。
   > Astro 把同一个 `<script>` 块里的多个 `import` 合并成一个模块脚本，
   > 所以标签数仍是 **1**，变的是体积：**587 → 2534 字节**。断言按实测写成「总数 ≤ 2、合计 ≤ 4 KB」。
   >
   > ⚠️ **2026-09-26 再次变更：本条已解冻，新上限尚未确定。**
   > 因视觉方向改为莱茵生命风格（需动画/灯箱等客户端能力），此上限进入 brainstorming 重新议定。
   > 在定案之前，**不要以本条作为拒绝新功能的理由**；定案后必须回来更新本节与
   > `tests/build-output.test.ts` 的对应断言。见 `site-decisions.md` 的视觉方向变更记录。
5. **第三方零加载**：构建产物中不出现任何外部域名的 `src` / `href`（除文章正文里的作者手写外链）。
6. **Lighthouse**（阶段 7 真跑，贴原始数字）：Performance / Accessibility / Best Practices / SEO 四项。
7. **内容层未被污染**：构建前后 `content/` 的文件哈希不变。
