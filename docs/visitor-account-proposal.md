# 访客账户讨论方案

状态：用户于 2026-10-20 确认公开名片＋私人资料设置，随后明确选择账密登录并授权实施。已实现的具体方案见 `superpowers/specs/2026-10-20-visitor-accounts-design.md`，使用与上线方法见 `writing-guide.md` §14.7。下文为最初讨论稿；其中邮箱/手机验证码和邮箱站主登录已被账密方案取代，不是当前实现。

## 推荐的使用方式

留言和评论默认直接编辑、匿名提交。登录是编辑区的一处可选入口，只有主动点击才显示登录表单；不拦截评论、不自动跳转登录页。登录前写的内容保留。

支持邮箱验证码和手机短信验证码，两种联系方式绑定同一个内部用户 ID；验证成功后可以设置昵称、头像和个性签名。联系方式不对外展示，不把密码管理作为第一版负担。手机号需要另外选择短信服务及发送预算，邮箱也需要配置可靠的发信渠道。

评论中显示头像、昵称、时间；签名放进点昵称展开的个人名片，避免每条评论都变高。登录用户后续改头像与名字时，历史评论仍归同一账户；删除账户时允许匿名化保留评论或删除本人评论，具体规则待确认。

匿名访客和历史留言继续保留原名字及正文，使用默认头像。历史留言不因“昵称相同”自动归给新注册账户，防止冒领。默认头像做 6 个本站自绘的莱茵风格图案：叶脉、双螺旋、实验瓶、晶体、星轨、无限环；由稳定标识分配，不依赖外部头像服务。自定义头像统一转为静态图片并去除元数据，第一版不支持动图。

## 个人主页

建议第一版只做个人名片与私人的资料设置页，暂不做关注、私信、动态等社交功能。日后若确实需要公开主页，可加入 `/people/<随机公开标识>/`，只显示用户主动公开的资料和已审核评论；默认不公开联系方式，也不强制展示评论历史。这样不用为了换头像就建立一套社交网络。

## 站主登录

站主也可以使用邮箱验证登录，但管理权限由服务端预先绑定的账户 ID 决定，不由昵称、前端开关或注册信息决定。页面给站主加明确身份标识，管理入口与普通资料设置分开；敏感管理操作再次验证。现有写作台的管理密钥仍只保留在本机/服务端，不进入访客网页。

## 实现前需要定下的事项

1. 邮箱、手机号如何绑定同一个人，以及丢失其中一种联系方式后的找回方式；更换联系方式需要重新验证。
2. 验证码发送限频、失败次数和预算上限；不让匿名评论被验证码流程打扰。
3. 昵称可以重复，但不能冒用站主标识；头像与签名的审核、屏蔽及举报规则。
4. 会话使用 HttpOnly / Secure Cookie，处理过期、退出和跨设备登录，不能把管理密钥当登录凭证。
5. 评论表新增可空 author_id，旧数据无需强制迁移成账户；匿名评论维持现有能力。
6. 登录不等于免审核；匿名与登录用户均受反垃圾和频率限制，访客资料也只按纯文本渲染。
7. 账户注销、评论保留、资料公开与备份恢复的规则需要写清楚。

推荐先确定“名片而非公开个人主页”、站主绑定方式与发信/短信服务，再实现账户体系。
