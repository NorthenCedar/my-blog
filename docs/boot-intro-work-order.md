## 0. 边界（一屏读完）

**做什么**：给**首页**加一段 20.16 s 的一次性开场动画，复刻上游 `LBEILC/RhineLabUI`（MIT）开场的**方法与数值**。

**一句话技术路线**：`1920×1080` 舞台 + 等比缩放，各条轨迹全部写成 **CSS `@keyframes` 百分比停点**（CSS 不占 JS 预算 ⇒ 20.16 s 完整长度放得下，决策 #4）；覆盖层是**装饰**（`aria-hidden`），首页正文照常留在 HTML 里（决策 #21）；JS 只负责三件事（会话标记 / skip / 收尾），目标 <800 B。

## 2. 时间轴总表

**上游基准**：原片 `1920×1080` / **25 fps**；`appTime = 原片时间 − 5`；播放起点 `app 1.76 s`（= 原片 6.76 s）；总长 **20.16 s**（`src/main.ts:1192-1194`、`src/boot-motion.ts:24-26`）。

**帧 ↔ 秒 ↔ 动画百分比**（本工单统一换算）：

```
f        = floor((appTime + 5) × 25)          # 原片帧号
appTime  = f / 25 − 5                          # 秒
p%       = (f − 169) / 504 × 100               # 本开场动画的进度（169 帧 = 起点，673 帧 = 终点）
delay_s  = (f − 169) / 25                      # 给逐字 span 用的绝对延迟
```

## 4. 落到 CSS 的写法

### 4.1 帧 → 百分比停点

```
p% = (f − 169) / 504 × 100        # §2 已给公式与常用帧表
```

每条轨迹一张 `@keyframes`，把 §3 的关键帧逐点写成 `p% { … }`。**段与段之间没有 `animation` 嵌套**：每个元素一条独立的、`animation-duration: var(--dur-boot)`、同一时间原点的动画（各自 `animation-delay` 为 0，靠 `%` 定位），这样"某条轨迹改了帧点"不会牵动别的元素。

**缓动**：一律 `linear`（上游的空间位移是单调三次 Hermite 保速插值；用 `linear` + 密集停点比 `ease` 更接近，见 §8 风险 5）。闪切/二值量用 `steps(1, end)`（§4.6）。

### 4.2 容器、堆叠、锁滚动、收尾

```
<div class="boot" data-boot-overlay>          ← 覆盖层根（唯一顶层元素，便于断言与整体移除）
  <div class="boot-deco" aria-hidden="true">  ← ★ 装饰子树：aria-hidden 只包在这里
      … 全部动画元素 …
  </div>
  <button class="boot-skip" type="button" aria-label="跳过开场">SKIP ↗</button>   ← ★ 按钮是 .boot-deco 的**兄弟**
</div>
```

- **`aria-hidden` 不能包住可聚焦元素**（`#16` 要求在覆盖层里放真按钮）⇒ 装饰层与按钮必须是**兄弟**。这是本工单最容易踩的 a11y 坑。
- **类名冲突**：`base.css:47-58` 已经占了 **`.skip`**（"跳到正文"链接）。开场按钮**必须**用 `.boot-skip` 之类的名字，**不要**照抄上游的 `.skip` —— 否则会继承 `left:-9999px` 那套。
- **挂载点**：新组件 `src/components/BootIntro.astro`（结构 + 组件内 `<style>`），由 `src/pages/index.astro` 在 `<Base>` 默认槽的**最前面**引入（紧跟现有门控脚本之后）。落在首页 ⇒ 其余 14 页产物不受影响（与 B2 的"只落首页"同一手法）。
- **堆叠**：`position:fixed; inset:0; z-index:60`（首页现有：装饰 0 < 正文 1 < 扫描带 2 < 刻度尺 3 < HUD 4 < OS 条 5；base.css 的 `.skip` 跳转链接是 99，保持在其下）。
- **门控（fail-safe，方向与站上既有口径一致）**：

```css
html:not(.boot-on) [data-boot-overlay] { display: none; }   /* 默认不显示 */
html.boot-on      [data-boot-overlay] { display: block; }
html.boot-on      { overflow: hidden; }                     /* 锁滚动 */
@media (max-width: 767px)   { [data-boot-overlay] { display: none !important; } }  /* Q3 */
@media (prefers-reduced-motion: reduce) { [data-boot-overlay] { display: none !important; } } /* #6 */
```

  只有 JS 明确判定"该播"才加 `boot-on`。于是"无 JS / reduced-motion / 小屏 / 本会话已播 / JS 抛错"五种情形**全都自动安全**（覆盖层根本不渲染，动画也不创建）。
  门控脚本仍在**覆盖层之前**同步执行（沿用现有 `<script is:inline>` 的位置），因此不会有"先闪一下覆盖层再隐藏"。
  **必须保留 `classList.add('js')` 字面**：`tests/b2-motion.test.ts:63-66` 靠这个字符串断言"门控脚本只出现在首页"。
- **`--dur-boot: 20160ms`** 与 **`--dur-boot-out: 400ms`** 放 `src/styles/tokens.css` 动效段（设计决定，进 token）；其余全部数值硬编码在组件的 `@keyframes` 里（理由见 §4.4）。
- **收尾（#7 #9）**：
  1. 覆盖层里放一个 **0 尺寸的"时钟"元素** `.boot-clock { animation: boot-total var(--dur-boot) linear both; }`（`boot-total` 是一条什么都不改的空动画，只用来定时）。
     **为什么需要它**：子元素动画结束时的 `animationend` 会**冒泡**到覆盖层根，若直接监听根节点会在 0.7 s 处误触发收尾（水印/打字那几条先结束）。`animationend` 必须判 `e.target` 是时钟元素。
  2. `animationend`（时钟）→ 给根加 `.boot-out`（`transition: opacity var(--dur-boot-out)`）→ `transitionend` → `remove()` + `document.documentElement.classList.remove('boot-on')` + **焦点交回主标题**。
  3. **焦点交回**：`#16` 要求交回主标题。首页 `<h1 class="display">` 默认不可聚焦 ⇒ 给它加 `tabindex="-1"`（首页一处属性改动，属视觉层的最小必要改动），跳过/播完时 `h1.focus()`。**顺序**：先 `focus()` 再 `remove()`（反过来会先失去焦点节点、焦点掉到 `<body>`）。
  4. **播放标记**：进入播放**时**就写 `sessionStorage.setItem('boot-intro','1')`（刷新不再重播，`#6`）；skip 也写（`#16` 不要重播）。`sessionStorage` 调用必须 `try/catch`（无痕/禁用会抛）。

### 4.3 圆环类几何怎么用纯 CSS 表达（本节是实现成败的关键）

`@keyframes` **不能改 SVG `path` 的 `d`**，所以不能照抄上游"每帧算 `arc()` 拼 d"。但 §3.4 的所有轨迹都能拆成三个**可动**的量：

| 上游量 | 纯 CSS 等价物 |
|---|---|
| 半径 `r` | `transform: scale(r)`（圆心不动 ⇒ 等比缩放等价） |
| 起始角 `start` | `transform: rotate(start)` |
| 弧长 `sweep` | `stroke-dasharray`（配 `pathLength="1"` 归一化，与半径无关） |

具体做法：

```html
<circle class="arc arc-outer" r="1" pathLength="1" />
```
```css
.arc { fill:none; transform-box: view-box; transform-origin: 960px 540px; }
@keyframes arc-outer {
  63.0952% { transform: rotate(470deg)  scale(2000); stroke-dasharray: 0.0833 1; }  /* 30°/360° */
  …
  100%     { transform: rotate(-90deg)  scale(246);  stroke-dasharray: 1 1; }
}
```

- `pathLength="1"` ⇒ **dash 值以"周长=1"计**，与当前 `scale` 无关：弧长比例 = `sweep/360`，起始偏移 = `-start/360`（用 `stroke-dashoffset`，或把 `start` 折进 `dashoffset`）。`sweep = 360°` 时 `1 1` 自然是整圆，**不需要上游那段 2π 特判**。
- 半径变化 2000→246 用 `scale` 一步到位；`rotate` 用**展开角**（外环 470→−90、白环 −100→270、内环 −20→201.5，正是 §3.4 的原值，直接用）。
- **两侧小圆**（自己的圆心也在动）用三层嵌套，各自只动一个属性：
  `<g class="side-pos">`（`transform: translate(x,y)`，26 点）→ `<g class="side-arc">`（`rotate(start)`）→ `<circle>`（`scale(radius)` + `stroke-dasharray: sweep/360`）。
- **橙点 / 卫星点 / 黑白弧端圆点**：`<g class="orbit">`（`rotate(θ) translateX(R)`，一条 keyframes 同时动两个函数）→ `<circle>`（`r` 另一条）。卫星的相位差用每条点自己的静态 `rotate(i·60°)` 包裹层，生长曲线**逐颗一条绝对时间轴规则**（起点 548+3i 帧，`dotGrowth` 的 11 点）—— **全部零 JS**。
- **中央大点**：`<circle>` 的 `scale(coreRadius)`；闪变帧（546/547/549/550）就是 42.93 → 42.43 之间的 4 个停点，用 `steps(1,end)` 表达"整帧跳变"。
- **不动的 `stroke-width`**：`stroke-width` 在缩放过的 `<g>` 里会被一起放大 ⇒ **必须把描边画在没被 scale 的元素上**，或接受放大后的视觉（上游的 `stroke-width:2.4/4` 是在**未缩放**的 path 上、半径靠 `d` 变化 ⇒ 描边粗细恒定）。**推荐**：内层再套一个 `<g class="unscale">` 用 `scale(1/r)` 抵消 —— 但 `r` 在动，抵消也要动 ⇒ 更省事的做法是**接受描边随半径缩放**，只在人眼复核（B-6）里确认观感；若不可接受，最后手段是允许**极少量** JS 逐帧写 `stroke-width`（但这会占 JS 预算，与 #20 冲突）⇒ **本工单选择"接受缩放"，并在 §8 记为已知偏差**。
- **Logo 轮廓**：`pathLength="1"` + `stroke-dasharray: "length 1−length"` + `stroke-dashoffset: −start`（§3.2 的 34 行直接写进 keyframes）；`stroke-width` 6 点直接动 `stroke-width`（**它是 CSS 可动画属性**，不需要额外技巧）。
- **`transform-box: view-box` + `transform-origin` 用舞台坐标**（`960px 540px` / 各小圆自己的圆心）：这是 SVG 里做 `rotate/scale` 的唯一稳妥写法，别用默认的 `fill-box`。
- **`filter: blur()`** 只用在两处（跳变帧 2.2px、退场 8px），符合站上"不动 layout、只动 paint"的既有口径。

### 4.4 token 与硬编码的分界

| 类别 | 去处 | 理由 |
|---|---|---|
| 开场总时长 `20.16s`、交棒淡出 `400ms` | **进 `tokens.css`**：`--dur-boot: 20160ms` / `--dur-boot-out: 400ms` | 是**设计决定**，且断言要按名字查（§6.1-S5） |
| 颜色 | 复用现有 token（`--ink` `--paper` `--on-band` `--code-bg`）；确需新色（欢迎黑底 `#080a08`、背景 `#e7e7e1` 三停点）→ 加进 `tokens.css` 的**装饰段**，用 8 位 hex 承载 alpha 的既有做法，**不进对比度断言表**（覆盖层 `aria-hidden`、纯装饰），但注释里要写清"为什么安全" | `tokens.css:86-92` 的既有约定 |
| **全部轨迹数值、帧→% 停点、几何 px、字号、字距** | **硬编码在组件里**，每条注明来源（`上游文件:行`） | 它们是**测量数据**，不是设计决定 —— 把测量值做成可主题化的 token 没有意义，反而会让"改主题"误伤测量结果 |
| 舞台尺寸 `1920×1080` | 硬编码（缩放比用 `min(calc(100vw / 1920px), calc(100dvh / 1080px))` 算，除数**必须带单位**） | 同上 |

**样式落点**：`BootIntro.astro` 的组件内 `<style>`（Astro 会把它并进共享 CSS 文件，但只有首页引用它 ⇒ 其余页面的 HTML 不受影响）。**不要**往 `tokens.css` 里塞轨迹数值。

**`typed()` 的等价公式**（照抄语义，别用上游的 `slice`）：


### 4.6 硬切与闪切

- 二值量（`accessOpacity`、`logoOpacity`、`authOpacity`、`scanVisible`、`companyVisible`、`databaseOpacity`）在停点处用 `steps(1, end)`，或在相邻两个 `%` 上直接写 `0 / 1`（间隔 ≥1 帧 = 0.1984 %，比任何插值都"硬"）。
- 7 帧闪切（569–575）与 4 帧跳变（525/526/528/529）：每个帧点一个 `%` 停点，**不插值**（值本身就是整帧跳变量）。
- **这就是 #15 里那条"`steps(1)` 硬切闪"**：不是指某个具体动画，而是这套"整帧跳变不做补间"的表达纪律。

### 4.7 舞台缩放与小屏

```css
/* 实现里的最终形式：除数**必须带单位**（见 §11 坑 2，实测确认过） */
.boot-deco { position:absolute; left:50%; top:50%; width:1920px; height:1080px;
             transform: translate(-50%,-50%) scale(min(calc(100vw / 1920px), calc(100dvh / 1080px)));
             transform-origin: 50% 50%; }
```
- **背景与白场不在舞台上，而是铺满视口**（`.boot-bg` / `.boot-white` 是覆盖层根的直接子元素）：16:9 舞台在 16:10/手机竖屏等视口上会留缝，缝里会漏出首页的 HUD / OS 状态条。上游的生产行为也是「正常入场铺满实际视口，只有逐帧对照才用固定 1920×1080 舞台」——**只有图形留在舞台上**，所以 #8 的数值照抄不受影响。
- 用 `100dvh` 而不是 `100vh`（移动端地址栏收放会导致 `vh` 抖动）——虽然 ≤767px 不播，但平板/异常视口仍走这条路径。
- `#8` 的数值照抄前提是"1920 基准 + 等比"；小屏不播（Q3）后，这条只服务 ≥768px 的视口（该档最小 scale ≈ 768/1920 = 0.4 ⇒ 18px 实渲染约 7.2px；平板横屏 scale≈0.53 ⇒ 9.5px）。**站主 2026-09-26 审定时定：768–1024 照播，断点维持 767px**；实测截图（B-10 覆盖 768×1024 一档）作为记录，若日后觉得小字不够看再单独决定提断点。

## 8. 风险与不确定

1. **代码 vs 文档的四处冲突**（§3.0 已列）——一律以代码为准；**别拿勘察报告的数值表直接开工**（那张表取自被覆盖的早期 CSS）。
2. **"保速插值"会退化成"分段线性"**（`#4` 已接受）：视觉接近但不等于上游。兜底 = B-5 抽 12 帧 + B-6 的人眼抽检帧。
3. **20.16 s 首屏对 LCP/SEO 的处置**（交接 §4 点名要处置的）：
   - **SEO 不受影响**：覆盖层 `aria-hidden` 且是纯装饰，正文一个字都在 HTML 里（`#21`，由 S4 守）。
   - **LCP 必须实测、不能用推断代替**：构建后跑一次 Lighthouse（本地 preview 或线上），把 FCP/LCP/TBT/CLS 与当前 100/100/100/100 的基线并列记录。若 LCP 恶化到 >2.5 s，前滚修复的备选（按代价排序）：① 让覆盖层首帧先画"轻量白场"而不是大块黑底渐变；② 只对首访播（已经是）；③ 把首访的 `welcome` 段白场提前。
   - **"首屏 20 s 不可用"是站主已知情的选择**（`#5` 不缩短，因为有 skip）；缓解 = skip + Esc + 会话一次 + reduced-motion 不播 + 小屏不播。
4. **窄屏可读性**：已按 Q3 决定 **≤767px 不播**；**768–1024 照播**（站主 2026-09-26 审定时定，断点维持 767px）。该区间 scale 0.4–0.53 ⇒ 18px 正文实渲染 7–9.5px、权限字 26.5px→10.6–14px —— **已知偏小、已接受**；用 B-10 的 768×1024 档截图记录实际观感，日后要提断点再单独决定（提断点不影响任何数值）。
5. **覆盖层与 B2 入场的关系**：已按 Q2 决定"B2 照常播、被盖住"⇒ 交棒瞬间首页是稳态。**已知代价**：首访看不到 B2 那 4 条入场（老访客/无 JS/小屏/reduced 反而看得到）。这是有意的取舍，别在实现时"顺手"加耦合。
6. **`animationend` 冒泡**：子元素动画的结束事件会冒泡到根 ⇒ 收尾必须挂**专用时钟元素**并判 `e.target`（§4.2）。这是本节最容易写错的一处。
7. **`preserveAspectRatio` 差异**：我们的标志 viewBox 比例（2.0）与槽位 296×177（1.67）不同 ⇒ 实际绘制区 296×148；截图里若"标志与字的相对高度"不对味，微调槽位高度（不动帧点）。
8. **描边随缩放变粗**（§4.3 末条）：环的 `stroke-width` 在 `scale(r)` 里会一起缩放。**本工单选择接受**（避免为它引 JS），在 B-6 截图里确认；若不可接受，另开一轮讨论（代价是破 `#20` 或改用更复杂的"反向缩放层"）。
9. **CSS 体积与落位（已按 §10-9 实现，下面是最终实测值）**：生成结果 = **79 条 `@keyframes` / 56,595 字节**（原估 4–8 KB，错了约 8 倍 —— 停点数近 1300 而不是"约 200"）。落位方案已按建议改为"生成 `src/styles/boot.css`（gitignore）+ 组件 import"（`scripts/gen-boot-css.mjs`，`npm run build` / `dev` 前置调用；`--check` 是它的两侧冒烟路径）：

   | 指标 | 基线 | 现在 | 增量 |
   |---|---:|---:|---:|
   | `index.html` raw | 13,326 B | 24,288 B | **+10,962** |
   | `index.html` gzip | 4,533 B | 6,677 B | **+2,144** |
   | `_astro/*.css` 合计 raw | 28,372 B | 80,248 B | +51,876 |
   | `_astro/*.css` 合计 gzip | 6,989 B | 17,265 B | **+10,276** |
   | 首屏 html+css（gzip） | 11,522 B | 23,942 B | +12,420 |

   **关键性质**：那 51 KB 只在**首页**的 CSS 里（实测 14 个其它页面对开场 CSS 的引用数 = 0、`boot-` 字串数 = 0），所以文章页/相册页的预算一点没动。
   **对照**：内联方案实测 `index.html` +61,200 raw / +13,418 gzip，且 `is:global set:html` **同样不抽离** —— 所以"落成真实 .css"这一步是必须的，不是优化。
   **首次访问的 gzip 增量 ≈ +12.4 KB 省不掉**（要省只能砍停点 = 砍保真）；换来的是一次性开场、且只对首页。
   HTML 侧：+95 个逐字 span + 覆盖层结构 ≈ 10 KB raw（gzip +2.1 KB）——已验证"摘掉覆盖层后正文与基线逐字节相同"（§11）。
10. **a11y 两条**：① `aria-hidden` 子树内不得有可聚焦元素 ⇒ skip 按钮必须是**兄弟**；② 开场抢焦点会改变键盘用户的起点 ⇒ 交回 `h1[tabindex="-1"]`。另外**不要**给覆盖层加 `role="dialog"`/`aria-modal`（它不是对话，是装饰；加了反而要处理焦点陷阱）。
11. **命名冲突**：`base.css` 已占 `.skip`（跳到正文）⇒ 开场按钮用 `.boot-skip`。上游的 `.boot`/`.brand`/`.powered` 类名在我们站上**不冲突**（首页没有同名类），可以照用；但 `.brand` 与 `Band.astro` 的 `Brandline` 无关，别混。
12. **`sessionStorage` 异常**（无痕/策略禁用）：`try/catch`；写失败就退化成"可能重播一次"，不影响可用性。
13. **reduced-motion 的全局压平**（`base.css:60-67` 把 duration 压到 `0.01ms`）：若靠 `animationend` 收尾，在 reduced 下会立刻触发。我们已按 §4.2 走 `boot-on` 门控（reduced 下根本不加类 ⇒ 覆盖层不渲染、动画不创建），所以这条只是"别改成依赖事件"的提醒。
14. **上游 Logo 坐标空间换算**（§3.2）：终值已对齐我们现有 symbol（2.2/1.8），但**中间停点是我们按比例算的近似**，必须人眼复核一次。

**这一整轮踩到并已修掉的坑（别再踩）**：

1. **`set:html` 的模板字符串里不能用反引号** —— 注释里写 `` `.boot-deco *` `` 会把模板字符串提前截断，报的是 `deco is not defined` 这种看不出因果的错。**这轮栽了三次**，每次都是构建期才炸。
2. **`scale()` 的参数必须是纯数**：`calc(100vw / 1920)` 求出来是**长度** ⇒ 整条 transform 被丢掉（实测 computed = none，舞台既不居中也不缩放 = 覆盖层根本没盖首页）。要写 `calc(100vw / 1920px)`（长度/长度 = 数，已实测确认；`/1920` 与 `*0.00052` 都非法）。
3. **通配 `.boot-deco *{position:absolute}` 比单类选择器更具体** —— 想要 `relative`/正常流的必须带 `.boot-deco` 前缀（品牌三行与 `OS` 就是这样叠在一起的）。
4. **同一元素的多条动画必须写在一条 `animation` 里** —— 分两条规则写，后一条 shorthand 会把前一条整体覆盖。
5. **别用 `animation-delay` 做错峰**：那会让被延迟的元素落到"相对自己的时间轴"上，"把整层 seek 到某一帧"就不成立了（截图验收到 268 帧会看见本该 278 帧才入场的文字）。改成"每行/每颗一条绝对时间轴规则"后，一个 `currentTime` 值 = 一个绝对帧 ✓。
6. **连续多帧保持同一个值时，keyframes 段的两端都要打点** —— 只打起点会被线性插值出中间值（595 帧读出 0.825 而不是 0.65；DATABASE 的 627/629/633 三个段末也会漏）。逐帧二值量最好按"值变化的帧 + 每段末帧"生成，别手写。

### 13.1.1 抠图的四个要点（都踩过）

1. **按方向分流做 alpha**：素材里的**软阴影**不能一起抠进来。白面与阴影"与背景的差值"区间重叠（白面 Δ≈26、阴影 Δ≈5–20），
   单靠差值分不开 ⇒ 比背景亮的低阈值就保留（结晶主体），比背景暗的必须够暗（Δ>22）才算折面棱线，浅的判为背景。
2. **只取最上面那条墨带**：素材下方还有"正常选择 / NORMAL SELECT"文字标签，按整体包围盒裁会把标签也抠进来。
3. **缩放自己做**（预乘 → 盒式平均 → 解预乘）：sharp/vips 对带 alpha 的 resize 是否预乘没有可靠约定，
   实测直接把结晶"乘暗"了（平均亮度掉到 100 出头）。
4. **`fit: contain` 的补边默认是不透明黑**（`background` 默认 alpha=1）⇒ 图上会多出一条黑条，必须显式给全透明。
   （这条与上一条是我第一次出图时纸面上一眼看见的两个问题。）
5. **洞必须保住**：包围盒内 44–57% 的像素是背景（机械手拇指与食指之间的洞、各处凹口）。
   按差值做 alpha 天然保住这些洞（洞里的像素与背景一致 ⇒ 透明），**不要做"填洞"**。站主专门提醒过这一点。

### 13.2 不做剩下的（15 个，逐条给理由 —— 站主要加随时说）

- **帮助选择 / 个人选择 / 位置选择**：站上没有"帮助 / 用户 / 定位"这类可点对象。
- **后台运行（忙）**：站点没有超过 1 秒的异步等待（评论提交走本机 Worker，很快）。
- **移动 / 垂直调整 / 水平调整 / 对角调整一·二**：站上没有任何可拖拽、可拉伸的东西。
- **手写**：没有画布输入。
- **候选**：没有输入法候选场景。
- **不可用（两个）**：只在"评论提交中"出现一瞬；`cursor:default`（系统箭头）已经表达了"这里没得点"，
  不值得为它再多两张位图。

### 13.3 机制（零 JS，刻意不走"JS 跟手"那套）

1. **CSS `cursor: url(...) <热点>, <关键字兜底>`**：热点 = 结晶刀刃尖端 `2 2` / I 型正中 `16 16`。
   **必须带兜底关键字** —— 图没加载或被拦时光标不能整个消失（有断言守着）。
2. **文字上用主题 I 型**（`--cursor-text`），元素清单：`p / li / h1-h6 / code / pre / textarea / input[type=text…]`。
   实现上用 `:where()` 包起来（特异性 0），这样链接/按钮靠"元素自身声明 > 继承"自然取胜、与顺序无关；
   并且**不写 `.prose *`** —— 后代选择器会把正文里的链接一起按成 I 型。disabled 控件保留系统 `default`。
3. **不用 SVG 光标**：Safari 直接忽略 SVG；位图出两档 —— **主图 64×64**（清晰）+ **兜底 32×32**（Safari 的上限），
   两个 url 各带自己的热点，最后再跟关键字。Chrome/Edge 取 64、Safari 取 32、都失败落回系统光标（实测 Chrome
   会把三级链原样保留在计算值里，说明链表达有效）。
   （HiDPI 双倍图没有别的出路 —— `image-set()` 不适用于 cursor。）
4. **不做"JS 跟随的 div 光标"**：那要 `pointermove` 每帧改 transform（性能、延迟、可访问性都更差），
   CSS 光标是原生延迟、零 JS、不占首页那 7168 B 预算。
5. **素材**：真源是 `assets/cursors-source/{normal,link}.png`（站主给的参考图，进仓库）+ 生成器里的矢量 I 型；
   `scripts/gen-cursors.mjs` 产出 6 张位图到 `public/cursors/`（gitignore，构建/开发前生成）
   **并生成 `src/styles/cursors.css`（三个 token，Base.astro 引入）**。
   `--check` 两侧冒烟：同步 exit 0、改一字节 exit 1、token 文件一致性一起查。
7. **URL 必须带内容指纹 `?v=<sha1 前 8 位>`**（token 之所以要"生成"就是为了这个）：
   光标图文件名固定、内容会变（本站从手画稿换成过抠图稿），而浏览器按 URL 缓存图片 ⇒
   不带指纹时站主刷新后取到的还是旧图，看起来就是"**跟上次没变化**"（2026-09-26 实际发生）。
   指纹写进查询串后：图一改 URL 就变，浏览器必然重取；热点也由生成器一起写，不会与图片漂移。
   断言从"三条 token 有指纹"升级成"**产物 CSS 里每一条 `/cursors/` 引用都带指纹**"——防的是整类漂移。
6. **白结晶 + 深描边**：原版是深底网页上的纯白结晶（无描边），本站是**纸白底** ⇒ 直接照搬会看不见。
   抠图时给每个图形补一圈 **1px 深色描边（`--ink`，透明度 0.6）**并轻微提亮（幂曲线 0.72）。
   描边要薄 —— 厚了会把结晶压成"灰贴纸"（第一版就是 0.85 的 3×3 膨胀，太沉）。
   阴影不做烘焙：本体自带的软阴影已被方向分流排除，靠描边保证两边背景都读得出来。

### 13.4 验证

- **静态**（`tests/build-output.test.ts`）：三条 `cursor` 声明必须是**三级链**（主图 url+热点 → 32 兜底 url+热点 → 关键字）；
  六张位图必须存在且尺寸对（主图 64、兜底 32）并带 alpha（直接读 PNG 的 IHDR）；**扫描 29 个源文件**，
  禁止任何裸 `pointer` 之类声明 —— 那是 (0,1,0) 特异性、会顶掉主题光标（本轮已经踩到 **5 处**：
  prose、comments×2、相册×2，外加生成的开场 CSS 里我自己写的 `.boot-skip{cursor:pointer}`）。
- **生成器两侧冒烟**：`node scripts/gen-cursors.mjs --check` 同步 exit 0；故意改一字节 exit 1；
  重新生成后 6/6 一致（抠图用的是自己写的预乘盒式平均 ⇒ 可复现）。
- **浏览器级**（`_tmp-cursor-computed.mjs`，**16 条全 PASS**）：首页 / 文章页 / 相册页逐元素读
  `getComputedStyle().cursor` —— 页面底与控制台标签 = 正常选择、正文与标题与 textarea = 主题 I 型、
  按钮与链接 = 链接选择，以及**正文里的外链仍是链接选择**（没被 `.prose` 压成 I 型）。
- **人眼复核**：系统光标**拍不进截图**（CDP 截图不含鼠标指针），所以单独做对照页
  （1×/8×/4×，纸面与深底两种背景）→ `_tmp-boot-shots/cursor-review.png`；抠图过程中另有一张
  `matte-review.png`（原图与抠图并排 + 深底验洞），逐张看过。**深底那张就是"洞有没有被填"的判据**。
