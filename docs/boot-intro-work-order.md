## 0. 边界（一屏读完）

**做什么**：给**首页**加一段 20.16 s 的一次性开场动画，复刻上游 `LBEILC/RhineLabUI`（MIT）开场的**方法与数值**。

**一句话技术路线**：`1920×1080` 舞台 + 等比缩放，各条轨迹全部写成 **CSS `@keyframes` 百分比停点**（CSS 不占 JS 预算 ⇒ 20.16 s 完整长度放得下，决策 #4）；覆盖层是**装饰**（`aria-hidden`），首页正文照常留在 HTML 里（决策 #21）；JS 只负责三件事（会话标记 / skip / 收尾），目标 <800 B。

## 2. 时间轴总表

**上游基准**：原片 `1920×1080` / **25 fps**；`appTime = 原片时间 − 5`；播放起点 `app 1.76 s`（= 原片 6.76 s）；总长 **20.16 s**（`src/main.ts:1192-1194`、`src/boot-motion.ts:24-26`）。

**帧 ↔ 秒 ↔ 动画百分比**（本工单统一换算）：

```
f        = floor((appTime + 5) × 25)          # 原片帧号
appTime  = f / 25 − 5                          # 秒
p%       = (f − 169) / 504 × 100               # 本开场动画的进度（169 帧 = 起点，673 帧 = 终点）
delay_s  = (f − 169) / 25                      # 给逐字 span 用的绝对延迟
```

## 4. 落到 CSS 的写法

### 4.1 帧 → 百分比停点

```
p% = (f − 169) / 504 × 100        # §2 已给公式与常用帧表
```

每条轨迹一张 `@keyframes`，把 §3 的关键帧逐点写成 `p% { … }`。**段与段之间没有 `animation` 嵌套**：每个元素一条独立的、`animation-duration: var(--dur-boot)`、同一时间原点的动画（各自 `animation-delay` 为 0，靠 `%` 定位），这样"某条轨迹改了帧点"不会牵动别的元素。

**缓动**：一律 `linear`（上游的空间位移是单调三次 Hermite 保速插值；用 `linear` + 密集停点比 `ease` 更接近，见 §8 风险 5）。闪切/二值量用 `steps(1, end)`（§4.6）。

### 4.2 容器、堆叠、锁滚动、收尾

```
<div class="boot" data-boot-overlay>          ← 覆盖层根（唯一顶层元素，便于断言与整体移除）
  <div class="boot-deco" aria-hidden="true">  ← ★ 装饰子树：aria-hidden 只包在这里
      … 全部动画元素 …
  </div>
  <button class="boot-skip" type="button" aria-label="跳过开场">SKIP ↗</button>   ← ★ 按钮是 .boot-deco 的**兄弟**
</div>
```

- **`aria-hidden` 不能包住可聚焦元素**（`#16` 要求在覆盖层里放真按钮）⇒ 装饰层与按钮必须是**兄弟**。这是本工单最容易踩的 a11y 坑。
- **类名冲突**：`base.css:47-58` 已经占了 **`.skip`**（"跳到正文"链接）。开场按钮**必须**用 `.boot-skip` 之类的名字，**不要**照抄上游的 `.skip` —— 否则会继承 `left:-9999px` 那套。
- **挂载点**：新组件 `src/components/BootIntro.astro`（结构 + 组件内 `<style>`），由 `src/pages/index.astro` 在 `<Base>` 默认槽的**最前面**引入（紧跟现有门控脚本之后）。落在首页 ⇒ 其余 14 页产物不受影响（与 B2 的"只落首页"同一手法）。
- **堆叠**：`position:fixed; inset:0; z-index:60`（首页现有：装饰 0 < 正文 1 < 扫描带 2 < 刻度尺 3 < HUD 4 < OS 条 5；base.css 的 `.skip` 跳转链接是 99，保持在其下）。
- **门控（fail-safe，方向与站上既有口径一致）**：

```css
html:not(.boot-on) [data-boot-overlay] { display: none; }   /* 默认不显示 */
html.boot-on      [data-boot-overlay] { display: block; }
html.boot-on      { overflow: hidden; }                     /* 锁滚动 */
@media (max-width: 767px)   { [data-boot-overlay] { display: none !important; } }  /* Q3 */
@media (prefers-reduced-motion: reduce) { [data-boot-overlay] { display: none !important; } } /* #6 */
```

  只有 JS 明确判定"该播"才加 `boot-on`。于是"无 JS / reduced-motion / 小屏 / 本会话已播 / JS 抛错"五种情形**全都自动安全**（覆盖层根本不渲染，动画也不创建）。
  门控脚本仍在**覆盖层之前**同步执行（沿用现有 `<script is:inline>` 的位置），因此不会有"先闪一下覆盖层再隐藏"。
  **必须保留 `classList.add('js')` 字面**：`tests/b2-motion.test.ts:63-66` 靠这个字符串断言"门控脚本只出现在首页"。
- **`--dur-boot: 20160ms`** 与 **`--dur-boot-out: 400ms`** 放 `src/styles/tokens.css` 动效段（设计决定，进 token）；其余全部数值硬编码在组件的 `@keyframes` 里（理由见 §4.4）。
- **收尾（#7 #9）**：
  1. 覆盖层里放一个 **0 尺寸的"时钟"元素** `.boot-clock { animation: boot-total var(--dur-boot) linear both; }`（`boot-total` 是一条什么都不改的空动画，只用来定时）。
     **为什么需要它**：子元素动画结束时的 `animationend` 会**冒泡**到覆盖层根，若直接监听根节点会在 0.7 s 处误触发收尾（水印/打字那几条先结束）。`animationend` 必须判 `e.target` 是时钟元素。
  2. `animationend`（时钟）→ 给根加 `.boot-out`（`transition: opacity var(--dur-boot-out)`）→ `transitionend` → `remove()` + `document.documentElement.classList.remove('boot-on')` + **焦点交回主标题**。
  3. **焦点交回**：`#16` 要求交回主标题。首页 `<h1 class="display">` 默认不可聚焦 ⇒ 给它加 `tabindex="-1"`（首页一处属性改动，属视觉层的最小必要改动），跳过/播完时 `h1.focus()`。**顺序**：先 `focus()` 再 `remove()`（反过来会先失去焦点节点、焦点掉到 `<body>`）。
  4. **播放标记**：进入播放**时**就写 `sessionStorage.setItem('boot-intro','1')`（刷新不再重播，`#6`）；skip 也写（`#16` 不要重播）。`sessionStorage` 调用必须 `try/catch`（无痕/禁用会抛）。

### 4.3 圆环类几何怎么用纯 CSS 表达（本节是实现成败的关键）

`@keyframes` **不能改 SVG `path` 的 `d`**，所以不能照抄上游"每帧算 `arc()` 拼 d"。但 §3.4 的所有轨迹都能拆成三个**可动**的量：

| 上游量 | 纯 CSS 等价物 |
|---|---|
| 半径 `r` | `transform: scale(r)`（圆心不动 ⇒ 等比缩放等价） |
| 起始角 `start` | `transform: rotate(start)` |
| 弧长 `sweep` | `stroke-dasharray`（配 `pathLength="1"` 归一化，与半径无关） |

具体做法：

```html
<circle class="arc arc-outer" r="1" pathLength="1" />
```
```css
.arc { fill:none; transform-box: view-box; transform-origin: 960px 540px; }
@keyframes arc-outer {
  63.0952% { transform: rotate(470deg)  scale(2000); stroke-dasharray: 0.0833 1; }  /* 30°/360° */
  …
  100%     { transform: rotate(-90deg)  scale(246);  stroke-dasharray: 1 1; }
}
```

- `pathLength="1"` ⇒ **dash 值以"周长=1"计**，与当前 `scale` 无关：弧长比例 = `sweep/360`，起始偏移 = `-start/360`（用 `stroke-dashoffset`，或把 `start` 折进 `dashoffset`）。`sweep = 360°` 时 `1 1` 自然是整圆，**不需要上游那段 2π 特判**。
- 半径变化 2000→246 用 `scale` 一步到位；`rotate` 用**展开角**（外环 470→−90、白环 −100→270、内环 −20→201.5，正是 §3.4 的原值，直接用）。
- **两侧小圆**（自己的圆心也在动）用三层嵌套，各自只动一个属性：
  `<g class="side-pos">`（`transform: translate(x,y)`，26 点）→ `<g class="side-arc">`（`rotate(start)`）→ `<circle>`（`scale(radius)` + `stroke-dasharray: sweep/360`）。
- **橙点 / 卫星点 / 黑白弧端圆点**：`<g class="orbit">`（`rotate(θ) translateX(R)`，一条 keyframes 同时动两个函数）→ `<circle>`（`r` 另一条）。卫星的相位差用每条点自己的静态 `rotate(i·60°)` 包裹层，生长曲线**逐颗一条绝对时间轴规则**（起点 548+3i 帧，`dotGrowth` 的 11 点）—— **全部零 JS**。
- **中央大点**：`<circle>` 的 `scale(coreRadius)`；闪变帧（546/547/549/550）就是 42.93 → 42.43 之间的 4 个停点，用 `steps(1,end)` 表达"整帧跳变"。
- **不动的 `stroke-width`**：`stroke-width` 在缩放过的 `<g>` 里会被一起放大 ⇒ **必须把描边画在没被 scale 的元素上**，或接受放大后的视觉（上游的 `stroke-width:2.4/4` 是在**未缩放**的 path 上、半径靠 `d` 变化 ⇒ 描边粗细恒定）。**推荐**：内层再套一个 `<g class="unscale">` 用 `scale(1/r)` 抵消 —— 但 `r` 在动，抵消也要动 ⇒ 更省事的做法是**接受描边随半径缩放**，只在人眼复核（B-6）里确认观感；若不可接受，最后手段是允许**极少量** JS 逐帧写 `stroke-width`（但这会占 JS 预算，与 #20 冲突）⇒ **本工单选择"接受缩放"，并在 §8 记为已知偏差**。
- **Logo 轮廓**：`pathLength="1"` + `stroke-dasharray: "length 1−length"` + `stroke-dashoffset: −start`（§3.2 的 34 行直接写进 keyframes）；`stroke-width` 6 点直接动 `stroke-width`（**它是 CSS 可动画属性**，不需要额外技巧）。
- **`transform-box: view-box` + `transform-origin` 用舞台坐标**（`960px 540px` / 各小圆自己的圆心）：这是 SVG 里做 `rotate/scale` 的唯一稳妥写法，别用默认的 `fill-box`。
- **`filter: blur()`** 只用在两处（跳变帧 2.2px、退场 8px），符合站上"不动 layout、只动 paint"的既有口径。

### 4.4 token 与硬编码的分界

| 类别 | 去处 | 理由 |
|---|---|---|
| 开场总时长 `20.16s`、交棒淡出 `400ms` | **进 `tokens.css`**：`--dur-boot: 20160ms` / `--dur-boot-out: 400ms` | 是**设计决定**，且断言要按名字查（§6.1-S5） |
| 颜色 | 复用现有 token（`--ink` `--paper` `--on-band` `--code-bg`）；确需新色（欢迎黑底 `#080a08`、背景 `#e7e7e1` 三停点）→ 加进 `tokens.css` 的**装饰段**，用 8 位 hex 承载 alpha 的既有做法，**不进对比度断言表**（覆盖层 `aria-hidden`、纯装饰），但注释里要写清"为什么安全" | `tokens.css:86-92` 的既有约定 |
| **全部轨迹数值、帧→% 停点、几何 px、字号、字距** | **硬编码在组件里**，每条注明来源（`上游文件:行`） | 它们是**测量数据**，不是设计决定 —— 把测量值做成可主题化的 token 没有意义，反而会让"改主题"误伤测量结果 |
| 舞台尺寸 `1920×1080` | 硬编码（缩放比用 `min(calc(100vw / 1920px), calc(100dvh / 1080px))` 算，除数**必须带单位**） | 同上 |

**样式落点**：`BootIntro.astro` 的组件内 `<style>`（Astro 会把它并进共享 CSS 文件，但只有首页引用它 ⇒ 其余页面的 HTML 不受影响）。**不要**往 `tokens.css` 里塞轨迹数值。

**`typed()` 的等价公式**（照抄语义，别用上游的 `slice`）：


### 4.6 硬切与闪切

- 二值量（`accessOpacity`、`logoOpacity`、`authOpacity`、`scanVisible`、`companyVisible`、`databaseOpacity`）在停点处用 `steps(1, end)`，或在相邻两个 `%` 上直接写 `0 / 1`（间隔 ≥1 帧 = 0.1984 %，比任何插值都"硬"）。
- 7 帧闪切（569–575）与 4 帧跳变（525/526/528/529）：每个帧点一个 `%` 停点，**不插值**（值本身就是整帧跳变量）。
- **这就是 #15 里那条"`steps(1)` 硬切闪"**：不是指某个具体动画，而是这套"整帧跳变不做补间"的表达纪律。

### 4.7 舞台缩放与小屏

```css
/* 实现里的最终形式：除数**必须带单位**（见 §11 坑 2，实测确认过） */
.boot-deco { position:absolute; left:50%; top:50%; width:1920px; height:1080px;
             transform: translate(-50%,-50%) scale(min(calc(100vw / 1920px), calc(100dvh / 1080px)));
             transform-origin: 50% 50%; }
```
- **背景与白场不在舞台上，而是铺满视口**（`.boot-bg` / `.boot-white` 是覆盖层根的直接子元素）：16:9 舞台在 16:10/手机竖屏等视口上会留缝，缝里会漏出首页的 HUD / OS 状态条。上游的生产行为也是「正常入场铺满实际视口，只有逐帧对照才用固定 1920×1080 舞台」——**只有图形留在舞台上**，所以 #8 的数值照抄不受影响。
- 用 `100dvh` 而不是 `100vh`（移动端地址栏收放会导致 `vh` 抖动）——虽然 ≤767px 不播，但平板/异常视口仍走这条路径。
- `#8` 的数值照抄前提是"1920 基准 + 等比"；小屏不播（Q3）后，这条只服务 ≥768px 的视口（该档最小 scale ≈ 768/1920 = 0.4 ⇒ 18px 实渲染约 7.2px；平板横屏 scale≈0.53 ⇒ 9.5px）。**站主 2026-09-26 审定时定：768–1024 照播，断点维持 767px**；实测截图（B-10 覆盖 768×1024 一档）作为记录，若日后觉得小字不够看再单独决定提断点。

## 8. 风险与不确定

1. **代码 vs 文档的四处冲突**（§3.0 已列）——一律以代码为准；**别拿勘察报告的数值表直接开工**（那张表取自被覆盖的早期 CSS）。
2. **"保速插值"会退化成"分段线性"**（`#4` 已接受）：视觉接近但不等于上游。兜底 = B-5 抽 12 帧 + B-6 的人眼抽检帧。
3. **20.16 s 首屏对 LCP/SEO 的处置**（交接 §4 点名要处置的）：
   - **SEO 不受影响**：覆盖层 `aria-hidden` 且是纯装饰，正文一个字都在 HTML 里（`#21`，由 S4 守）。
   - **LCP 必须实测、不能用推断代替**：构建后跑一次 Lighthouse（本地 preview 或线上），把 FCP/LCP/TBT/CLS 与当前 100/100/100/100 的基线并列记录。若 LCP 恶化到 >2.5 s，前滚修复的备选（按代价排序）：① 让覆盖层首帧先画"轻量白场"而不是大块黑底渐变；② 只对首访播（已经是）；③ 把首访的 `welcome` 段白场提前。
   - **"首屏 20 s 不可用"是站主已知情的选择**（`#5` 不缩短，因为有 skip）；缓解 = skip + Esc + 会话一次 + reduced-motion 不播 + 小屏不播。
4. **窄屏可读性**：已按 Q3 决定 **≤767px 不播**；**768–1024 照播**（站主 2026-09-26 审定时定，断点维持 767px）。该区间 scale 0.4–0.53 ⇒ 18px 正文实渲染 7–9.5px、权限字 26.5px→10.6–14px —— **已知偏小、已接受**；用 B-10 的 768×1024 档截图记录实际观感，日后要提断点再单独决定（提断点不影响任何数值）。
5. **覆盖层与 B2 入场的关系**：已按 Q2 决定"B2 照常播、被盖住"⇒ 交棒瞬间首页是稳态。**已知代价**：首访看不到 B2 那 4 条入场（老访客/无 JS/小屏/reduced 反而看得到）。这是有意的取舍，别在实现时"顺手"加耦合。
6. **`animationend` 冒泡**：子元素动画的结束事件会冒泡到根 ⇒ 收尾必须挂**专用时钟元素**并判 `e.target`（§4.2）。这是本节最容易写错的一处。
7. **`preserveAspectRatio` 差异**：我们的标志 viewBox 比例（2.0）与槽位 296×177（1.67）不同 ⇒ 实际绘制区 296×148；截图里若"标志与字的相对高度"不对味，微调槽位高度（不动帧点）。
8. **描边随缩放变粗**（§4.3 末条）：环的 `stroke-width` 在 `scale(r)` 里会一起缩放。**本工单选择接受**（避免为它引 JS），在 B-6 截图里确认；若不可接受，另开一轮讨论（代价是破 `#20` 或改用更复杂的"反向缩放层"）。
9. **CSS 体积与落位（已按 §10-9 实现，下面是最终实测值）**：生成结果 = **79 条 `@keyframes` / 56,595 字节**（原估 4–8 KB，错了约 8 倍 —— 停点数近 1300 而不是"约 200"）。落位方案已按建议改为"生成 `src/styles/boot.css`（gitignore）+ 组件 import"（`scripts/gen-boot-css.mjs`，`npm run build` / `dev` 前置调用；`--check` 是它的两侧冒烟路径）：

   | 指标 | 基线 | 现在 | 增量 |
   |---|---:|---:|---:|
   | `index.html` raw | 13,326 B | 24,288 B | **+10,962** |
   | `index.html` gzip | 4,533 B | 6,677 B | **+2,144** |
   | `_astro/*.css` 合计 raw | 28,372 B | 80,248 B | +51,876 |
   | `_astro/*.css` 合计 gzip | 6,989 B | 17,265 B | **+10,276** |
   | 首屏 html+css（gzip） | 11,522 B | 23,942 B | +12,420 |

   **关键性质**：那 51 KB 只在**首页**的 CSS 里（实测 14 个其它页面对开场 CSS 的引用数 = 0、`boot-` 字串数 = 0），所以文章页/相册页的预算一点没动。
   **对照**：内联方案实测 `index.html` +61,200 raw / +13,418 gzip，且 `is:global set:html` **同样不抽离** —— 所以"落成真实 .css"这一步是必须的，不是优化。
   **首次访问的 gzip 增量 ≈ +12.4 KB 省不掉**（要省只能砍停点 = 砍保真）；换来的是一次性开场、且只对首页。
   HTML 侧：+95 个逐字 span + 覆盖层结构 ≈ 10 KB raw（gzip +2.1 KB）——已验证"摘掉覆盖层后正文与基线逐字节相同"（§11）。
10. **a11y 两条**：① `aria-hidden` 子树内不得有可聚焦元素 ⇒ skip 按钮必须是**兄弟**；② 开场抢焦点会改变键盘用户的起点 ⇒ 交回 `h1[tabindex="-1"]`。另外**不要**给覆盖层加 `role="dialog"`/`aria-modal`（它不是对话，是装饰；加了反而要处理焦点陷阱）。
11. **命名冲突**：`base.css` 已占 `.skip`（跳到正文）⇒ 开场按钮用 `.boot-skip`。上游的 `.boot`/`.brand`/`.powered` 类名在我们站上**不冲突**（首页没有同名类），可以照用；但 `.brand` 与 `Band.astro` 的 `Brandline` 无关，别混。
12. **`sessionStorage` 异常**（无痕/策略禁用）：`try/catch`；写失败就退化成"可能重播一次"，不影响可用性。
13. **reduced-motion 的全局压平**（`base.css:60-67` 把 duration 压到 `0.01ms`）：若靠 `animationend` 收尾，在 reduced 下会立刻触发。我们已按 §4.2 走 `boot-on` 门控（reduced 下根本不加类 ⇒ 覆盖层不渲染、动画不创建），所以这条只是"别改成依赖事件"的提醒。
14. **上游 Logo 坐标空间换算**（§3.2）：终值已对齐我们现有 symbol（2.2/1.8），但**中间停点是我们按比例算的近似**，必须人眼复核一次。

**这一整轮踩到并已修掉的坑（别再踩）**：

1. **`set:html` 的模板字符串里不能用反引号** —— 注释里写 `` `.boot-deco *` `` 会把模板字符串提前截断，报的是 `deco is not defined` 这种看不出因果的错。**这轮栽了三次**，每次都是构建期才炸。
2. **`scale()` 的参数必须是纯数**：`calc(100vw / 1920)` 求出来是**长度** ⇒ 整条 transform 被丢掉（实测 computed = none，舞台既不居中也不缩放 = 覆盖层根本没盖首页）。要写 `calc(100vw / 1920px)`（长度/长度 = 数，已实测确认；`/1920` 与 `*0.00052` 都非法）。
3. **通配 `.boot-deco *{position:absolute}` 比单类选择器更具体** —— 想要 `relative`/正常流的必须带 `.boot-deco` 前缀（品牌三行与 `OS` 就是这样叠在一起的）。
4. **同一元素的多条动画必须写在一条 `animation` 里** —— 分两条规则写，后一条 shorthand 会把前一条整体覆盖。
5. **别用 `animation-delay` 做错峰**：那会让被延迟的元素落到"相对自己的时间轴"上，"把整层 seek 到某一帧"就不成立了（截图验收到 268 帧会看见本该 278 帧才入场的文字）。改成"每行/每颗一条绝对时间轴规则"后，一个 `currentTime` 值 = 一个绝对帧 ✓。
6. **连续多帧保持同一个值时，keyframes 段的两端都要打点** —— 只打起点会被线性插值出中间值（595 帧读出 0.825 而不是 0.65；DATABASE 的 627/629/633 三个段末也会漏）。逐帧二值量最好按"值变化的帧 + 每段末帧"生成，别手写。

### 13.1.1 抠图的四个要点（都踩过）

1. **按方向分流做 alpha**：素材里的**软阴影**不能一起抠进来。白面与阴影"与背景的差值"区间重叠（白面 Δ≈26、阴影 Δ≈5–20），
   单靠差值分不开 ⇒ 比背景亮的低阈值就保留（结晶主体），比背景暗的必须够暗（Δ>22）才算折面棱线，浅的判为背景。
2. **只取最上面那条墨带**：素材下方还有"正常选择 / NORMAL SELECT"文字标签，按整体包围盒裁会把标签也抠进来。
3. **缩放自己做**（预乘 → 盒式平均 → 解预乘）：sharp/vips 对带 alpha 的 resize 是否预乘没有可靠约定，
   实测直接把结晶"乘暗"了（平均亮度掉到 100 出头）。
4. **`fit: contain` 的补边默认是不透明黑**（`background` 默认 alpha=1）⇒ 图上会多出一条黑条，必须显式给全透明。
   （这条与上一条是我第一次出图时纸面上一眼看见的两个问题。）
5. **洞必须保住**：包围盒内 44–57% 的像素是背景（机械手拇指与食指之间的洞、各处凹口）。
   按差值做 alpha 天然保住这些洞（洞里的像素与背景一致 ⇒ 透明），**不要做"填洞"**。站主专门提醒过这一点。

### 13.2 不做剩下的（15 个，逐条给理由 —— 站主要加随时说）

- **帮助选择 / 个人选择 / 位置选择**：站上没有"帮助 / 用户 / 定位"这类可点对象。
- **后台运行（忙）**：站点没有超过 1 秒的异步等待（评论提交走本机 Worker，很快）。
- **移动 / 垂直调整 / 水平调整 / 对角调整一·二**：站上没有任何可拖拽、可拉伸的东西。
- **手写**：没有画布输入。
- **候选**：没有输入法候选场景。
- **不可用（两个）**：只在"评论提交中"出现一瞬；`cursor:default`（系统箭头）已经表达了"这里没得点"，
  不值得为它再多两张位图。

### 13.3 机制（零 JS，刻意不走"JS 跟手"那套）

1. **CSS `cursor: url(...) <热点>, <关键字兜底>`**：热点 = 结晶刀刃尖端 `2 2` / I 型正中 `16 16`。
   **必须带兜底关键字** —— 图没加载或被拦时光标不能整个消失（有断言守着）。
2. **文字上用主题 I 型**（`--cursor-text`），元素清单：`p / li / h1-h6 / code / pre / textarea / input[type=text…]`。
   实现上用 `:where()` 包起来（特异性 0），这样链接/按钮靠"元素自身声明 > 继承"自然取胜、与顺序无关；
   并且**不写 `.prose *`** —— 后代选择器会把正文里的链接一起按成 I 型。disabled 控件保留系统 `default`。
3. **不用 SVG 光标**：Safari 直接忽略 SVG；位图出两档 —— **主图 64×64**（清晰）+ **兜底 32×32**（Safari 的上限），
   两个 url 各带自己的热点，最后再跟关键字。Chrome/Edge 取 64、Safari 取 32、都失败落回系统光标（实测 Chrome
   会把三级链原样保留在计算值里，说明链表达有效）。
   （HiDPI 双倍图没有别的出路 —— `image-set()` 不适用于 cursor。）
4. **不做"JS 跟随的 div 光标"**：那要 `pointermove` 每帧改 transform（性能、延迟、可访问性都更差），
   CSS 光标是原生延迟、零 JS、不占首页那 7168 B 预算。
5. **素材**：真源是 `assets/cursors-source/{normal,link}.png`（站主给的参考图，进仓库）+ 生成器里的矢量 I 型；
   `scripts/gen-cursors.mjs` 产出 6 张位图到 `public/cursors/`（gitignore，构建/开发前生成）
   **并生成 `src/styles/cursors.css`（三个 token，Base.astro 引入）**。
   `--check` 两侧冒烟：同步 exit 0、改一字节 exit 1、token 文件一致性一起查。
7. **URL 必须带内容指纹 `?v=<sha1 前 8 位>`**（token 之所以要"生成"就是为了这个）：
   光标图文件名固定、内容会变（本站从手画稿换成过抠图稿），而浏览器按 URL 缓存图片 ⇒
   不带指纹时站主刷新后取到的还是旧图，看起来就是"**跟上次没变化**"（2026-09-26 实际发生）。
   指纹写进查询串后：图一改 URL 就变，浏览器必然重取；热点也由生成器一起写，不会与图片漂移。
   断言从"三条 token 有指纹"升级成"**产物 CSS 里每一条 `/cursors/` 引用都带指纹**"——防的是整类漂移。
6. **白结晶 + 深描边**：原版是深底网页上的纯白结晶（无描边），本站是**纸白底** ⇒ 直接照搬会看不见。
   抠图时给每个图形补一圈 **1px 深色描边（`--ink`，透明度 0.6）**并轻微提亮（幂曲线 0.72）。
   描边要薄 —— 厚了会把结晶压成"灰贴纸"（第一版就是 0.85 的 3×3 膨胀，太沉）。
   阴影不做烘焙：本体自带的软阴影已被方向分流排除，靠描边保证两边背景都读得出来。

### 13.4 验证

- **静态**（`tests/build-output.test.ts`）：三条 `cursor` 声明必须是**三级链**（主图 url+热点 → 32 兜底 url+热点 → 关键字）；
  六张位图必须存在且尺寸对（主图 64、兜底 32）并带 alpha（直接读 PNG 的 IHDR）；**扫描 29 个源文件**，
  禁止任何裸 `pointer` 之类声明 —— 那是 (0,1,0) 特异性、会顶掉主题光标（本轮已经踩到 **5 处**：
  prose、comments×2、相册×2，外加生成的开场 CSS 里我自己写的 `.boot-skip{cursor:pointer}`）。
- **生成器两侧冒烟**：`node scripts/gen-cursors.mjs --check` 同步 exit 0；故意改一字节 exit 1；
  重新生成后 6/6 一致（抠图用的是自己写的预乘盒式平均 ⇒ 可复现）。
- **浏览器级**（`_tmp-cursor-computed.mjs`，**16 条全 PASS**）：首页 / 文章页 / 相册页逐元素读
  `getComputedStyle().cursor` —— 页面底与控制台标签 = 正常选择、正文与标题与 textarea = 主题 I 型、
  按钮与链接 = 链接选择，以及**正文里的外链仍是链接选择**（没被 `.prose` 压成 I 型）。
- **人眼复核**：系统光标**拍不进截图**（CDP 截图不含鼠标指针），所以单独做对照页
  （1×/8×/4×，纸面与深底两种背景）→ `_tmp-boot-shots/cursor-review.png`；抠图过程中另有一张
  `matte-review.png`（原图与抠图并排 + 深底验洞），逐张看过。**深底那张就是"洞有没有被填"的判据**。

## 14. 跟手光标环 + 点击涟漪（2026-09-26，站主给的参考实现）

## 15. 跟手光标形态修订（2026-09-26，站主两条指令）

> §14 的形态（细绿圆环）已被本节取代：现在是指针处的**白色中心点 + 半透明圆盘**，原生光标隐藏。

### 15.1 涟漪为什么会"往右下角飞"（先复现，再修）

**实测复现**：点击 (500,300)，涟漪圆心连续采样 = `628,373 → 957,561 → 1094,639 → 1136,663 → 1152,672`。
**根因**：`scale` 被写成了**独立属性**（`@keyframes { scale: 2.4 }`）。它与 `transform` 里的
`translate3d(x,y,0)` 合成时，**位移被一起放大约 2.4 倍** ⇒ 圆心 ≈ 位置 × scale（500 × 2.4 ≈ 1200，与实测 1152 对得上）。
**修法**：位置挪进 CSS 变量 `--x/--y`，把 `scale()` 写进**同一串 transform**
（`translate3d(var(--x),var(--y),0) translate(-50%,-50%) scale(…)`）⇒ 合成顺序唯一，圆心不动。
修后同一采样：**5 帧全部 (500,300)**（±2px），且直径仍从 68 扩散到 163 ✓。
这条已进探针 ④b —— **是一条能对这个 bug 变红的回归网**（不是"看着对"）。

### 15.2 形态：白色中心点 + 半透明盘

| 元素 | 形态 | 说明 |
|---|---|---|
| 点 `.cr-dot` | 8px 白点 + 发丝深边 | **不缓动** —— 它就是指针本身（实测精确到 ±1px） |
| 盘 `.cr-disc` | 34px，缓动跟手；悬停可点元素缩到 22px、描边转绿 | |
| 涟漪 `.cr-ripple` | 68px 白环，在点击处扩散淡出 | |
| 层级 | 点 66 / 盘 65 / 涟漪 64 | **都在开场覆盖层（60）之上**：原生光标已隐藏，指针标记必须始终可见（§14 藏在开场层下面的做法在这一版不成立了） |
| 原生光标 | `cursor:none`，但由 **JS 加类**（`html.cursor-none`） | 脚本没跑就不加 ⇒ 站上三件套光标仍是兜底，**不会出现"没有光标"** |

**与站主参考图必须不同的一处**：参考图是深底上做的，白盘白点都清楚；本站是**纸白底**，
白盘在白底上看不见、白点也会消失 ⇒ 盘改用**极淡墨色纱**（`rgb(26 26 26 / 8%)`）以保持"盘比点暗"的关系，
点加一圈发丝深边。深底上纱几乎不可见、白点自然发光 ⇒ 两边都读得出。
（放大图：`_tmp-boot-shots/cursor-dot-paper.png` 与 `cursor-dot-dark.png`；后者是**合成场景** ——
页面底色临时改成 `#0e0e0e`，因为本站大面积深色只有代码块，而代码块属于文字、会进入让位态。）

**文字上让位（保留站主先前的选择）**：正文/标题/代码/段落仍是主题 I 型光标，此时**点与盘一起隐藏**
（否则白点叠在 I 型上成"双重光标"）。想改成"文字上也一律白点"：把脚本里 `TXT` 那一行的元素删掉即可。

**一处实现教训**：显隐**不要用内联 `style.opacity`** —— 内联会压过样式表里的 `.cr-text{opacity:0}`，
让"文字让位"静默失效（本轮就是这样红了一次）。改用两个类（`cursor-live` 显形 / `cr-text` 让位）由 CSS 定序。

**代价**：内联脚本 **1167 字节**（首页 5163/7168、文章页 3701/4096、相册页 3138/6144）✓

**验证**：`_tmp-cursor-ring-check.mjs` **24 条全 PASS** —— 结构/层级、`cursor-none` 的可控性与文字例外、
白点精确跟手（±1px）、盘缓动收敛、悬停缩小 + 绿边、文字上点盘让位、**涟漪圆心 5 帧不漂**、
reduced-motion 与触摸设备下隐藏且**不加** `cursor-none`。

## 16. 光标最终简化（2026-09-26，站主："把链接选择和文本选择那两个全删了，只留白色中心点"）

### 16.1 删了什么

- **两枚光标全删**：`link.png` / `link-32.png` / `text.png` / `text-32.png`、两条 token（`--cursor-link` / `--cursor-text`）、
  以及抠图源图 `assets/cursors-source/link.png`（生成器里的 TARGETS 也只剩 normal）。
- **5 处 `--cursor-link` 引用**一并删掉（正文代码块按钮、评论按钮、相册筛选与灯箱按钮），
  否则会留下"指向已删 token"的死声明（计算值变 unset，行为不可预期）。
- **"文字让位"整段删掉**：白点现在在任何地方都显形（正文、链接、按钮、输入框一视同仁）。
  ⇒ 代价如实说：**正文里不再有 I 型光标**（"这里能选中"的提示没了，选中本身仍正常）。
  这是站主的明确取舍（页面上只留一个白点），不是疏漏。

### 16.2 这一轮抓到一个真 bug（只有"读计算值"才抓得到）

**现象**：删干净之后，**链接上原生箭头光标仍然在**（与白点并存），而正文、按钮都正常。
**根因**：`cursor:none` 原本写在组件的 `<style>` 里，写成 `html.cursor-none *`。
**Astro 会把组件样式作用域化** ⇒ 编译成 `html.cursor-none [data-astro-cid-…]`，
于是只有本组件那三个元素被隐藏，其余元素只能靠**继承**拿 `none` ——
而链接有 **UA 的 `a{cursor:pointer}`** 声明，元素自身声明压过继承 ⇒ 链接漏网。
**修法**：这条移进全局样式 `base.css`（`html.cursor-none, html.cursor-none *`），
`*` 必须是不带作用域的全局选择器。
**为什么值得记**：当时**静态断言全绿**（它只查"CSS 里有没有 cursor:none"），
只有浏览器里逐个元素读 `getComputedStyle().cursor` 才暴露 —— 又一次印证"能在浏览器里量的，就别只查字符串"。
回归网：探针里加了一条**点名针对 UA 那条规则**的断言（"链接上也必须是 none"）。

### 16.3 兜底仍然保留

`--cursor-default`（正常选择那枚结晶箭头，64 主 + 32 兜底 + 内容指纹）保留，作为
**无 JS / 脚本被拦时的兜底**：`cursor:none` 由 JS 加类，脚本没跑时它接管 ⇒ 不会出现"一个光标都没有"。
线上实测（关掉脚本执行）：html / 控制台标签 / 正文 / 链接**四项都回落到这一枚** ✓。

### 16.4 代价与验证

- 内联脚本从 1167 B 降到 **1027 B**（删掉了 TXT 那套逻辑）：首页 5023/7168、文章页 3561/4096、相册页 2998/6144 ✓
- 静态断言：改成一枚 token + 2 张位图，并**新增两条防残迹**断言 —— 不许残留 `--cursor-text` / `--cursor-link`、
  已删的四张位图不许再出现在产物里 ✓
- 浏览器级：`_tmp-cursor-ring-check.mjs` **25 条全 PASS**（含"链接上也必须是 none"）
- 线上：`_tmp-live-cursor-check.mjs` 全 PASS（有 JS 时全站 none；无 JS 时 html/控制台/正文回落兜底、
  **链接是系统手型** —— UA 的 `a{cursor:pointer}` 是元素自身声明、压过继承，这反而合适，如实记为预期而非 bug）
- **两处探针/断言的自我修正**（都不是产品问题，但值得记）：
  ① "等构建标记"第四次踩坑，且这次是**删除型部署** —— HTML 里没有任何新增元素可当标记，
     只能改用**否定条件**（CSS 里不再有 `--cursor-text` / `--cursor-link` 才算新版本上线）。
     纪律补一句：**删除型部署要用"某东西消失了"当标记。**

     ⇒ 扫描前先剥注释。**文本扫描的通用纪律：先剥注释再扫。**

### 17.2 抠图与体积（这一轮的主要技术点）

- **alpha 按方向分流**（与光标那轮同源）：比背景亮的低阈值就保留（磁带主体是浅色），
  比背景**够暗**才算刻线/轮廓 —— 否则素材自带的那层软阴影会一起抠进来，在页面底色上糊出一块灰。
- **缩放自己做，不用 sharp 的 resize**：实测同一张图
  「不缩放 q70 = **40.1 KB**」而「sharp 缩到 700px q68 = **88.9 KB**」——**缩小反而胖一倍**
  （vips 处理带 alpha 的缩放那个老毛病，与光标那轮同源；矩阵里还测了 q50–q80 都在 38–42 KB，
  说明体积由图像本身的复杂度支配，不是质量参数）。自写预乘降采样后：620px≈42.6、560px≈37.9、480px≈31.7 KB。
- 最终取 **560×452、q64、38.2 KB**（页面按 ≤460 CSS px 显示 ⇒ 1.2×，HiDPI 也够）。

**代价如实说**：这是首页第一屏里**最重的一个资源**（该页首屏 html+css gzip 才 ~24 KB）。
站主要求放它，所以放了；要减就把 §17.3 的 `width` 调小并重跑生成器（改生成器里的 `WIDTH`）。

| 项 | 取值 |
|---|---|
| 位置 | `right: -4vw; bottom: -6vh` —— 像"摆在桌面边上"，不是贴一张图 |
| 尺寸 | `width: min(38vw, 460px)`，`aspect-ratio: 560/452` |
| 透明度 | `0.92`（浅色物件，纸底上本来就轻） |
| 窄屏 | `≤767px` 不显示（手机是纵向长页，右下角会被正文反复压过） |

### 17.4 两条既有约束抓到了我（都是它们该干的事）

1. **"所有图片 alt 非空"**：我第一版写了 `<img alt="">` ✗。装饰图的正确做法不是给空 alt 破例，
   而是**用 CSS 背景**（语义上它就不是内容）⇒ 改成 `<div class="bg-cassette" aria-hidden="true">` +

2. **B3"开场是纯增量"的基线比对**：新背景层让首页 `<main>` 与基线差了 50 字节 ✗（误报 ——

**另一处"先量再写断言"**：窄屏隐藏那条断言我按 `max-width: 767px` 写，实测压缩器会改写成
`@media (width<=767px)` ⇒ 断言改成只认 `767px` 这个数、不写死语法（本轮第三次踩同类坑）。

## 18. 扫描读数改毛玻璃（2026-09-26，站主手机截图："把扫描那个框改成半透明（毛玻璃）的，别挡字"）

### 18.1 症状与根因（先在 390 宽复现，再改）

站主在手机上滚首页时拍到：扫描带的读数**把文章标题中间几行挖掉了**。
按同一场景复现（390×844，把「钢琴八级之后…」滚到扫描带上）后**完全对上**：

- `.band-readout` 的底色是 **`background: var(--paper)`（不透明）** ⇒ 它压在标题上就是把那几行盖死；
- 同一张图里读数内容还**折成了两行**（"扫" / "描：" 都断了行），把标题盖掉大半 —— 因为读数是**整条标题**，
  手机上必然折行。

### 18.2 改法

| 项 | 改成 | 为什么 |
|---|---|---|
| 底色 | `rgb(250 250 247 / 55%)`（压缩后 `#fafaf78c`） | 扫描带固定在视口中央，滚动时**必然**压到正文 ⇒ 底色必须透 |
| 模糊 | `backdrop-filter: blur(7px) saturate(1.05)` | 毛玻璃：底下的字看得出轮廓，读数自己也读得清 |
| 宽度/折行 | `max-width: min(72vw, 52ch)` + `white-space: nowrap`，`b` 上 `text-overflow: ellipsis` | 读数是整条标题 ⇒ 一律单行截断，不再盖掉大半屏 |

改后同一场景：读数一行 + 省略号，标题"钢琴八级之后：我学了那么多东西…"**完整可读** ✓
（对照图 `_tmp-boot-shots/band-readout-before.png` / `-after.png`）。

### 18.3 一处平台差异（如实记）

源码里同时写了 `-webkit-backdrop-filter` 与 `backdrop-filter`，**压缩器按目标浏览器把前缀版裁掉了**
（产物里 `webkit-backdrop` 出现 0 次）。影响：Safari ≤17 只拿到半透明、少一层模糊——
"别挡字"仍然成立（半透明在那），只是没那么"毛"。要连旧 Safari 也毛玻璃，得调 lightningcss 的目标浏览器，
那是全局构建配置、影响面大，本轮不动。

### 18.4 追加：整条扫描带换成"真·透明玻璃"（站主："直接改透明玻璃的样式"）

扫描带上真正的"实体"只有读数那一块（其余是 1px 细线 + 14×7 端帽），所以玻璃化 = 把它那层色去掉、改用玻璃配方：

| 项 | 18.2 的版本 | 18.4 定稿 |
|---|---|---|
| 底色 | `rgb(250 250 247 / 55%)`（纸色板，纸白页面上仍像块"板子"） | `rgb(250 250 247 / 22%)`（几乎不上色，靠模糊分层） |
| 模糊 | `blur(7px) saturate(1.05)` | `blur(12px) saturate(1.2)` |
| 边缘 | 无 | `1px solid rgb(250 250 247 / 45%)` + `inset 0 1px 0 rgb(255 255 255 / 40%)`（上缘高光）—— 玻璃质感的关键 |
| 端帽 `.band-cap` | 实心 `--hair` | 同样玻璃化：`60%` 透白 + `blur(6px)` + 极淡描边 |

产物形态：`background:#fafaf738; border:1px solid #fafaf773; backdrop-filter:blur(12px)saturate(1.2)` ✓
（断言只认"半透明 + 有 backdrop-filter + 单行截断"，不绑定具体数值，所以这轮没改断言。）

**还剩一点重叠，如实说**：读数现在是单行 25px 高、内容是整条标题，它横在标题第一行上时，
两层深色字仍会叠在一起（比"整段被挖掉"好得多，但不算零重叠）。要做到零重叠只有两条路：
① 手机上把这行读数缩得更短或干脆不显示；② 把它挪到右侧空白处。**这两条都属于设计取舍，等站主定。**

## 24. 页面过渡动画（2026-09-27 站主给了完整时间线）

### 24.1 落地的时间线（总 **771ms** 实测，落在站主要求的 0.8–1.0 秒内）

| 时刻 | 站主要求 | 实测（暂停 + 定位后读真实几何） |
|---|---|---|
| 0ms | 全屏毛玻璃蒙版，blur(15px) | `backdrop-filter: blur(15px) saturate(1.05)`；两块蒙版合拢盖满视口（上 0→455，下 446→900） |
| 150ms | 第二阶段介入、与①交叠 | 模糊已降到 `blur(4.73px)`；**线宽仍是 0**（轴线 150ms 才起步） |
| 300ms | ① 结束 | 模糊 `blur(0px)`（对焦完成）；线宽 **1277px**（几乎抽满） |
| 400ms | ③ 开始 + ④ 开始 | 蒙版仍合拢；内容 `opacity .55 / scale .98` 起步 |
| 500ms | ③ 前 100ms 极快 | 上蒙版底边已从 455 冲到 **68**（86% 位移在这 100ms 里完成）；内容已到 `.86 / .994` |
| 600ms | ④ 结束（与③并行、无错落） | 内容 `opacity 1 / scale 1` |
| 800ms | ③ 结束 | 蒙版完全离场（上底边 0 / 下 top 900）、轴线 opacity 0 |

缓动全部按要求：①`ease-out` ②`cubic-bezier(0.16,1,0.3,1)` ③`cubic-bezier(0.1,0.9,0.2,1)`（前 100ms 极快、后 300ms 减速）④`ease-out`；
位移/缩放只用 `transform`、透明度只用 `opacity`（模糊只能用 `filter/backdrop-filter`，这条例外写在 transition.css 顶上）。

### 24.2 两个实现要点（都是为了"不闪"）

1. **目标页的第一帧就已经盖住** —— 蒙版标记由 `<head>` 里一段 **inline 同步脚本**加（不是 module，module 会被 defer 到绘制之后）：
   上一页在点击时把标记写进 `sessionStorage`，目标页在**首次绘制前**读出来补上 `pt-on pt-play`。
   证据：新页第一帧"最暗像素 229 / 暗像素占比 0"，而结束帧是"26 / 0.94%" —— 首帧里**一个深色像素都没有**。
2. **上一页只盖不播、目标页才播** —— 两页的静止态长得一模一样 ⇒ 换页过程无缝；动画只在目标页播一次。
   拦截条件写全了：只认站内、普通左键、非 `_blank`/`download`、非同页（只有 hash 不同）不盖；
   `prefers-reduced-motion` 时整套不参与（实测：蒙版不出现、导航照旧跳转成功）。

### 24.3 抓到的真 bug：毛玻璃整个失效（压缩器把标准属性删了）

第一版 `transition.css` 里 `backdrop-filter` 与 `-webkit-backdrop-filter` 都写了 ——
**压缩器按目标浏览器把标准那条删掉、只留 `-webkit-`** ⇒ Chrome 里 computed 值是 `none`，
毛玻璃完全没生效（那正是"首帧会闪内容"的隐患）。**只写标准属性、交给构建期加前缀**才修好。
（对照组：`src/pages/index.astro` 里的 `.band-readout` 同样两条都写，压缩器却删了 `-webkit-` 那条 ——
两处管道（`.astro` 作用域样式 vs 普通 `.css`）的目标浏览器策略不一致，所以这条不能靠推理，只能**看产物**。）

### 24.4 测量方法也踩了一次

第一版用 `sleep(200)` 后截图抓中间帧 —— 截图本身有几百毫秒延迟 ⇒ 抓到的是"下一阶段"（数据自相矛盾：
t≈420 时内容已经全清晰）。改成 **`animations.pause()` + `currentTime = t`** 精确定格后再读几何，
才拿到 24.1 那张表。另外：CSS 动画的 `effect.getTiming().easing` **恒为 `linear`**，
真正的缓动在**关键帧**的 `easing` 上（第一版读错地方，三条假红）。

## 26. 过渡动画引出的两处回归：相册灯箱被挡 / 手机抽屉被正文盖住（2026-09-27）

站主报两条，都**先复现并量清楚**再动手（`_tmp-gallery-drawer-diag.mjs` 打出了关键数值）。

### 26.1 相册点照片会触发过渡，且照片看不到

**根因（两条叠加）**：

1. 灯箱是**页面内 JS 拦下点击**（`preventDefault`）自己开大图，**根本不会真的跳转**。
   而 `transition.ts` 原来在**捕获阶段当场**判断 —— 那时别的处理器还没跑，`e.defaultPrevented` 还是 `false`
   ⇒ 被误判成"要跳转"，于是盖上蒙版、还写了 handoff 标记（下一次导航会白播一遍过渡）。
2. 蒙版的 `z-index: 58` **高于**灯箱的 `50` ⇒ 就算挂错了，蒙版也直接压在灯箱上，照片被挡。

**修法**：捕获阶段只做初筛，真正的判断放进 **`queueMicrotask`**（本轮事件的所有同步处理器都跑完再看 `defaultPrevented`）；
蒙版 `z-index` **58 → 45**，并把层叠阶梯写成注释固定下来：
`正文 ≤4 < 过渡蒙版 45 < 相册灯箱 50 < 开场覆盖层 60 < 跟手光标 64+`；
相册缩略图链接再加一个显式的 `data-no-transition`（双保险）。

### 26.2 手机端抽屉在非首页点不到、被正文盖住

**根因（一条链）**：上一页点击时置了 handoff 标记、但那次跳转被拦下（没真发生）⇒
下一个页面照样挂上 `pt-play`、播了一遍"没人要的"过渡；而 `pt-content` 是 `animation-fill-mode: both`，
结束帧的 `transform: scale(1)` **会一直留在 `.shell` 上** ⇒
**一个非 `none` 的 transform 会造出层叠上下文** ⇒ 后面的 `<main>` 就盖住了顶栏里的抽屉。

两组实测数据正好互为对照（`_tmp-gallery-drawer-diag.mjs`）：

| 页面 | html 上的类 | `.shell` 的 transform | 抽屉那一行的最上层 | 点「友链」 |
|---|---|---|---|---|
| `/about/`（坏） | `pt-on pt-play` ✗ | `matrix(1,0,0,1,0,0)` ✗ | `header.pagehead`（正文）✗ | 没跳 ✗ |
| `/talks/`（好） | 无 `pt-*` ✓ | `none` ✓ | `a`（抽屉里的链接）✓ | 跳到 `/links/` ✓ |

首页没事纯属侥幸：console 外壳那一份动画只做淡入、不做缩放（没有 transform）⇒ 没有多出层叠上下文。

**修法**：动画跑完（**950ms**，晚于 800ms 的时间线）由 `transition.ts` 摘掉 `pt-on pt-play` ⇒ 那个 transform 随之消失。
定时器只会晚、不会早 ⇒ 真机上不可能把动画截断。（探针里为了定格测量，临时挡掉了这个定时器 —— 探针自身跑 1.6 秒，
不改的话会在定格中途把动画收掉，第一版就是这么假红了 4 条。）

## 27. 关于页头像「加载后跳一下 + 不跟滚动」（2026-09-27）

站主："刚打开关于界面时头像在图一位置，随后跳到图二位置，并且不跟随鼠标滚轮上下而上下。"

### 27.1 根因（先用探针量出来，不是猜的）

第一版头像用的是 `position: fixed`（当时想的是"固定在右侧空白处别跑掉"）。问题出在**过渡动画**上：

`pt-content` 会给 `.shell` 加 `transform: scale(0.98 → 1)`；而被 transform 的祖先会成为 `position: fixed`
的**包含块** ⇒ 动画期间头像按"相对 `.shell`"定位；动画结束、`pt-on/pt-play` 被摘掉后 `transform` 变 `none`，
包含块又换回视口 ⇒ **位置突变**。探针（`_tmp-avatar-jump-diag.mjs`）实测：

```
+   0ms  {x:1066, y:252, w:125, position:fixed, shellTransform:matrix(0.98,…)}   ← 站主的"图一"
+1000ms  {x:1075, y:246, w:128, shellTransform:matrix(1,0,0,1,0,0)}             ← 动画跑完
+2000ms  {x:1075, y:198, w:128, position:fixed, shellTransform:none}            ← 类被摘掉 ⇒ 跳了 48px
滚动 300px 后：{x:1075, y:198, scrollY:227}                                      ← y 一点没动（fixed 的本性）
```

### 27.2 修法：改成**布局定位**（放进页头，桌面两栏 grid）

- 头像连同「北杉」搬进 `<header class="pagehead">`；
- 桌面（≥1024px）页头变成 `grid-template-columns: 1fr auto`：标题在左、头像在右（`margin-top: 2.5rem`，对着标题下半部分）；
- 手机端不动（仍是标题下方居中、头像与名字同轴 —— 站主上次认可的版式）。

两个问题一起消失：位置由排版决定（**不会变**），元素在正文流里（**自然跟着滚**）。实测：

```
+0ms(1095,216) +300ms(1095,216) +700ms(1104,208) +1100ms(1104,208) +1600ms(1104,208) +2400ms(1104,208)
滚到 300px：y 208 → -92（差值≈滚动量）· 回到顶部：y 复原 208
```

注意 0→700ms 那 8px 是**动画本身的缩放**（有意为之），不是跳变；关键是 **1600 → 2400ms 之间完全不动**。

## 29. 页面过渡 v2：无菌纸 / 墨绿结构线 / 医疗橙点缀（2026-09-27 站主给定完整规格）

站主给了配色、材质、四阶段时间线（总 **2.2 秒**）与技术要求。整个过渡重写为 `src/styles/transition.css`，
**时间线全部用 CSS 变量表达**（规格明确要求"必须用 CSS 变量精确控制交叠"），没有任何 JS 时间轴（站上零第三方）。

### 29.1 时间线（CSS 变量 → 实测）

| 变量 | 值 | 阶段 | 实测（暂停 + currentTime 定位后读真实状态） |
|---|---|---|---|
| `--pt-focus-dur` | 800ms | ① 临床聚焦 | t=0 柔雾 `blur(30px)`、内容被完全盖住；t=600 已降到 12.6px；t=800 正好 10px |
| `--pt-scan-dur` | 300ms | ① 橙色扫描线 | t=120 画面里实测 **1149 个橙色像素**（t=0 为 0）；t=300 已扫到视口底部 |
| `--pt-axis-at` + `--pt-axis-dur` | 600+800ms | ② 坐标锁定 | t=600 准星/轴线**仍是 0**（faithful：600ms 才出现）；t=650 准星可见；t=800 轴线 1057px；t=1200 抽满 1277px |
| `--pt-hatch-at` + `--pt-hatch-dur` | 1200+1000ms | ③ 无菌舱门 | t=1400（+200ms）上蒙版底边从 455 冲到 **173**（=62%，冲击感）；t=1800 到 91（=80%）；t=2200 完全离场 |
| `--pt-content-at` + `--pt-content-dur` | 1800+400ms | ④ 内容落地 | t=1800 内容 opacity 从 0.45 起、`scaleY(0.98)`；t=2200 到位；标题与正文 +50ms 错落 |

关键帧里的"机械停顿感"用**分段 timing-function** 实现（`pt-hatch` 在 20% 处用一个快曲线冲到 62%，之后换减速曲线到 80%、再到 100%）。

### 29.2 验证时抓到的三个**真 bug**（都是量出来的，不是看出来的）

1. **CSS 变量作用域**（最隐蔽）：时间线变量原来声明在 `.pt` 上，而第四阶段要动画的 `.shell > *`（标题/正文）
   **不在 `.pt` 子树里** ⇒ `var(--pt-content-at)` 解析为空 ⇒ 整条 `animation` 简写被判无效丢弃 ⇒
   内容浮现**静默不生效**。探针里表现为"`getAnimations()` 里根本没有 400ms 那条、内容 opacity 一直是 1"。
   修法：时间线变量提到 `html.pt-on` 上（调色板仍留在 `.pt`，它只被 `.pt` 子树用到）。
2. **`both` 的反向填充**：基准线/刻度的"消散"动画用了 `fill-mode: both`，而它在 animation 列表里**靠后**
   ⇒ 在延迟期间就把自己的 0%（`opacity: 1`）反向填充上去，压过入场动画的 0%
   ⇒ **准星/节点/基准线在 600ms 之前就可见了**（定格图 t=120 里那个橙色小点就是证据）。修法：消散那条改 `forwards`。
3. **接缝线必须跟着舱门散掉**（结尾态推演发现）：基准线是独立元素、不随舱门移动 ⇒ 门开了它会孤零零横在正文上。
   修法：1200ms 起 500ms 内把基准线/刻度/准星/节点一起淡出（1700ms 前消失），与"边缘流光随距离消散"同一逻辑。

### 29.3 探针自己踩的两个坑（记下来免得下次又怀疑产品）

- **橙色像素判据太松**：第一版用 `r-b>60` 数"医疗橙"，把站上本来就偏暖的米色纸底与背景美术也数进去了
  ⇒ t=0 就报 1180 个（假红）。收紧成 `r≥230 && r-g≥60 && g-b≥40`（#ff8c42 的 r-g=115、g-b=74；米色只差 2）后，
  t=0 是 **0**、t=120 是 **1149**，信号干净。

### 31.4 站主定稿修订：线色回退、圆点挪到交点上、呼吸改成自上而下（同日）

站主看完那版后给了明确修订（附了一张交点特写）：**线色变回上一轮的颜色**（我那次加深被退回 ⇒
`--page-grid-line` 回到 `#1a1a1a0b` ink @4.3%）；**圆点必须落在网格线与线的交点上**、且比线粗一点；
**明暗变化明显一点**、整体呼吸**自上而下循环**。四条都照办，其中第 2 条揪出一个**真 bug**：

#### 真 bug：`radial-gradient` 的圆心默认在元素中心，`background-position` 挪不动它

我原来写的是 `radial-gradient(circle, …)` + `background-position: 0 0`，并且还"验证"过对齐 ——
但那条断言只比了 `background-size`（48px ✓），**等于什么都没验**。真相是：

- 网格线画在 tile 的**边缘**（tile 原点就是交点）；
- 而 `radial-gradient` 的圆心默认在 **tile 中心**；
- `background-position` 只能平移**整个 tile**，**改变不了圆心在 tile 内的位置**
  ⇒ 圆点一直落在**格子正中**，离交点差半个格子（24px）。

取证（`_tmp-diag-grid-phase.mjs`，先把正文与美术隐藏再量）：
`竖线 x = 48,96,144…（间距 48 ✓）`；`交点(48,48) 最暗=234 · 只有竖线=241 · **格子正中=226 <- 最暗**` ✗。
修法：把圆心写进渐变 —— **`radial-gradient(circle at 0 0, …)`**（其余三个象限由相邻 tile 补齐，无缝）。
修后同一处量到：**交点 217 · 单线 240 · 格子正中 249（＝纸底）** ✓，并据此把断言阈值定成实测值
（交点最暗应比单线暗 ≥10；格子正中必须 ≈ 纸底）。

#### 呼吸改成"自上而下循环"：一张纸色薄雾扫过

原来只是整层 opacity 在 0.35↔1 之间摆 ✗（且看不出方向）。现在三层结构（顺序即绘制顺序）：

| 层 | 画什么 |
|---|---|
| `.paper-grid` 自身背景 | 网格线（48px、1px、4.3%） |
| `::before` | **交点圆点**（`circle at 0 0`；核心 1.5px + 柔边到 2.6px ⇒ 比线粗） |
| `::after` | **纸色薄雾**：`linear-gradient(180deg, transparent 4%, var(--paper) 40%, transparent 76%)`，`opacity .95`，`grid-breathe 9s linear infinite` 从 `translateY(-100%)` 扫到 `+100%` |

薄雾压过的地方网格变暗、掠过后变亮 ⇒ 视觉上就是**整片网格自上而下循环呼吸**；只用 `transform`（合成层、不重绘），
首尾都在画面外所以循环无缝；`prefers-reduced-motion` 下不扫（`opacity:0`，网格与圆点仍在）。
实测：薄雾位移 `-26.8 → +213.2`（递增＝向下 ✓），关键帧 `-100% → +100%` ✓。

#### 又一个验证侧的坑：`visibility: hidden` 会继承

探针为了"只量背景"把正文与美术隐藏 ✗ —— 结果连**网格层也一起被藏了**（它在被隐藏元素的子树里），
隐藏后整张截图最暗 250（＝纯纸底），采样一个交点都找不到。修法：隐藏后**显式把网格层恢复 `visible`**
（子元素可以覆盖继承来的 hidden）。

### 31.5 第三版定稿：去掉薄雾，只让圆点呼吸，且上下错开时机（同日）

第一版的方向判定我拿"最亮时刻"比，得到"自下而上"，于是把关键帧反过来写 ✗ —— 结果改错了：
