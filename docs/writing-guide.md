## 0. 先记住一句话

**文字都在 `content/`，版式都在 `src/`。**

| 你想改的东西 | 去哪改 | 要不要懂代码 |
|---|---|---|
| 写新文章、改文章 | `content/posts/<文件夹>/index.md` | 不用 |
| 换文章里的图片 | 同一个文件夹 | 不用 |
| 站名 / 首页简介 / 页脚邮箱 / GitHub | `content/site.md` | 不用 |
| 关于页 | `content/pages/about.md` | 不用 |
| **发说说（可带图）** | `content/pages/talks.md`（图放 `src/assets/talks/`）—— 见 §18 | 不用 |
| **加/换友链** | `content/pages/links.md` —— 见 §19 | 不用 |
| **写日志** | `content/pages/log.md` —— 见 §20 | 不用 |
| **看/删留言** | `content/pages/guestbook.md` 是页面文案；留言本身在数据库 —— 见 §21 | 不用 |
| 加相册、加照片 | `content/gallery/<相册名>/` —— 见 §17 | 不用 |
| **归档页搜索/年月筛选** | 自动的，不用配 —— 见 §23 | 不用 |
| **关于页头像 / 名字 / 社交账号 / 技术栈** | `content/pages/about.md` 的 frontmatter —— 见 §24 | 不用 |
| **说说的点赞与评论** | 自动的，不用配 —— 见 §25 | 不用 |
| **页脚统计（运行时长 / PV / UV）** | 时长起点在 `content/site.md` 的 `since` —— 见 §26 | 不用 |
| 标签清单 | `src/tag-registry.ts` | 会改一行数组就行 |
| **导航菜单（右上角那排）** | `src/lib/nav.ts` —— 见 §22 | 会改一行数组就行 |
| 配色 / 字号 / 间距 / 字体 | `src/styles/tokens.css` | 要认一点代码 |
| 域名 | `astro.config.mjs` 一行 | 要认一点代码 |

**记住两条安全线：**

- 改错了都能撤（见 §13 回滚），因为每次发布都在 git 里有记录。
- **本地改完 ≠ 线上变了。** 只有 `git push` 之后，Cloudflare 才重新构建上线。

## 1. 在哪敲命令

### 打开终端

按 `Win`，输入 `powershell`，回车。或者在文件资源管理器里进到 `<博客仓库>`，在地址栏输入 `powershell` 回车。

### 每条命令之前先做这一件事

```powershell
cd <博客仓库>
```

所有 `npm` 命令都必须在**这个目录**下跑，否则会找不到项目。

### 你会用到的全部命令

```powershell
npm run dev       # 启动本地预览，改完立刻能看到（按 Ctrl+C 停止）
npm run build     # 只构建，不跑测试
npm run verify    # 构建 + 跑全部测试（共 524 条：522 通过 / 1 设计内跳过；偶发再多 1 条本机环境失败）—— 推送前必跑
npm test          # 只跑测试
git add -A        # 把改动标记为"要提交"
git commit -m "说明"   # 存成一个版本
git push          # 推到 GitHub → 自动上线
```

> **这台机器的一个坑**：沙箱默认会拦 vite 的子进程，`npm run dev` / `build` / `test` 会报 `spawn EPERM`。
> 需要在更宽的文件权限下运行（之前整个开发过程都是这么跑的）。

## 2. 写一篇新文章（完整流程）

### 2.1 建文件夹

```powershell
cd <博客仓库>
mkdir content\posts\my-new-post
```

**文件夹名 = 网址。** 规则（现在是**构建期硬校验**，写错直接构建失败）：

- 只能小写字母、数字、单个连字符：`my-new-post` ✅
- 不能大写、下划线、空格、中文、首尾连字符、连续连字符：`My_Post` ❌ `我的文章` ❌
- 最长 60 字符
- **发布后不要改**（改了就是死链，见 §5）

### 2.2 建正文文件

```powershell
notepad content\posts\my-new-post\index.md
```

（推荐用 VS Code，能实时预览 Markdown。）

最小可用版本：

```markdown
---
title: 文章标题
date: 2026-10-01
summary: 一句话摘要，最多 80 字。
tags: [随笔]
draft: true
---

正文从这里开始。
```

### 2.3 frontmatter 九个字段，逐个说

| 字段 | 必填 | 写什么 | 写错的后果 |
|---|---|---|---|
| `title` | ✅ | 标题，可以很长、可以中文 | 缺了 → 构建失败 |
| `date` | ✅ | `2026-10-01` 格式。**加不加引号都行** | 格式不对 → 构建失败 |
| `summary` | ✅ | 摘要，**最多 80 字**，出现在列表页和搜索引擎 | 超 80 字 → 构建失败 |
| `tags` | ✅ | `[随笔]` 这种数组，**1–3 个**，必须是已登记的（§4） | 没登记/超 3 个/空 → 构建失败 |
| `draft` | ✅ | `true`（草稿）或 `false`（发布）。**必须写** | 漏了 → 构建失败 |
| `updated` | ⬜ | `2026-10-05`。写了，文章页会显示「更新于 2026-10-05」 | 早于 `date` → 构建失败 |
| `cover` | ⬜ | 头图路径，如 `./cover.jpg` | ⚠️ **目前只校验、不上页面**（见 §3.5） |
| `coverAlt` | ⬜ | 头图的 alt 文字 | 有 `cover` 没它（或是空串）→ 构建失败 |
| `slug` | ⬜ | 想改网址时写，如 `my-url` | 与文件夹名不一致 → **告警**（不失败），网址用 `slug` 的值 |

**`date` 是排序依据**：列表、归档全按它倒序。写未来的日期会让文章排在最前面。

### 2.4 正文能用的全部语法

| 你想要的 | 怎么写 | 效果 |
|---|---|---|
| 二级标题 | `## 标题` | 会进目录（TOC），带锚点 |
| 三级标题 | `### 标题` | 会进目录（缩进一级） |
| 一级标题 | `# 标题` | **别用** —— 文章标题已经是 h1，再用会破坏语义 |
| 加粗 | `**重点**` | **重点** |
| 斜体 | `*曲名*` | *曲名* |
| 行内代码 | `` `draft: true` `` | 等宽小底纹 |
| 链接 | `[文字](https://example.com)` | 可点，hover 变橙 |
| 站内链接 | `[另一篇](/posts/other-post/)` | 相对路径，换域名不会失效 |
| 图片 | `![描述](./照片.jpg)` | 见 §3 |
| 引用 | 行首 `> ` | 左侧粗黑条 |
| 无序列表 | `- 项目` | 圆点 |
| 有序列表 | `1. 项目` | 数字 |
| 嵌套列表 | 缩进两格再写 `-` | 二级缩进 |
| 表格 | 见下 | 会横向滚动 |
| 代码块 | 见下 | 黑底 + 复制按钮 |
| 分隔线 | `---` 单独一行 | 一条细线 |

**表格**：

```markdown
| 表头 | 表头 |
| --- | --- |
| 单元格 | 单元格 |
```

**代码块**（\`\`\` 后面写语言名，会有语法高亮）：

````markdown
```js
const a = 1;
```
````

常用语言名：`js` `ts` `bash` `json` `yaml` `python` `html` `css` `text`

### 2.5 本地看效果

```powershell
npm run dev
```

浏览器打开 `http://localhost:4321`。**草稿在这里也能看见**，标题旁会有「草稿」标记。
改文件保存后页面自动刷新。看完按 `Ctrl+C` 停止。

### 2.6 发布

1. 把 frontmatter 的 `draft: true` 改成 `draft: false`
2. 跑检查：

```powershell
npm run verify
```

看到 `Tests 521 passed` 就对了（数字会随新增护栏上升；旁边两行都不是代码问题）：`1 skipped` 是设计内的跳过
（「上游镜像已清」「未构建」这类前提缺失的占位，见 `tests/` 里的 `skipIf` 条件）；
`1 failed` 是本机已知环境故障 `spawnSync node EBUSY`（`tests/tokens.test.ts` 用相对路径 `node`
起子进程在本机必失败），用绝对路径直跑 `node scripts/assert-tokens.mjs` 复核那 11 项即可。
**除这条已知故障外必须全绿，否则别推。**

3. 提交并推送：

```powershell
git add -A
git commit -m "post: 新文章标题"
git push
```

约 1 分钟后上线。确认：

```powershell
curl.exe -sI https://northcedar.top/posts/my-new-post/ | Select-String "HTTP/"
```

### 2.7 撤回一篇文章

把 `draft` 改回 `true` 再推 —— **别删文件夹**。

文章会从列表、标签页、归档、RSS、sitemap 消失，直接访问网址变 404，连它的图片也不会被部署。

### 2.8 彻底删掉一篇文章

```powershell
Remove-Item content\posts\my-new-post -Recurse -Force
npm run verify
git add -A
git commit -m "post: 删除 xxx"
git push
```

⚠️ 删了就没了（除非用 git 回滚，见 §13）。**但如果这篇文章已经在网上被搜索收录或被人转过，那个网址会变成 404。**

### 2.9 更新一篇文章（改完让读者知道这篇动过）

改正文就直接改 `index.md`。想让读者知道它更新过，加/改一行 `updated`：

```yaml
date: 2026-09-30      # 首次发布的日期，别动
updated: 2026-10-08   # 文章页会显示「更新于 2026-10-08」
```

- `date` 是**第一次发布**的日子，不跟着更新走 —— 归档、排序、RSS 都按它。
- `updated` **不能早于** `date`，写反了构建会失败（见 §11）。
- 一次「重写」也是这个用法。2026-10-08 重写《从 HTML 到莱茵生命》就是这么标的：
  `date` 保持 9 月 30 日不动，只把 `updated` 加到当天。
- ★ 但站主要「把日期改成今天」时走的是**另一条路**：直接把 `date` 改成今天，并**把 `updated`
  删掉**。原因：`date` 与 `updated` 是**并排渲染**的，留着 `updated` 会印成
  「2026-10-08 更新于 2026-10-08」。2026-10-08 站主就这么要过一次（那篇刚从 `updated` 改回 `date`）。
  判断依据很简单 —— **看站主是要"读者知道它动过"，还是要把首发日挪到今天**。

## 3. 图片

### 3.1 放哪里

**放进那篇文章自己的文件夹**，和 `index.md` 并排：

```
content/posts/my-new-post/
├── index.md
├── 封面.jpg
└── IMG_20260930.jpg
```

**不要**建 `images/` 之类的公共目录，也不要用绝对路径（`D:\...`）—— 那样换机器/换主题就断了。

### 3.2 怎么引用

```markdown
![一句话说清图里拍的是什么](./IMG_20260930.jpg)
```

**三个要点：**

1. 路径以 `./` 开头，指向同文件夹
2. **中括号里的字必须写，而且要是人话。** 那是 `alt`，给看不到图的人（和搜索引擎）读的。
   - ✅ `![傍晚的操场，跑道上有三个人在散步](./a.jpg)`
   - ❌ `![图片](./a.jpg)`、`![](./a.jpg)`
3. **空 alt 不会让构建失败，但会让 `npm test` 失败。**
   Cloudflare 只跑构建、不跑测试 —— 所以空 alt 会**静默上线**。这就是为什么推送前必须跑 `npm run verify`。

### 3.3 图片会被自动怎么处理

- 自动转成 **WebP**（体积小很多）
- 自动生成**多尺寸** `srcset`：手机下小图、桌面上大图
- 自动撑满正文栏宽度，**不用你写宽度**
- 带 `loading="lazy"`（滚到才加载）

**所以你什么都不用管** —— 原图直接丢进去就行，不用预先压缩、不用改尺寸、不用转格式。

### 3.4 尺寸建议

- 竖图/横图都行，宽度 1600px 左右足够（再大也看不出来，只是白占体积）
- 单张控制在 2 MB 以内（Cloudflare 免费版单文件上限 25 MB，但没必要挑战它）

### 3.5 封面图（`cover`）—— 目前不能用

契约里定义了 `cover` + `coverAlt` 两个字段，构建会校验它们（有 cover 必须有 coverAlt），
**但主题目前不渲染头图** —— 写了也不会显示。三篇文章都没用过，当时按 YAGNI 搁置了。

**你要用头图的话先告诉我**，我加渲染。

### 3.6 用 Typora 写作时怎么设（**本站不用图床**）

站主 2026-09-27 问："我的博客用的是 GitHub 图床吗，是的话 Typora 里怎么设置？"
**答案是：不用图床，一个都不用。** 三条理由，任一条都足够：

1. 仓库里**没有任何第三方图床的引用**（`raw.githubusercontent` / jsDelivr / imgur / sm.ms 都搜不到）；
2. 站上有条硬约束 **「零第三方请求」**，`tests/build-output.test.ts` 里就有断言守着 ——
   把图片放到图床，那条测试会当场变红；
3. 代码仓库 `NorthenCedar/personal` 是**私有**的（GitHub API 返回 404）⇒ 就算放上去，
   `raw.githubusercontent.com` 的链接访客也**打不开**。

本站的做法很简单：**图片就是仓库里的文件**，放在那篇文章自己的文件夹里，用 `./` 相对路径引用（见 §3.1 / §3.2），
构建时自动转 WebP、自动出多尺寸 `srcset`。

所以 Typora 要设成"**把图复制进文章文件夹 + 用相对路径**"，四个开关：

| Typora 设置项（文件 → 偏好设置 → 图像） | 设成 | 为什么 |
|---|---|---|
| 插入图片时 | **复制到当前文件夹** | 正好符合 §3.1「和 `index.md` 并排」；别选"上传图片" |
| 优先使用相对路径 | ✅ 勾上 | 绝对路径（`D:\…`）换机器就断 |
| 对本地位置的图片应用上述规则 | ✅ 勾上 | 从桌面拖进来的图会被复制进文章文件夹 |
| 对网络位置的图片应用上述规则 | ✅ **尤其要勾** | 从网上粘贴的图会被下载到本地 —— 不勾的话它就是一条第三方请求，违反零第三方约束 |

**上传服务 / PicGo 那一栏不要配**（配了就是把图往外送）。

最后一步别忘：Typora 插进来的语法是 `![](图片名.jpg)`，**中括号里是空的** ——
按 §3.2 补一句人话再推送；推送前跑一次 `npm run verify`，空 alt 会被它拦下来。

#### ⚠️ Typora 的图是"未跟踪文件"，只 `git add` 那篇 `index.md` 是不够的（2026-09-27 真踩过）

用 Typora 写完一篇带图的文章后，`git status` 里会出现这样的东西 —— **那些图还没进仓库**：

```
?? content/posts/xxx/image-20260928000308825.png     ← 只在硬盘上，仓库里没有
```

**只 `git add` 那篇 `index.md` 就推送**会怎样：本地构建能过（图就在硬盘上 ✓），
但 Cloudflare 上只有仓库内容 ⇒ 构建报 `Rolldown failed to resolve import "image-….png"`、
部署 **Failure**、线上继续挂着上一个成功的部署 —— 表现就是那句"我 push 了，怎么没上线" ✗。
（已实测复现：把图挪走，`npm run build` 直接 exit 1；挪回来 exit 0。）

**推送前对一下这三条**：

```bash
git status --short                    # 除了 index.md，图片也要被列出（A / AM 才算进去了）
git add content/posts/<你的文章>/      # 直接 add 整个文章文件夹，图就一起进去了
npm run verify                        # 构建 + 测试都过再推
```

（顺带：`draft: true` 的文章**不会**上线，这是设计 —— 列表/标签/归档/RSS 全隐藏、直接访问 404。
写完了想发，把那行改成 `false` 再推。）

（相册是另一条路：照片放进 `public/gallery/<专辑名>/`，构建时由脚本生成 WebP 与缩略图，见相册那节。）

## 4. 标签

### 4.1 现在登记了这 8 个

```
AI · 建站 · 摄影 · 成长 · 随笔 · 钢琴 · 教程 · 工具
```

（唯一事实来源是 `src/tag-registry.ts`。这一段是它的镜像 —— 你在那里加了标签，这里也该同步。）

**用没登记的标签 → 构建直接失败**，并告诉你具体是哪个标签、在哪篇文章里。

这是故意的设计：防止半年后出现「前端 / 前端开发 / frontend」三个同义标签，让标签页变成垃圾堆。

### 4.2 加一个新标签（两步，缺一不可）

**第一步**：打开 `src/tag-registry.ts`，往数组里加：

```ts
export const TAGS = ['AI', '建站', '摄影', '成长', '随笔', '钢琴', '读书'] as const;
```

**第二步**：**确保至少有一篇文章真的用它**（把 `读书` 加进某篇文章的 `tags:`）。
否则 `npm test` 会失败 —— 有个测试守着「每个登记标签至少有一篇文章用它」。

> 所以：**要写那类文章了再加标签**，别提前登记。空标签会让标签页出现一个点了没内容的入口。

### 4.3 改名 / 删除标签（危险）

- **删掉一个还有文章在用的标签** → 那些文章构建失败（标签没登记了）
- **给标签改名** → 等于「删旧 + 加新」，所有用旧标签的文章都要改 frontmatter
- 两个标签合并（比如把「随笔」并进「成长」）→ 也要先改所有文章的 `tags:`

安全顺序永远是：**先改文章 → 再改注册表**。

### 4.4 每篇几个

**1–3 个**。超了构建失败。

怎么选：第一个放**主题**（成长/摄影/AI），第二个放**体裁**（随笔/建站），第三个才放**具体锚点**（钢琴）。

### 4.5 标签页现在长什么样（2026-10-06 换的，你不用碰）

两页都是**格线矩阵** + 本区自己的一层 ∞ 底纹 + 一台「准星」装置：

| 页面 | 是什么 | 一格里的内容 |
|---|---|---|
| `/tags/` | 全部标签排成一张格纸 | 格号（01…08）+ 标签名 + 篇数 |
| `/tags/<标签>/` | 这个标签下的文章排成同一张格纸 | 日期 + 标题 + 摘要 + 标签行 |

**加/删标签会自动改变格数**（格号是位置派生的，不用手写）：4 列时 8 个标签正好两行；
再加一个就变成"最后一行差三格"（格纸的正常样子，不是显示错误）。

**背景那层 ∞** 是这一区专用的（其余页仍是百褶 ∞）。素材是站主给的那张图里抠出来的，
原生只有 467px 宽，所以**它不能放大**（放大了会糊）—— 想让它更大只能换更高分辨率的图。
两个旋钮如果想微调（一般不用）：

```css
/* src/components/TagsPlate.astro 的 .tags-inf */
width: var(--plate-w, min(64vw, 934px, 170vh));   /* 934 = 原生 467 × 2，别超 */
opacity: var(--plate-op, 0.08);                   /* 站上装饰底纹那一档就是 8% */
```

手机上、以及系统开了"减少动态效果"时，**整个装置不出现**（这是有意做的降级）。

### 4.6 404 页现在长什么样（2026-10-06 换的，你不用碰）

404 页（`northcedar.top/404` 或随便一个不存在的地址）有**两样装饰**，都是这一页专用的：

**① 底纹 ∞（换掉了全站内页那层「百褶 ∞」）**
素材是站主给的图里抠出来的 —— **左半边是开口的**那个无限符号。
抠图时把原图里「无限」两个汉字**用周围的灰色填掉**了（所以你看到的是干净的符号，没有那两个字），
并把**全部西文小字标注**（`INFINITY` / `IT REFERENCE 2017` / 左上角 `01` / `Patience` / 右下角说明行等）
一起去掉了。原图右半边那束斜向的灰色光楔**保留着** —— 它是构图的一部分，不是标注。

它**比版心宽、两端出画** —— 这是故意的：原图本来就是"一张出画的大构图"，
切掉两边像"裁了一张大图"，而不是"把符号裁坏了"。
（对比：标签页那个 ∞ **不许出血**，因为它自己的构图是收在画里的。）

```css
/* src/pages/404.astro 的 .frac-inf */
width: var(--plate-w, min(148vw, 2160px, 240vh));  /* 2160 = 原图 1080 × 2，别超 */
opacity: var(--plate-op, 0.18);                     /* 与它替换掉的百褶 ∞ 同档浓度 */
```

**② 装置「裂痕 FRACTURE」**（2026-10-07 第三版：**整块玻璃被砸了"一下"**）

这一页的玻璃**一进来就已经裂着**了 —— 整张裂纹网极淡地铺在上面（约 5% 的灰，隐隐一层）。
鼠标在页面上**划过**（不用点）时，指针碰到哪一条，那一条就**从碰到的地方向两端一段一段跳着亮起来**
（段与段之间有短停顿，所以读起来是「啪啪啪」而不是「哒哒哒」）；**手离开之后，它会把这条自己走完**。
没碰到的那些仍旧极淡 ⇒ 你会看到「划过的那片清楚起来、没划过的还隐隐在那儿」。

裂纹的形貌按**真实冲击玻璃**的定式来（第三版就是在这一条上重做的）：

- **只有一个爆点**，而且**故意偏在左上**（不是正中央 —— 正中的爆点读起来像"排版出来的装饰"）。
  第二版是"1 主爆点 + 4 个次级点"，铺开之后读起来是**五朵星芒**，不是一块碎了的玻璃。
- **放射纹先裂、同心环后裂**，而且**环止于放射线**（裂纹遇到已有的自由面就停）——
  所以环是**一段段弦**、端点正好落在放射线上，交叉口全是 T 形。第二版的环是自成一体的波浪圆圈。
- 爆点近旁有一小片**粉碎区 + 雾化区**（真玻璃在爆点周围会碎成末）。
- **碎片外大内小**：越往画幅边缘格子越大（爆点边上是粉末级碎屑，边缘是手掌大的整块）。
- 放射纹是**近直线，但会偶尔"顿"一下**（像撞到玻璃里的杂质），**不是平滑的弯**。

**裂口是有"厚"的**（这就是"玻璃质感"）：玻璃有几毫米厚，砸开后断面朝向不同 ⇒
**一侧背光成暗缝、另一侧迎光出亮边**。所以每道裂纹实际画了三层（暗带 → 暗缝 → 亮芯）。
全页**只有一支光**（左上），所有裂纹的亮/暗边朝向一致 —— 不然就不是"一块玻璃"而是"一沓贴纸"。
★ 顺带：**压在深色页脚带上的裂纹现在看得见了**（第二版看不见）—— 深色底上反而是那根**亮边**最清楚，
正是"裂口反光"的样子。

它同样会**自己绕开正文的文字**（从字的缝隙里穿，离字形盒至少 6px）；撞上文字盒会**先小角度偏一点，
偏不动就跨过去接着走**（所以文字背后不会留下一大片空白）。

几件它**故意不做**的事，别当成 bug：

- **不点也能裂、点了不会碎**：站主要的是"划过"，不是点击。
- **裂了不愈合**：亮起来就是永久的（真玻璃不会自己长回去）。总量是**建网时定死的**，不会越划越多。
- **一次只牵一条**：以指针为圆心 56px 内**最近**的那条线被唤醒，然后向两端走完（实测最远牵到 636px，
  约 11.4 倍触发半径）—— 不会"全屏一起亮"，也不会"指针画到哪才有哪"。
- **每次打开长得一样**：形状种子写死了，同一个窗口尺寸下**逐点相同**（这是为了能验收）。
  代价是**改窗口大小会整张网重算**，已经亮起来的部分会回到"极淡"。
- **剩下没划到的地方会不会碰不到**：不会。只剩一个爆点，靠的是**放射线 + 破环**把全页铺满 ——
  实测全页 **94.67%** 的像素离最近的裂纹都在触发半径以内（离网最远的地方 221px）。
- **线有多密**：整张网是**刻意拉稀过的**（站主第四轮「线不要那么密，稀疏一点」）。
  密度不在一个旋钮上，是**五个**一起管：`RAYS`（辐条）· `CRUSH_N` / `MIST_N`（爆点近旁的碎屑）·
  `BRANCH_P`（分叉）· `RING_Q`（环的疏密）。★ 拉稀的时候**放射线不能太稀** ——
  它是"指针随处能碰到裂纹"这条保证的骨架，所以每拉一次都要重量上面的可触达率。
- **它会往下长到页面底部之外吗**：不会。整页都能裂（画布跟着整篇文档走），
  但**滚下去之后裂纹还留在原处** —— 它记的是"字在哪"，不是"屏幕在哪"。
- **手机上不出现**、**系统开了"减少动态效果"也不出现**：这是有意做的降级
  （手机上根本没有"划过"这个动作；而这一台没有"静止的最终画面"可以退，所以干脆不装）。

想知道它长什么样/怎么调：`src/scripts/fracture.ts`（机制，文件头把"为什么"写全了，常数表也在那儿：
`SEED` 形状种子 / `SEG` 段长 / `DWELL` 每跳的停顿 / `REVEAL_R` 触发半径 / `PAD` 与文字的安全距离 /
`IMPACT_X`·`IMPACT_Y` 爆点位置 / `RAYS` 放射线根数 / `BRANCH_*` 分叉 / `RING_*` 同心环（`RING_Q` 决定
碎片外大内小）/ `CRUSH_*`·`MIST_*` 粉碎与雾化区 / `KINK_*`·`DRIFT` 折点 / `LX`·`LY` 光照方向）+
`src/pages/404.astro`（挂载与底纹）+ 颜色 token（**四道**，都在 `tokens.css`）：
`--deco-fracture-band`（裂口暗带 8%）· `--deco-fracture-line`（暗缝 22%）·
`--deco-fracture-light`（亮芯 60%，偏迎光侧）· `--deco-fracture-ghost`（未揭示的底 5%）。

## 5. 网址（URL 与 slug）

### 5.1 规则

- 文件夹名就是网址：`content/posts/my-new-post/` → `https://northcedar.top/posts/my-new-post/`
- 只允许小写字母、数字、单个连字符，最长 60
- **构建期硬校验**，不合法直接失败

### 5.2 发布之后不要改文件夹名

改了 = 旧网址变 404 = 所有转到过那篇的链接、搜索引擎收录全部失效。

**想改标题就只改 `title`，网址不动。**

### 5.3 想自定义网址

在 frontmatter 写：

```yaml
slug: my-custom-url
```

网址会变成 `/posts/my-custom-url/`。但如果它和文件夹名不一致，构建会**告警**提醒你最终用的是哪个（契约要求告警，不是失败）。

**什么时候该用**：中文标题、想换一个更好记的网址、文件夹名起得不好但懒得改文件夹。

首屏右上那块玻璃里现在有两行读数：

## 8. 改版式（`src/`）—— 进阶

> ⚠️ 这一节改的是**视觉规范**，有硬约束（对比度、间距阶梯）。改完必须跑 `npm run verify`。

### 8.1 配色：`src/styles/tokens.css`

```css
--paper: #fafaf7;         /* 页面底（乳白，不是纯白） */
--ink: #1a1a1a;           /* 主文字，也是黑带底色 —— 对纸 16.64:1 */
--muted: #5a5a56;         /* 次级文字（摘要、日期） —— 6.62:1 */
--hair: #d8d5ce;          /* 装饰细线，不承载文字 */
--accent: #2d7d46;        /* 绿：对纸 4.86:1 */
--accent-ink: #266b3b;    /* 纸上小字专用绿 —— 6.18:1 */
--accent-bright: #4caf50; /* 深色底上的绿：对 --ink 6.26:1；**对纸只有 2.66** */
--signal: #e87722;        /* 橙：对纸只有 2.83:1 ⇒ 图形色，不许承载文字 */
--signal-text: #b45309;   /* 纸上小字可用的橙 —— 4.80:1 */
```

**三条硬约束：**

1. **文字对比度必须 ≥ 4.5:1。** 现在真正会掉进坑里的是这两个：
   - `--accent-bright`（对纸 2.66:1）**只许用在深色底**（`--ink` / `--code-bg`）上，例如黑带里那条 2px 下划线；
   - `--signal`（对纸 2.83:1）是**图形色**，任何时候都不许承载文字；要在纸上写橙字就用 `--signal-text`。
   - 顺带说清一件变了的事：2026-09-25 配色换成莱茵方向（绿）之后，`--accent` 是 4.86:1，
     **纸上小字也达标了** —— 旧方向那条「橙只能用在 ≥24px 大字」的限制已经不成立，别再照它写。
2. **改了颜色，`npm test` 会失败** —— 这是故意的。有个脚本从 `tokens.css` 读真实颜色、按 WCAG 公式复算，和期望值比对。你必须：
   - 打开 `scripts/assert-tokens.mjs`
   - 把对应那行的期望值改成新算出来的数字
   - **确认它仍然不低于下限**（那行最后一个数字）

   改完跑 `node scripts/assert-tokens.mjs` 看是否全绿。
3. **alpha 一律写 8 位 hex**（如 `#1a1a1a0b`），组件里**不许写 `rgba()`** —— 颜色只能住在 `tokens.css`。

### 8.2 字号与间距：同一个文件

```css
--fs-display ~ --fs-mono    /* 11 档字号 */
--sp-1 ~ --sp-8             /* 8 档间距，4px 基准 */
--measure: 34em;            /* 正文行宽（中文约 34 字/行） */
--wrap: 82rem;              /* 整页最大宽度 */
--band-h: min(74vh, 42rem); /* 首屏黑带高度 */
```

**规则**：间距不许出现阶梯外的值（组内用 `--sp-1~4`，组间用 `--sp-5~8`）。
正文内部的段落间距（`1.15em` 那种）是排版节奏，用 `em` 是允许的例外。

1. **看部署状态**（最直接，一条命令）：

   ```powershell

   ```

## 14. 评论（自建，2026-09-26 上线）

评论区在每篇文章底部。读者填**名字 + 留言**即可发表，**不用登录、不用邮箱、没有验证码**。
数据存在你自己的 Cloudflare D1 里，**不经过任何第三方**。

**顺序：新的在最上面**（2026-09-27 按站主要求改的；留言板、文章评论、说说评论三条路径一致）。
自己刚发的那条会立刻出现在最顶上，并在时间后面标一个「刚发表」。
顺序只在**接口**里决定一处（`ORDER BY created_at DESC, id DESC`），所以三条路径不会各排各的。

### 14.1 本地怎么调评论（**和写文章不一样**）

```powershell
cd <博客仓库>
npm run build
npx wrangler pages dev dist --port 8788
```

然后浏览器打开 `http://127.0.0.1:8788/posts/camera-in-gaosan/`。

> ⚠️ **`npm run dev` 不跑评论** —— 它是 Astro 的静态预览，不会执行 Cloudflare Functions，
> 所以评论会显示「留言没能加载出来」。**日常写文章照旧用 `npm run dev`；只有要调评论时才用上面这条。**

首次使用要先建本地表：

```powershell
npm run comments:init
```

（本地数据库存在 `.wrangler/` 下，已在 `.gitignore` 里，不会被提交。）

### 14.2 怎么删一条评论

> ⚠️ **最容易踩的坑：`wrangler d1 execute` 默认打的是【本地】数据库。**
> 不加 `--remote` 时，你的命令作用在 `.wrangler/` 里的本地副本上 —— **看起来成功，但线上什么都没变**。
> 我上线时就踩过：以为把表建到线上了，结果线上库一直空着，评论 API 报 500。
> 判据：加上 `--remote` 后输出里会出现 `"served_by": "v3-prod"` 和真实的 `num_tables`。

先看有哪些（**本地**用 `--local`，**线上**用 `--remote`）：

```powershell
npx wrangler d1 execute beishan-comments --local --command "SELECT id, slug, name, substr(body,1,40) AS body, created_at FROM comments ORDER BY id DESC LIMIT 20"
```

删掉指定的一条：

```powershell
npx wrangler d1 execute beishan-comments --remote --command "DELETE FROM comments WHERE id = 42"
```

删掉某篇文章下的全部（比如被灌了）：

```powershell
npx wrangler d1 execute beishan-comments --remote --command "DELETE FROM comments WHERE slug = 'my-post'"
```

### 14.3 线上首次上线要做的三步

1. `npx wrangler login`（打开浏览器点同意）
2. `npx wrangler d1 create beishan-comments` → 记下返回的 `database_id`
3. Cloudflare 控制台 → Workers & Pages → `personal` → Settings → Functions → **D1 bindings**：
   变量名填 **`COMMENTS_DB`**，选中刚才那个库；**生产环境和预览环境各绑一次**

绑完再 `git push` 一次，评论就能用了。

### 14.4 反垃圾是怎么做的

| 机制 | 说明 |
|---|---|
| **蜜罐字段** | 表单里有个真人看不见的「网站」输入框。机器人会填，一填就**假装成功但扔掉**（返回 201，不写库）—— 让它以为得手，不来重试 |
| **频率限制** | 同一个 IP **每分钟最多 2 条**，超了返回 429「发表太频繁」 |
| **隐私** | 数据库里**只存 IP 的哈希**，不存原始 IP |

挡不住的：**人工发的广告**。看到就用 14.2 的命令删掉。

### 14.5 回复（2026-09-28 上线，像 QQ 动态的楼中楼）

每条评论（文章页、留言页、说说的评论都一样）下面有一个「回复」小字按钮：

- **层级只有两层**：回复一条回复时会归到同一条顶层评论下面，显示成「A 回复 B：内容」——
  不会出现第三层缩进，手机上也不会挤成一条细线。
- **顺序**：顶层评论新的在上；同一条下面的**回复旧的在上**（对话要顺着读）。
  计数（「评论 N 条」）含回复。
- **怎么删一条回复**：跟删评论同一个命令，只是换表——
  `npx wrangler d1 execute beishan-comments --remote --command "DELETE FROM replies WHERE id = 7"`。
- **数据**：回复在独立的 `replies` 表（`migrations/0003_replies.sql`，2026-09-28 已应用到线上库）。
  表里不存原始 IP，跟评论同一条隐私线。
- **别删 `src/scripts/reply-common.ts`** —— 三处（文章/留言/说说）的回复交互全靠它共用；
  它还刻意不 import `functions/` 下的任何代码（会把后端整包拖进浏览器产物，JS 预算直接爆）。

### 14.6 评论的边界（明确不做）

无头像（头像要请求外部服务）、无邮箱、无验证码、无表情。
~~无嵌套回复~~ → 2026-09-28 加了两层回复（见 14.5）；层级就到两层，不做无限嵌套。
**评论功能依赖 JavaScript** —— 站点是静态的，评论只能运行时取；关掉 JS 只会看到表单骨架。

## 16. 这个网站容不容易打开

**线上地址：https://northcedar.top**

它是**纯静态站点**，托管在 Cloudflare 的全球 CDN 上 —— 没有服务器进程、没有数据库，所以**不存在"服务器挂了"这回事**。只要 Cloudflare 在，网站就在。

**优点**：全球 CDN 加速、自动 HTTPS、免费版没有带宽限制、不会被单台机器拖垮。任何设备（手机/平板/别人的电脑）打开网址就能看，不需要装任何东西。

**但要诚实说清楚不确定性**：

1. **中国大陆的访问速度我不能保证。** 从你这台机器实测是通的、响应也快，但那是**单点、单时刻**的观测。Cloudflare 的免费版节点在大陆的可达性会随网络环境波动，这不是我能承诺的。
2. **没有备案。** 用的是 `pages.dev` 免费子域，所以走的是境外节点。真要稳定的大陆访问，唯一的路是买域名 + ICP 备案 + 国内云。

## 17. 相册（`/gallery`）—— 怎么加照片

> 2026-09-26 上线。文章配图看 §3；**成组的照片放相册**（会自动进首页 S3 与 `/gallery` 页）。

### 17.1 加一个相册：三步

**第一步 · 建文件夹**：`content/gallery/<相册名>/`
（名字可以用中文，它只会出现在图片地址里，不影响网址结构。）

**第二步 · 把原图直接丢进这个文件夹**（jpg / png 都行，和 `index.md` 放同一层）。

**第三步 · 建 `content/gallery/<相册名>/index.md`**，照这个格式：

```yaml
---
title: 一些风景
date: 2026-09-25
images:
  - src: ./011.jpg
    alt: 天窗
  - src: ./012.jpg
    alt: 上海的晚霞
---
```

两条硬规矩：
- **`alt` 每张都必须写**。缺了**构建会直接失败**，报错会指出是哪个相册的哪张图。
  它同时就是相册页里显示在图下面的那行字 —— 写你自己认得出的那句话。
- `src` 写 `./文件名`，文件名与文件夹里那张**一模一样**（大小写敏感）。

### 17.2 加完之后：什么都不用做

构建时脚本会自动：

| 自动做的事 | 说明 |
|---|---|
| 原图 → **两档 webp** | 1280（灯箱用）/ 800（网格用），写进 `public/gallery/` |
| 生成 `manifest.json` | 页面的图片地址与宽高都从它来 |
| **原图不部署** | 30 MB 原图**不会**进产物（这是刻意的） |
| 首页 S3 取图 | 自动取**最新相册**（按 `date` 倒序）的**前 3 张** |
| `/gallery` 收录全部 | `/gallery/` 是**入口页**（一册一条，§17.10）；`/gallery/<册名>/` 才是砖墙 + 灯箱（§17.8） |
| 只重编改过的图 | 指纹缓存：没动的图秒过；整批重编约 1 分钟 |

`public/gallery/` 是**生成物、不入库**（换台电脑第一次构建会全量重编，正常）。

### 17.3 三条规则

- **单张 ≤ 2 MB**（同 §3.4）。Cloudflare 免费版单文件上限 25 MB，但没必要挑战它。
- **`alt` 每张都要写**（见 17.1），它既是无障碍要求、也是页面上的图说。
- **顺序 = `images:` 里的行顺序**。想调整，把行挪一下即可。

### 17.4 删照片 / 删相册 / 调整

- **删一张**：从 `index.md` 里删掉它的 `src` + `alt` 两行，再删文件夹里那张原图。
- **删整个相册**：把 `content/gallery/<相册名>/` 整个文件夹删掉。
- **换一张图**：把新图放进文件夹、改 `index.md` 里的文件名（或直接覆盖同名文件 —— 内容变了会自动重编）。
- 生成物里的旧 webp **会自动清理**：脚本会删掉「不在当前清单里」的文件，不用你手动去 `public/gallery/` 里清。
- ⚠️ **相册名会变成图片地址的一段**，加了照片之后就**别改文件夹名**（同 §5.2 的道理）。

### 17.5 加完照片后的检查

```powershell
npm run build
```

构建日志里会有一行：

```
[gallery] 3 个相册 / 82 帧 × 2 档 = 164 个文件；本次编码 6、命中缓存 158；产物 14.3 MB；首页取「一些风景」前 3 张；耗时 …
```

看到它就说明成了 —— **`本次编码` 的数字 = 你这次动了多少张**（没动的命中缓存）。若你加了图但这里还是 0，说明 `index.md` 里没写进去。
**有任何一张源图找不到，构建会直接失败**（这是刻意的：宁可构建红，也不要页面上一个破图）。

本地看效果：`npm run dev` 后打开 `/gallery/`（地址同 §2.5），首页的 S3 也会跟着变。

### 17.6 常见问题

- **加了图但首页没变？** 首页只取**最新相册**（`date` 最大的那个）的前 3 张。要让某个相册上首页，把它的 `date` 改新（或直接看 `/gallery/`）。
- **相册页有图但灯箱打不开？** 灯箱要 JS；关掉 JS 时点图会直接打开大图（这是刻意的降级），不是坏了。
- **构建报某张图「源图不存在」？** 文件名大小写、或图没放进相册文件夹。`src` 必须与文件名逐字符相同。

### 17.7 相册页首屏那块「显影板」（2026-10-01 上线）

进 `/gallery/` 首先看到的是一整屏深墨绿的板 —— **它从页面最顶端开始，导航栏浮在它上面**
（导航是半透明的，能透出底下的板）。板中间有一行手写花体的英文站名。
**鼠标移上去没有任何额外的圈**：这块板用的是**全站光标**（一个白点 + 一圈极淡的墨色圆盘，
`src/components/CursorRing.astro`），滞后的那个是擦出来的痕迹本身 —— 两个位置差就是
"被拽着走"的读数。★ 原来这里另加过一个 16px 白圈（2026-10-01 照抄参考站），
2026-10-08 站主决定删掉：它和全站光标在指针处叠成了三层同心（34 / 16 / 8 px），
而参考站自己**没有**全站光标、所以只叠一层。见 `docs/rhinelab-spec.md` §6.63。
**不动鼠标它就是一块纯色**；鼠标（或手指）在上面划过，会像擦掉玻璃上的雾一样擦出下面那张照片。
擦出来的那道痕**会像水一样继续流动**（边缘一直在动），**约 2.3 秒后沿原路退回去**，
画面回到纯色。往下滚才是相册本身。

- **每次打开随机一张照片**，只从**横着的**照片里抽（竖幅铺进整屏只能裁成中间一条）。
- 鼠标划过网格里任意一张横幅照片，板里会淡入那一张 —— 想让某张"上板"，划过它就行。
- 那行花体字是**擦不掉**的（它压在显影层之上，跟参考站 lowkeytp.art/liquid-reveal/ 一样）。
- **手机上不整屏**（触屏涂抹不习惯）：退回页头右侧的小板，高按照片原比例。

想改的话，参数都在 `src/scripts/develop.ts` 顶部，注释写了每个是什么：

| 想改什么 | 改哪个 |
|---|---|
| 笔触多粗 | `RADIUS_K`（整屏）/ `RADIUS_SMALL_K`（手机小板）—— 都是"**板高**的多少倍"（参考站 `size*1.35/height`） |
| 擦痕留多久 | `LIFE`（**秒**）—— 从满到看不见 ≈ `LIFE × 0.81`；参考站旋钮 2.8 |
| **水流动得多快** | `FLOW_A`（curl noise 幅度）/ `FLOW_SPD_X,Y`（流场自己漂移的速度） |
| 笔"跟不跟手" | `FOLLOW_K`（一阶指数平滑速率，越大越贴手；参考站是 18） |
| 边界碎不碎 | `EDGE_A`（扰动幅度，越大越破碎）/ `EDGE_F`（频率，越大越细） |
| 板多高 | `src/pages/gallery/index.astro` 里 `.bath` 的 `height: 100svh`（第五轮起**不再减顶栏高**：顶栏已 `position:absolute` 浮在板上；板另用 `margin-top: calc(-1 * var(--sp-7))` 抵消 `.shell` 的上内边距，才顶得到页面最顶端） |
| 花体字内容 | `content/site.md` 的 `wordmark`（**不要写死在代码里**） |

⚠️ 改完 `RADIUS_K` 这类"按板高比例"的值，**板尺寸一变就要重算** —— 整屏和小板的短边差 4 倍，
同一个系数搬过去手感会完全不对（这条踩过一次，站主当场就指出来了）。
⚠️ **别动场分辨率**（`FW_MAX`）或"空块跳过"那一步：这是 CPU 跑得动这套场的关键，
实测 512 的场要 37 ms/帧（27 fps），现在的 320 是 9.1 ms。要改先跑 `_probe/bench-field3.mjs`。
改完照 §8.6 跑一遍 `npm run verify`，再用 `node _probe/cdp-bath-water.mjs` 量一下。

### 17.8 照片陈列区：分「板」+ 错缝砖墙（2026-10-07 重做 · 2026-10-07 再拆）

> ★ **这一节描述的砖墙现在住在 `/gallery/<册名>/`，一册一页。**
> `/gallery/` 本身**不再铺开照片** —— 那里放的是「一册一条」的入口条，见 **§17.10**。
> 砖墙的版式、类名（`.wf` / `.plate` / `.plate-body` / `.lb`）与 `data-*` 契约**一字未改**，
> 只是整块搬进了 `src/components/PhotoWall.astro`，由 `src/pages/gallery/[album].astro` 一册一页地渲染。

往下滚过显影板与螺旋盘，在**每一册自己的页面**上看到的就是**照片陈列区**。
它原来是 `column-count:3` 的瀑布流 —— 82 张平铺成一条无限长的流，不丑，但**没有结构**：
没有章节、没有承托面、没有编目，看的人只能一直往下滑。现在换成四笔：

1. **分板**：一个相册一块「板」，板头一行编目读数 —— `板 01 · 一些风景 · 57 帧 · 2026-09-25`。
   板的上沿是一条墨色纸边（承托面靠**这条线 + 留白**，不靠染色）。
2. **错缝砖墙**：板内 4 列网格，**偶数列整体下沉一档** ⇒ 从"一张表"变成"一片"。
   这一条就是"不平铺直叙"的真正来源。
3. **一律不裁图**：每格是 1:1 的**方槽**，图在槽里**居中、按原比例**。竖幅不会被裁成中间一条。
4. **框内编目号**：左下角 `NO.001`，三位零填充、**按册**编号 ⇒ 用本站的 HUD 语言做"标本标签"。

**加一个相册、改相册名与日期，都不用动这里** —— 板数、板号、帧数、日期全部从
`public/gallery/manifest.json` 现读（板号 = 相册在清单里的**位次**）。
★ 搬成"一册一页"之后**相册页没有板头**（页头 `PageReadout` 已经给了同一组读数，再打一遍是重复）。
代码在 `src/components/PhotoWall.astro`（模板 + `<style>` + 灯箱脚本）。

| 想改什么 | 改哪个（都在 `src/components/PhotoWall.astro`） |
|---|---|
| 一排放几张 | `.plate-body` 的 `grid-template-columns` —— 三档：桌面 `repeat(4, 1fr)` / ≤1180 `repeat(3, …)` / ≤680 `repeat(2, …)` |
| **错缝幅度** | `.plate-body` 的 `--stagger`（**百分比**，按格宽解析）—— 45% / 40% / 18%。用百分比是为了"同一句在 4/3/2 列下自动等比缩放"，不必为每档重算长度 |
| 哪几列下沉 | `.plate-body > figure:nth-child(4n + 2)` / `(4n + 4)` 那一组 |

| 编目号钉在哪 | `.plate-body .no` 的 `left` / `bottom` |

| 悬停推近 | `@media (hover: hover) and (prefers-reduced-motion: no-preference)` 里那个 `scale(1.03)` |

**六条改之前先看一眼的硬性质**（`tests/gallery-plate.test.ts` 全部守着）：

1. ★★ **`.wf` 这个类名不能删，`figure` 必须仍是它的后代** ——
   首屏那台整屏显影板（`src/scripts/develop.ts`）订阅的正是它。
   ★ 2026-10-07 起那个钩子从 `.wf figure` 换成了**更中性的 `[data-bath-src] figure`**
   （砖墙离开入口页后，入口页的 `<figure>` 只剩入口条里那些 ⇒ 名字得跟着搬家）。
   标记本身在 `src/components/AlbumRow.astro` 的 `.ar` 容器上，**两边必须一起改**。
2. ★★ **错缝必须用 `margin-top`，不能用 `transform`** —— transform 不占位，
   网格算行高时按"没下沉"算，下沉那一列会咬到下一行上。margin 占位才是真错缝。
3. ★★ **换列数时，每一档都要先把旧周期的错缝归零、再写新周期**（1180 档先归零 `4n+2/4n+4`，
   680 档再归零 `3n+2`）。漏归零就会出现"有的列下沉、有的列不下沉"。
4. ★ **档案视图一律不加 `object-fit`** —— 本站是档案不是社交相册，裁图会裁掉构图。
   ★ **唯一例外是入口条的细条**（`AlbumRow.astro` 的 `.ar-frame img`，那里必须 `cover`）。
5. ★ **板号是固定编目位次**（相册在清单里的第几个就是第几块，不因筛选/翻页重编号）；
   **`NO.` 是按册三位零填充**（每册都从 001 起），不是全站连续号。
   ★ 2026-10-07 起入口页**没有筛选条**了 —— "筛到单册"这件事变成了"进那一册的页面"。
6. ★ **灯箱的相册名来自每个 `figure` 的 `data-album-title`**。
   图下的 `figcaption` 里现在**只有** alt（相册名已提到板头，再重复 82 遍是噪音）⇒
   老写法 `fig.querySelector('figcaption span')` 会静默拿到空串（这条真踩过）。

**明确没有采用的**（写在这里免得下次又想到）：`object-fit:cover` 统一裁成等格 ·
格内指针视差 · 板底染色 / 左右出血 · 大字号标题压在照片上。理由都在 `docs/site-decisions.md`。

### 17.9 另一条路看照片：「螺旋盘」（2026-10-07 上线）

**它住在两个地方**（同一台装置、同一份实现 —— 组件 `src/components/SpiralPlate.astro`）：

| 在哪 | 怎么到 | 滚轮 | 回头路 |
|---|---|---|---|
| **相册页中间**（显影板之下、入口条之上） | 直接往下滚相册页 | ✅ 接管（到两端让路，见下） | 不需要（你本来就在相册页里） |
| **独立页** `/gallery/spiral/`（全屏专注） | 相册页末尾那行「**螺旋盘 · 全屏打开（滚轮翻片） →**」 | ✅ 接管（到两端让路） | 底部「← 回到相册（砖墙视图）」 |

页序（2026-10-07 站主定）：「把螺旋盘放到**显影板的下面**，螺旋盘下面接现在的放照片的部分」
⇒ **显影板（整屏）→ 螺旋盘 → 按册入口条**。

分工：砖墙是**目录层**（一眼扫完、按册分板、有编目号），
螺旋盘是**画廊层**（一次只把注意力交给一张，划动沿着一条 3D 螺旋走）。
**不是新旧关系** —— 砖墙一个字没改。

怎么用：**滚轮**（竖着滚就是往前/往后翻）· **左右拖动**（鼠标 / 手指，与滚轮并存）·
**键盘 ← → / Home / End** · **Tab** 走到哪一张就转到哪一张 ·
**点照片**缓缓放大到眼前、再点同一张开灯箱 · **点空白**慢慢回到原处。
★ **两档都接管滚轮**（站主 2026-10-07：「把螺旋的那个划动方式还是改为滚轮」）。
相册页那一档在文档流中间，所以靠**两端让路**守住"装置不劫持页面"：滑到整条线的头/尾，
装置**不再拦**那一滚，页面接着滚。**代价是明说的**：进装置后要先滚过一段才出得来；
想快些走出去，用拖动或 ← → 直接跳到尽头，或点装置外面让页面滚。

几何是**算出来的**，没有一处写死的尺寸。想调手感，改**组件**里这几个数（两个页面共用一份，
**只改这一处**；页面文件里已经没有 `.sp-*` 了 —— 有门闩盯着，写回去就红）：

| 想改什么 | 改哪个 | 现在的值 | 一句话说清 |
|---|---|---|---|
| **螺旋"转"多快**（每片转角） | `src/components/SpiralPlate.astro` 的 `--sp-ang-deg` | `28`（度，**不带单位**） | 越小越像"一条缓缓退后的带子"，越大越像"一圈圈绕的管子" |
| **同时看得见几张** | 同文件脚本里的 `FADE_OUT` | `5.0`（张） | 与上一项**是一对**：可见窗口扫角 = 两者相乘，**必须 ≥ 110°** 才看得出"绕"（见下） |
| 焦点那一张独占多宽 | 脚本里的 `FADE_IN` | `0.7` | 只让焦点那张是"全实" |
| **淡到多淡就干脆不显示** | 脚本里的 `FADE_OFF` | `0.2` | 剪掉"极淡的残影"（低于它一次收成 0）。太低（0.12）盖不住 op 0.137 那张 · 太高（>0.35）会切掉"还看得出形状"的螺旋侧壁 |
| 片子多大 | `.sp-viewport` 的 `--sp-tile` | `clamp(120px, 13.6vw, 196px)` | 半径与每片升高都由它换算 |
| 螺旋多陡 | 脚本里的 `Y_K` | `0.30`（× 片宽） | 越大越"立"，太大两端会被盒子切掉 |
| 3D 多深 | 脚本里的 `P_K` | `2.4`（× 半径） | 越小透视越猛 |
| 装置多高 | `.sp-on .sp-viewport` 的 `height` | `min(70svh, 620px)` | 纵向跨度必须落在它里面 |
| **点开放大多少** | `.sp-viewport` 的 `--sp-zoom` | `1.9`（窄屏 ≤680 那档 `1.5`） | 1.34 读作"弹出来"、不够"到眼前"。窄屏必须收：最矮那档盒高只有 320px |
| 放大/复原多快 | `.sp-on .sp-frame` 的 `transition` | `calc(var(--dur-enter) × 1.6)` ≈ 1.02s | 站主要的"**缓缓**放大 / **慢慢**回去"；640ms 太快 |
| 惯性多重 | `src/scripts/helix-core.ts` 的 `LOOKAHEAD` / `K` / `ZETA` | `0.22` / `90` / `0.86` | 甩出去多远 / 多快跟到位 / 过冲多大 |

★★ **两个旋钮是一对，别单独动**：`--sp-ang-deg × FADE_OUT = 可见窗口扫过的总角度`。
小于大约 110°，投影在可视范围内就是**单调**的 —— 整台会读成"一条斜排的照片带"而不是螺旋。
第一版就是 18° × 3.6 = 64.8°，实测卷回率 **1.000**（好看不出来）；现在是 28° × 5.0 = 140°，卷回率 **0.501**。
`tests/gallery-spiral.test.ts` 守着这条关系（还有"纵向跨度不能超出盒子"），改坏了会红。

★★ **`FADE_OFF` 是"剪尾巴"，不是"少看几张"**：`0.2` 对应 |Δ| ≈ 3.80 ⇒ 可见片 = 焦点**左右各 3 张**。
站主 2026-10-08 报的「照片**缩小时**出现的边缘异常」，实测就是 **op 0.137** 的那一张邻片
（投影 74×96px、区域均色 `rgb(209,211,204)`，比纸白暗 15~41 级）—— 它半透明地叠在纸上，
读起来不是"一张远处的照片"，而是"照片旁边一块脏的残影"。
★ 定位它靠的是**逐片量 rect + computed opacity**，不是调阈值试出来的
（第一版取 0.12 恰好差一点点没盖住 0.137）。
★ 门闩钉了**上下界**（`0.12 < FADE_OFF < 0.35`）—— 只卡上界会给"越淡越看不见"发许可证，
只卡下界会把螺旋侧壁也切掉。

★★ **远侧柔边（2026-10-09，§6.65）**：站主第三次报「照片边缘残留色块」，这次的病根是
**照片自己的硬边被透视压扁** —— 转到 56° / 84° 的那两片在屏幕上只剩 52.7 / 28.0px 宽，
照片里本来就有的彩色竖条（墙角、门框）压扁后就读成了"一块色"。
修法：**远侧那条边渐隐进纸白**（`mask-image`），只挂在 |Δ| > 1 的片上（脚本给它们加 `.sp-fade` 类）。
强度由 `helix-core.ts` 的 `edgeOf()` 按转角算：±1 片以内**精确为 0**，之后平滑爬升，到 ±3 片饱和在 `EDGE_MAX`。

| 想改什么 | 改哪个 | 现在的值 | 一句话说清 |
|---|---|---|---|
| 远侧渐隐多深 | `src/scripts/helix-core.ts` 的 `EDGE_MAX` | `0.6`（渐隐段占片宽的比例） | ★ 必须 `< 1`（到 1 = 整片抹掉 = 退回已否掉的"藏掉"）；低于 `0.4` 门闩会红（84° 那片的硬边压不下去） |

❌ **不许改 opacity 来"顺便"淡一点**（柔边与淡出互不相干，门闩盯着 opacity 那一行）。
❌ **不许用 `clip-path` 代替**（硬切出来的还是一道硬边）—— 全文禁止。
⚠ 转过约 78° 之后，片的"远侧"在屏幕上会卷到朝内那边 ⇒ 最外那张片的**屏幕外缘**看着没变、渐隐在它朝内一侧。几何如此，不是 bug。
⚠ 焦点两侧的 ±1 片在停稳后可能与改前差约 0.5 级（肉眼不可见）：那是 Chrome"挂过遮罩又摘掉"留下的栅格差，
不是它们带着遮罩（停稳时它们没有类）。要根除只能所有片常驻遮罩，那会动焦点片 ⇒ 不做。

★★ **放大片保护层（2026-10-09，§6.66）**：照片从放大缩回时，Chrome 偶发漏擦它原来占过的那圈，留下条纹。
修法是放大片的 `.sp-item::after` 垫一块比它大一圈（`inset: -60%`）、颜色 `--paper-ghost`（纸色 @ 2/255，肉眼看不见）的底，
缩回后再挂 `UNZOOM_MS`（1300ms）才摘。
❌ 不许挂到 `.sp-frame` 上（它会被 overflow 切掉）；❌ `--paper-ghost` 不许改成 00（全透明会被合成器跳过，保护失效）。
⚠ 改 `--dur-enter` 或缩回过渡倍数时，`UNZOOM_MS` 要跟着够长 —— 门闩会算给你看。

**三条别动的东西**：

1. ★★ **`.sp-item` 的变换顺序**（`rotateY` → `translateZ` → `translateY`）。
   换个顺序得到的不是螺旋（`translateZ` 在前是**柱面**）。有断言守着。
2. ★★ **`.sp-on` 只许由脚本给 `<html>` 挂**，而且**挂在 `<html>` 上** ⇒ CSS 里它的前导段必须写 `:global(.sp-on)`。
   无 JS 与"减少动效"下**根本不建装置**，页面就是那个平铺网格（82 张全在，一条不少）。
3. ★★★ **照片片（`.sp-frame`）上不许有任何描边** —— `border`、`outline`、
   以及 `box-shadow: inset …` 一律禁止（站主 2026-10-07：「点击螺旋盘里的照片会有绿色框，直接删了」）。
   原来有 `border: 1px solid transparent` + `.sp-item.on .sp-frame { border-color: var(--accent) }` 两层，
   一起删掉了 —— 留 `transparent` 那层也会让 2px 边框宽度继续吃掉照片内容。
   ★ "哪张是焦点"现在**只由读数承担**（右下角 `.sp-hud` 报 `NN / 82` 与册名），
     另有量规上那枚 `.sp-mark` 绿标记（位置标记，不是框）。
     键盘可达性不受影响：那条走的是 `.sp-viewport:focus-visible` 的**容器级 outline**，仍然保留。
4. ★★★ **方槽（`.sp-frame`）与照片盒（`.sp-frame img`）**两层都不许有底色** ——
   占位底已**整个去掉**（站主 2026-10-08 第二次报同一处之后的定稿）。**
   方槽是 `aspect-ratio: 1` 而照片按 `max-*: 100%` **不裁**（红线：全站没有 `object-fit`），
   所以片铺不满时必然露出一圈；站主 2026-10-07 报的那圈"边缘"就是露出的底。
   ★ 那块底**原本的用途是"图还没到之前的占位提示"**，但它**一旦是可见颜色就是异常**：
     ① 挪到 img 上（2026-10-07）之后仍然不行 —— 82 张全是 `loading="lazy"`，
        装置态下**只有一半会被触发加载**（实测 20 秒后仅 41/82 绘制），
        未绘制的那一半就是一块**可见的淡绿方块**（叠纸白 `rgb(238,243,236)`，差 12/7/11）；
     ② 换个色也没用 —— 换个色还是块，而"图还没到"的提示在这一台里本来就不成立
        （装置态下片是 3D 旋转 + 淡出的，访客分不清"没加载"与"还没转到"）。
   ⇒ **定稿**：`background: none` 在槽上、也在 img 上 ⇒ 未绘制处 = 纸白，与页面无缝。
   ❌ **不许改用 `object-fit: cover` 裁满**（本站是档案不是社交相册，裁图会切构图）。
   ❌ **不许让槽跟着照片变形**（`.sp-item` 是 `var(--sp-tile)` 定尺，82 片的 3D 位姿全按它算）。
   ❌ **不许把任何 `--deco-plate-*` / `--accent-wash` 当 `background` 写回来**（换个层复活也不行，门闩钉了全文禁区）。
   ⚠ 露边的**几何**（18–33%）改不掉 —— 但底色差 0（即"没有颜色"）就看不见了。
   ★ 排查同类问题时**别只筛某个颜色通道**：站主 2026-10-08 纠正过一次
     「为什么要纠结于绿像素？那个明明是**图片自己的边缘**，**颜色和图片有关**」——
     拿 `greenish` 去筛，不带绿的"边"永远筛不到。正解是**沿照片四边逐像素报真实 RGB**。

**加点什么之前先看**：`docs/rhinelab-spec.md` §6.44（这一台的设计记录与实测读数）、§6.65（远侧柔边）· §6.66（放大片保护层）·
`docs/site-decisions.md`（拍板与"没采用的"）。

### 17.10 相册入口条：一册一条 + 手风琴（2026-10-07 上线）

`/gallery/` 现在**不铺开照片**了。往下滚过显影板与螺旋盘，是**一册一条**的入口条：

```
板 01  一些风景         57 帧 · 取样 15   2026-09-25
[大幅的第一张][梳][梳][梳][梳][梳][梳] …    ← 默认第一张放大，其余是等宽细条（约 58px）
001 天涯
```

**一条里最多 15 张**（站主定的上限）。多的**等距抽样、含首尾**（57 帧取 001 / 005 / … / 057），
所以编号是**册内真实序号**，不是重新编 1…15。少于 15 帧的册全取。
★ 为什么抽样：57 张全铺在1440 档下每条只有 12.2px —— 照片被压成看不出内容的彩色锯齿。

**怎么用**：

| 动作 | 结果 |
|---|---|
| **点关着的那张** | **那一张放大**，之前放大的缩回去（放大态跟着搬家） |
| **点当前放大那张** | **直接进入这一册的页面** `/gallery/<册名>/`，那里是 §17.8 那块砖墙（照片框本身就是链接，页面上**没有**额外的进入按钮） |
| **Tab / ← →** | 在条内挪焦点；`←` `→` 在条内是"挪一条"，不是滚页面 |
| 悬停 / 聚焦 | 框内一圈发丝线（**不去动照片本身** —— 照片是档案，不该被滤镜改色） |

**加一个相册**：`content/gallery/<相册名>/` 照 §17.1 走完，`manifest.json` 里多一项 ⇒
入口页**自动多一条**（页面上没有任何地方写着"三条"）。路由是
`src/pages/gallery/[album].astro` 的 `getStaticPaths()`。

| 想改什么 | 改哪个（都在 `src/components/AlbumRow.astro`） |
|---|---|
| 放大那张多宽 | `.ar` 的 `--ar-open`：`clamp(190px, 30%, 380px)`（百分比 ⇒ 窄屏自己收窄） |
| 照片多高 | `.ar` 的 `--ar-h`：`clamp(88px, 11vw, 152px)` |
| 细条之间的缝 | `.ar` 的 `--ar-gap`：`3px` |
| 过渡快慢 | `.ar-item` 的 `transition: width var(--dur-enter)`（**包在 `prefers-reduced-motion: no-preference` 里**） |
| 编号在多宽以下不印 | `@container (max-width: 20px)` 那一块 |
| **一条最多几张** | 组件顶部的 `const MAX = 15`（改这一个数，抽样与门闩一起变） |
| **细条圆角**（胶囊） | `.ar-frame` 的 `border-radius: 999px`（**别写 `50%`** —— 非正方形框上会解析成椭圆） |
| **放大那张圆角**（小） | `.ar:not(.ar-on) .ar-item:first-child .ar-frame, .ar.ar-on .ar-item.on .ar-frame { border-radius: 6px }`（**必须与放大态那两条同构且互斥**） |
| **悬停抬多少** | `.ar-item:hover` 的 `translateY(calc(var(--hover-lift) * -1))` + `box-shadow: var(--glass-shadow)` + `z-index: 2` |

**六条改之前先看一眼的硬性质**（`tests/gallery-album-row.test.ts` 守着）：

1. ★★ **默认放大态写在 CSS**（`.ar:not(.ar-on) .ar-item:first-child`），脚本只负责挂 `.ar-on`
   把决定权交给 `.on`。**两条规则必须互斥** —— 同时生效会出现"切到第 5 张后第一张赖着不缩"。
2. ★★ **焦点激活要区分指针与键盘**：`pointerdown` 记时刻，`focus` 里 250ms 内的一律不算键盘。
   Chrome 点链接是 `pointerdown → focus → click`，无条件激活的话**第一次点击就直接进相册**了。
3. ★★ **条宽算式里必须带本册帧数**（模板写入 `--ar-n`），不许写死任何宽度：
   写死的话 57 张那一行会横向溢出、10 张那一行会留一大块空。
   实测三册三档 `Σ宽 + (n−1)×gap − 容器宽 ≤ 1.8px`、`scrollWidth == clientWidth`。
4. ★ **编号字号用容器查询单位**（`min(0.6rem, 55cqw)`）—— 跟着这一条的宽度缩。
   ★★ 但"塞得进"不等于"读得出"：12px 的槽里三位数字只有 6.7px，57 个连排是**一条灰色污迹**
   ⇒ 细条要 `@container` 藏起来，**且只许 `visibility: hidden`** ——
   `display: none` 会让图注行塌成 0，切换放大态时整条行上下跳约 19px。
5. ★ **相册名撞保留字（`spiral` / `index`）要在构建期报错**。Astro 7 对"静态路由 + 动态路由
   产出同一路径"**没有任何检测**，会静默覆盖、少一页。
6. ★ **`data-bath-src` 是显影板的素材池钩子**，删了它首屏那块板就没底图（划过才出来）。
7. ★ **抽样那三行不许"简化"**：只钉 `MAX = 15` 太弱 —— 改成"取前 15"或删掉去重它照样绿。
   要同时钉：步长式 `Math.round((k * (all.length - 1)) / (MAX - 1))`（**含首尾**）·
   去重那句（步长取整会撞出重复下标）· 产物里每条恰好 15 张且首尾编号正确。
8. ★ **悬停必须抬 `z-index`**（`2`）—— 不抬会被右邻压住，视觉上像没生效。
9. ★ **圆角落在 `.ar-frame`**（`overflow:hidden` 那层），不是 `img` 上。
9a. ★★ **圆角分两档**：细条 `999px`（胶囊，实测半径 28.9px）、放大那张 `6px`。
    写成同一档都不对：都 3px 是"削角"（看不出弧度）、都 999px 则大图是"胖胶囊"（像按钮）。
    分档那两条要**在** `.ar-frame` 那条之后（同特异性才覆盖得掉）。
9b. ★★ **不许加「进入 →」按钮**（站主：「别加这个进入按钮，点大图就直接进」）。
    行动召唤＝**照片本身**：`.ar-frame` 就是 `<a href={href}>`，页面上没有第二个按钮。
    多一个按钮＝同一个目的地说了两遍，还会压在照片上、悬停时抢戏。
    ⇒ 门闩两头钉：组件里不许再出现 `.ar-go`／那个按钮，**同时**要求 `.ar-frame` 必须仍是真`<a href>`。

10. ★ **不许用 `display: none` 藏任何东西**（这条对 `.ar-cap-no` 也适用）—— 图注行高度得固定，
    否则切换放大态时整条行上下跳。要藏就 `visibility`。

**明确没有采用的**：横向滚动的封面条 · 竖排瀑布流 · 把放大那张做成大图预览（那是灯箱的活，
而灯箱在相册页里）· 悬停时放大细条（会让人失去"这是刻度条"的感觉）·
**悬停时给照片加滤镜/去饱和**（沿用显影板"不修色"的立场：照片是档案，不是社交相册）。

**加点什么之前先看**：`docs/rhinelab-spec.md` §6.45 / §6.46（这两轮的设计记录与实测读数）·
`docs/site-decisions.md`（拍板与"没采用的"）。

## 18. 说说（`/talks`）—— 短的、没成为文章的东西

> 2026-09-26 上线（导航「说说」）。碎碎念、随手拍的、看到的一句话都放这儿；
> 内容在 `content/pages/talks.md`，**一条 = `date` + `text`**。

### 18.1 发一条（不带图）

打开 `content/pages/talks.md`，在 `items:` 下面加一条：

```yaml
items:
  - date: 2026-09-26
    text: 终于做的像一个真正的博客了！
  - date: 2026-09-25
    text: 今天路过海边，风很大。
```

- `date` 写 `YYYY-MM-DD`；**页面自己按日期倒序**，所以写在文件里的位置其实不影响顺序。
- 想让某句话后面跟个链接，加一行 `href: https://…`。
- 想删一条：把 `- date:` 开头的那三行删掉即可。

### 18.2 发一条带图的

**第一步 · 把图片放进 `src/assets/talks/`**（不是 `content/`！原因见下）。

**第二步 · 在 talks.md 里写文件名**：

```yaml
  - date: 2026-09-26
    text: 今天的晚霞。
    images:
      - src: 20260926-1.jpg
        alt: 窗外的晚霞
      - src: 20260926-2.jpg
        alt: 楼下那只猫
```

- 一条说说**可以带多张图**（页面上自动排成两列；手机一列）。
- **一张图一个 `alt`，必填**（全局硬规矩：所有图片 alt 非空，缺了构建会红）。
- 图片会自动转 WebP、出 480/760 两档 srcset、懒加载、带宽高（不会跳版）——**你不用管**。
- 图片为什么放 `src/assets/talks/` 而不是 `content/`：站上所有图片都要参与**构建期优化**，
  而只有 `src/` 里的资源能被 Astro 处理。这是内容层唯一的例外，别放错地方。

### 18.3 页面上的两台「装置」（你不用碰，但值得知道）

说说页有一层**动态背景**和一层**背景纹样**，都是纯装饰、都不读内容：

- **浮游 FLOAT**（`src/scripts/float.ts`）：斜飘的雨线 + 屏幕下半部的椭圆涟漪（一环一环往外推）。
  逻辑在 `_probe/_float-lab.src.html`（实验台，`?grid=1&t=12.3` 出并排样机）、规范在 §6.29。
- **墨点螺旋底纹**（`src/assets/talks/plates/drift-main.webp`）：替代全站内页那层百褶 ∞，
  只在说说页出现。★ **它不在 `src/assets/talks/` 根目录** —— 那条 glob 是**非递归**的，
  把图片直接丢进 `talks/` 会被当成"说说的配图"一起收进产物（多一份）。
  尺寸已按你的目检**收在视口内**（任何窗口下四边都留余量，不会被切）；想再小或更淡说一声，
  两个旋钮 `--plate-w` / `--plate-op` 挂在底纹层上。
- 每条说说还会在自己**原来的位置**上下小幅漂浮（±4px、8 秒一个来回，相邻三条错开相位）。
  它**只动 `transform`** ⇒ 不参与排版、不改顺序、不影响你写的内容。
- 每条说说的**底色是透明的**（不垫色块），所以那层墨点螺旋底纹会一直透出来。
  想让某一条或全部加个底色，改 `.talk` 的 `background` 一行即可。

### 18.4 常见问题

- **图没显示、页面上出现一行「找不到图片 xxx.jpg」？** 说明文件名对不上或没放进 `src/assets/talks/`
  （页面对这种情况**不是**静默失败，会明着写出来 —— 这是刻意的）。
- **想把某条说说的图换掉？** 换文件（同名覆盖即自动重编）或改 `src` 里的文件名。

### 19.4 背景那层墨笔 ∞ + 页面上的「星座」（2026-10-05 上线）

本页有两层装饰，都在 `Base.astro` 的 **`plate` 具名槽**里（不在 `.shell` 内部——
`.shell` 在页面过渡里会被 `transform`，被 transform 的祖先会成为 `position:fixed`
的包含块，装饰层会跳位）。

| 层 | 是什么 | 素材 / 逻辑 |
|---|---|---|
| `.inf-ink-plate` | 背景那支手绘墨笔 ∞（**替代**全站共用的百褶 ∞） | `src/assets/links/inf-ink.png`（**带 alpha**，1920×1090） |
| `.const-bg` | 装置「星座」：靠近的点连出细线，停留越久连得越多 | `src/scripts/constellation.ts` |

**几件要知道的事**：

- **本页把共用的百褶 ∞ 关掉了**（`:global(body.links-plate .page-inf) { display: none }`）。

- **墨笔 ∞ 是墨绿的**（染成 `--accent-ink`），不是原图的黑。素材本身**不带死色**——
  抠图只留了不透明度，颜色全在 token 上 ⇒ 想换颜色改 `tokens.css` 就行，不用重新抠图。
- **桌面 9% / 手机 6%**：9% 是按桌面 1400px 定的，窄屏上笔锋占比大三倍，不降会糊成一片。

- **「星链」约 0.1 秒成形**：靠近的点连出的线由 `SPEED`（`constellation.ts`）**单点**控制，
  现为 `1/0.12`。站主提过两轮"快一点"，三档依次是 0.97 s → 0.42 s → **0.10 s**。
  ★ 它是**观感参数**，但**有门闩**：契约要求「到位耗时 = (LIMIT + BOTH_BONUS) / SPEED」
  落在 50 ms ~ 200 ms —— **慢回去会被咬，快到只剩"闪"也会被咬**。所以别再"凭感觉"调它，
  要调先看 `docs/rhinelab-spec.md` §6.38（那一节有把"出现"逐帧量出来的办法）。
- **加友链不用动装置**。星星的数量和位置是按视口面积算的，不读卡片内容——
  你加几个 friend 都不会让星图变。

**改星图的样子**（都在 `constellation.ts` 顶部的常数里）：

| 想改 | 改这个 |
|---|---|
| 星星疏密 | `AREA`（每多少 px² 一颗；越大越稀） |
| 指针多远开始连 | `R_NEAR` |
| 最远能连多远 | `R_LINK` |
| 连多快 | `SPEED`（进度/秒，约 1.15s 走满一程） |
| 一次最多连到多亮 | `LIMIT`（0.62） |
| 同时最多几条线 | `MAX_EDGES`（14，超出后最旧的退休） |

⚠ 两条别改的：① 线一旦连上**不回落**（站主要的就是"停留越久连得越多"）；
② 星星位置用**整数哈希**、不是随机源 —— 改了就截图不可复现、没法验收。

## 20. 日志（`/log`）—— 每次改了什么

> 2026-09-26 上线（导航「日志」）。内容在 `content/pages/log.md`。
> 体例：**日期 + 版本号 + 这个版本改了什么（一条一行）**。

```yaml
items:
  - date: 2026-09-26
    version: v1.4
    changes:
      - 留言板上线，发留言不再刷新页面
      - 说说支持配图了
```

- **新的写最上面**（页面也自己按日期倒序，位置同样不影响）。
- `version` 可以不写（不写就只显示日期）。
- 这一页现在有 v1.0–v1.3 的历史记录（2026-09-25 / 09-26 那几次改版），是我按真实改动写的；
  之后每次改完顺手加一条就行 —— 也可以不写，它就是给自己看的。

### 20.1 页面右边那支「走时仪」（2026-10-04 上线）

日志页右侧竖着一支**时间刻线尺**，是这一页的装置。**它读的是这一页自己的内容**（不读日期以外的东西）：

- **一根齿 = 一条改动**，**齿越长 = 那天改得越多**。所以哪几天动得勤，扫一眼齿的高度就知道
  —— 这正是「时间刻线随更新频率变化」那句的落点。
- 每格底下两行小字：`X 版 · Y 项`（那天几个版本、共几条改动）和日期。
- **某一天没改动**：那格画一根**短虚线**（不是空白），免得看着像图断了。
- **点某一格** ⇒ 跳到那天**第一条**日志（同一天有多条时只挂一个锚点，不会重复）。
- 它**自己一动不动**，也不吃 JavaScript（整支尺是构建时算好的一张 SVG）
  ⇒ 所以没有任何"会不会卡、会不会闪"的问题。
- **手机（≤1023px）不显示它** —— 右侧腾不出地方，日志正文与锚点跳转照旧。
- **它会「长」一次**（2026-10-04 加的）：打开日志页时，全部齿**从左往右依次长出来**，
  一天一格地推进，之后**永久静止**（只播一次，不会反复动）。长完的时间 = 最晚那格的序号 × 90ms
  + 齿自己的 480ms ⇒ 现在 13 格、**约 1.6 秒**长完（原来 9 格时是约 1.2 秒）。
  ★ 所以**日子记得越多，这一段就越长** —— 想固定它，改的是每个齿 `--tooth-delay` 的那个 90ms。
  ★ 同日又调了一次：**整段生长排在页面过渡之后**才开始（原本和过渡重叠了 0.3 秒，
  读起来像"卡了一下"）。过渡本身约 0.9 秒，所以齿现在在**打开页面约 1 秒后**才冒头 ——
  这是有意的。从站内导航过来时正好；**直接打开 `/log/` 也会等这一秒**（不做条件判断，
  理由见 §6.30 那种"靠实现细节吃饭"的风险）。想整体挪，改一个数：
  CSS 里的 `--tooth-lead`（默认 `1000ms`）。
- **背景那层 ∞ 会「呼吸」**（同一天加的，**同日又调过一次**）：慢下来一涨一缩，
  **24 秒一个来回**（12 秒吸 / 12 秒呼），轮廓可见地放大缩小（实测约 52 像素），
  **只动位置、不改深浅**。想让它更明显或彻底关掉，说一声 —— 幅度和快慢都是几个数字的事。
  ★ 提一句：最初那版是 96 秒、幅度小到 13 像素以内，**实测轮廓只涨 6 像素、相当于
  0.14 像素/秒** —— 比人眼分辨慢运动的门槛还低一个数量级，所以"加了但看不见"。
  现在这版是 2.45 像素/秒，才是真的能看见。想调：`animation: log-inf-breathe 24s`（周期）
  与 `@keyframes` 里的 `translate3d` / `scale`（幅度），两个要一起改。
- 这两样**都不吃 JavaScript**，也照顾"减少动效"设置：系统里开了减少动效，
  齿直接完整显示、底纹直接停住，**信息一样都不少**。

### 20.3 往日志里加一条时的坑：正文别写裸的「冒号+空格」（2026-10-08 补）

**每条 `- ` 的正文里不要出现 ASCII 冒号紧跟一个空格。** 那个文件是 YAML，`「词: 值」`是它的
键值分隔符 —— 一旦出现，这一条就不再是**字符串**而被读成**映射**，Astro 拿到一个对象、直接
字符串化 ⇒ **整条文字消失，页面上只剩 `[object Object]`**（v2.1 的第 3 条就这样上线过，
而且当时全站测试全绿 —— 因为没有任何断言看着日志页的内容）。

- 写 CSS 值就写成 `background:none`（**冒号后不留空格**），不触发。
- 中文冒号「：」不受影响（本站正文里的冒号基本都是它）。
- 想彻底躲开，整条用引号括起来也行：`- "…… : ……"`。
- 有判据兜底了：`tests/build-output.test.ts` 的「日志页 changes」那组会读 `dist/log/index.html`，
  发现整条渲染成 `[object Object]` 就报错。判据是 li 的**原始内层 HTML** 恰好等于这四个字，
  所以**在正文里引用这个字样不会误伤**。

### 20.4 日志写多细？（2026-10-08 定）

日志条目的**详略是可以变的**，而且变它**会牵动右边那支走时仪** —— 记住这条就不会踩到：

- 到 2026-10-08 为止两种写法并存：**早期（v1.17 及更早）是详版** —— 一条写一段，为什么这么做、
  踩了什么坑都记下；**v1.18–v2.3 是简版** —— 每版 3–5 句，只说「做了什么」，分析全删。
  后者是站主 2026-10-08 定的（原话「把 v1.18 以后的日志都精简一下只说做了什么事」）。
- ★ **为什么它不只是"改文字"**：走时仪的**齿高 = 该版 `changes` 的条数**。条目一精简，齿高整体
  收窄、那台装置肉眼可见地矮了一截，连带两条契约阈值跟着放宽（见 spec §6.60.4）。
  **写日志的时候，其实是在给那台装置喂数据。**
- 想再精简一轮、或想把细节加回来，都可以 —— 只要知道齿高会跟着动，阈值要再看一眼
  （`tests/log-chrono.test.ts`）。

两条你可能会关心的实现说明：

- ★ **「装置整个不显示，只有开 F12 才有」这类症状先查 `activityGate`**（2026-10-06）。
  `rl-core.ts` 的 `createActivityGate` 给 `onScreen` 的初值是 `true` 而不是 `false` ——
  因为 IntersectionObserver 的首次回调是异步的、且对 `position:fixed` 的满屏元素
  **不保证一定来**（实测 1920×1000 视口下自建 IO 回调 0 次）。初值 `false` 时，
  "IO 没来"直接等价于"永久停帧"⇒ 一笔都画不出；而开 F12 会强制重排、触发 IO
  重新求值 ⇒ 恢复。**这就是"开 F12 激活了装置"的真身。** 凡有帧循环的装置都共用这函数
  （唯一的例外是相册页「显影板」：它把这三样内联在自己文件里，`develop.ts` 零 import ——
  见 `rl-core.ts` 头部注记；走时仪零 JS、准星零 rAF，都根本没有帧循环可门控）。
- **墨痕为什么不做成"只在留言区"** —— 试过两版**都有区域**的写法，两版都不对

两条 2026-10-06 晚补的说明（都是实测出来的，不是设计意图）：

- ★★ **「停住不出墨」是站主要求的，别再自作主张加回去**（2026-10-06 晚）。
  上一轮把「墨痕可以一直跟随鼠标」理解成「停住时笔尖也持续洇墨」，加了驻留落墨；
  站主验收后要求去掉。这是一次**过度解读**：「跟随」说的是痕的**位置**跟着笔走，
  不是「笔不动时纸自己出墨」。
  ⇒ 教训：**凡是"增强持续感"的需求，先问一句"停住时应该发生什么"**，
  否则很容易做出用户没要的、还很难解释的常驻墨团。
  停住时该发生的恰恰是「只淡不增」—— 那正是墨在纸上干涸的样子。
  ⚠ 反过来也别矫枉过正：停住**不是**清屏，旧墨仍要按各自年龄继续消退。
  判据见 `_probe/_ink-accept.mjs` 的 A 组（停住 1.5s、每 16ms 派发 ±0.4px 亚像素抖动，
  要求像素**不增**且无突变式清屏）。
- ★★ **「画了但太弱」和「没画」是两回事，量级判据必须落到像素数**（2026-10-06 晚）。
  站主反馈「发评论那个效果我没看到」，插桩诊断发现链路全通
  （事件到了、落点在视口内、画布已显形），但**整段生命周期的着色像素峰值只有 229**
  ——对照墨痕划过整屏是 3~4 万像素。原因不是失效，而是三个量级都太小：
  水滴半径 4~9px（πr²·dpr² ≈ 230，正好对上实测）、扩散环压成 `ry=rx*0.42` 的扁椭圆
  且线宽仅 2.2px、生命期 2.4s。
  ⇒ 重做为「带拖尾的水滴砸下 → 炸开一团 → 三圈近圆涟漪 + 11 颗溅射小珠」，
    实测峰值 **9610 像素 / alpha 250**，扩散段峰值是下落段的 10 倍。
  衰减指数从 `(1−u)²` 降到 `(1−u)^1.3`：平方衰减在 u=0.7 时只剩 0.09，
  墨还没扩散到最大就已经淡没了。
  **⇒ 视觉类验收一定要有"像素数量级"这条判据**，
  只看"有没有画到东西"会把"画了 229 个像素"当成"生效了"。

### 21.2 墨痕的回收必须按**时间**判，不能按浓度判（2026-10-06 事故，全站通用）

**症状**：留言页整页看不到任何墨痕，刷新 / 换窗口尺寸 / 清缓存全无效。
上一个 commit 刚修完 `activityGate` 的 `onScreen` 初值（那次是真的，但**不是这个症状的原因**）。

**根因（线上插桩实测，不是推断）**：用 CDP 的 `Fetch` 域拦下线上真实 chunk 换成插桩版，
在 1920×1000 下量到：

```
gate=[true,true]  calls=41  pushed=200  gcRemoved=200  blobs=0  ink=0
gcAges=[0.0002,0.0002,0.0002,0.0002,0.0002,0.0001,...]  negAges=0
```

墨点**确实落了 200 个**，但每个都在落纸后 **0.1~0.2 毫秒**被回收了。

机制：清理循环的判据写的是 `blobAlpha(age) <= 0.002`（按**浓度**判），
而 `blobAlpha` 的上升段是 `age/(LIFE*0.08)`，落纸瞬间浓度 ≈ 0.0006
⇒ 每个刚落下的点都被当成「已经淡干净」回收。
Chrome 每帧的顺序是**先派发输入事件、再跑 rAF**，所以真实鼠标移动时，
`pointermove` 落的点在**同一帧内**就被删 ⇒ 屏幕上永远是干净的。

**为什么十几轮探针全绿**（这次最贵的教训，写在这里防止重演）：
它们都在**同一个 JS task 内**用 `for` 循环派发 300 个合成 `PointerEvent`，
中间**不跑帧** ⇒ 清理循环执行时点的年龄已经攒到几百毫秒 ⇒ 点全活下来。
先后测到 `39944 / 61185 / 46656 / 32095`，**全是假绿**。
换成「事件与帧交替」（真实鼠标的节奏）立刻归零。

⇒ **探针必须复现生产的时序**，否则量到的是理想时序下的行为，与真机相反。

**修法（两处，同一条纪律）**：

| 位置 | ❌ 原来 | ✅ 现在 |
| --- | --- | --- |
| 回收循环 | `if (blobAlpha(age) <= 0.002) splice` | `if (age > LIFE) splice` |
| `draw()` 跳过 | `if (k <= 0.002) continue` | `if (age > LIFE) continue` |

判据统一成**寿命**（`age > LIFE`），`blobAlpha` 只剩「画的时候多浓」一个职责。
注意同一段代码里**落滴的回收本来就是按时间判的**（`ts - d.t0 > DROP_LIFE`）——
两套判据不一致就是 bug 的形状，照抄落滴那条即可。

**顺带修的第二处**：`rise` 原本是 `Math.min(1, age/(LIFE*0.08))`，从 0 爬上来，
等于「墨要 0.34 秒后才显形」，与母题「落下时最实」相反。
加 `RISE_FLOOR = 0.55`：落纸即半实的墨，随后在 `LIFE*0.08` 内吃满。

**验证**（`_probe/_ink-verify.mjs` 同时跑三种时序并列对比，判据以 T2/T3 为准）：

| 时序 | 事故时 | 修好后 |
| --- | --- | --- |
| T2 事件与帧交替 | ink=0, blobs=0, removed=200 | ink=38300, blobs=261, removed=0 |
| T3 `Input.dispatchMouseEvent` | ink=0, blobs=0 | ink=38942, blobs=259, removed=0 |
| 回收时的年龄 | `0.0002`（落纸即删） | `4.22`（= LIFE，寿命到了才删） |

- 契约 `tests/guestbook-inkdrop.test.ts` 加了两条锁住它：
  GC 判据必须含 `> LIFE`、且**不得**出现按浓度判的写法；`age=0` 的浓度必须为正且高于阈值。
- 变异测试 `_probe/_ink-mutate.mjs` 六个变异（含「退回本次事故的原始写法」）全部被抓住。

## 22. 导航栏（右上角那排）—— 现在有哪些、怎么改

导航是**全站共享**的，唯一事实来源是 `src/lib/nav.ts` 里的一个数组（**不是** `Brandline.astro`，那是旧位置）：

```ts
export const NAV_LINKS = [
  { href: '/', label: '主页', key: 'index' },
  { href: '/about/', label: '关于', key: 'about' },
  ...
];
```

- **想改名**：改 `label`（例如把「主页」改成「首页」）。
- **想调顺序**：把数组里的行上下挪。
- **想删一项**：删掉那一行。
- **想加一项**：加一行 `{ href: '/xxx/', label: '名字', key: 'yyy' }`，
  同时要把 `NavKey` 那个类型里也加上 `'yyy'`，并且那个页面得真的存在（否则点进去是死链）。
  **加完直接告诉我更稳** —— 加一项会改全站每个页面。
- 手机端（≤1023px）自动换成右上角的**抽屉菜单**，用的是同一份清单，所以改了 PC 的手机也同步。
- 文章详情页会把「归档」标成当前项（文章属于归档这份清单）；其他页面标自己那一项。

### 22.1 顶栏的玻璃 & 手机端的抽屉（想动内页顶栏先看这条）

**一句话**：内页顶栏（`.topbar`）自己**不带**模糊/变换，玻璃挂在 `.topbar::before` 上。

为什么（2026-10-08 站主报「手机端除了主页，其他页点不出来导航菜单」的根因）：
`backdrop-filter` 除了"糊一层"，还会**顺手做两件要命的事** ——

| 它做了什么 | 后果 |
|---|---|
| 建立 `position:fixed` 后代的**包含块** | 抽屉的 `.navshell` 是 `fixed; inset:0`，被收编后只铺满顶栏那条细带（实测 **62px**），面板里只剩「导航菜单」四个字 |
| 建立**层叠上下文** | `.navshell` 的 `z-index:40` 被锁在顶栏内部，而 `body.chrome-page main` 是 `z-index:1` ⇒ 抽屉还被正文压住 |

`transform` / `filter` / `perspective` / `will-change` / `contain` 会带来**同样的**两个后果
（首页 `index.astro` 里早就有一条注释专门躲开 `transform`，原因一模一样）。

**所以，想改内页顶栏的样子，请改这三处，别往 `.topbar` 本身加东西**：

| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 玻璃的颜色 / 模糊强度 / 底线 / 顶部高光 | `src/components/Topbar.astro` 的 `body.chrome-page .topbar::before` | `z-index` **必须是 0**；写 `-1` 会让 ∞ 底纹不透过来，玻璃变成一层纯白片 |
| 条高 / 内边距 / 字体 | `body.chrome-page .topbar`（**只放布局**） | 底线写 `transparent` 占位（颜色在 ::before 上画），删掉顶栏会矮 1px |
| 站名 / 导航 / 汉堡按钮的可见性 | `body.chrome-page .topbar > *:not(.navshell):not(.navtog)` 那组"抬到玻璃层之上"的规则 | ⚠ **排除 `.navshell` 与 `.navtog`**：前者是 `fixed`、后者小屏下是 `absolute`，被覆盖抽屉当场坏 |

**改完怎么验**（别靠肉眼）：

```bash
node _probe/_nav-probe.mjs          # 量各页抽屉铺没铺满视口 + 面板有没有被正文盖住
```

它逐页输出 `shell <盒高>（应=视口高）` 与「层叠命中」；红的那页会直接告诉你
**是哪个祖先建立了包含块**。改顶栏样式后跑一遍，全绿才算没伤到抽屉。
静态护栏在同一条测试里：`tests/nav-drawer-overflow.test.ts`。

### 23.1 归档页右侧那台「索引卷尺」（INDEX TAPE，2026-10-01 上线）

想改的话：

| 想改什么 | 改哪里 |
|---|---|
| 尺子多宽 / 多高 | `src/pages/archive.astro` 里 `.tape` 的 `width` 与 `height` |
| 刻度粗细 / 留墨的颜色 | 同文件 `.tape-tick` 的 `width`、`.tape-tick.past` 的 `background` |
| 游标跟手的手感 | `src/scripts/index-tape.ts` 里 `createSpring(0, { stiffness: 170, damping: 18 })` —— 调小更"硬"、调大阻尼更"粘"（过冲变小） |
| 手机断点 | 同文件 `@media (max-width: 767px)` 那个 `display: none` |

⚠️ **刻度是从你的文章自动推出来的**，不要写死年份 —— 明年发了 2027 的文章，
「2027」那一根刻度会自动出现在最上面。有条测试就是从文章文件真数篇数来比对刻度读数的。

⚠️⚠️ **尺子必须待在 `plate` 槽里（`<Fragment slot="plate">`），别搬回普通 slot**（2026-10-04 修过一次）。
它用 `position: fixed` 贴视口右缘，而**页面切换那 900ms 里 `.shell` 会带上 `filter: blur()`** ——
普通 slot 会落进 `.shell`，`filter` 会让 `.shell` 变成它的定位参照，于是尺子在切换瞬间
被推到视口下方（实测偏 596px，读数器正好压到年份刻度上）。`plate` 槽在 `.shell` 之外 ⇒ 免疫。
（当年加这个槽就是为了解决同一类问题，那时关于页的背景也跳过 91px。）
`z-index: 2` 要留着 —— 尺子得压在正文之上。

⚠️ 别改`data-pos` 的含义：那是**构建期算好的百分比位置**（0~100），
脚本靠它换算成像素。刻度要"等距"也是这条契约（测试会查相邻刻度的间距是否相等）。

参数换算表与设计决策见 `docs/rhinelab-spec.md` **§6.25**。

## 24.2 关于页的两栏版式（`/about`）

> 2026-10-03 站主：「右半部分太空，重新排版」。此前所有内容都限在正文宽度里单列排下来，
> 1280 视口下右半约 600px 全空。

### 现在长什么样

**1024px 起分两栏；低于 1024px 是原来的单列**（顺序一字未变）。

| 栏 | 装什么 | 为什么归在这边 |
|---|---|---|
| **左栏** | 页头（标题 + 头像）· 签名 · 正文 | 叙述类：窄栏、安静，适合连续阅读。宽度就是 `--measure` |
| **右栏** | 社交账号 · 技术栈 · 源码语言占比 | 读数类：清单与仪表。行短可扫读，窄栏里比通栏里更好读（通栏时一行只剩三五个字、两端全空）|

分栏依据不是「为了填满」，而是**内容本来就分两类**。

### 想改什么改哪个

| 想改 | 改哪儿 |
|---|---|
| 两栏的宽度比例 / 断点 | `about.astro` 的 `.about-grid`（`grid-template-columns`）|
| 哪块归左栏、哪块归右栏 | 模板里挪 `.about-main` / `.about-side` 的位置 |
| 右栏块与块之间的分隔 | `.about-side .fig-block` 的 `padding-top` + `border-top` |
| 右栏标题的大小 | `.about-side .fig-h` |
| 手机端的顺序 | **别动** —— 靠 `display:contents` 保住（见下） |

### 三条别动的约定

1. **正文 `.prose` 的宽度一个 token 都不许在本页改。** 它的宽度仍由 `src/styles/prose.css` 的
   `max-width: var(--measure)` 给，本页只靠 grid 第一列约束它。`tests/about-two-col.test.ts`
   守着这条（断言本页不得给 `.prose` 设 `width` / `max-width` / `font-size` / `line-height`）。
2. **窄屏顺序靠 `display:contents`，不要改成 grid 显式定位。** 若写 `grid-row` / `grid-column`，
   **DOM 顺序就会决定窄屏顺序** —— `aside` 在 `main` 之后，签名会掉到正文后面
   （改版前签名在正文之前）。`display:contents` 让 aside 不生成盒子、子元素直接参与父级流动。
3. **右栏块间距不要用 `gap`。** gap 与 `border-top` 同时存在时，两个半段间距会夹着一条线，
   看起来像「双线夹一段空白」。分隔只用「上边框 + `padding-top`」。

## 24.3 关于页的参考图底纹（`/about` 的背景层）

> 2026-10-03 站主要求：「直接用参考图里的素材，雕像月相各种图案都在那了，不要自己画」
> +「直接放到背景里，不要单独做一个卡片」+「背景最好用白色」。

### 是什么

`.ref-plate` 是 `position:fixed; inset:0` 的装饰层（`aria-hidden` + 空 alt + `pointer-events:none`），
里面四块**从站主参考图里取景**的元素，全部是**构建期裁好的小图**：

| 块 | 内容 | 摆位 |
|---|---|---|
| `ref-moon` | **月相序列环**（站主点名）| 右上角，大半滑出视口 |
| `ref-statue` | **维纳斯雕像**（站主点名）| 左下，贴左缘 |
| `ref-birds` | 飞鸟 + 同心圆线 | 右上偏下 |
| `ref-dial` | 圆盘 + 星芒 + 直尺 | 右下角 |

窄屏（≤767px）只留月相与雕像（站主点名的那两个）并再压淡一档。

### ★ 三条别动的约定

1. **必须裁文件，不能只用 CSS 取景。**
   CSS 的 `overflow:hidden` + 偏移能在浏览器里"取景"，但**浏览器仍会下载整张原图** ——
   原图 3–4 MB，三张就是 10 MB+。现在四张共 **482 KB**（进仓的源图），
   产物按视口出多档 srcset，`about/index.html` 引用的 webp 合计 < 2.5 MB。

## 29. 首页那个 3D DNA（站上唯一的第三方库）

**你平时不用管它**，下面三点只在你要动它的时候才看：

1. **它是懒加载的**，不会拖慢首屏。只有同时满足「容器在 + 你没开系统的减少动效 + 浏览器支持 WebGL +
   首屏真的滚进了视口」才会下载。开了减少动效、或用不支持 WebGL 的设备访问，一个字节都不下。
2. **模型是 `public/dna-slim.glb`**（328 KB），three 本体在 `src/vendor/` 下三个文件里。
   ⚠️ 它们**不能**挪进 `public/` —— 有一条测试守着「产物的 JS 必须都在 `dist/_astro/` 下」，
   从 `public/` 直拷出来的 `.js` 会被判成「手拷进来的」。
3. **★ 想在 DNA 里多用 three 的某个功能时，先改 `src/scripts/dna-scene.ts`** ——
   那里逐个登记了本站用到的 three 符号。原因是打包器只能对**具名**导入做瘦身：
   直接写 `import('three')` 拿到的是整个命名空间，它判断不出哪些没用到，整包 657 KB 会原样进产物；
   走这一层收口后是 542 KB。漏登记不会报错、只会静默变成 `undefined`，所以那里刻意不做 `export *`。

想整体关掉 DNA：删掉 `src/pages/index.astro` 里 `<script>` 那段对 `../scripts/dna3d` 的引用即可，

## 25. 素材处理 —— 「把照片里的东西抠出来」的标准流程（2026-10-05 立）

站主给一张照片，说"把里面的 X 抠出来"——本轮是墨笔 ∞。这条流程**可复用**，
下次抠别的东西照着走，别重新踩坑。

### 25.1 先量，别先动手

跑一遍统计再决定算法（托管 Python 有 PIL 12.3 + numpy 2.5）：

| 要看的 | 为什么 |
|---|---|
| 灰度 p1/p50/p99 | 纸白基线是多少、动态范围干不干净 |
| 32×32 块的 std 中位 | **纸纹起伏**——它决定阈值能取多低 |
| 深色区的**饱和度**（max−min） | 决定"能不能保原色"。本站素材饱和度 ≈1（中性黑）|
| 分块找 std 最小的区域 | 那是纯纸面，拿它当基线，别采到墨上 |

### 25.2 决定要不要 AI matting

**对比度干净就不用**。本轮纸白 237 / 墨黑 0 ⇒ 直接线性反相当 alpha：

```
alpha = (纸白 − 灰度) / 纸白
```

上 rembg 之类的模型反而会**吃掉飞白边缘**（那些淡墨是这张图的读法）。

### 25.3 三道清理，**顺序是硬约束**

| 步骤 | 本轮取值 | 做错的后果（实测） |
|---|---|---|
| ① 硬阈值 | `0.06`（灰度 < 222.8） | 取 0.03 → 纸纹全进来，墨迹行段数 **68 → 1**（满图）；取 0.12 → 飞白淡墨被砍 |
| ② gamma 提亮 | `a ** 0.75`，**必须在 ① 之后** | gamma 先做会把 0 附近的值放大约 3 倍，**已压掉的噪点全部复活** |
| ③ 去噪 | **删面积 < 5 的连通域** | 形态学开运算（半径 2）削掉 **25%**，把要保留的飞白一起削了；删小域只掉 1.67% |

★ 阈值取值法：**取"纸纹谷底再高一档"**。本轮纸纹谷底 225 ⇒ 对应 0.05，
所以取 0.06 —— 余量只有 2 灰阶，是这张图能取的最紧档。

### 25.4 分辨"残留"是素材还是噪点—— 看 alpha 均值，不看坐标

主体之外散着一堆小域时，**别按位置猜**。量alpha 均值：

- 主体墨迹 **0.87**
- 四角残留 **0.14–0.36** ⇒ 相机噪点与纸纹暗块，删

本轮按"**到主体 bbox 距离 > 200px**"一刀切，保留 **98.33%** 墨迹，
bbox 从满图 1920×1920 收敛到 1915×1058。

### 25.5 落盘规矩

- **素材不带死色**：想让它跟 token 走，就只留 alpha 通道、RGB 统一填成要用的 token 值
  （本轮填 `#266b3b` = `--accent-ink`）。⇒ 以后换颜色改 `tokens.css`，不用重抠。
- 放`src/assets/<page>/`，走 `astro:assets` 的 `<Image>`（自动出多档 webp + srcset）。
- **挂在 `plate` 槽**（`.shell` 之外），并**关掉本页共用的那层旧底纹**。
- CSS 里**不要叠底色**——素材自带 alpha，叠一层等于双重压暗。契约会查这条。

⚠ 本轮做错的一件事，记在这里别再犯：给 canvas 加 `hidden` 属性做"脚本到位才露面"——
**`hidden` 是 `display:none`，装置量不到尺寸（`clientWidth` 恒为 0）**，
画布永远空着而构建不报错。**canvas 的显隐只能用 opacity 门控**（见 §19.4）。

### 25.6 相册页背景那层 ∞（2026-10-08 换的）

你给的那张**蓝墨手绘 ∞** 抠出来、改成墨绿，**替换掉了相册三页（`/gallery/`、`/gallery/<册名>/`、
`/gallery/spiral/`）原来那层「百褶 ∞」**。它和日志页那层是同一套做法，只是换了张图。

### 25.7 照片的档位、缓存与「换图必须换文件名」（2026-10-08）

照片只有**两档**（`manifest.json` 的 `widths`）：**800**（网格 / 螺旋里贴的）与 **1280**（灯箱看的）。

| 想问的 | 一句话回答 |
|---|---|
| 点开大图慢在哪？ | 大档最大那张 475 KB，且站上没配缓存头 ⇒ CF 默认 `must-revalidate` **每次回源验证**（实测 TTFB 1.1–1.3 s、下载 4.1–6.1 s） |
| 现在怎么快起来的？ | ① `public/_headers` 给 `/_astro/*` 与 `/*.webp` 上了 1 年 `immutable`；② 开灯箱时**先用已经缓存的 800 档显形**，1280 在后台解码好再无声换上（`src/scripts/big-image.ts`） |
| 再加一档行不行？ | 行（`gen-gallery-webp.mjs` 加一档 + `manifest.widths` 加一项），但要重跑一次全部图；**本轮没做**，因为 1+2+3 的收益已经够了 |

★★ **一条必须记住的纪律：`public/gallery/**` 里的图不许原地覆盖，换了内容要另存新名。**

原因就是上面那个 `immutable`：文件名不变 ⇒ 读者一年内一直看到旧图（连 `Ctrl+F5` 都不一定管用，
因为 CDN 那一层也信 immutable）。本站是序号名（`01-800.webp`），所以"换图"= **新增一个序号**，
旧的删掉即可。这条写在了 `public/_headers` 的注释里。

**想改什么改哪里**

| 想要的 | 改哪儿 |
|---|---|
| 缓存时长 / 去掉 immutable | `public/_headers`（⚠ 给 HTML 长缓存是灾难，别写 `/*`） |
| 「先小后大」的时机、要不要预取下一张 | `src/scripts/big-image.ts`（两套灯箱共用这一个文件） |
| 灯箱里那只 `<img>` 的 `loading` | **别在 HTML 里去掉 `lazy`** —— 打开那一刻由 `showBig` 改成 eager，否则页面加载时就会去拉 475 KB |

**怎么验**：`npx vitest run tests/gallery-image-load.test.ts`（8 条：缓存头 / 不许给 HTML 长缓存 /
换图时机 / 竞态防护）；要肉眼看得证据就 `python _probe/_sp-side-lb.py`，看**灯箱那两个变体**
（`spiralthumb` = 拦掉 1280 档，箱里仍有图 ⇒ 秒显成立；`spiralfull` = 放行，最终换成 1280 且画面
不空白）。判据直接打在图上。
⚠ 同一个脚本里的 `impl` 变体查的是「螺旋侧壁」，那套改法已按站主要求撤回（spec §6.61.1），
现在读出来必然 `SIDES=0/82` —— 那个变体已无用。


## 31. 本机写作台（`<写作台目录>`）

**是什么**：一个跑在自己电脑上的写作界面 —— **不是网站的一部分**，不进仓库、不影响构建。
左侧是栏目、右侧是工作区；窗口左上那三个红黄绿小灯是**真的**能关 / 最小化到任务栏 / 最大化的
桌面窗口按钮（站主点名要照参考图做的那三个）。

**怎么开**：双击桌面上的「写作台」（或 `<写作台目录>//写作台.bat`）。
起不来就用「写作台（调试）.bat」（带控制台），出错的线索在 `运行日志.txt`。

| 栏目 | 它动的是哪儿 |
|---|---|
| 写作 | `content/posts/<slug>/index.md`，配图放**同一个目录** |
| 说说 | `content/pages/talks.md`；配图进 `src/assets/talks/`（站上唯一允许放图的地方） |
| 日志 | `content/pages/log.md`（正文末那条改动记录 = 站上显示的「最近更新」） |
| 相册照片 | `content/gallery/<相册>/` 里的原图 + `index.md` 登记 |
| 留言 | 读**线上** D1（Cloudflare）；删除要管理密钥，见下 |
| 发布 | 跑 `npm run verify`（构建 + 测试）→ 提交 → 推送 `main` |

**四条它不替你兜的事**

1. **界面上的校验只是"早点告诉你"** —— 真正算数的是 `npm run verify`。推送前那一步会替你跑它。
2. **新加进相册的图仍要登记到 `index.md`**（带 alt），否则站上不显示 —— 这是站上的规矩，不是工具偷懒。
3. **推到 `main` 就是在发布**（1–3 分钟）。写作台走的是 GitHub API 通道，
   **它自动建的提交 sha 与本地不同**（内容逐字节相同，别慌），细节见 `docs/rhinelab-spec.md` §6.67。
4. **它的配色是 `src/styles/tokens.css` 的镜像**（`ui/style.css`）。站上改了 token，
   写作台那份也要跟着改，否则两边会慢慢长歪。

**才能删线上留言：两件事，密钥必须一样**

1. Cloudflare → Pages 项目 `personal` → Settings → Environment variables → 新增 `ADMIN_TOKEN`，
   类型选 **Secret**。值自取（`openssl rand -hex 32` 的输出就很好）。
   命令行等价：`npx wrangler pages secret put ADMIN_TOKEN --project-name personal`
2. 写作台 →「设置」→「留言管理密钥」→ 填**同一个值** → 保存。

**没配也照常用**：写文章 / 说说 / 日志 / 传图 / 一键推送都不受影响，只有「留言」页会说
"还没配管理密钥"。站上那条接口是 **fail closed** 的 —— `ADMIN_TOKEN` 一旦没配，
它对**任何**请求都回 500、一个人都不放行：宁可"用不了"，也不要"谁都能删"
（`AGENTS.md` §3 第 8 条 · 设计记录 `docs/rhinelab-spec.md` §6.67）。
